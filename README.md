# recon — 纯本地物体 3D 扫描建模内核

跨平台（iOS / Android）物体级高精度三维重建内核。全部运算在设备本地完成，  
无服务器、无上传、无网络传输。

---

## 核心原则

```
几何建模精准度  >  模型拓扑完整性  >  纹理质量  >  运行速度
```

- 允许重建耗时变长、占用内存偏高，**绝不以精度换速度**
- 低端机降级只降并行度 / 分块策略，**不降精度参数**
- 关键帧只要对精度有增益即全量保留
- 全参数开放用户调节，附快速 / 标准 / 高精度三档预设

## 双管线（平级，非主次）

| 探测结果               | 分支            | 主导几何                | 尺度来源               |
| ------------------ | ------------- | ------------------- | ------------------ |
| LiDAR / ToF / 运动深度 | `BRANCH_RGBD` | MVS 主导 + TSDF 融合    | 深度锚定 + **强制参照物复核** |
| 无深度传感器             | `BRANCH_MONO` | MVS（VIO + SfM + 稠密） | **强制参照物标定**        |

两条分支**同为同等精度路径**。曲面精度由多视图几何决定，深度传感器提供的是  
尺度锚定与弱纹理区覆盖，不构成能力分级。详见 `docs/00_架构总纲.md` §4.5。

> 消费级 IMU 的尺度精度仅 5%~10%（实测：直线 9.2%、圆周 6.4%、8 字 4.8%），  
> 远不足以满足"绝对精准物理尺度"。参照物标定可达 0.3%~0.5%，是唯一达标来源，  
> 在**全机型**上均为强制步骤。

## 目录

```
core/          重建核心（C++17，跨端共享）
  include/recon/   对外边界：recon_c_api.h 是唯一跨语言入口
  src/             util / capture / sync / rgbd / calib / postproc / export
platform/       平台适配（ios: AVFoundation+ARKit+CoreMotion；android: CameraX+ARCore）
shaders/        计算着色器（Metal / Vulkan）
tools/          license_scan.py（许可硬门禁）、recon_cli.cpp（桌面验证工具）
tests/unit/     单元测试
docs/           15 篇工程规格文档（约 21000 行）
```

## 构建

```bash
# 配置
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release

# 构建
cmake --build build

# 测试
cd build && ctest --output-on-failure

# 许可门禁（独立前置任务，命中 GPL/AGPL 即失败）
python tools/license_scan.py --third-party third_party
```

要求 CMake ≥ 3.22、支持 C++17 的编译器。可选依赖：Ceres（BSD-3-Clause）、  
Eigen3（MPL-2.0，边界项 B-1）、OpenCV（Apache-2.0）、xatlas（MIT）。

### 平台构建

```bash
# Android：NDK r28+（16KB 页对齐），AGP 8.5.1+
cmake -S . -B build-android -G Ninja \
  -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK/build/cmake/android.toolchain.cmake \
  -DANDROID_ABI=arm64-v8a -DANDROID_PLATFORM=android-26

# iOS：通过 Xcode 生成工程
cmake -S . -B build-ios -G Xcode -DIOS=ON
```

## CLI

```bash
./build/recon_cli params        # 打印参数注册表（128 项，含三档预设）
./build/recon_cli capability    # 打印设备能力探测结果
./build/recon_cli export in.obj out.glb   # 校验并导出模型
```

| 项目          | 实测                           | 说明                  |
| ----------- | ---------------------------- | ------------------- |
| 角点初始定位      | 0.865 px                     | 亚像素坐标生效（响应图十字抛物线插值） |
| **KLT 跟踪**  | **平均 0.0031 px，最大 0.102 px** | 双向一致性检查后；剔除率 9.1%   |
| MSCKF 零空间残差 | **0.0000 px**                | 35/35 约束全部成立        |

## 泊松网格化精度实测（合成球面，解析真值）

测试条件：半径 50 mm 的球面，20000 个均匀采样点（采样间距 1.18 mm），  
深度按 §1.3 的点云密度约束**自动选定** = 7（r = 0.8594 mm）。  
真值半径精确已知 → 径向误差直接就是形状误差。

| 阶段                  | 实测                                          | 说明                        |
| ------------------- | ------------------------------------------- | ------------------------- |
| **实际边长 / 标称 r**     | **1.02**                                    | §1.3 声明区间 0.8~1.2 ✓       |
| **网格覆盖率**（面积 / 球面积） | **107.4%**                                  | 含外扩区，主体完整                 |
| 主体三角形边长中位           | 0.9380 mm                                   |                           |
| **流水线后拓扑**          | **非流形边 0，边界环 11282（= 未填孔洞数）**               | 填了的洞真的闭合，没填的洞如实上报         |
| **S7 短边坍缩 + 边翻转**   | 最小内角 P1 2.69°→**5.06°**，P5 5.44°→**10.75°** | 狭长面 4.7%→**1.1%**；非流形边仍 0 |

**深度=9（r = 0.215 mm，点云间距的 5.5 倍）—— 验证细网格不再碎裂**

| 指标             | 实测                                                             |
| -------------- | -------------------------------------------------------------- |
| 致密化            | k = 6，点数 20000 → 72 万                                          |
| 活跃单元 / 未定义格点查询 | 1,355,396 / **0**（求解域完全连通）                                     |
| MC 产出 → 裁剪后三角形 | 1,814,127 → 1,793,942（只删 1%）                                   |
| **网格覆盖率**      | **88.8%**                                                      |
| 实际边长 / 标称 r    | **1.03**                                                       |
| 流水线后           | 非流形边 **0**，绕序不一致 6.7%（参考量：泊松 MC 不可定向结构 + 假邻接边残余，见 §2.5.1 (26)） |

同一配置在修复前覆盖率只有 **7.3%**。

关键实现决策（详见 `docs/06_网格化与后处理.md` §2.5.1）：

- **MC 表的编号体系必须与表来源一致**（本模块最严重的缺陷）：表数据用  
  `CornerIndex = x+2y+4z` 与 `EdgeIndex(orientation,i,j)`，而实现按 Bourke 经典  
  顺序写 → **12 条棱里 8 条端点错位** → `kEdgeMask` 与 `kTriangles` 引用对不上  
  → 大量三角形被静默丢弃（实测 181 万 → 30 万，非流形边 3262）。已加  
  `TestMcTableConsistency` 单测：256 个 case、820 个三角形、0 处越界。
- **点云切平面致密化**：活跃单元 = 「点云支撑 + 一环」，点云间距是单元边长的  
  k 倍时这些单元团**互不连通** → 求解域断开 → `value_at()` 对未覆盖格点返回  
  0.0，而 iso 也≈0 → 等值面恰好被「未定义区」切碎。致密化把点云沿切平面展开到  
  「等效间距 ≤ r」让单元连成片。**不增加几何信息**，形状精度上限仍是点云密度。
- **screened 项强度必须远小于对角项**：写成 67% 时整块点云区域被压平在 iso 上，  
  等值面 f = iso 在区域内部根本不存在 → 网格碎成孤立片。改为 ~12%。
- **同一逻辑写两遍必然漂移**：裁剪的 τ 需要点云间距，早期在裁剪处重写了一遍  
  「最近邻中位数」却漏了排除自身 → `cloud_spacing = 0` → τ 退化成 `2r` →  
  主体被裁掉一半（删 79%）。现在只保留 `EstimatePointSpacing()` 一份实现。
- **Marching Cubes 而非 Marching Tetrahedra**：MT 共享体素对角线必然产生  
  非流形边（实测 11675 条 → 换 MC 后降到 59 条，降 99.5%）
- **提取层必须用 `depth` 而非 `depth-1`**：旧实现让实际网格比标称分辨率  
  **粗一倍**（边长比 2.10，违反 §1.3 的 0.8~1.2 声明）
- **泊松场的量纲**：梯度累积必须除以边长 `h`（不是体积 `h³`），否则  
  条件数劣化到 3.8e6、PCG 发散
- **孔洞填充复用原边界顶点**：用投影出的新顶点组环会导致原边界边仍只有  
  1 个面 —— 孔洞根本没被闭合，还凭空多出一圈边界环
- **补洞必须校验绕序**：填充面若与相邻原面在共享边同向，说明补片穿进了  
  网格内部（那不是真洞，是外扩区切口）→ 宁可留洞
- **孤立面片要删不要补**：外扩区的三角形碎片补面会造出完全重合的面
- **S4 与 S5 必须成对迭代**：S4 的顶点分裂必然撕开已闭合的洞，  
  拆完要补，补完可能又造出非流形边
- **绕序传播对碎片化网格有害**：`OrientFacesConsistently` 的 BFS 会沿  
  「恰好共用一条边的假邻接边」把互不相邻的面片串成一块并强加种子朝向 →  
  把泊松输出原本整齐朝内的整块翻错（面积朝外 87.8% → 66.8%，不可逆）。  
  改用「逐分量径向符号翻转 + 不传播局部多数表决」后，面积朝外稳定保持  
  87.6%。「绕序一致」与「朝向正确」在泊松碎片化输出上**互斥**，须明确取舍  
  （见 `docs/06` §2.5.1 (26)）

## MVS 精度实测（合成场景，解析真值）

测试条件等比缩放自手机典型工况（f=2500px、B=100mm、Z=0.35m → f=400px、B=16mm）：

| 阶段         | 深度误差中位      | 说明                   |
| ---------- | ----------- | -------------------- |
| 整数视差       | 5.56 mm     | 1 px 视差 = 19.1 mm 深度 |
| **亚像素细化后** | **0.88 mm** | **改善 6.3 倍**         |

理论预期（δd = 0.15 px）为 2.87 mm，实测优于理论 3.3 倍。  
外推到真实手机参数：误差按 Z²/(f·B) 缩小 6.25 倍 → **约 0.14 mm**，  
与 `docs/05_单目管线.md` §6.1 的 0.074–0.171 mm 精度预算一致。

关键实现决策（详见 05 文档 §5.3.1.1）：

- 搜索参数用**逆深度 1/Z**，不用视差（多视图下各源视图视差不同，  
  用单一基线换算会引入系统偏差）
- 随机搜索半径用**相对比例**（当前深度 ±30%），不用固定像素数
- 细化窗口按 **1 px 视差对应的逆深度变化** 设定，否则抛物线拟合看不到真实代价形状
