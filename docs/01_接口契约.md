## 1. 跨语言边界原则

### 1.1 五条铁律

| 原则           | 内容                                                                                                   | 违反后果           |
| ------------ | ---------------------------------------------------------------------------------------------------- | -------------- |
| **POD-only** | 跨边界只传 POD 结构体与标量。不传 `std::` 容器、迭代器、智能指针、引用、异常对象                                                      | ABI 不稳定，二进制不兼容 |
| **所有权明确**    | 入参指针一律由调用方持有，核心层不接管；核心层返回的 `char*` / `void*` 缓冲区一律由调用方用 `recon_free_string` / `recon_free_buffer` 释放 | 泄漏 / 双重释放      |
| **无异常跨界**    | C++ 异常在边界内全部捕获，转为 `recon_status` 错误码 + `recon_get_last_error` 的文本                                    | App 崩溃         |
| **线程安全**     | 句柄默认**不可**跨线程并发调用；标注 `_thread` 后缀的函数可跨线程并发调用，其余需外部串行化                                                | 数据竞争           |
| **版本号**      | `RECON_ABI_VERSION` 随破坏性变更递增；App 与 core 必须同版本                                                        | 结构体布局错位        |

### 1.2 头文件包含的唯一性（强制）

| 规则      | 内容                                                                                                                                                                                              |
| ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **H-1** | Swift / Kotlin 侧**不得**直接 `#include` 任何 `core/` 内部头文件（`types.h`、`status.h`、`params.h` 及其以下的任何头）。唯一允许包含的是 `core/include/recon/recon_c_api.h`                                                      |
| **H-2** | iOS 侧 `Recon-Bridging-Header.h` 与 `ReconCore/include/module.modulemap` 中出现的头文件**有且仅有** `recon/recon_c_api.h`。12 文档 §4.2 当前的 module map 含 `types.h` / `status.h` 两项，与本规则冲突，须回填为仅 `recon_c_api.h` |
| **H-3** | Android 侧 `ReconBridge.kt` 只经 JNI 调用，JNI 层（`platform/android/**.cpp`）只允许 `#include "recon/recon_c_api.h"`                                                                                       |
| **H-4** | `platform/ios/*.mm` / `platform/android/*.cpp` 属于平台实现层，允许 include 平台头与 `recon_c_api.h`；**不允许** include `core/` 的算法头（`core/vio/`、`core/mvs/` 等）                                                  |
| **H-5** | `recon_c_api.h` 自身**不得** include 任何 `core/` 内部头、任何 C++ 标准库头、任何第三方头。它只 include `<stdint.h>` 与 `<stddef.h>`                                                                                       |
| **H-6** | `recon_c_api.h` 不得出现 `extern "C"` 之外的 C++ 语法（无模板、无类、无引用、无默认实参、无重载）                                                                                                                              |

> **CI 强制**：`tools/abi_audit.py` 扫描 Swift / Kotlin / ObjC++ / JNI 源文件的 `#include` / `import`，命中 `core/` 内部头即失败。检查项编号对应 11 文档 §7.2 的清单。

### 1.3 ABI 兼容规则

| 变更类型                       | App 版本   | 管线版本     | `RECON_ABI_VERSION` |
| -------------------------- | -------- | -------- | ------------------- |
| 新增函数（不删不改旧函数）              | MINOR +1 | MINOR +1 | 不变                  |
| 新增错误码（追加数值）                | MINOR +1 | 不变       | 不变                  |
| 修改任一 POD 结构体字段布局 / 顺序 / 类型 | MAJOR +1 | MAJOR +1 | **+1**              |
| 移除或重命名 C ABI 函数            | MAJOR +1 | MAJOR +1 | **+1**              |
| 改动错误码语义（不只是新增）             | MAJOR +1 | MAJOR +1 | **+1**              |

> `RECON_ABI_VERSION` 当前值：**1**。版本判定与 12 文档 §7.1 同步。

### 1.4 线程模型总则

| 约定        | 内容                                                                                                                                                                                                             |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 句柄并发      | `recon_context*` 在同一时刻只允许**一个**线程调用其上的任意函数。需要并发时由调用方加锁，或改用编排层的任务队列接口                                                                                                                                           |
| 允许并发调用的函数 | 仅 §2.3 标注「可并发」的纯查询类函数：`recon_get_abi_version`、`recon_get_pipeline_version`、`recon_get_capability`、`recon_get_progress`、`recon_get_last_error`、`recon_params_list_keys`、`recon_free_string`、`recon_free_buffer` |
| 回调线程      | 进度 / 状态文字 / 日志回调均由**核心线程**触发（同一线程串行，不重入）。回调内**不得**调用同一 `recon_context` 的其他 API（重入保护）                                                                                                                           |
| 阻塞        | 除显式标注外，本文的 API 不长时间阻塞；`recon_push_frame` 在写盘队列拥塞时最多阻塞 1000 ms 后返回 `RECON_ERR_CAPTURE_BACKPRESSURE`                                                                                                             |

## 2. `recon_c_api.h` 完整定义

> ### ⚠️ 契约漂移裁定（2026-10-31）
>
> 本节与仓库中的真实头文件 `core/include/recon/recon_c_api.h` **存在两套互不兼容的接口设计**。
> 裁定结果与依据如下，**§2.1 / §2.2 / §2.3 的 37 函数版本已被标注为「未采纳草案」**。
>
> | 项 | **docs/01 §2.1（本节）** | **`core/include/recon/recon_c_api.h`（实际）** |
> |---|---|---|
> | 函数总数 | **37** | **21** |
> | 上下文句柄 | `recon_context*`（不透明指针 typedef） | `void*` |
> | 版本函数 | `recon_get_abi_version(int32_t*)` 返回 `recon_status` | `recon_abi_version()` 直接返回 `uint32_t` |
> | 参数接口 | `recon_params_set/get/get_effective/get_group/list_keys/apply_preset/reset/validate`（8 个） | `recon_set_param/get_param/apply_preset/export_params`（4 个） |
> | 会话续算 | `recon_resume_session` / `recon_abort_capture` / `recon_get_frame_quality` | **不存在** |
> | 进度/回调 | `recon_get_progress` / `recon_set_callbacks` / `recon_get_last_error` / `recon_set_log_level` | 回调经 `recon_run_reconstruction` 入参传入，**无独立注册函数** |
> | 导出校验 | `recon_export_validate` / `recon_get_export_report` | **不存在**（校验在 `recon_export` 内联完成） |
> | 能力探测 | `recon_get_capability` | `recon_probe_capability` |
> | 尺度标定 | `recon_run_scale_calibration` / `recon_get_scale_result` | `recon_calibrate_scale`（一次性返回结果） |
>
> **裁定：以实际头文件（21 函数）为准。** 依据：
> 1. **该版本已实现并有测试覆盖** —— `core/src/util/c_api.cpp`（462 行）+ `tests/unit/test_c_api.cpp`，且 `test_pipeline.cpp` 走通全链路。**能跑、有测试**的版本优先于纯文档版本（本项目铁律「单测孤岛不等于系统可跑」的反向应用：系统已在跑）。
> 2. **下游文档只引用交集（实测，非估计）** —— 用脚本扫描 `docs/` 中除本文外的全部 md，提取其中出现的 `recon_*` 标识符并按归属分类，结果：
>    - **被其他文档引用的 C ABI 函数共 8 个**：`recon_start_session` / `recon_push_frame` / `recon_finish_capture` / `recon_run_reconstruction` / `recon_cancel` / `recon_create` / `recon_destroy` / `recon_export` —— **全部落在交集内**。
>    - **草案独占的 23 个函数，无任何下游文档引用**（0 处）。
>    - 其余 `recon_*` 出现均为**类型名**（`recon_config` / `recon_mesh_info` / `recon_status` / `recon_pose` …）或**构建目标/文件名**（`recon_core` / `recon_vision` / `recon_shaders_metal` …），不是函数。
>    - 因此，**分歧部分（only-doc 23 与 only-real 7）没有任何下游消费者**，改文档不会波及实现。
>    - 注：**交集大小 = 14**（两侧都有的函数数），与「被其他文档引用数 = 8」是两个不同口径，勿混。
> 3. **POD 类型定义以真实头文件为准（实测）** —— 真实头文件定义 **10 个** `recon_*` 结构体，**全部**在草案中也有同名定义（成员布局一致）：`recon_config` / `recon_frame_packet` / `recon_mesh_info` / `recon_export_options` / `recon_scan_stats` / `recon_scale_result` / `recon_capability` / `recon_camera_intrinsics` / `recon_pose` / `recon_imu_sample`。
>    草案**另独占 9 个**结构体（真实头文件中不存在）：`recon_context`（真实侧用裸 `void*`）、`recon_progress`、`recon_callbacks`、`recon_reconstruction_options`、`recon_export_report`、`recon_frame_quality`、`recon_param_value`、`recon_param_issue`、`recon_calibration_request`。
>    ⚠️ **注意**：真实头文件中的 `recon_progress_cb` 是**回调函数指针 typedef**，与草案的 `recon_progress` **结构体**同名不同物，勿混。
>    **差异仅在「函数层 + 草案独占结构体」两处；两侧共有的 10 个结构体布局一致。** 因此本次裁定**不改动任何已存在 POD 的布局，不影响 ABI 版本号**（`RECON_ABI_VERSION` 仍为 1）。
>
> **未决事项（明确保留，不假装已解决）**：草案独占的 **23 个函数**按「有无替代机制」如实三分如下（此分类已逐函数核对真实头文件，非推测）：
>
> **A. 纯命名/形态差异 —— 替代完整（12 项）**
> `recon_get_abi_version`→`recon_abi_version()`（直接返回 `uint32_t`）；`recon_get_capability`→`recon_probe_capability`；`recon_run_scale_calibration`+`recon_get_scale_result`→`recon_calibrate_scale`（一次性填充 `recon_scale_result`）；`recon_params_set/get/get_effective/get_group/list_keys/apply_preset/reset/validate`（8 个）→`recon_set_param`/`recon_get_param`/`recon_apply_preset`/`recon_export_params`（4 个）。合计 **2+2+8=12**，**能力无缺失，仅拆分粒度不同。**
>
> **B. 由回调入参覆盖 —— 替代完整但形态不同（4 项）**
> `recon_get_progress`→`recon_run_reconstruction` 的 `recon_progress_cb` 入参；`recon_set_callbacks`→同函数的 `progress_cb`/`status_cb`/`log_cb` 三个入参（**无需独立注册函数**）；`recon_get_last_error`→`recon_status_cb` 的 `text` 入参 + 各函数 `recon_status` 返回值。`recon_set_log_level` **替代不完整**：`recon_log_cb` 能按 `level` 过滤回调，但头文件**没有设置日志级别的入口**——属半缺口（低风险，可在下一版补 `recon_set_param` 的日志键，或接受「回调侧过滤」）。
>
> **C. 真实缺口 —— 无任何替代机制（7 项，UI 需要时必须扩展头文件）**
> | 缺失函数 | 名义能力 | 现状（真实头文件） |
> |---|---|---|
> | `recon_get_export_report` / `recon_export_validate` | 导出后逐项校验报告（**docs/09 §3.10 的 17 项校验结果列表**） | `recon_export` **内联**做校验并只返回 `RECON_ERR_EXPORT_VALIDATION_FAILED`（1001）；**无逐项报告出口** → UI **当前无法填充 17 项列表** |
> | `recon_resume_session` | 断点续算（**docs/09 T-22 明示「允许从最近阶段检查点恢复」**） | 无恢复入口（`recon_cancel` 后只能重启重建，已落盘原始帧可复用） |
> | `recon_get_frame_quality` | 逐帧质量实时反馈 | `recon_scan_stats` 只有**会话级**聚合（`anomaly_*` 计数器），**无逐帧接口** |
> | `recon_get_mesh_attribute` | 逐顶点/逐面属性读取 | `recon_get_mesh_info` 只有**计数**，无属性数组出口 |
> | `recon_get_pipeline_version` | 流水线版本字符串 | 无（当前 ABI 版本经 `recon_abi_version` 可得，流水线版本无出口） |
> | `recon_abort_capture` | 中止采集 | **部分覆盖**：客户端停推帧 + `recon_cancel` 即可（无独立「中止采集」语义函数） |
>
> **结论与约束**：C 类 7 项中，**真正阻塞 UI 的只有导出报告链**（docs/09 §3.10 的 17 项列表）与**断点续算**（docs/09 T-22）；其余 5 项为次要或已有工作区绕法。
> **这些能力若要落地，必须先扩展头文件（递增 `RECON_ABI_VERSION`）并同步本锚点**；在此之前，**UI 侧不得假设它们存在**。
> 注：docs/09 目前**显式引用**的 C ABI 函数仅 3 个（`recon_finish_capture` / `recon_run_reconstruction` / `recon_cancel`，见 T-17/T-22），**全部落在交集内**；上表 C 类属**设计层待办**，不是「已有代码在调用缺失函数」的运行时故障。
>
> 详细裁定记录与取证过程见 `.workbuddy/memory/` 的对应日期条目。
>

### 2.1 头文件全文

> **以下为未采纳草案（37 函数版），保留供参考。真实头文件见 `core/include/recon/recon_c_api.h`。**
> 两者的差异对照与裁定依据见上方锚点。**新增实现或修改接口前必须先读上方锚点。**

```c
/* ==========================================================================
 * recon_c_api.h — 本项目唯一的跨语言边界
 * --------------------------------------------------------------------------
 * 维护规则：
 *   1. 本文件不得 include 任何 core/ 内部头、任何 C++ 标准库头、任何第三方头。
 *   2. 只允许 C99 语法 + extern "C" 包裹。
 *   3. 破坏性变更（结构体布局 / 函数签名 / 错误码语义）必须递增
 *      RECON_ABI_VERSION，并同步 12 文档 §7.1 的版本判定表。
 *   4. 所有跨边界类型必须是 POD（trivially copyable）；禁止位域、禁止
 *      非平凡构造、禁止变长数组、禁止 flexible array member。
 *   5. 所有 const char* 入参由调用方持有；所有返回的缓冲区由调用方用
 *      recon_free_string / recon_free_buffer 释放。
 * ========================================================================== */

#ifndef RECON_RECON_C_API_H_
#define RECON_RECON_C_API_H_

#include <stddef.h>
#include <stdint.h>

#ifdef __cplusplus
extern "C" {
#endif

/* --------------------------------------------------------------------------
 * 导出宏
 * ------------------------------------------------------------------------ */
#if defined(_WIN32)
#  if defined(RECON_CORE_BUILD)
#    define RECON_API __declspec(dllexport)
#  else
#    define RECON_API __declspec(dllimport)
#  endif
#else
#  if defined(RECON_CORE_BUILD)
#    define RECON_API __attribute__((visibility("default")))
#  else
#    define RECON_API
#  endif
#endif

/* --------------------------------------------------------------------------
 * 版本宏
 * ------------------------------------------------------------------------ */
#define RECON_ABI_VERSION        1
#define RECON_ABI_VERSION_STRING "1.0"

/* 相机内参。单位：像素 / 毫米（基线以毫米给出时另标）。 */
typedef struct recon_camera_intrinsics {
    float    fx;                 /* 像素，无效时为 0 */
    float    fy;                 /* 像素，无效时为 0 */
    float    cx;                 /* 像素 */
    float    cy;                 /* 像素 */
    uint32_t width;              /* 图像宽，像素 */
    uint32_t height;             /* 图像高，像素 */
    float    distortion[5];      /* k1,k2,p1,p2,k3，k1..k3=0 表示无畸变 */
    float    baseline_mm;        /* 深度相机与 RGB 相机基线，毫米；0 = 同光心 */
    uint32_t distortion_model;   /* 0=无 1=RADIAL_KANNALA_BRANDT 2=BROWN_CONRADY */
    uint32_t reserved;           /* 置 0 */
} recon_camera_intrinsics;

/* 位姿。R 为行主序 3×3，t 单位米。 */
typedef struct recon_pose {
    float    rotation[9];        /* 行主序 3×3，正交阵 */
    float    translation[3];     /* 米 */
    uint32_t valid;              /* 0=无位姿 1=有效 */
    uint32_t source;             /* 0=平台 1=VIO 2=SfM/BA 3=用户 */
} recon_pose;

/* 单条 IMU 采样。 */
typedef struct recon_imu_sample {
    int64_t  timestamp_ns;       /* 纳秒，session timebase，与帧时间同源 */
    float    gyro[3];            /* rad/s */
    float    accel[3];           /* m/s^2，比力（含重力反作用） */
    uint32_t status;             /* bit0 gyro 有效 bit1 accel 有效 bit2 已饱和 */
    uint32_t reserved;           /* 置 0 */
} recon_imu_sample;

/* 帧包：跨边界唯一的数据单元。
 * 边界格式固定：rgb_data = BGRA8；depth_data = uint16 毫米（沿光轴 z）。 */
typedef struct recon_frame_packet {
    uint64_t frame_id;               /* 会话内单调递增，从 1 开始 */
    uint64_t timestamp_ns;           /* 曝光中点估计，纳秒，session timebase */
    uint32_t rgb_width;              /* 像素 */
    uint32_t rgb_height;             /* 像素 */
    uint32_t depth_width;            /* 像素；0 = 无深度 */
    uint32_t depth_height;           /* 像素；0 = 无深度 */
    uint32_t has_depth;              /* 0/1 */
    uint32_t depth_tier;             /* recon_depth_tier */
    uint32_t depth_source;           /* recon_depth_source */
    uint32_t reserved0;              /* 置 0 */
    const uint8_t* rgb_data;         /* BGRA8，长度 >= rgb_stride*rgb_height；可为 NULL（= 无图像） */
    uint32_t rgb_stride;             /* 字节/行 */
    const uint8_t* depth_data;       /* uint16 毫米；has_depth=0 时为 NULL */
    uint32_t depth_stride;           /* 字节/行 */
    const uint8_t* depth_confidence; /* uint8，0=无效；可为 NULL */
    const recon_camera_intrinsics* intrinsics; /* 可为 NULL */
    const recon_pose* pose;          /* 平台位姿先验；可为 NULL */
    const recon_imu_sample* imu;     /* 本帧之前的时间窗采样；可为 NULL */
    uint32_t imu_count;              /*imu 为 NULL 时必须为 0 */
    uint32_t reserved1;              /* 置 0 */
    float    motion_blur_score;      /* 平台侧预估计，0..1 */
    float    exposure_us;            /* 曝光时长，微秒 */
    uint32_t iso;                    /* ISO 感光度 */
    uint32_t reserved2;              /* 置 0 */
} recon_frame_packet;
```

### 2.2 POD 类型字段规格

> 全部类型均为 POD（trivially copyable）。所有 `reserved` / `reserved0..2` 字段必须置 0，核心层读到非 0 值按 `RECON_ERR_INVALID_ARGUMENT` 处理。

#### 2.2.1 `recon_status` / `recon_warning`

| 项       | 规格                                                       |
| ------- | -------------------------------------------------------- |
| 底层类型    | `enum`（C++ 侧 `static_assert(sizeof(recon_status) == 4)`） |
| 取值      | §4 的完整错误码 / 告警码表                                         |
| 语义      | 错误码表示**本次调用失败**；告警码表示**成功但有降级或风险**                       |
| 可为 NULL | 不适用（值类型）                                                 |

#### 2.2.2 `recon_camera_intrinsics`

| 字段                 | 类型       | 语义             | 单位  | 可为 NULL      |
| ------------------ | -------- | -------------- | --- | ------------ |
| `fx` / `fy`        | float    | 焦距             | 像素  | 否（0 = 无效）    |
| `cx` / `cy`        | float    | 主点             | 像素  | 否            |
| `width` / `height` | uint32   | 该内参对应的图像尺寸     | 像素  | 否            |
| `distortion[5]`    | float[5] | k1,k2,p1,p2,k3 | 无量纲 | 否（全 0 = 无畸变） |
| `baseline_mm`      | float    | 深度相机–RGB 基线    | 毫米  | 否（0 = 同光心假设） |
| `distortion_model` | uint32   | 畸变模型枚举         | —   | 否            |
| `reserved`         | uint32   | 置 0            | —   | 否            |

> FOV ≥ 100° 的广角必须使用 `RADIAL_KANNALA_BRANDT`（02 C-4）。

#### 2.2.3 `recon_pose`

| 字段               | 类型       | 语义                       | 单位  | 可为 NULL |
| ---------------- | -------- | ------------------------ | --- | ------- |
| `rotation[9]`    | float[9] | 行主序 3×3 旋转矩阵             | 无量纲 | 否       |
| `translation[3]` | float[3] | 平移                       | 米   | 否       |
| `valid`          | uint32   | 0 = 无位姿，1 = 有效           | —   | 否       |
| `source`         | uint32   | 0=平台 1=VIO 2=SfM/BA 3=用户 | —   | 否       |

> 指针 `pose` 本身可为 NULL，表示该帧无平台位姿先验（纯视觉路径）。

#### 2.2.4 `recon_imu_sample`

| 字段             | 类型       | 语义                                      | 单位    | 可为 NULL |
| -------------- | -------- | --------------------------------------- | ----- | ------- |
| `timestamp_ns` | int64    | 采样时刻，session timebase，与相机同源             | 纳秒    | 否       |
| `gyro[3]`      | float[3] | 角速度                                     | rad/s | 否       |
| `accel[3]`     | float[3] | 比力（含重力反作用）                              | m/s²  | 否       |
| `status`       | uint32   | bit0 gyro 有效 / bit1 accel 有效 / bit2 已饱和 | —     | 否       |
| `reserved`     | uint32   | 置 0                                     | —     | 否       |

#### 2.2.5 `recon_frame_packet`

| 字段                             | 类型                             | 语义                        | 单位   | 可为 NULL                    |
| ------------------------------ | ------------------------------ | ------------------------- | ---- | -------------------------- |
| `frame_id`                     | uint64                         | 会话内单调递增，从 1 开始            | —    | 否                          |
| `timestamp_ns`                 | uint64                         | 曝光中点估计时刻，session timebase | 纳秒   | 否                          |
| `rgb_width` / `rgb_height`     | uint32                         | RGB 尺寸                    | 像素   | 否                          |
| `depth_width` / `depth_height` | uint32                         | 深度尺寸；0 = 无深度              | 像素   | 否                          |
| `has_depth`                    | uint32                         | 0/1                       | —    | 否                          |
| `depth_tier`                   | uint32                         | `recon_depth_tier`        | —    | 否                          |
| `depth_source`                 | uint32                         | `recon_depth_source`      | —    | 否                          |

**边界格式 vs 落盘格式（必须区分）**：

| 层               | RGB                 | 深度              | 依据                |
| --------------- | ------------------- | --------------- | ----------------- |
| C ABI 边界        | **固定 BGRA8**        | uint16 毫米，沿光轴 z | 11 §3.7；平台层负责转换   |
| 落盘 `frames.bin` | 平台原生（NV21 / YUV420） | uint16 毫米，沿光轴 z | 02 §5.5 F-1 / F-2 |

> 00 文档 §7.2 的 `recon_frame_packet` 是节选版。本文在 `rgb_data` 之前补充了 `depth_source` 与 `reserved0`，在尾部补充了 `exposure_us` / `iso` / `reserved2`；字段增补不改变原有字段顺序。**本布局为 `RECON_ABI_VERSION = 1` 的最终定义**，00 文档 §7.2 须按本文回填。

> **裁定：以实际头文件（47 项）为当前实现基准；本节 168 项为规格（目标态）。** 依据：
> 1. **代码零处硬编码错误码数值（实测）** —— 全仓库 `core/` `tests/` `tools/` 中，
>    `RECON_*` 错误码**只以符号名引用**（C enum 语义），**无任何** `= 2575` 式的数值字面量
>    （脚本核验通过，命中的 `2575`/`512` 均为注释、尺寸与参数值）。因此**错误码数值可安全重编号**，
>    不影响实现与测试。
> 2. **代码引用的 47 个错误码全部在头文件中定义** —— 零处引用未定义符号（编译干净）。
>    `RECON_ERR_EXPORT_NONMANIFOLD` 仅出现在 `exporter.cpp` 的**注释**中，非代码引用。
> 3. **下游文档引用的 66 个错误码中，63 个头文件未定义** —— 这些是**规格中列出、实现未落地**
>    的错误码（详见下方「待实现清单」）。其中 **docs/09 UI 规格**引用了 6 个缺失码
>    （`RECON_ERR_EXPORT_*` / `RECON_ERR_MESH_BAKE_NO_COVERAGE` / `RECON_ERR_MESH_EMPTY_INPUT` /
>    `RECON_ERR_MESH_NONMANIFOLD_UNFIXED` / `RECON_ERR_MESH_POISSON_OOM` / `RECON_ERR_MESH_UV_FAILED`），
>    **UI 侧当前不得假设这些码存在**。
>
> **本节阅读约定**：
> - §4.1 的编号规则（N-1..N-5）是**目标态规范**，描述 168 项规格表的设计意图；
> - §4.2–§4.16 的表格列出**规格全量**，**不表示已实现**；
> - **实际可用的错误码以头文件 `enum recon_status` 为准**（47 项）；
> - **修改头文件错误码后，必须同步 `tools/abi_drift_check.py` 的基线常量**，否则闸门会拦下提交。
>
> **守护闸门**：`tools/abi_drift_check.py`（CMake target `abi_drift_check`，CI job `abi-drift`）
> 已扩展至**同时校验错误码集合**：头文件新增/消失错误码、下游文档引用未定义错误码，任一发生即失败。
>
> **待实现清单（下游文档已引用、头文件未定义的 63 个码）**：见 §4.20。

### 5.3 三档预设的应用流程

```
用户点选档位
   │
   ├─▶ recon_params_apply_preset(ctx, preset)
   │      ├─ 对每个参数：locked_by_user == 1 ? 保持不变 : 写入新预设值
   │      ├─ 写入后统一过 C1~C5 夹取与联动
   │      └─ 记录被预设覆盖的项数与被保留的锁定项数（供 UI 提示，08 §3.4）
   │
   └─▶ recon_params_validate(ctx) → 问题列表 → UI 显示"已修正"标记
```

| 规则   | 内容                                                            |
| ---- | ------------------------------------------------------------- |
| PS-1 | 预设**只改参数值**，不改变 `BRANCH_RGBD` / `BRANCH_MONO` 的选择（08 §2.1 P1） |
| PS-2 | 预设**不改变**任何布尔参数的语义（如"简化默认关闭"在三档中都关闭）（P2）                      |
| PS-3 | 预设**不改变**降级策略的白名单 / 黑名单归属（P3）                                 |

| PS-5 | 预设切换**不触发**任何重建。重建的启动与取消由 UI 显式发起                             |

### 6.3 线程归属

| API 分组                                                 | 允许的调用线程      | 阻塞性                           | 理由               |
| ------------------------------------------------------ | ------------ | ----------------------------- | ---------------- |
| `recon_create` / `recon_destroy`                       | 任意（仅一次）      | `recon_destroy` 阻塞直到后台任务结束    | 生命周期唯一入口         |
| `recon_get_abi_version` / `recon_get_pipeline_version` | 任意           | 无                             | 纯读常量             |
| `recon_get_capability`                                 | 任意           | 首次 100~800 ms                 | 探测内部加锁           |
| `recon_get_last_error`                                 | 任意           | 无                             | 读原子快照            |
| `recon_set_callbacks` / `recon_set_log_level`          | 任意           | 无                             | 原子替换指针           |
| `recon_start_session` / `recon_abort_capture`          | **后台线程**     | 100~2000 ms                   | 涉及目录删除           |
| `recon_push_frame`                                     | **采集线程**（专用） | ≤ 1000 ms                     | 高频路径，不允许 UI 线程调用 |
| `recon_finish_capture`                                 | **后台线程**     | 100~5000 ms                   | 排空写盘队列           |
| `recon_get_scan_stats` / `recon_get_frame_quality`     | 任意           | 无                             | 读快照              |
| `recon_params_*`                                       | **后台线程**     | 无（除 `apply_preset` 100 ms）    | 写路径需与重建线程同步      |
| `recon_run_scale_calibration`                          | **后台线程**     | 0.3~8 s                       | 阻塞计算             |
| `recon_set_manual_scale`                               | 任意           | 无                             | 纯赋值              |
| `recon_run_reconstruction`                             | **后台线程**     | 30 min ~ 2 h                  | 绝对禁止 UI 线程调用     |
| `recon_get_progress` / `recon_is_cancelled`            | 任意           | 无                             | 读原子快照            |
| `recon_cancel`                                         | 任意           | 无（立即返回）                       | 只置标志             |
| `recon_get_mesh_info` / `recon_get_mesh_attribute`     | 任意           | `get_mesh_attribute` ≤ 200 ms | 读结果缓冲            |
| `recon_export` / `recon_export_validate`               | **后台线程**     | 2~~30 s / 1~~10 s             | 文件 IO            |
| `recon_free_string` / `recon_free_buffer`              | 任意           | 无                             | 释放               |

> **UI 线程禁令**：`recon_run_reconstruction`、`recon_export`、`recon_run_scale_calibration`、`recon_push_frame`、`recon_start_session`、`recon_finish_capture`、`recon_abort_capture` **禁止**在 UI 线程调用。UI 层必须把耗时调用派发到后台队列，并在结果回调里更新界面。

### 6.4 取消语义

| 项      | 规格                                                                                                                                     |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 触发     | `recon_cancel(ctx)`。幂等；重复调用返回 `RECON_OK`。**立即返回**，不等待任何任务结束                                                                            |
| 传播     | 置位上下文内的原子取消标志；各阶段在自己的**检查点**读取该标志                                                                                                      |
| 检查点粒度  | CPU 阶段：每批次（默认 64 帧 / 64 个特征块）；GPU 阶段：每个 dispatch 批次（单个 tile，单批 ≤ 200 ms）；IO：每次文件写                                                      |
| 返回时限   | `recon_run_reconstruction` 在取消后 **最长 2000 ms** 返回 `RECON_ERR_CANCELLED`；`recon_push_frame` 在取消后最长 **1000 ms** 返回 `RECON_ERR_CANCELLED` |
| GPU 中断 | GPU 任务**不可抢占式中断**。已在 GPU 上运行的工作由 `waitIdle` 收敛（上限 5000 ms），不产生悬垂资源。取消标志在下一个 dispatch 边界生效                                              |
| 内存处理   | 取消时，**已由核心层分配但尚未交给调用方的所有中间缓冲**由所属阶段的析构 / RAII 路径释放，随函数返回一并回收。**已经交给调用方的缓冲区不受影响**（调用方仍需 `recon_free_buffer` / `recon_free_string`）      |
| 已产出的结果 | 取消前已完成的阶段产物（稠密点云、网格、贴图）**保留**在上下文中，可通过 `recon_get_mesh_info` 读取；已写盘的原始帧**保留**                                                          |
| 检查点    | 编排层在每个阶段边界写检查点到 `<cache_dir>/checkpoints/`。取消后可通过 `recon_run_reconstruction`（`resume_from_checkpoint = 1`）从最近检查点续算                     |
| 落盘一致性  | 取消不破坏已落盘数据。`manifest.json` 的 `state` 置为 `cancelled`，`index.bin` 按最后一个**完整**记录截断                                                        |
| 清理超时   | `recon_abort_capture` 的 8 步清理若超过 2 s，记 `RECON_ERR_CANCEL_TIMEOUT` 并继续（03 CN-5）                                                         |

### 6.5 回调线程与重入

| 规则   | 内容                                                                             |
| ---- | ------------------------------------------------------------------------------ |
| CB-1 | 三个回调均由**核心线程**触发，同一回调**不重入**                                                   |
| CB-2 | 回调执行期间禁止调用同一 `recon_context` 的任何其他 API（会死锁）。需要回传数据时把请求投递给 UI 自己的队列             |
| CB-3 | 进度回调频率上限 **10 Hz**（09 §3.6 进度条 200 ms 线性插值的要求）。核心层内部可高频更新，但只在 100 ms 窗口内合并推送一次 |
| CB-4 | 状态文字回调遵循 02 §4.9.1：纯文字、≤ 14 汉字、无 emoji、无感叹号、一次只显示 1 条                          |
| CB-5 | 日志回调的 `message` 为 UTF-8，最长 512 字节，超长截断                                         |
| CB-6 | `recon_set_callbacks` 替换回调时不阻塞正在执行的回调返回；旧回调可能仍会收到最多 1 次调用                      |
| CB-7 | 回调中禁止调用 `recon_destroy`                                                        |

### 6.6 并发与锁

| 资源                    | 保护方式                                         |
| --------------------- | -------------------------------------------- |
| `recon_context` 顶层状态机 | 单一互斥锁 `ctx->state_mutex`，只保护状态字段的读写，不保护长耗时操作 |
| 写盘队列                  | 无锁队列（容量 64），生产者 = 核心线程，消费者 = 写盘线程            |
| 帧采集队列                 | 无锁队列（容量 8），生产者 = 采集线程，消费者 = 核心线程             |
| 参数集 `ParamSet`        | 读写锁；重建期间写操作（H 类热更新）走"延迟应用"，在阶段边界生效           |
| GPU 资源                | `ComputeBackend` 内部串行化，同一时刻只允许一个 dispatch 队列 |
| 会话文件                  | 写盘线程独占；其他线程只读                                |

### 7.2 帧容器格式

#### 7.2.1 `frames.bin` 负载布局

```
[RGB 段][深度段][置信度段]   ← 每帧连续，按索引精确寻址
```

| 段   | 内容                   | 长度               | 约束                                               |
| --- | -------------------- | ---------------- | ------------------------------------------------ |
| RGB | 平台原生格式像素行（stride 对齐） | `rgb_raw_size`   | F-2：不转格式，解码端按 `manifest.capture.pixel_format` 解释 |
| 深度  | uint16，毫米，**沿光轴 z**  | `depth_size`     | F-1：ARCore / ARKit 均为此语义                         |
| 置信度 | uint8，0 = 无效         | `depth_size / 2` | 无置信度来源时该段长度为 0                                   |

| 约束  | 内容                                                                                |
| --- | --------------------------------------------------------------------------------- |
| F-1 | 深度单位固定毫米、沿光轴 z，不沿视线射线                                                             |
| F-2 | 平台原生格式不做转换即写入（iOS YUV420 / Android NV21）                                          |
| F-3 | 段之间**不做 4 字节对齐填充**，偏移由索引精确记录                                                      |
| F-4 | 默认**不压缩**（RAW）。`ZSTD` 为可选编码，写入 `manifest.files.<name>.encoding` 字段；未出现该字段即为 `raw` |

#### 7.2.2 `imu.bin` 记录布局（定长 40 B）

| 偏移 | 大小 | 字段                     | 说明                   |
| -- | -- | ---------------------- | -------------------- |
| 0  | 8  | `t_ns`                 | i64，session timebase |
| 8  | 12 | `gx, gy, gz`           | f32×3，rad/s          |
| 20 | 12 | `ax, ay, az`           | f32×3，m/s²（比力）       |
| 32 | 4  | `t_raw_lo`, `t_raw_hi` | u32×2，平台原始时间戳        |
| 36 | 4  | `status`               | u8 传感器状态 + 3 B 保留    |

| 约束   | 内容                                          |
| ---- | ------------------------------------------- |
| IM-1 | 采样率目标 200 Hz；1 分钟会话 ≈ 960 kB，10 分钟 ≈ 9.6 MB |
| IM-2 | 严格按 `t_ns` 递增写入，写入顺序 = 采样顺序                 |

#### 7.2.3 `index.bin` 索引记录（定长 64 B，小端）

| 偏移 | 大小 | 字段                     | 说明                    |
| -- | -- | ---------------------- | --------------------- |
| 0  | 8  | `frame_id`             | u64，会话内单调递增           |
| 8  | 8  | `t_ns`                 | i64，session timebase  |
| 16 | 8  | `t_exposure_center_ns` | i64                   |
| 24 | 4  | `flags`                | u32，位定义见下             |
| 28 | 4  | `rgb_offset`           | u32，帧负载区内 RGB 段起始偏移   |
| 32 | 4  | `rgb_size`             | u32                   |
| 36 | 4  | `rgb_raw_size`         | u32（解压后字节数）           |
| 40 | 4  | `depth_offset`         | u32，0 = 无深度           |
| 44 | 4  | `depth_size`           | u32                   |
| 48 | 2  | `q_total`              | u16，0–65535 映射 0–1    |
| 50 | 2  | `q_blur`               | u16                   |
| 52 | 2  | `q_texture`            | u16                   |
| 54 | 2  | `q_overlap`            | u16                   |
| 56 | 4  | `imu_start_index`      | u32，`imu.bin` 中的起始样本号 |
| 60 | 2  | `imu_count`            | u16                   |
| 62 | 2  | `reserved`             | u16，置 0               |

**`flags` 位定义**（跨文档契约锚点，写盘方与重建方必须一致）：

| 位           | 含义                           | 置位方            | 消费方                    |
| ----------- | ---------------------------- | -------------- | ---------------------- |
| **bit0**    | **关键帧**                      | 03 §5.1 增益判据   | 重建流程（唯一依据，不得用 bit1 替代） |
| bit1        | 通过质量门限                       | 02 §4          | 落盘层级判定                 |
| bit2        | 含深度                          | 平台适配层          | 重建（决定是否走深度通道）          |
| bit3        | 卷帘快门                         | 平台适配层          | 重建（附加位姿不确定度）           |
| bit4        | 疑似运动模糊                       | 平台适配层          | 重建（深度降权）               |
| bit5–bit12  | `priority`（priority/255 近似值） | 03 §5.4（重建期回写） | 重建调度顺序                 |
| bit13–bit31 | 保留，置 0                       | —              | —                      |

**索引操作复杂度**：

| 操作             | 复杂度          | 实现                                                                               |
| -------------- | ------------ | -------------------------------------------------------------------------------- |
| 按 `frame_id` 查 | O(log N)     | `mmap` + 二分（记录按 `frame_id` 有序）                                                   |
| 按时间区间查         | O(log N + K) | 二分定位 + 顺序扫                                                                       |
| 追加             | O(1)         | 顺序追加写，**不重写历史**                                                                  |
| 断点恢复           | O(N) 一次      | 扫描尾部，截断到最后一个**完整**记录（校验 `frame_id` 连续性且 `rgb_offset + rgb_size ≤ frames.bin` 长度） |

### 7.4 跨版本兼容规则

| 场景                            | 判定  | 行为                                                                                              |
| ----------------------------- | --- | ----------------------------------------------------------------------------------------------- |
| `schema_version` **小于**当前支持版本 | 旧会话 | 按 §7.4.1 的"缺失字段默认值"规则读取，**允许重建**                                                                |
| `schema_version` **等于**当前支持版本 | 同版本 | 正常路径                                                                                            |
| `schema_version` **大于**当前支持版本 | 新会话 | `recon_resume_session` 返回 `RECON_ERR_FORMAT_VERSION_UNSUPPORTED`，UI 提示"数据版本过新，请更新应用"。**不得**尝试解析 |

#### 7.4.1 旧版本会话的字段默认值

| 字段                        | 旧版本缺失时的取值                                  | 影响                                                          |
| ------------------------- | ------------------------------------------ | ----------------------------------------------------------- |
| `capture.depth_semantics` | `axial_z`                                  | 若该机型实际为径向，尺度会有 12.9% 系统偏差且参照物复核无法发现 → 复核时强制做包围盒硬校验（07 §4.4） |
| `files.*.encoding`        | `raw`                                      | 无影响                                                         |
| `capture.fps`             | 由 `index.bin` 的 `t_ns` 差分统计推算              | 仅影响 U-02 显示                                                 |
| `pipeline_version`        | `unknown`                                  | 仅影响报告字段                                                     |
| `resume_cursor`           | 由 `index.bin` 扫描得出                         | 记录 `RECON_W_SESSION_CURSOR_FIXED`                           |
| `branch_hint`             | 由 `index.bin` 的 flags bit2 统计 + 设备能力重新探测推算 | 仅作提示                                                        |
| `checksums`               | 无                                          | 续算前重新计算并写入；不比对（无法比对）                                        |

#### 7.4.2 索引格式的版本化

| 项   | 规则                                                                                                           |
| --- | ------------------------------------------------------------------------------------------------------------ |
| V-1 | `index.bin` **本身不带版本头**。版本由 `manifest.json.schema_version` 承载。理由：索引要求定长可二分，插入头会破坏 `mmap` 二分的对齐假设             |
| V-2 | 当前 `schema_version = 1` 对应索引记录长度 **64 B**。改变记录长度必须递增 `schema_version`                                        |
| V-3 | 读取时用 `sizeof(IndexRecord)` 与 `manifest.schema_version` 推出的期望长度比对；不符返回 `RECON_ERR_FORMAT_VERSION_UNSUPPORTED` |
| V-4 | `flags` 的保留位（bit13–bit31）读到非 0 时**忽略该位**，不视为错误，保证向前兼容                                                        |
| V-5 | 新版本写入时，旧版本的 `reserved` 字段必须保持 0                                                                              |
| V-6 | `index.bin` 的追加是 O(1) 且**不重写历史**；续算输出写入 `sessions/<id>_resume/`，不修改原目录（02 §5.3.3）                            |

### 7.5 完整性校验时机

| 时机           | 校验内容                                                                    | 失败处置                                               |
| ------------ | ----------------------------------------------------------------------- | -------------------------------------------------- |
| 会话结束         | 所有索引引用的字节区间均存在且不越界；`index.bin` 的 `frame_id` 连续                          | 记 `RECON_W_SESSION_TRUNCATED`，按最后一个完整记录截断          |
| 落盘线程（每 64 帧） | 尾部记录的 `rgb_offset + rgb_size ≤ 当前文件长度`                                  | 丢弃尾部不完整帧                                           |
| 续算启动         | `manifest.checksums` 与实际文件 SHA-256 比对                                   | 不匹配 → `RECON_ERR_CHECKSUM_MISMATCH`，拒绝续算并提示"数据不完整" |
| 异常退出后启动      | 扫描 `sessions/*/manifest.json`，`state == "recording"` → 标记 `interrupted` | 保留数据供续算（02 CN-2）                                   |
| 取消后启动        | `state ∈ {"cancelling"}` → 直接删除会话目录                                     | 03 CN-1                                            |

### 7.6 `events.jsonl` / `quality.csv`

**`events.jsonl`**（每行一条 JSON）：

| 字段         | 说明                                                   |
| ---------- | ---------------------------------------------------- |
| `t_ns`     | 事件时刻                                                 |
| `type`     | `anomaly` / `gate_reject` / `state_change` / `error` |
| `detector` | `D1`..`D6` / `null`                                  |
| `level`    | `info` / `warn` / `severe`                           |
| `code`     | 错误码或告警码（§4 的权威名或数值）                                  |
| `text`     | 用户可见文案（09 §5）或空                                      |
| `detail`   | 检测量数值（对象）                                            |

**`quality.csv`** 列定义：

```
frame_id,t_ns,q_total,q_blur,q_texture,q_exposure,q_overlap,sat_ratio,blob_ratio,lowtex_ratio,flow_px,omega_norm,reject_reason,flags
```

| 约束  | 内容                                                                |
| --- | ----------------------------------------------------------------- |
| Q-1 | 每帧一行，**包括被拒帧**（拒帧信息对验收分析必需）                                       |
| Q-2 | 写入顺序与 `index.bin` 同序                                              |
| Q-3 | `reject_reason` 的非 0 取值见 02 §4.8；`flags` 位定义同 `index.bin` 的 flags |

### 7.7 跨语言可见的文件访问

| 文件                                     | 谁写      | 谁读             | 跨语言侧能否直接访问                                                    |
| -------------------------------------- | ------- | -------------- | ------------------------------------------------------------- |
| `manifest.json`                        | 核心层     | 核心层 / UI（只读摘要） | **否**，通过 `recon_get_scan_stats` / `recon_get_last_error` 获取摘要 |
| `index.bin` / `frames.bin` / `imu.bin` | 核心层写盘线程 | 核心层重建          | **否**                                                         |
| `params.json`                          | 核心层     | 核心层            | **否**，通过 `recon_params_*`                                     |
| `recon_mesh_info.json`                 | 核心层     | 核心层            | **否**，通过 `recon_get_mesh_info`                                |
| `export_check_report.json`             | 核心层     | 核心层            | **否**，通过 `recon_get_export_report`                            |
| 导出产物（`.glb` / `.obj` / `.ply`）         | 核心层     | 外部 DCC         | **是**（这是唯一设计给外部消费的文件）                                         |
| `calib/<model>_<os>.json`              | 平台层     | 核心层（只读）        | **否**                                                         |

> **原则**：跨语言边界只暴露**语义**（通过 API），不暴露**文件布局**。文件布局是 core 的内部实现细节，允许在不提升 `RECON_ABI_VERSION` 的前提下演进（前提是 `schema_version` 兼容规则成立）。
