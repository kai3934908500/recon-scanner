## 2. 采集通道抽象

### 2.1 接口设计原则

| 原则 | 落地方式 |
|---|---|
| 平台无关 | `CaptureSource` 只暴露"帧 + IMU + 设备能力"，不含任何 AR/VR 专用类型（不含 ARFrame/ARCore Frame） |
| 零拷贝优先 | 平台缓冲区通过 `shared_ptr` + 自定义 deleter 移交所有权，核心层不复制像素 |
| 回调线程可控 | 帧回调在**独立采集线程**触发，不在 UI 线程、不在相机内部回调线程 |
| 无异常跨界 | `CaptureSource` 全部 `noexcept`；错误通过返回值/状态对象传出 |
| 能力探测前置 | `Probe()` 只做一次，结果缓存为 `DeviceCapability`，不重复查询系统 API |

### 2.2 `recon::CaptureSource` 接口定义

文件位置：`core/capture/capture_source.h`（C++17，不跨语言边界；跨语言入口仍是 00 §7 的 `recon_c_api.h`）。

```cpp
#pragma once
#include <cstdint>
#include <functional>
#include <memory>
#include <string>
#include <vector>

namespace recon {

// ---------------------------------------------------------------------------
// 基础枚举（数值与 core/include/recon/types.h 保持一致）
// ---------------------------------------------------------------------------
enum class DepthSource : uint8_t {
  kNone     = 0,   // 无深度
  kHwLidar  = 1,   // 硬件 LiDAR（iOS ARKit sceneDepth，见 00 §8.1）
  kHwTof    = 2,   // 硬件 ToF
  kAlgo     = 3,   // 软件/运动深度（ARKit motion depth / ARCore Depth API）
};

enum class DepthTier : uint8_t {
  kNone      = 0,
  kMotion    = 1,  // 仅运动推断的软件深度
  kTof       = 2,
  kLidar     = 3,
};

enum class PixelFormat : uint8_t {
  kBgra8   = 0,    // 内部标准格式
  kNv21    = 1,    // Android 相机原生
  kYuv420 = 2,    // iOS 相机原生
  kRgba8   = 3,
};

enum class TimeSource : uint8_t {
  kHostMonotonic = 0,  // 主机单调时钟（已归一到 session timebase）
  kSensorClock   = 1,  // 传感器时钟，需仿射映射
  kUnknown       = 2,
};

// ---------------------------------------------------------------------------
// 配置
// ---------------------------------------------------------------------------
struct CaptureConfig {
  uint32_t rgb_width        = 1920;
  uint32_t rgb_height       = 1080;
  uint32_t target_fps       = 30;
  uint32_t depth_width      = 0;      // 0 = 不请求深度
  uint32_t depth_height     = 0;
  bool     enable_depth     = false;
  bool     enable_imu       = true;
  bool     use_platform_tracking = true;  // 允许 ARKit/ARCore 提供位姿先验
  bool     allow_late_frame_drop = false;  // 见 §2.7
  uint32_t imu_rate_hz      = 200;         // 目标 IMU 采样率，平台不支持时回退
  // 曝光策略（枚举与 08 文档 cap_exposure_mode 一致）：
  // 0 = auto（自动曝光）, 1 = 手动锁定 ISO+快门（静止类物体优先）, 2 = AE 优先
  uint8_t  exposure_mode    = 1;
  uint32_t fixed_exposure_us = 8000;   // 对应 cap_exposure_time_us（默认 8000 µs）
  uint32_t fixed_iso        = 400;     // 对应 cap_iso（默认 400）
};

// ---------------------------------------------------------------------------
// 设备能力（Probe 一次，缓存）
// ---------------------------------------------------------------------------
struct DeviceCapability {
  DepthSource best_depth_source = DepthSource::kNone;
  DepthTier   depth_tier        = DepthTier::kNone;
  uint32_t    max_rgb_width     = 0;
  uint32_t    max_rgb_height    = 0;
  uint32_t    max_fps           = 0;
  bool        has_hw_depth      = false;
  bool        has_platform_tracking = false;
  bool        has_lidar         = false;
  uint32_t    imu_max_rate_hz   = 0;
  uint32_t    imu_actual_rate_hz= 0;
  TimeSource  camera_time_source = TimeSource::kUnknown;
  TimeSource  imu_time_source    = TimeSource::kUnknown;
  uint32_t    rolling_shutter_rows = 0;   // 0 = 全局快门
  std::string device_model;
  std::string os_version;
};

// ---------------------------------------------------------------------------
// 帧与缓冲区
// ---------------------------------------------------------------------------
using BufferDeleter = void (*)(void* handle) noexcept;

struct ImageBuffer {
  void*        data   = nullptr;  // 像素首地址
  uint32_t     width  = 0;
  uint32_t     height = 0;
  uint32_t     stride = 0;       // 字节/行
  PixelFormat  format = PixelFormat::kBgra8;
  size_t       size_bytes = 0;
  std::shared_ptr<void> owner;   // 持有底层资源，末位引用释放时调用 deleter
};

struct ImuSample {
  int64_t  t_ns          = 0;    // session timebase（已归一）
  int64_t  t_raw_ns      = 0;    // 平台原始时间戳，未归一
  float    gyro[3]       = {0,0,0};  // rad/s，IMU 坐标系
  float    accel[3]      = {0,0,0};  // m/s^2，比力（含重力反作用）
  uint8_t  sensor_status = 0;   // bit0 gyro 有效, bit1 accel 有效, bit2 已饱和
};

struct FramePacket {
  // --- 标识与时间 ---
  uint64_t frame_id     = 0;    // 会话内单调递增，从 1 开始
  int64_t  t_ns         = 0;    // session timebase（单调，与 IMU 同源）
  int64_t  t_raw_ns     = 0;    // 平台原始时间戳
  int64_t  t_exposure_center_ns = 0;  // 曝光中点估计（t_ns 语义）

  // --- 图像 ---
  ImageBuffer rgb;
  ImageBuffer depth;              // width==0 表示无深度
  ImageBuffer depth_confidence;   // uint8，可空

  // --- 元数据 ---
  DepthSource depth_source = DepthSource::kNone;
  DepthTier   depth_tier   = DepthTier::kNone;
  uint32_t    exposure_us  = 0;
  uint32_t    iso          = 0;
  float       focus_distance_m = 0.0f;  // 0 = 未知
  uint32_t    flags        = 0;   // bit0 疑似运动模糊, bit1 卷帘快门, bit2 曝光已锁定

  // --- 平台位姿先验（可空）---
  bool  has_pose = false;
  float pose_t_wb[3] = {0,0,0};   // device→world 平移，m
  float pose_q_wb[4] = {0,0,0,1}; // device→world 四元数 (w,x,y,z)
  bool  pose_is_metric = false;   // true=米制，false=仅方向可靠

  // --- 观测质量原始量（供质量门限与异常检测使用，核心层不信任平台结论）---
  float motion_blur_score = 0.0f;  // 平台侧预估计（可选，0=未提供）
};

using FrameCallback  = std::function<void(FramePacket&&)>;
using ImuCallback    = std::function<void(const ImuSample&)>;
using ErrorCallback  = std::function<void(int code, const char* msg)>;

// ---------------------------------------------------------------------------
// 抽象接口
// ---------------------------------------------------------------------------
class CaptureSource {
 public:
  virtual ~CaptureSource() = default;

  virtual DeviceCapability Probe() = 0;

  virtual bool Configure(const CaptureConfig& cfg, ErrorCallback on_error) = 0;
  virtual bool Start(ErrorCallback on_error) = 0;
  virtual void  Stop() = 0;

  // 帧回调在独立采集线程触发；回调内部不得阻塞超过 2 ms。
  virtual void SetFrameCallback(FrameCallback cb) = 0;
  virtual void SetImuCallback(ImuCallback cb) = 0;

  // 曝光控制（仅在 exposure_mode != 0 时使用）
  virtual bool SetExposureLock(bool locked, uint32_t exposure_us, uint32_t iso) = 0;

  // 时间轴健康检查：返回 true 表示时间戳序列健康
  virtual bool CheckTimeHealth(int64_t* out_detail) = 0;
};

}  // namespace recon
```

#### 2.2.1 `CaptureConfig` 字段 ↔ 08 文档 `cap_*` 键名映射

> **命名权威**：键名的**唯一定义处**是 08 文档 G1 组（`cap_*`）。本节的 `CaptureConfig` C++ 字段名是 08 键名的**内部映射名**，二者必须一一对应；出现分歧时以 08 文档为准（与 08 文档 §0 的声明一致）。

| `CaptureConfig` 字段 | 08 文档键名 | 生效时机 | 默认值（标准档） | 说明 |
|---|---|---|---|---|
| `rgb_width` | `cap_resolution_width` | 采集前 | 1920 | 16:9 高度由 `cap_resolution_height` 给出 |
| `rgb_height` | `cap_resolution_height` | 采集前 | 1080 | — |
| `target_fps` | `cap_frame_rate` | 采集前 | 30 | — |
| `enable_depth` | `cap_depth_enabled` | 采集前 | 1 | 无深度设备时该项无效 |
| —（平台能力探测给出） | `cap_depth_rate` | 采集前 | 30 | 深度帧率上限由 `Probe()` 与设备能力决定，不由 `CaptureConfig` 直接携带 |
| `enable_imu` | `cap_imu_enabled` | 采集前 | 1 | 关闭则退化为纯单目（尺度必须标定） |
| `imu_rate_hz` | `cap_imu_rate_hz` | 采集前 | 200 | 平台不支持时回退 |
| `exposure_mode` | `cap_exposure_mode` | 采集前 | 1 | 枚举：**0=auto, 1=手动锁定, 2=AE 优先** |
| `fixed_exposure_us` | `cap_exposure_time_us` | 采集前 | 8000 | 仅 `exposure_mode ≠ 0` 时使用 |
| `fixed_iso` | `cap_iso` | 采集前 | 400 | 仅 `exposure_mode ≠ 0` 时使用 |
| `depth_width` / `depth_height` | —（平台能力探测给出） | 采集前 | 由设备决定 | 深度尺寸由 `Probe()` 的 `best_depth_source` 决定，非用户可调 |
| `use_platform_tracking` | —（内部开关） | 采集前 | true | 允许 ARKit/ARCore 提供位姿先验；**仅作先验**，不作位姿真值（§2.3） |
| `allow_late_frame_drop` | —（内部开关） | 采集前 | false | 见 §2.7；平台层不得自行丢帧 |
| — | `cap_white_balance_mode` / `cap_white_balance_kelvin` | 采集前 | 1 / 5200 | 白平衡策略，由 L2 平台层直接消费 08 键，不经 `CaptureConfig` 传递 |
| — | `cap_focus_mode` / `cap_focus_distance_m` | 采集前 | 0 / 0.35 | 同上 |
| — | `cap_rolling_shutter_correction` | 采集前 | 1 | 同上 |
| — | `cap_ring_buffer_frames` / `cap_disk_cache_enabled` / `cap_disk_cache_quota_mb` | 采集前 | 600 / 1 / 8192 | 由核心层与写盘线程消费 |
| — | `cap_thermal_throttle_threshold_c` | 采集前 | 42.0 | 由 L5 编排层消费 |
| — | `cap_min_frames_before_finish` | 采集前 | 12 | 由 UI 层消费 |
| — | `cap_quality_gate_*`（8 项） | 采集前 | 见 08 §1 G1 | 由核心层质量门限消费（§4） |

**未在 `CaptureConfig` 中携带的 08 键名**：说明其消费方不在 L2 平台层（白平衡/对焦/卷帘由 L2 直接消费 08 键；缓冲/磁盘/热限流/门限由 L4/L5/UI 消费）。**这不构成契约缺口** —— L2 通过 `recon_params_*` 接口读同一份 `ParamSet`，不需要把全部参数复制进 `CaptureConfig`。

> **ISO 默认值的口径**：08 文档 `cap_iso` 默认 **400**（三档 800 / 400 / 200），本文 `fixed_iso` 默认值已与之对齐。早期版本的 `fixed_iso = 100` 与 08 不一致，**已修正**。
>
> **曝光模式枚举的口径**：08 文档 `cap_exposure_mode` 的合法范围是 `[0, 2]`，枚举为 **0=auto, 1=手动锁定, 2=AE 优先**。早期版本本文只定义了 0/1 两值，**已补齐第 3 个枚举值并对齐枚举语义**。

#### 2.2.2 与 00 §7.2 C ABI 的映射

00 §7.2 的 `recon_frame_packet` 是**跨语言 POD 边界**，只承载 POD 指针与标量；本节的 `recon::FramePacket` 是**核心层内部 C++ 结构**，携带所有权。两者通过 `recon::ToCFramePacket()` 单向转换。

| 00 §7.2 字段 | 本节对应 | 转换规则 |
|---|---|---|
| `frame_id` | `frame_id` | 直接复制 |
| `timestamp_ns` | `t_ns` | 直接复制（已归一到 session timebase） |
| `rgb_width` / `rgb_height` | `rgb.width` / `rgb.height` | 直接复制 |
| `rgb_stride` | `rgb.stride` | 直接复制 |
| `rgb_data`（BGRA8） | `rgb.data` | **像素格式必须为 BGRA8**，见下方格式约定 |
| `depth_width` / `depth_height` | `depth.width` / `depth.height` | 直接复制；无深度时填 0 |
| `depth_stride` | `depth.stride` | 直接复制 |
| `has_depth` | `depth.width > 0` | 派生 |
| `depth_tier` | `depth_tier` | 直接复制，枚举值一一对应 |
| `depth_data`（uint16 mm） | `depth.data` | 沿光轴 z 的毫米深度（00 §8.2） |
| `depth_confidence` | `depth_confidence.data` | 可为 NULL |
| `intrinsics`（指针） | **不在帧内** | 内参是会话级常量，移入 `recon::CaptureSessionConfig`，避免每帧携带同一份指针 |
| `pose`（指针） | `has_pose` + `pose_t_wb` + `pose_q_wb` | 值拷贝；`pose_is_metric=false` 时 C ABI 侧填 NULL（下游按"仅方向可靠"处理） |
| `imu`（指针）+ `imu_count` | `imu` / `imu_count` | **不在帧内**，改为会话级 IMU 环形缓冲 + 帧的 IMU 索引区间（见 §3.5.6）。逐帧拷贝 IMU 会使 C ABI 结构体大小随采样率变化，破坏 POD 边界稳定性 |
| `motion_blur_score` | `motion_blur_score` | 直接复制 |

**像素格式约定（与 00 §7.2 的 `// BGRA8` 保持一致）**

| 项 | 规格 |
|---|---|
| 要求 | 进入 C ABI 的 `rgb_data` 必须是 **BGRA8** |
| 平台原生格式 | iOS `kCVPixelFormatType_420YpCbCr8BiPlanarFullRange`（YUV420）、Android `NV21`/`RGBA_8888` |
| 转换位置 | L2 平台层（00 §3.1 允许 L2 做"获取与转换"）。iOS 用 `CVPixelBufferPool` + `CGBitmapContext`/`vImage`；Android 用 CPU 转换或 `AHardwareBuffer` + L3 Metal/Vulkan 一次性转换 |
| 转换代价 | 1080p BGRA = 7.91 MiB/帧，30 fps 下写入带宽 237 MiB/s。属可接受范围，但**必须**实测（列为不确定项 U-10 一部分） |
| 落盘格式 | 落盘**不做**格式统一，按 `PixelFormat` 原生格式写入 `frames.bin`（02 §5.5）。理由：落盘是异步的，不占用采集线程预算；BGRA 转换只在本就需要像素访问时按需进行 |
| 例外 | 若平台原生即为 BGRA8/RGBA8（部分 Android 设备），跳过转换，`rgb.format = kBgra8` |

> **显式偏差说明**：00 §7.2 未定义 `depth_tier` 之外的分层字段，本节未新增任何影响跨端一致性的字段。新增字段（`t_raw_ns`、`t_exposure_center_ns`、`exposure_us`、`iso`、`focus_distance_m`、`flags`、`pose_is_metric`）全部为**核心层内部字段**，不出现在 C ABI POD 中；若 01 文档决定将其中的 `exposure_us` 与 `flags` 暴露到 C ABI，需同步更新 00 §7.2。

### 2.3 平台实现矩阵

| 能力 | iOS 实现 | Android 实现 | 备注 |
|---|---|---|---|
| 相机采集 | `AVCaptureSession` + `AVCaptureVideoDataOutput` (`platform/ios/CameraController.swift` → `CaptureSourceIOS.mm`) | `CameraX` `ImageAnalysis`/`ImageProxy` + `ImageReader` (`platform/android/CameraController.kt` → `CaptureSourceAndroid.cpp`) | iOS 需 `alwaysDiscardsLateVideoFrames` 策略显式设定 |
| 深度 | `ARSession` `sceneDepth`/`smoothedSceneDepth` + `ARMeshAnchor`（仅做尺度锚定与先验，见 00 §8.1） | `ARCore` Depth API / Camera2 `DEPTH_OUTPUT` 直出 ToF | `ALGO` 深度不得单独作尺度真值（00 §8.2） |
| IMU | `CMMotionManager` deviceMotion（陀螺 + 加计） | `SensorManager` `TYPE_GYROSCOPE` + `TYPE_ACCELEROMETER` | 必须用 `SENSOR_DELAY_GAME`/最高可用档 |
| 位姿先验 | `ARFrame.camera.transform`（device→world） | `ARCore` `Camera.getPose()` | **仅作先验**，不作为位姿真值 |
| 时间戳 | `CMSampleBuffer.presentationTimeStamp` | `ImageProxy.getTimestamp()` | 见 §3.3 / §3.4 |
| 缓冲所有权 | `CVPixelBuffer` 保留 + `CVPixelBufferRelease` | `ImageProxy` 需 `close()`；底层 `Image` 需 `acquire()`/`close()` | 见 §2.4 |

### 2.4 图像内存所有权与生命周期

#### 2.4.1 所有权规则表

| 资源 | 分配者 | 移交方式 | 释放者 | 释放时机 |
|---|---|---|---|---|
| iOS `CVPixelBuffer` | `AVCaptureVideoDataOutput` 内部池 | `CVPixelBufferRetain` + 放入 `shared_ptr`（deleter = `CVPixelBufferRelease`） | 最后一个 `shared_ptr` 引用销毁时 | 核心层处理完该帧后（可能跨帧持有） |
| iOS 深度 `CVPixelBuffer` (float16/float32) | `ARSession` | `CVPixelBufferRetain` + `shared_ptr` | 同上 | 同上 |
| Android `ImageProxy` | CameraX | **不得**跨线程持有超过一帧；转换为自有 `AHardwareBuffer`/堆缓冲后立即 `close()` | `ImageProxy.close()` | `onFrame` 回调内结束前 |
| Android `Image` (ToF) | Camera2 `ImageReader` | `Image.acquire()` 增加引用计数 → `shared_ptr`（deleter = `Image.close()`） | 最后引用 | 核心层释放 |
| IMU 采样 | 平台层栈上 POD | 值拷贝 | 无 | 立即 |
| 特征/描述子 | 核心层 | 值/智能指针 | 核心层 | 见 13 文档 |

#### 2.4.2 生命周期时序

```
采集线程                        核心层                        落盘线程
   │                              │                             │
   ├─ onFrame(FramePacket&&)      │                             │
   │   ├─ 引用计数 +1             │                             │
   │   ├─ push 到无锁队列 ───────►│ pop                        │
   │   └─ return (不阻塞)         │ ├─ 时间同步 (§3)            │
   │                              │ ├─ 质量门限 (§4)             │
   │                              │ ├─ 关键帧判定 (03)           │
   │                              │ ├─ 写盘入队 ────────────────►│ 压缩 + 落盘
   │                              │ └─ release 引用计数          │
   │                              │    └─ 引用归零 → 释放像素     │
   ▼                              ▼                             ▼
```

#### 2.4.3 硬约束

| ID | 约束 |
|---|---|
| M-1 | 采集线程禁止执行：像素拷贝、压缩、文件 IO、特征提取、任何锁等待（除无锁队列的原子操作） |
| M-2 | 单帧在核心层的最大驻留时间（入队 → 释放）目标 ≤ 200 ms，硬上限 1000 ms；超时强制释放并记 `RECON_ERR_CAPTURE_BACKPRESSURE` |
| M-3 | 核心层任何情况下不得对 `FramePacket` 的像素做原地修改（`ImageBuffer::data` 视为 `const`） |
| M-4 | **两个队列必须区分**（容量不同、职责不同，不得混为一谈）：<br>① **采集 → 核心队列**：容量 **8 帧**（按 1920×1080×4 B ≈ 7.9 MiB 计，约 63 MiB）。存放尚未完成时间同步与质量门限判定的帧。<br>② **核心 → 写盘队列**：容量 **64 帧**（约 506 MiB）。存放已判定为关键帧、等待写入 `frames.bin` 的帧。详见 §5.6.1 W-3 / W-4。<br>③ IMU 环形缓冲 4096 样本（200 Hz → 20.5 s） |
| M-5 | 落盘线程不参与采集线程的引用计数持有，落盘期间缓冲所有权独占 |

## 3. 时间同步

### 3.1 三时钟源

| 编号 | 时钟源 | iOS 取值 | Android 取值 | 性质 |
|---|---|---|---|---|
| C1 | 相机帧时间戳 | `CMSampleBufferGetPresentationTimeStamp`（host clock, mach_absolute_time 派生） | `ImageProxy.getTimestamp()`（`SENSOR_TIMESTAMP`，见 `SENSOR_INFO_TIMESTAMP_SOURCE`） | 可能为 sensor clock，可能含卷帘偏移 |
| C2 | IMU 时间戳 | `CMDeviceMotion.timestamp`（秒，需 ×1e9；与 `CACurrentMediaTime` 同源） | `SensorEvent.timestamp`（ns，BOOTTIME 家族） | 硬件采样时刻，延迟最小 |
| C3 | 单调时钟 | `CACurrentMediaTime()` × 1e9（monotonic） | `SystemClock.elapsedRealtimeNanos()`（monotonic，含 suspend） | 参考时钟，不受用户改系统时间影响 |

#### 3.1.1 统一时间轴定义

```
T_session = T_mono − T_session_start          (ns, 单调递增)
所有落盘与内部计算使用 T_session。
```

| 约束 | 规则 |
|---|---|
| T1 | 内部一律用 `int64_t` ns，不用 `double` 秒（避免 2^53 ns ≈ 104 天外的精度损失与浮点累积误差） |
| T2 | 任一外部时间戳进入核心层，必须先经 §3.2 归一化到 `T_session` |
| T3 | 单调性：归一后 `t_ns` 必须严格递增；违例按 §3.8 处理 |

### 3.2 时间轴归一（仿射映射）

对每一个外部时钟源 `c`，维护仿射映射：

```
T_session(c) = α_c · T_raw(c) + β_c
```

| 参数 | 含义 | 求解方式 |
|---|---|---|
| `α_c` | 时钟速率比 | 最小二乘拟合（≥ 200 组配对样本） |
| `β_c` | 偏移 | 同上，与 `α_c` 同时求解 |
| `T_c` | 映射置信度 | 由拟合残差决定：RMS(residual) ≤ 1e-5 s → `T_c = HIGH`；≤ 1e-3 s → `MEDIUM`；否则 `LOW` |

#### 3.2.1 相机时间源分情况处理

| `SENSOR_INFO_TIMESTAMP_SOURCE` / 平台 | 映射策略 | 置信度 |
|---|---|---|
| iOS（host clock） | `α = 1`，`β = 0`（PTS 与 `CACurrentMediaTime` 同源） | HIGH |
| Android `SOURCE_REALTIME` | `α = 1`，`β = 0`（同 `elapsedRealtimeNanos`） | HIGH |
| Android `SOURCE_SENSOR_CLOCK` | 求解 `α, β`（该时钟与 BOOTTIME 速率相同，仅偏移） | MEDIUM |
| Android `SOURCE_UNKNOWN` | 求解 `α, β`；速率偏差 `abs(α − 1)` 落入 **[50 ppm, 100 ppm)** 区间 → 触发重标定（§3.2.2），`abs(α − 1) ≥ 100 ppm` → 拒绝使用该时间戳并触发 `RECON_ERR_SYNC_UNRELIABLE_CAM_TS` | MEDIUM→禁用 |

#### 3.2.2 求解算法（在线，持续更新）

```
输入: 帧序列 { (T_raw_cam(k), T_mono_deliver(k)) }，k = 1..N
1. 取最近 N = 240 帧（≥ 8 s）
2. 最小二乘拟合 T_mono_deliver = α · T_raw + β
3. 剔除残差 > 5σ 的样本，重新拟合（最多 3 轮）
4. 更新 α, β 与置信度；置信度下降为 LOW 时冻结当前值并告警
```

> 交付时刻 `T_mono_deliver` 只能作为**弱观测**（它含交付抖动），因此拟合出的 `α` 是真实速率的**有偏估计**。真实速率由 §3.7 的 IMU–相机长期互相关校验（§3.8.4）复核。

**速率偏差的单一口径（全文档唯一）**

| 判据 | 阈值 | 动作 |
|---|---|---|
| 正常 | `abs(α − 1) ≤ 50 ppm`（5e-5） | 接受当前拟合值 |
| **重标定** | `abs(α − 1) > 50 ppm` | **触发重新标定**（重新拟合 `α, β`），记 `RECON_ERR_SYNC_CLOCK_DRIFT` |
| **拒用** | `abs(α − 1) ≥ 100 ppm`（1e-4） | 拒绝使用该相机时间戳，改用 §3.4.2 的主机时钟回落方案，记 `RECON_ERR_SYNC_UNRELIABLE_CAM_TS` |

> 这两个阈值是**同一个判据的两级**，不是两条互斥规则：50 ppm 是重标定触发线，100 ppm 是拒用线。§3.7 预算表 S7 行的"50 ppm"指的是**重标定触发线**（即两次重标定之间允许的最大速率偏差，对应 1 s 内 50 µs 漂移量），**不是**标定后的残余速率精度。§3.8.4 的长期健康度检测使用同一条 50 ppm 触发线。

### 3.3 iOS 时间戳对齐

#### 3.3.1 `CMDeviceMotion.timestamp` 与 `CACurrentMediaTime()`

| 事实 | 说明 |
|---|---|
| 同源 | `CMDeviceMotion.timestamp` 与 `CACurrentMediaTime` 都基于 `mach_absolute_time`，单位分别是 s 与 s，量级一致 |
| 不同点 | `CMDeviceMotion.timestamp` 标称的是**底层原始采样时刻**，而 `CMDeviceMotion` 对象是 CoreMotion 内部滤波（低通 + 延迟）后的融合结果，融合输出相对原始采样**滞后** |
| 不可查询 | 融合链路的滞后量不由公开 API 给出，随机型与采样率变化 |

**工程结论与做法**

| 步骤 | 做法 |
|---|---|
| 1 | `t_imu_session = CMDeviceMotion.timestamp × 1e9 − T_session_start_mono`，直接使用，**不做** `CACurrentMediaTime()` 二次对齐（两者同源，二次对齐只会引入舍入） |
| 2 | 用 `CMMotionManager.deviceMotionUpdateInterval` 显式设定采样间隔（默认 1/200 s，iOS 允许的档位由设备决定） |
| 3 | **标定 CoreMotion 融合滞后** `τ_cm`：静止持机 30 s，记录 `CMDeviceMotion.timestamp` 与同源 `CACurrentMediaTime()` 的关系；用「设备绕 Z 轴匀速旋转 + 陀螺积分 vs deviceMotion.rotationRate」交叉比对，回归得到 `τ_cm` |
| 4 | 补偿：`t_imu_corrected = t_imu_session − τ_cm`，`τ_cm` 写入设备标定文件（见 §3.9.4） |
| 5 | 每次静止段启动时复核 `τ_cm`：若与标定值偏差 > 2 ms，标记 `RECON_ERR_SYNC_CM_DRIFT` 并重新估计 |

| 项 | 保守取值 |
|---|---|
| `τ_cm` 典型范围 | 5–30 ms（依机型） |
| 标定可重复性要求 | 同机型 5 次标定的 `τ_cm` 标准差 ≤ 1 ms |
| 未标定时的处理 | 保守取 `τ_cm = 15 ms`，并在误差预算中按 15 ms 计入（而非按 0 计入） |

#### 3.3.2 相机时间戳与曝光中点

| 项 | 说明 | 保守取值 |
|---|---|---|
| PTS 语义 | `presentationTimeStamp` 为该帧**提交/曝光开始**时刻（平台定义），非曝光中点 | — |
| 曝光时长 | 由 `AVCaptureDevice` 的 `activeFormat` + `ISO` 反推不可靠；改用固定曝光模式并记录 `exposure_us` | 8 000 µs |
| 曝光中点修正 | `t_exposure_center = t_pts + exposure_us / 2 + τ_exposure_pipeline` | `τ_exposure_pipeline = 0`（保守，不外推） |
| 卷帘快门 | 逐行曝光，行间最大时差 = `t_frame − t_exposure`；`flags` bit1 置位 | 1080p @30 fps 约 33 ms |
| 处置 | 卷帘快门的行间时差在位姿层面作为**附加不确定度**计入（§3.7），不做逐行补偿 | — |

### 3.4 Android 时间戳对齐

#### 3.4.1 `SensorEvent.timestamp` 与 `SystemClock.elapsedRealtimeNanos()`

| 事实 | 说明 |
|---|---|
| 同源 | `SensorEvent.timestamp` 为设备开机以来的纳秒数，与 `SystemClock.elapsedRealtimeNanos()` 同属 BOOTTIME 家族 |
| 硬件采样时刻 | 陀螺/加计的 `timestamp` 为**硬件采样时刻**（含 FIFO 批量入队的正确回填），不是回调时刻 |
| 厂商差异 | 部分厂商 HAL 用 CLOCK_MONOTONIC（不含 suspend），此时设备息屏/休眠期间会产生偏移 = suspend 时长 |
| 交付延迟 | SensorFIFO 批量回调的交付抖动可达数十 ms，但**不改变 timestamp**，故不影响精度 |

**工程做法**

| 步骤 | 做法 |
|---|---|
| 1 | `t_imu_session = SensorEvent.timestamp − T_session_start_boot`（`T_session_start_boot` 取首个 IMU 样本的 `elapsedRealtimeNanos` 与 `timestamp` 之差） |
| 2 | 校验 `timestamp` 单调性；出现倒退 → §3.8.1 |
| 3 | 息屏/恢复后（`onResume`）立即做**时间轴重锚定**：重新取 `elapsedRealtimeNanos()` 与 `SensorEvent.timestamp` 的差值，偏差 > 5 ms 则重估 `β` 并清空 IMU 预积分窗口 |
| 4 | 未标定 `τ_fifo` 时保守取 0（因为 timestamp 已是硬件时刻，无需补偿） |

#### 3.4.2 相机时间戳

| 情况 | 处理 |
|---|---|
| `SENSOR_INFO_TIMESTAMP_SOURCE == SOURCE_REALTIME` | 直接使用，`α=1, β=0` |
| `SOURCE_SENSOR_CLOCK` / `SOURCE_UNKNOWN` | §3.2.2 仿射拟合 |
| `ImageProxy.getTimestamp()` 返回 0 或非法 | 视为不可用，改用 `SystemClock.elapsedRealtimeNanos()` 在回调入口采样，标记 `RECON_ERR_SYNC_CAM_TS_FALLBACK`，该帧的相机–IMU 配准误差按 1 帧时长计入预算 |

### 3.5 IMU 预积分

#### 3.5.1 记号与约定

| 符号 | 含义 | 单位 |
|---|---|---|
| `R_{W←I}` | IMU→世界旋转 | — |
| `b_g`, `b_a` | 陀螺零偏、加计零偏 | rad/s, m/s² |
| `ω_m`, `a_m` | 原始测量（比力，`a_m = R(a_W − g_W)`） | rad/s, m/s² |
| `g_W` | 世界重力向量，`g = 9.80665` | m/s² |
| `Δt_k` | 第 k 个 IMU 采样间隔 | s |
| `ΔR, Δv, Δp` | 区间预积分量 | —, m/s, m |

约定：所有旋转增量在 **body frame** 表达；`Exp/Log` 为 SO(3) 的指数/对数映射；`J_r(φ)` 为 SO(3) **右雅可比**。

#### 3.5.2 右雅可比

```
θ = ‖φ‖
J_r(φ) = I − ((1 − cos θ)/θ²) φ^ + ((θ − sin θ)/θ³) (φ^)²
J_l(φ) = I + ((1 − cos θ)/θ²) φ^ + ((θ − sin θ)/θ³) (φ^)²
J_r(φ)^{-1} = I + ½ φ^ + ( 1/θ² − (1 + cos θ)/(2 θ sin θ) ) (φ^)²
```

小角度数值稳定化（必须实现）：

| 条件 | 处理 |
|---|---|
| `θ < 1e-6` | `J_r ≈ I − ½ φ^ + ⅙ (φ^)²`；`J_r^{-1} ≈ I + ½ φ^ + 1/12 (φ^)²` |
| `1e-6 ≤ θ < 1e-4` | 用 `sin/cos` 的级数展开（`1−cosθ ≈ θ²/2 − θ⁴/24`） |
| 其他 | 直接计算 |

#### 3.5.3 名义递推（中点法）

两采样区间 `[t_k, t_{k+1}]`，`Δt = t_{k+1} − t_k`：

```
ω̃_k = ½(ω_m,k + ω_m,k+1) − b_g,k
ã_k  = ½(a_m,k + a_m,k+1) − b_a,k

ΔR_{k+1} = ΔR_k · Exp(ω̃_k Δt)
Δv_{k+1} = Δv_k + ΔR_k · ã_k Δt
Δp_{k+1} = Δp_k + Δv_k Δt + ½ ΔR_k · ã_k Δt²
```

| 项 | 阶 | 说明 |
|---|---|---|
| `ΔR` | 精确（对常角速度） | 一阶 Manifold 递推，误差来自 `ω̇` |
| `Δv` | 2 阶 | 误差 `O(Δt³·ä)` |
| `Δp` | 2 阶 | 误差 `O(Δt⁴)` |

选 **中点法**（而非后向欧拉）的理由：后向欧拉的 `Δv` 误差 `O(Δt²)`，在 200 Hz、`|a| = 10 m/s²` 下单区间误差 `1.25e-4 m/s`，1 s 内累积可达 `2.5e-2 m`，超出 §3.7 预算；中点法同条件误差 `O(Δt⁴)`，1 s 累积 < 1e-6 m。

> 与 R-PREC-1 冲突仲裁：若中点法因成本被替换为后向欧拉，必须同时把 IMU 采样率提到 400 Hz 以上，否则不允许。

#### 3.5.4 噪声离散化

连续时间噪声模型（加性白噪声 + 零偏随机游走）：

```
ω̃(t) = ω(t) + n_g(t),   n_g  ~ N(0, σ_g² I)      [rad/s/√Hz]
ã (t) = a(t) + n_a(t),   n_a  ~ N(0, σ_a² I)      [m/s²/√Hz]
ḃ_g(t) = n_bg(t),        n_bg ~ N(0, σ_bg² I)     [rad/s²/√Hz]
ḃ_a(t) = n_ba(t),        n_ba ~ N(0, σ_ba² I)     [m/s³/√Hz]
```

> 噪声密度符号的量纲与 08 文档的 `vio_imu_noise_gyro` / `vio_imu_noise_acc` / `vio_imu_bias_walk`（Allan 方差标定输出）**完全一致**：白噪声项是**密度**（rad/s/√Hz、m/s²/√Hz），零偏游走项也是密度（rad/s²/√Hz、m/s³/√Hz）。本节是 05 文档 §3.3.3 的上游，两处必须一致。

**离散化到采样间隔 `Δt`（关键）**

> **本节是 02 文档与 05 文档之间噪声离散化的唯一约定处。** 05 文档 §3.3.3–§3.3.4 的预积分实现必须与本节一致，不得引入其他文献的离散化写法（如 `σ_g² + σ_bg²·Δt²` 这类把连续密度直接相加的写法——它把**密度**与**离散方差**混在一个和里，量纲不成立）。

**离散方差的量级规则（两条，不可写反）**

| 噪声类型 | 连续密度 | 采样时刻 k 的**离散方差** | 经状态传播后进入的角度/速度通道量级 |
|---|---|---|---|
| 陀螺**白噪声** | `σ_g²` | **`σ_g²/Δt`** | 角度：`σ_g²·Δt`；姿态（二阶传播）：`σ_g²·Δt³` |
| 加计**白噪声** | `σ_a²` | **`σ_a²/Δt`** | 速度：`σ_a²·Δt`；位置：`σ_a²·Δt³/4` |
| 陀螺零偏**随机游走** | `σ_bg²` | **`σ_bg²·Δt`** | 角度：`σ_bg²·Δt³`；姿态：`σ_bg²·Δt⁵` |
| 加计零偏**随机游走** | `σ_ba²` | **`σ_ba²·Δt`** | 速度：`σ_ba²·Δt³`；位置：`σ_ba²·Δt⁵/4` |

> **两条必须记住的量级规则**：
> ① **白噪声项 = `σ²/Δt`** —— 离散方差随 `Δt` 减小而**增大**（因为采样带宽变宽）。写成 `σ²·Δt` 会让高频 IMU 的协方差被严重低估（`Δt` = 5 ms 时低估 200 倍），滑窗优化会过度相信视觉约束，表现为位姿在弱纹理段"贴住"漂移的 SfM 结果。
> ② **随机游走项 = `σ²·Δt`** —— 离散方差随 `Δt` 减小而**减小**；它经状态传播后进入角度/速度通道的量级是 **`σ²·Δt³`**。

**协方差噪声协方差矩阵（维度闭合版本，与 05 §3.3.4 的 `Q_ν` 一致）**

```
Q_ν = blkdiag( (σ_g²/Δt)·I₃ , (σ_a²/Δt)·I₃ , (σ_bg²·Δt)·I₃ , (σ_ba²·Δt)·I₃ )
```

其中四个块依次对应 05 文档 §3.3.4 的噪声输入向量 `ν = [n_g (3), n_a (3), w_g (3), w_a (3)]`。

**等效单步噪声（若需要以"速率方差"形式书写）**

```
Σ_g,d = ( σ_g²/Δt ) · I₃              等效角速度采样噪声 [rad²/s²]
Σ_a,d = ( σ_a²/Δt ) · I₃              等效比力采样噪声   [m²/s⁴]
```

> **量纲提醒**：`σ_g²`（密度，rad²/s²/Hz = rad²/s）与 `σ_g²/Δt`（离散方差，rad²/s²）**单位不同，不可直接相加**。零偏游走项 `σ_bg²·Δt`（rad²/s²）与白噪声离散项同量纲，但在 `Q_ν` 中分属**不同噪声通道**（`w_g` vs `n_g`），也不合并为一个 `Σ`。
>
> **05 文档 §3.3.4 是维度闭合的完整实现**（15 维误差状态 `[δθ, δv, δp, δb_g, δb_a]`、12 维噪声输入、`A`(15×15) 与 `B`(15×12) 的具体块结构、以及单元测试断言）。本节给出的是 05 实现的**上游约定**：噪声密度的量纲定义与四条离散化量级规则。两者必须一致；如需修改，**先改本节再改 05**，不得单方面偏离。

**零偏作为显式状态时的传播（本产品采用）**

```
b_g' = b_g + w_g ,   w_g ~ N(0, σ_bg²·Δt · I)
b_a' = b_a + w_a ,   w_a ~ N(0, σ_ba²·Δt · I)
```

零偏增量 `Δb = w·Δt` 已在 `Q_ν` 的 `σ_bg²·Δt` 块中计入（该块就是**每步的零偏增量方差**），不再额外乘 `Δt`；零偏对角度/速度/位移的耦合通过 05 §3.3.5 的一阶雅可比进入。

#### 3.5.5 偏置雅可比（分析式 + 一阶修正）

**偏置变化 `δb_g, δb_a` 时预积分量的修正（必须实现）**

设积分时零偏为 `b̂_g, b̂_a`，零偏增量 `δb_g = b_g − b̂_g`、`δb_a = b_a − b̂_a`。
修正**不重新积分**，用下面五块雅可比做一阶更新：

```
ΔR̂' = ΔR̂ · Exp( dr_dbg · δb_g )
Δv̂' = Δv̂ + dv_dbg · δb_g + dv_dba · δb_a
Δp̂' = Δp̂ + dp_dbg · δb_g + dp_dba · δb_a
```

其中 `Exp/Log` 为 SO(3) 指数/对数，`J_r(φ)` 为 SO(3) **右雅可比**（定义见 §3.5.2）。
姿态用**右扰动**：`ΔR(δb_g) ≈ ΔR̂ · Exp(dr_dbg·δb_g)`。

**五块雅可比的递推（规范形式）**

记第 k 步：`ω̂_k = ω_m,k − b̂_g`、`f̂_k = a_m,k − b̂_a`、`R̂_{k-1}` 为**本步更新前**的
`delta_q`、`Δt` 为该步时长。雅可比与预积分**同步递推**（初值全零）：

```
dr_dbg_k = Exp(−ω̂_k Δt)·dr_dbg_{k-1} − J_r(ω̂_k Δt)·Δt
dv_dbg_k = dv_dbg_{k-1} − R̂_{k-1}·[f̂_k]×·dr_dbg_{k-1}·Δt
dv_dba_k = dv_dba_{k-1} − R̂_{k-1}·Δt
dp_dbg_k = dp_dbg_{k-1} + dv_dbg_{k-1}·Δt − ½·R̂_{k-1}·[f̂_k]×·dr_dbg_{k-1}·Δt²
dp_dba_k = dp_dba_{k-1} + dv_dba_{k-1}·Δt − ½·R̂_{k-1}·Δt²
```

`[·]×` 为反对称矩阵，`R̂_{k-1} = I`（首步）时 `dr_dbg_0 = 0`。

**自洽性校验（必须是这个值，不是"接近零"）**

| 首步（`R̂_0 = I`、`dr_dbg_0 = 0`） | 值 | 含义 |
|---|---|---|
| `dv_dbg_1` | `0` | 零偏首步还不能经姿态影响速度 |
| `dp_dbg_1` | `0` | 同上，位置通道亦然 |
| `dv_dba_1` | `−Δt` | 与无旋转退化式 `∂Δv/∂b_a = −ΔR·Δt` 一致 |
| `dp_dba_1` | `−½Δt²` | 与 `∂Δp/∂b_a = −ΔR·½Δt²` 一致 |

**连续形式（仅作对照，实现以递推为准）**

当 `Δt → 0`、单步旋转很小时，`dr_dbg` 的递推退化为 `dr_dbg ≈ −J_r(ω̂ Δt)·Δt`
（累积意义上即 `∂Δθ/∂b_g ≈ −J_r(ω̂ Δt)·Δt`），另外两块退化为
`dv_dba ≈ −ΔR·Δt`、`dp_dba ≈ −ΔR·½Δt²`。

> **注（曾出错处，务必看清）**：早期 §3.5.5 与 05 §3.3.5 各写过一条
> `∂Δv/∂b_g ≈ −ΔR·(ω̃Δt)` 和一条 `−ΔR·(ãΔt)`，**两条都不对**——`∂Δv/∂b_g`
> 只能来自「零偏 → 姿态误差 → 比力旋转」这条链：`−R̂_{k-1}·[f̂]×·(∂Δθ/∂b_g)·Δt`，
> 其主项与 `f̂`（比力）和 `∂Δθ/∂b_g` **同时**有关，既不是纯 `ω̃` 也不是纯 `ã`。
> 这正是它必须用**递推**而非单步闭式表达的原因。

| 约束 | 规则 |
|---|---|
| P-1 | 上述五块雅可比递推为**规范形式**；实现后必须用中心差分校验：`tests/unit/test_preint_jacobian.cpp`，相对误差 < 1e-5，Δt ∈ {0.004, 0.005, 0.01} s，‖ω‖ ∈ {0, 1, 3 rad/s}。校验对象是「`Correct()` 的一阶修正 vs 以扰动后零偏重新积分」 |
| P-2 | 不得因数值不稳定而省略 `dp_dba`（`∂Δp/∂b_a`）项（该项直接决定尺度可观性，见 05 §3.9） |
| P-3 | 偏置重置（bias reset）后必须清空全部预积分量与**全部雅可比**并重新累积，不得在旧量上"打补丁" |
| P-4 | **已废弃**：早期版本在此处写过 `δθ_b ≈ −J_r(Δθ)^{-1}·(δb_g ⊗ Δθ_rate)`。该式**已删除，不得实现**：① `⊗` 被用于量纲不兼容的量（零偏与角增量）；② 预积分量的一阶角增量修正来自 `ΔR` 对 `δb_g` 的线性化（即 `dr_dbg`），不是 `J_r(Δθ)^{-1}`；③ `J_r` 的数值逆在 `θ → 0` 时条件数恶化 |
| P-5 | **规范形式以递推为准、以差分校验裁决**。§3.5.5 与 05 §3.3.5 的闭式表必须与本节的递推**一致**；若数值与闭式冲突，以实现 + 差分校验结果为准（本节即由此校正而来） |

### 3.6 相机–IMU 联合对齐

#### 3.6.1 对齐目标

| 目标 | 形式 |
|---|---|
| 输入 | 相机帧时刻 `t_c`（session 域）、IMU 序列 `{t_k, ω_k, a_k}` |
| 输出 | 该相机帧对应的**积分区间切分**：把 IMU 采样在 `t_c` 处切开，得到"整段 + 尾段" |
| 附带 | 时间残差 `r_t`，用于协方差膨胀 |

#### 3.6.2 分段线性插值切分算法（逐帧执行）

```
输入: IMU 序列 (t_k, ω_k, a_k) 严格递增; 相机时刻 t_c
1. 二分定位: 找到 k 使 t_k ≤ t_c < t_{k+1}
2. 若 t_c 落在区间中，令 δ = t_c − t_k,  Δt = t_{k+1} − t_k
3. 在 t_c 处插值出 (ω_c, a_c):
     α = δ / Δt
     a_c = (1−α) a_k + α a_{k+1}                // 比力：线性插值
     ω_c = (1−α) ω_k + α ω_{k+1}                // 角速度：线性插值
     （改进路径：对 ω 做 slerp/模长-相位分离插值，误差 < 1e-3 rad/s @200 Hz）
4. 把采样 k 拆为两段:
     段 A: (t_k → t_c)，用 ω̃ = ω_k − b_g, ã = a_k − b_a, Δt_A = δ
     段 B: (t_c → t_{k+1})，用 ω̃ = ω_c − b_g, ã = a_c − b_a, Δt_B = Δt − δ
     段 B 的起点的 ω/a 用插值值，而非 ω_{k+1}
5. 逐段用 §3.5.3 递推累加，得到该相机帧的积分贡献
```

| 插值误差来源 | 量级（200 Hz, `abs(ω̇) ≤ 2 rad/s²`） | 处置 |
|---|---|---|
| `ω` 线性插值误差 | ≤ `½ · abs(ω̈) · Δt²` ≈ 2.5e-5 rad/s | 计入协方差 |
| `a` 线性插值误差 | ≤ `½ · abs(ȧ) · Δt²` ≈ 1.25e-4 m/s²（abs(ȧ) ≤ 10 m/s³） | 计入协方差 |
| 切分带来的位置误差 | `≤ ½ · abs(a) · δ²`，δ ≤ 5 ms，abs(a)=10 → 1.25e-4 m | 计入协方差 |

#### 3.6.3 残差分配策略

切分后剩余的**时间不确定度** `σ_t`：

| 来源 | `σ_t` 取值 |
|---|---|
| 相机时间戳量化 | **1 µs**（ns 级时间戳按 1 µs 保守计入；见下方口径说明） |
| 曝光中点未知 | ½ · `exposure_us`（8 ms 快门 → 4 ms）；或按 `τ_exposure_pipeline` 估计 |
| IMU 采样间隔（未插值部分） | ½ · Δt_IMU = 2.5 ms @200 Hz |
| IMU 融合滞后 `τ_cm`（iOS） | 标定值，未标定取 15 ms |

**相机时间戳量化量级的口径（全文唯一）**

iOS `CMSampleBufferGetPresentationTimeStamp` 与 Android `SENSOR_TIMESTAMP` 均为**纳秒分辨率**的单调时钟值，其读数量化误差 ≤ 1 ns；按 1 µs 保守计入时间不确定度 `σ_t`。

本项**不包含** PTS 语义偏差（曝光起点 vs 提交时刻，原始量级 4 000 µs）与卷帘快门行间时差（原始量级 0–33 000 µs）——二者是 §3.7 误差预算表中的 S2 与 S4 项，独立计入。

> 早期版本曾在 §3.7 的 S1 行把本项写成"原始量级 500 µs / 残余 500 µs"，与本节的 1 µs 差 1000 倍，且该 500 µs 无法从平台 API 特性推出（ns 时间戳不存在 500 µs 的量化台阶）。**已统一为 1 µs**。

**残差注入规则（必须实现）**

```
1. 时间残差不进入状态方程，而以"位置-姿态耦合噪声"进入协方差:
     Σ_a ← Σ_a + ( σ_t · σ_a_rate )² I₃      // 比力速率误差经时间残差传导
     Σ_g ← Σ_g + ( σ_t · σ_ω_rate )² I₃
     Σ_p ← Σ_p + ( σ_t · |a| )² I₃           // 时间抖动直接造成位置误差
2. 相机帧与 IMU 观测的**时间残差 r_t = t_c − t_imu_interp**:
     若 |r_t| > 3σ_t → 标记 RECON_ERR_SYNC_RESIDUAL_LARGE，该帧的时间对齐置信度降为 MEDIUM
     若 |r_t| > 10σ_t → 该帧不参与 VIO 的 IMU 约束（仍可参与纯视觉），记 RECON_ERR_SYNC_RESIDUAL_REJECT
3. 上述 σ_t 的量级差异极大（iOS 未标定 τ_cm = 15 ms vs 理想 1 µs），
   因此 iOS 上"标定 τ_cm"是降低整体同步误差的第一优先项，见 §3.9.4。
```

|---|---|
| B-1 | **按平台分列**：每行只计入该平台实际存在的项。S5（iOS `τ_cm`）仅 iOS 计入；S6（Android HAL 时钟族）仅 Android 计入。二者**不得**互相计入或重复计入 |
| B-2 | **S8 取定值 200 µs**：由 §3.10.5 的 `t_d` 标准差验收上限（≤ 0.2 ms）换算，即相机–IMU 联合标定后残留的时间对齐不确定度 |
| B-3 | **算术和** = 该平台全部计入项的残余值直接相加（保守上界）；**RSS** = 各项残余平方和的平方根（统计独立假设下的代表值） |
| B-4 | 未标定场景只把 S5 从 300 µs 换成保守值 15 000 µs，其余项不变 |

| 场景 | 计入项 | 合计（算术和，保守） | 合计（RSS） |
|---|---|---|---|
| iOS，`τ_cm` **已标定** | S1 + S2 + S3 + S4 + **S5** + S7 + S8 + R1 + R2 + R3 + R4 + R5（S6 不计入） | ≈ **4 400 µs** | ≈ **1 720 µs** |
| iOS，`τ_cm` **未标定**（保守 15 000 µs 计入 S5） | 同上，S5 由 300 → 15 000 | ≈ **19 100 µs** | ≈ **15 100 µs** |
| Android，`SOURCE_REALTIME`，S6 已处理 | S1 + S2 + S3 + S4 + **S6** + S7 + S8 + R1 + R2 + R3 + R4 + R5（S5 不计入） | ≈ **5 100 µs** | ≈ **1 910 µs** |

> **S7（50 ppm）的含义**：50 ppm 是**重标定触发判据**（见 §3.2.1 / §3.8.4），不是标定后的残余速率精度。它在预算中代表"**在触发重标定之前**该判据允许的最大速率偏差"，即 1 s 内最多 50 µs 的漂移量——这是保守上界。仿射拟合生效后实际残余速率误差远小于此。判据本身见 §3.2.1：**50 ppm 触发重标定，100 ppm 拒用该时间戳**。
>
> **RSS 与验收判据的区别**：上表 RSS 是**全部误差源叠加**后的时间轴总不确定度；§3.7.1 的验收判据（对齐残差 RMS ≤ 2 000 µs）是对**相机–IMU 联合对齐残差**这一项的实测验收，二者不是同一个量。总预算大于单项验收上限是正常的（项间存在部分抵消与相关性）。

**验收判据**

| 判据 | 阈值 |
|---|---|
| 相机–IMU 联合对齐残差 RMS（标定后、静态+慢速段） | ≤ **2 000 µs** |
| 同一段 10 s 内残差漂移 | ≤ **300 µs** |
| 时间轴仿射残差 RMS | ≤ **1 000 µs**（`SOURCE_UNKNOWN` 时 ≤ 100 µs） |

> 诚实声明：**"微秒级"在本产品中指"误差预算以微秒为量化单位"，不是"整机端到端同步精度达到 1 µs"。** 端到端受限于曝光中点不确定度与卷帘快门，标定后可达 ~2 ms（RSS）。真正达成 1 µs 级需要硬件同步触发相机与 IMU，手机平台不提供该能力——这是物理限制，不做承诺。

### 3.8 时间戳异常检测与处理

#### 3.8.1 倒退

| 判据 | 阈值 | 处理 |
|---|---|---|
| 轻度倒退 | `t_k ≤ t_{k−1}` 且 `t_{k−1} − t_k ≤ 100 ms` | 丢弃该帧；`stats.time_backward++`；触发 `RECON_ERR_SYNC_TIME_BACKWARD` |
| 严重倒退 | `t_{k−1} − t_k > 100 ms` | 同上 + **时间轴重锚定**：重新解算 `β_c`；清空当前预积分窗口；记录 `RECON_ERR_SYNC_REANCHOR` |
| IMU 倒退 | 任意 `t_k ≤ t_{k−1}` | 丢弃该 IMU 样本；连续 3 次 → 关闭该传感器并告警 `RECON_ERR_SYNC_IMU_BACKWARD` |

#### 3.8.2 跳变（前向）

| 判据 | 阈值 | 处理 |
|---|---|---|
| 帧间隔跳变 | `t_k − t_{k−1} > 10 × (1/fps_nominal)` 且 `> 50 ms` | 标记 `gap_start` / `gap_end`；区间内**不生成 IMU 约束**；帧的 `flags` 置 `GAP` |
| 缺口时长 | 缺口 > 200 ms | 提示用户（文案见 §4.4），因该区间几何约束断裂 |
| IMU 跳变 | `Δt_k > 3 × 1/rate_nominal` 且 `> 20 ms` | 丢弃该样本，插入虚拟样本标记 |

#### 3.8.3 丢帧

| 判据 | 阈值 | 处理 |
|---|---|---|
| 帧丢失计数 | `lost = floor(Δt · fps_nominal) − 1` | 累加 `stats.frames_dropped` |
| 连续丢帧 | 连续 3 帧判定丢帧 | 提示（文案见 §4.4） |
| 关键帧缺口 | 丢失帧的 `frame_id` 不连续且跨度 > 5 | 记录到会话日志，13 文档分块时按缺口切块 |

#### 3.8.4 长期健康度（每 5 s 评估一次）

| 指标 | 定义 | 阈值 | 处理 |
|---|---|---|---|
| IMU 采样率偏差 | `abs(rate_actual / rate_nominal − 1) > 0.05` | 持续 3 个窗口 | `RECON_ERR_SYNC_IMU_RATE_DRIFT`，重新请求传感器速率 |
| IMU 间隔抖动 | `std(Δt) / mean(Δt) > 0.05` | 持续 3 个窗口 | 告警；协方差膨胀 ×2 |
| 时间轴速率漂移 | `abs(α − α_prev) > 50 ppm` | 一次 | 重新拟合并告警 `RECON_ERR_SYNC_CLOCK_DRIFT` |
| 相机–IMU 长期互相关峰偏移 | 互相关峰相对上一评估移动 > 500 µs | 一次 | 触发 `τ_cm` / `τ_exposure_pipeline` 重标定 |
| 静置段零偏跳变 | 静止检测下 `b_g` 变化 > 0.02 rad/s | 一次 | 重新估计零偏，重算预积分 |

> 相机–IMU 长期互相关：以相机帧的光流残差序列与 IMU 角速度序列做互相关，峰值位置即 `τ_cm + τ_exposure_pipeline` 的联合估计。互相关峰锐度（峰/次峰比）< 3 时判为不可靠，不更新。

### 3.10 相机–IMU 联合标定方案（Kalibr 风格）

#### 3.10.1 内参标定（先行，独立于 IMU）

| 项 | 规格 |
|---|---|
| 标定板（常规焦距） | 棋盘格 `9 × 6` 内角点，格边长 `25.00 ± 0.02 mm`，板尺寸 `200 × 125 mm`，亚光铝基板 |

#### 3.10.2 标定板（IMU 联合标定用）

沿用 §3.10.1 的 AprilTag 阵列板（Kalibr 的 `Aprilgrid` 思路）：`6 × 5` tag，边长 40 mm，间距 12 mm。**必须是刚性平面**，平面度 ≤ 0.5 mm。

| 约束 | 原因 |
|---|---|
| 板必须刚性 | 弯曲会引入无法建模的位姿误差 |
| tag 必须印刷精度 ≤ 0.02 mm | 直接进入重投影残差 |
| 板不能在标定中移动 | 移动会破坏"同一静态物体在两个坐标系下的观测"假设 |

#### 3.10.3 激励动作序列

| 阶段 | 时长 | 动作 | 目的 |
|---|---|---|---|
| S0 静止 | ≥ 5 s | 完全静止 | 估计 `b_g, b_a` 初值与噪声 |
| S1 绕 X 轴 | ≥ 6 s | 匀速绕板法向倾斜 ±45°，2 个来回 | 激励 `R_ic` 的 X 分量 |
| S2 绕 Y 轴 | ≥ 6 s | 绕水平面内轴旋转 ±45° | 激励 `R_ic` 的 Y 分量 |
| S3 绕 Z 轴 | ≥ 6 s | 绕光轴旋转 ±60°，2 个来回 | 激励 `R_ic` 的 Z 分量（最弱方向） |
| S4 自由平移 | ≥ 8 s | 沿三轴平移 ±0.15 m，缓慢 | 提高 `t_ic` 与 `t_d` 的可观性 |
| S5 复合 | ≥ 10 s | 走 8 字轨迹，同时缓慢转动 | 提高整体条件数 |

| 激励判据（必须校验，不满足则重录） | 阈值 |
|---|---|
| 每轴角激励标准差 | `σ_θg(axis) > 0.05 rad` |
| 每轴角激励幅度 | 峰值 > 0.35 rad |
| 平移激励幅度 | 峰值 > 0.05 m |
| 总时长 | ≥ 40 s 且 ≥ 30 s 有效运动 |
| 帧率 | ≥ 30 fps |

#### 3.10.4 优化问题

**待估参数**

| 参数 | 维度 | 初值 | 备注 |
|---|---|---|---|
| `K`（内参） | 4 或 8 | §3.10.1 结果（固定，不参与联合优化） | 联合优化内参会显著降低条件数，本产品**固定内参** |
| `D`（畸变） | 4 或 5 | 同上（固定） | |
| `R_ic` | 3 | 单位阵（按平台惯例预设轴向） | SO(3) 流形 |
| `t_ic` | 3 | 零 | m |
| `t_d` | 1 | 0 | 相机–IMU 时间偏移，**秒** |
| `b_g` | 3 | S0 静止段均值 | rad/s |
| `b_a` | 3 | S0 静止段均值 | m/s² |
| `σ_g, σ_bg, σ_a, σ_ba` | 4 | 设备先验值 | 第二阶段单独估计，不参与联合优化 |

**残差**

```
1) 视觉重投影残差（对每个相机帧 i、每个 tag 角点 j）:
     r_vis(i,j) = π(K, D, T_cw(i) · T_ic · T_wb(j) · P_j) − p_obs(i,j)
     权重 σ_vis = 1.0 px
     注: P_j 为 tag 角点在标定板坐标系中的坐标, p_obs 为像素观测

2) IMU 旋转残差（连续时间形式，非预积分）:
     r_gyro(i) = Log( R_{i,i+1} · Exp( −(ω̂_i − b_g) Δt_i ) )         [rad]
     其中 R_{i,i+1} = R_{w,i}^T · R_{w,i+1}
     权重 σ_gyro = σ_g

3) IMU 加计残差:
     r_acc(i) = R_{i,i+1} · (â_i) − â_{i+1} + ½ · g_W · Δt_i²          [m/s²]
     权重 σ_acc = σ_a

4) 零偏残差（静止段）:
     r_bg = b_g − mean(ω_m)          [rad/s]
     r_ba = b_a − mean(a_m) + g_W    [m/s²]
     权重 σ_bg_static = σ_g / √N_static
```

**总代价**

```
E = Σ_i Σ_j w_vis ‖r_vis(i,j)‖²
  + Σ_i w_gyro ‖r_gyro(i)‖²
  + Σ_i w_acc  ‖r_acc(i)‖²
  + w_bg ‖r_bg‖² + w_ba ‖r_ba‖²
```

| 项 | 取值 / 说明 |
|---|---|
| 优化器 | Ceres Solver（`third_party/ceres`，BSD-3-Clause） |
| `SO(3)` 参数化 | `ceres::Manifold`（Ceres ≥ 2.1 内置 `ceres::Manifold`）；不得用四元数直接优化 |
| 求解器 | `SPARSE_SCHUR` + `DENSE_SCHUR` 混合（视觉点为 Schur 块，IMU 参数在消去块） |
| 迭代上限 | 100 |
| 收敛判据 | `function_tolerance = 1e-10`，`gradient_tolerance = 1e-8`，`parameter_tolerance = 1e-9` |
| `t_d` 的可观测性 | `t_d` 与 `R_ic` 存在强耦合（旋转等价性），**必须**用 S3/S4/S5 的多轴激励解除；单轴数据不可标定 |
| 协方差 | 求解后由 Ceres 输出 `Covariance`，报告 `t_ic`/`t_d` 的标准差 |

**第二阶段：噪声参数**

| 方法 | 规格 |
|---|---|
| Allan 方差 | 静止采样 ≥ 10 min；计算 Allan 方差曲线，斜率 −1/2 截距 → `σ_g`, `σ_a`；斜率 +1/2 截距 → `σ_bg`, `σ_ba` |
| 采样率敏感性 | 分别在 100 / 200 Hz 下采集，交叉验证密度换算（`σ_dense = σ_sample / √(Δt)`） |
| 先验值（无标定文件时） | `σ_g = 3.0e-4 rad/s/√Hz`，`σ_bg = 3.0e-5 rad/s²/√Hz`，`σ_a = 2.0e-3 m/s²/√Hz`，`σ_ba = 5.0e-4 m/s³/√Hz` |

#### 3.10.5 验收判据

| 判据 | 阈值 | 不达标处理 |
|---|---|---|
| 视觉重投影 RMS | ≤ **0.5 px** | 重录或改内参模型 |
| IMU 旋转残差 RMS | ≤ **2 σ_g** | 重录 |
| IMU 加计残差 RMS | ≤ **2 σ_a** | 重录 |
| `t_ic` 标准差 | ≤ **0.5 mm** | 增加激励时长 |
| `t_d` 标准差 | ≤ **0.2 ms** | 增加平移激励 |
| `abs(t_ic)` 合理性 | ≤ 0.08 m | 拒绝该标定 |
| `abs(t_d)` 合理性 | ≤ 0.05 s | 拒绝该标定 |
| 重复性 | 同设备 5 次标定，`t_d` 极差 ≤ 0.5 ms | 标定流程需复核 |
| 闭合误差 | 优化后 IMU 残差无系统性漂移（斜率检验 p < 0.01 判失败） | 重录 |

| 项 | 规格 |
|---|---|
| 入口 | App 内"设备标定"独立流程（非扫描会话内） |
| 引导 | 纯文字步骤提示（与 03 的"无动效"原则一致），实时显示当前激励轴是否达标（文字 + 数值） |

| 执行位置 | 核心层 `core/capture/quality_gate.{h,cpp}`，输入 `FramePacket`，输出 `GateResult` |
| 执行频率 | **每帧**执行计算，但**不是每帧上报**（上报规则见 §4.7） |
| 降采样策略 | 检测类计算在 **1/4 降采样灰度图**上做；判定阈值按降采样后分辨率给出（已折算） |
| 分辨率一致性 | 检测统一在宽 960 px 的灰度图上进行（长边 960，短边按比例，偶数对齐）；阈值表中的像素量均按此基准 |
| 门限语义 | `GateResult.reject_reason` 非空 → 该帧**不进入重建**（被拒帧的原始数据仍落盘，见 §5.6.4，用于事后回溯与门限标定） |
| 与关键帧的关系 | **质量门限是帧进入重建的必要条件**：通过门限的帧**都会被送入关键帧增益评估**，不会被静默丢弃。是否最终成为关键帧，由 03 §5.1 的增益判据（几何增量 / 视角增量 / 质量分）判定 |

#### 4.1.1 `GateResult`

```
struct GateResult {
  bool  passed;                 // 是否进入重建
  uint32_t reject_reason;       // 位掩码，见下表
  float  q_blur;                // 清晰度分 0..1
  float  q_texture;             // 纹理分 0..1
  float  q_exposure;            // 曝光分 0..1
  float  q_overlap;             // 与上一帧重叠度 0..1
  float  q_total;               // 加权综合 0..1
  float  flow_px_per_frame;     // 光流中位速度
  float  omega_norm;            // IMU 角速度模长 rad/s
  float  lin_speed_est;         // 估算线速度 m/s（可用时）
  float  sat_ratio;             // 饱和像素比
  float  blob_ratio;            // 过曝连通域面积占比
  float  lowtex_ratio;          // 低纹理网格占比
  uint32_t blind_sector_id;     // 未覆盖扇区 id，0 = 无
};
```

| 位 | `reject_reason` | 含义 |
|---|---|---|
| 0 | `REJECT_FAST_MOTION` | 移动过快 |
| 1 | `REJECT_BLUR` | 画面模糊 |
| 2 | `REJECT_LOW_OVERLAP` | 重叠度不足 |
| 3 | `REJECT_SPECULAR` | 高光/反光 |
| 4 | `REJECT_LOW_TEXTURE` | 纹理缺失 |
| 5 | `REJECT_BLIND_SECTOR` | 视角盲区（**不拒绝该帧**，仅提示；保留该位仅用于日志） |

> 位 5 语义特殊：盲区是**空间覆盖**问题，不是**单帧质量**问题，因此不拒绝帧，仅提示用户补扫。

#### 4.1.2 检测用中间量（供 03/05 复用）

| 中间量 | 分辨率 | 复用方 |
|---|---|---|
| 960 宽灰度图 | 960 × H/2 | 特征提取前置 |
| Shi-Tomasi 角点（上限 1000，quality 0.01，minDistance 8） | 960 宽 | 05（但 05 必须按 R-PREC-4 用**不降级的完整特征数**，此处仅供检测） |
| KLT 稀疏光流（前帧 → 当前帧，双向一致性检查） | 960 宽 | 04/05 |
| 饱和掩码 / 过曝连通域 | 960 宽 | — |
| 16×16 网格纹理计数 | 960 宽 | — |

> **R-PREC-4 边界说明**：检测阶段的角点数上限 1000 是**检测**用途，不构成重建阶段的特征点数上限。重建阶段特征点数不可降级。若 05 文档担心 1000 与重建特征数混淆，检测路径应使用独立的降采样金字塔层（层 2），不与重建特征池共享。

### 4.2 检测项 1：移动过快

| 项 | 规格 |
|---|---|
| 观测量 A | IMU 角速度模长 `‖ω‖`，来自该帧 IMU 窗口（时间跨度 = 该帧前 100 ms） |
| 观测量 B | 光流中位速度 `v_flow`（px/frame，960 宽基准） |
| 观测量 C | 估算线速度 `v_lin`（m/s），仅在有深度或已建立尺度时可用 |

#### 4.2.1 判定阈值

| 级别 | 条件（任一满足） | 动作 |
|---|---|---|
| 提示级 | `‖ω‖ > 1.5 rad/s` (86 °/s) | 仅提示，不拒帧 |
| 提示级 | `v_flow > 18 px/frame` @960 宽 | 仅提示 |
| 警告级 | `‖ω‖ > 3.0 rad/s` (172 °/s) | 提示 + 拒帧（`REJECT_FAST_MOTION`） |
| 警告级 | `v_flow > 30 px/frame` | 同上 |
| 警告级 | `v_lin > 0.45 m/s`（有尺度时） | 同上 |
| 严重级 | `‖ω‖ > 6.0 rad/s` (344 °/s) | 拒帧 + 强提示 |

#### 4.2.2 自适应修正

| 条件 | 修正 |
|---|---|
| 已知深度 `Z`（BRANCH_RGBD） | 线速度估计改为 `v_lin = v_flow · Z / f`，`f` 取 960 宽下的等效焦距 `f_960 = fx · 960 / W` |
| 无深度（BRANCH_MONO） | 只用角速度 + 光流阈值；`v_flow` 阈值按"典型桌面物体 0.4 m、f_960 ≈ 700 px"折算得 18 px/frame ≈ 0.10 m/s 的**视差等效**量，不等价于真实速度，故只作辅助 |

#### 4.2.3 触发频率

| 项 | 规则 |
|---|---|
| 判定 | 每帧 |
| 上报 | 状态从"正常"切入"警告"时上报 1 次；持续期间不再重复上报 |
| 恢复 | 连续 10 帧满足"提示级"以下 → 恢复并上报 1 次恢复事件 |
| 最小间隔 | 同一状态切换的最小间隔 1 000 ms |

### 4.3 检测项 2：画面模糊

| 项 | 规格 |
|---|---|
| 算法 | Laplacian 清晰度（Variance of Laplacian, VoL） |
| 预处理 | 灰度 → 960 宽 → 3×3 Laplacian 核 `[[0,1,0],[1,−4,1],[0,1,0]]` → 取方差 |
| 附加 | 与 IMU 角速度联合判别运动模糊（见 §4.3.3） |

#### 4.3.1 绝对阈值

| 级别 | VoL（960 宽基准） | 动作 |
|---|---|---|
| 清晰 | > 150 | 正常 |
| 临界 | 60 – 150 | 仅提示 |
| 模糊 | 20 – 60 | 提示 + 拒帧 |
| 严重模糊 | < 20 | 拒帧 + 强提示 |

> VoL 与图像内容强相关（纯色墙面 VoL ≈ 0，高频树叶 VoL 可达 800+）。绝对阈值只在**同场景同曝光**下有意义，因此必须配合 §4.3.2 的自适应策略。绝对阈值的作用是"防止纯色表面被自适应逻辑误判为清晰"。

#### 4.3.2 自适应阈值

```
维持滑动窗口 W = 最近 30 帧（≈ 1 s @30 fps）的 VoL 序列，取中位数 M 与 MAD
定义相对清晰度 r = VoL_k / max(M, ε),  ε = 20（防止 M→0 时除零放大）
自适应模糊条件: r < 0.35 且 VoL_k < 150
自适应严重模糊: r < 0.15
```

| 约束 | 规则 |
|---|---|
| 窗口有效性 | 有效样本 < 10 帧时只用绝对阈值 |
| 稳健性 | 用中位数 + MAD 而非均值 + 标准差，避免单帧极值污染基线 |
| 场景切换 | 当 `M` 的变化率 > 3×/s（用户换物体）时重置窗口，计数 1 次"基线重置" |

#### 4.3.3 运动模糊联合判别

| 条件 | 结论 |
|---|---|
| `‖ω‖ > 3.0 rad/s` 且 `VoL < 0.5 · M` | 判为**运动模糊**（而非失焦），文案不同（见 §4.6 纹理缺失检测与 §4.9.2 文案表） |
| `‖ω‖ ≤ 1.0 rad/s` 且 `VoL < 0.35 · M` | 判为**失焦** |
| 两者都不满足 | 判为**模糊（原因未知）**，用通用文案 |

#### 4.3.4 触发频率

| 项 | 规则 |
|---|---|
| 判定 | 每帧 |
| 上报 | 状态切换时上报 1 次；持续期间不重复 |
| 恢复 | 连续 10 帧 `r > 0.6` → 恢复 |
| 最小间隔 | 1 500 ms |

### 4.4 检测项 3：帧重叠度不足

| 项 | 规格 |
|---|---|
| 观测量 A | 特征匹配覆盖率 `cov`：前帧角点中，双向 KLT 一致且通过几何验证的比例 |
| 观测量 B | 位姿增量：中位光流 `v_flow`（px/frame）与估计旋转量 `Δθ`（deg） |

#### 4.4.1 匹配覆盖率

| 步骤 | 规格 |
|---|---|
| 特征 | Shi-Tomasi，前帧上限 1000，`qualityLevel = 0.01`，`minDistance = 8` |
| 跟踪 | KLT（稀疏金字塔，层 3） |
| 双向一致性 | 反向跟踪误差 `> 1.0 px` 的点丢弃 |
| 几何验证 | RANSAC 本质矩阵，内点阈值 `2.0 px`（960 宽基准） |
| 覆盖率 | `cov = inliers / n_features_prev` |

#### 4.4.2 判定阈值

| 级别 | 条件 | 动作 |
|---|---|---|
| 正常 | `cov ≥ 0.55` | — |
| 提示 | `0.35 ≤ cov < 0.55` | 仅提示 |
| 警告 | `cov < 0.35` | 提示 + 拒帧 |
| 警告 | `v_flow > 26 px/frame` 且 `cov < 0.5` | 提示 + 拒帧 |
| 警告 | `Δθ > 15°`（同向旋转估计） | 提示 + 拒帧 |
| 严重 | `cov < 0.15` | 强提示 + 拒帧 |

> `cov` 低但 `v_flow` 也低 → 多为**纹理不足**导致的匹配失败，应由 §4.6 的纹理缺失检测归类，避免两条文案同时触发。文案归类规则：若 `低纹理网格占比 > 0.25`，则归入"纹理缺失"，不再报"重叠度不足"。

#### 4.4.3 触发频率

| 项 | 规则 |
|---|---|
| 判定 | 每帧（与关键帧判定复用同一份 KLT 结果，零额外成本） |
| 上报 | 状态切换时 1 次 |
| 恢复 | 连续 10 帧 `cov ≥ 0.55` |
| 最小间隔 | 1 500 ms |

### 4.5 检测项 4：高光/反光

| 项 | 规格 |
|---|---|
| 观测量 A | 饱和像素比 `sat_ratio` = `#{max(R,G,B) ≥ 250}` / 总像素 |
| 观测量 B | 过曝连通域面积占比 `blob_ratio` = `Σ area(过曝连通域) / 总像素`，仅统计面积 > 0.5% 图像的连通域 |
| 预处理 | 960 宽 RGB；过曝掩码 = `max(R,G,B) ≥ 252`；连通域用 8 邻域，标记传播 |

#### 4.5.1 判定阈值

| 级别 | 条件 | 动作 |
|---|---|---|
| 正常 | `sat_ratio ≤ 0.01` 且 `blob_ratio ≤ 0.02` | — |
| 提示 | `sat_ratio > 0.02` 或 `blob_ratio > 0.03` | 仅提示 |
| 警告 | `sat_ratio > 0.05` 或 `blob_ratio > 0.08` | 提示 + 拒帧 |
| 严重 | `sat_ratio > 0.12` 或 单个连通域面积 > 0.15 | 强提示 + 拒帧 |

#### 4.5.2 附带量（供纹理/重建参考）

| 量 | 定义 | 用途 |
|---|---|---|
| `specular_dir_hint` | 过曝区域在图像上的方位（±90° 范围的一维直方图峰值） | 引导用户朝**避开反光**的方向移动（03 文档使用） |
| `highlight_cells` | 过曝连通域所覆盖的 16×16 网格 id 集合 | 05 文档对这些网格的深度降权（**降权不丢弃**，符合 00 §8.2 的"保精度"策略） |

#### 4.5.3 触发频率

| 项 | 规则 |
|---|---|
| 判定 | 每帧（饱和比 O(N)，可降采样到 1/4 分辨率统计，阈值同步按面积比不变） |
| 上报 | 状态切换时 1 次；另每 3 s 允许一次"方向建议"更新（仅在引导模式使用） |
| 恢复 | 连续 15 帧 `sat_ratio ≤ 0.02` |
| 最小间隔 | 3 000 ms（反光成因变化慢，过快提示会打扰用户） |

### 4.6 检测项 5：纹理缺失

| 项 | 规格 |
|---|---|
| 网格 | 16 × 16 = 256 格（960 宽基准，每格 60 × H/16 px） |
| 单格统计 | 每格独立跑 Shi-Tomasi（`maxCorners = 40`，`qualityLevel = 0.005`，`minDistance = 6`），记录角点数 `n_g` |
| 网格加权 | 每格按面积比加权（避免非方形像素导致偏差） |
| 低纹理判据 | `n_g < 4` → 该格为低纹理 |

#### 4.6.1 判定阈值

| 级别 | 条件 | 动作 |
|---|---|---|
| 正常 | `lowtex_ratio ≤ 0.15` | — |
| 提示 | `0.15 < lowtex_ratio ≤ 0.30` | 仅提示 |
| 警告 | `0.30 < lowtex_ratio ≤ 0.50` | 提示 + 拒帧 |
| 严重 | `lowtex_ratio > 0.50` | 强提示 + 拒帧 |

| 说明 | 阈值依据 |
|---|---|
| `n_g < 4` 的含义 | 在 60×34 px（960×540 基准）的一格内少于 4 个角点，Shi-Tomasi 在该区域基本不可用 |
| 拒帧的理由 | 全局纹理过低时 SfM 特征匹配不可靠；但**只拒整帧不对齐格降权**，避免大面积均匀物体（白色陶瓷）被全丢 |

#### 4.6.2 空间定位

| 量 | 定义 |
|---|---|
| `lowtex_cells` | 低纹理格 id 集合（按行优先，id = row×16 + col） |
| `lowtex_centroid` | 低纹理格的加权质心（归一化坐标 [0,1]²） |
| `lowtex_bbox` | 低纹理格的包围盒 |

用于 03 文档生成"请向右移动"的方向建议（避开低纹理区）。

#### 4.6.3 触发频率

| 项 | 规则 |
|---|---|
| 判定 | 每帧（角点检测 256 格成本高，实现上按 **每 3 帧 1 次**采样，结果在中间帧沿用；`n_g` 变化慢，此采样率不损失信息） |
| 上报 | 状态切换时 1 次 |
| 恢复 | 连续 10 次采样 `lowtex_ratio ≤ 0.15` |
| 最小间隔 | 5 000 ms |

### 4.7 检测项 6：视角盲区

| 项 | 规格 |
|---|---|
| 参考系 | 物体中心 `C`（估计方法见 03 文档）与相机光心位置构成的球面方向 |
| 方位角 `ψ` | 水平面内，0° = 用户初始正前方，顺时针为正 |
| 俯仰角 `θ` | 相对水平面，+90° = 正上方，−90° = 正下方 |
| 直方图 | 方位 36 bin（10°/bin，ψ ∈ [−180°, 180°)），俯仰 18 bin（10°/bin，θ ∈ [−90°, 90°)），共 648 格 |

#### 4.7.1 覆盖标记规则

| 步骤 | 规则 |
|---|---|
| 1 | 每帧由 `Camera` 位姿 + `C` 算出 `(ψ, θ)`，标记 `(ψ, θ)` 所在格及其**四邻**格（跨格边界时按角度差 < 10° 决定） |
| 2 | 每格累计计数 `n_cell`；某格被判定为"已覆盖"当 `n_cell ≥ 3` |
| 3 | 方位扇区（10° 宽）被判为"盲区"当该扇区内**所有 18 个俯仰 bin** 均未覆盖 |
| 4 | 更大粒度：连续 3 个相邻方位扇区（30°）全盲 → 记为"盲区扇区"，`blind_sector_id` 编码为 `sector_start_bin` |
| 5 | 上/下方特殊判定：俯仰 ≥ +70° 的 bin 全未覆盖 → "顶部盲区"；≤ −70° 全未覆盖 → "底部盲区" |

#### 4.7.2 判定阈值

| 级别 | 条件 | 动作 |
|---|---|---|
| 提示 | 盲区扇区数 ≥ 1 且 已覆盖方位跨度 < 300° | 仅提示（引导模式下持续显示当前目标点位） |
| 警告 | 盲区扇区数 ≥ 3 | 提示 |
| 严重 | 盲区扇区数 ≥ 6 或 顶部+底部同时盲 | 强提示 + 在确认清单中列出（03 文档 §7） |

> 盲区检测**不拒帧**。拒绝会直接损失该方向的信息，与 R-PREC-3 冲突。

#### 4.7.3 触发频率

| 项 | 规则 |
|---|---|
| 判定 | 每帧更新直方图，每 10 帧评估一次盲区判定 |
| 上报 | 盲区集合发生变化时上报 1 次（新增/消失分别计） |
| 恢复 | 盲区消失时上报 |
| 最小间隔 | 8 000 ms |

| M11 | 提示 | 此处纹理不足 | 换个角度拍摄 |
| M12 | 警告 | 纹理不足，已跳过此帧 | 请换个角度 |
| M13 | 提示 | 该方向尚未覆盖 | 按提示继续移动 |
| M14 | 警告 | 底部尚未覆盖 | 抬起物体或翻转后补拍 |
| M15 | 警告 | 顶部尚未覆盖 | 改为俯视角度补拍 |
| M16 | 提示 | 拍摄已暂停 | 请检查提示后继续 |
| M17 | 提示 | 检测到丢帧 | 请放慢移动速度 |

#### 4.9.3 文案选择算法

```
按优先级 D1..D6 取当前处于"警告级及以上"的最高优先级项；
在其级别内按 上表编号升序 取第一条；
若该检测项处于"提示级"，取该级别的第一条；
若无任何检测项处于警告级 → 不显示异常文案。
```

### 4.10 节流与去重

| 规则 | 规格 |
|---|---|
| S-1 | 每个检测项独立状态机：`NORMAL → WARN → NORMAL`，只在**状态跳变**时产生事件 |
| S-2 | 同类事件最小间隔见 §4.8；间隔内的跳变被丢弃（不排队） |
| S-3 | 全局最小间隔：**1 200 ms** 内最多产生 1 条用户可见提示（跨类共享） |
| S-4 | 去重键 = `(检测项, 级别)`；相同键在 **60 s** 内不重复产生**用户可见**提示，但事件仍记入日志与统计 |
| S-5 | 严重级（M3/M6/M10/M12）**不受** S-3、S-4 限制，直接立即显示 |
| S-6 | 同一提示连续显示期间，UI 层不重复插入新元素，只在文案后追加计数（如"反光较强（3）"） |
| S-7 | 提示队列长度上限 1，**不排队**；被新提示覆盖的旧提示丢弃 |
| S-8 | 会话结束时不保留任何提示状态 |
| S-9 | 所有事件写入会话日志（§5.1），供 14 文档验收分析 |

| 约束 | 说明 |

### 5.2 文件格式取舍

| 候选 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| PNG / JPEG 序列 | 通用、工具链现成 | JPEG 有损（违反 R-PREC-3：直接损失纹理与特征精度）；PNG 编码慢（1080p 单帧 ≈ 40–80 ms，占用采集预算） | **不采用** |
| 原始裸流（`raw`） | 无损、最快 | 索引、随机访问、元数据全靠外部约定 | 部分采用（作为容器内部负载） |
| MP4 / MOV | 体积小、硬件编码 | 有损、不可随机访问单帧、无逐帧元数据 | **不采用** |
| 自研容器（定长索引 + 连续负载 + 可选无损压缩块） | 无损、可随机访问、索引紧凑、写入顺序化、可断点续算 | 需自己实现（工作量可控，约 600 行） | **采用** |

#### 5.2.1 自研容器取舍说明（明确理由）

| 决策点 | 选择 | 理由 |
|---|---|---|
| 是否压缩 | 默认**不压缩**（RAW），提供 `ZSTD` 可选模式 | R-PREC-1：压缩引入 CPU 预算与实现复杂度；实测 RAW 写入带宽需求见 §5.6，远低于现代手机 UFS 带宽 |
| 是否分块 | 是，按帧为块 | 支持并发读取与断点续算 |
| 是否自研 | 是（不引入 Protobuf/Cap'n Proto 等依赖） | 许可白名单约束（00 §1）+ 避免引入二进制 blob 依赖 |
| 索引格式 | 定长二进制记录（64 B/帧） | 可 `mmap` 后直接二分查找，无需解析 |

> 若后续 §5.6 实测发现写入带宽不足，再引入 ZSTD（BSD-3-Clause / GPLv2 双许可，取 BSD 侧）作为**可选**负载编码，并在 10 文档登记。此处不预先实现。

### 5.3 帧索引 `index.bin`

#### 5.3.1 记录布局（定长 64 B，小端）

| 偏移 | 大小 | 字段 | 说明 |
|---|---|---|---|
| 0 | 8 | `frame_id` | u64，会话内单调递增 |
| 8 | 8 | `t_ns` | i64，session timebase |
| 16 | 8 | `t_exposure_center_ns` | i64 |
| 24 | 4 | `flags` | u32，bit0 关键帧（由 03 文档 §5.1 判据置位）, bit1 通过质量门限, bit2 含深度, bit3 卷帘快门, bit4 疑似运动模糊, **bit5–bit12 保留给 03 文档的 `priority`（priority/255 的近似值）**，bit13–bit31 置 0 |
| 28 | 4 | `rgb_offset` | u32，帧负载区内 RGB 段起始偏移 |
| 32 | 4 | `rgb_size` | u32，RGB 段字节数（压缩后） |
| 36 | 4 | `rgb_raw_size` | u32，RGB 解压后字节数 |
| 40 | 4 | `depth_offset` | u32，0 = 无深度 |
| 44 | 4 | `depth_size` | u32 |
| 48 | 2 | `q_total` | u16，0–65535 映射 0–1 |
| 50 | 2 | `q_blur` | u16 |
| 52 | 2 | `q_texture` | u16 |
| 54 | 2 | `q_overlap` | u16 |

| 60 | 2 | `imu_count` | u16 |
| 62 | 2 | `reserved` | u16，置 0 |

**`flags` 位定义与跨文档锚点（写盘与重建的双向契约）**

| 位 | 含义 | 置位方 | 消费方 | 跨文档锚点 |
|---|---|---|---|---|
| **bit0** | **关键帧** | 03 文档 §5.1 的增益判据 | 重建流程（只把关键帧送入 BA / MVS / TSDF）；02 §5.6.4 的落盘层级 | **03 §5.1** |
| bit1 | 通过质量门限 | 02 §4 质量门限 | 落盘层级判定（L1 关键帧层 vs 调试保留） | 02 §4 |
| bit2 | 含深度 | 平台适配层 | 重建（决定是否走 RGBD 分支的深度通道） | 02 §2.2 |
| bit3 | 卷帘快门 | 平台适配层 | 重建（附加位姿不确定度） | 02 §3.3.2 |
| bit4 | 疑似运动模糊 | 平台适配层 | 重建（深度降权） | 02 §4.3.3 |
| bit5–bit12 | `priority`（priority/255 的近似值） | 03 §5.4（重建期回写） | 重建调度顺序 | 03 §5.4.3 |
| bit13–bit31 | 保留，置 0 | — | — | — |

> **bit0 是跨文档契约锚点**：02 文档只负责**记录**该位，是否置位完全由 03 文档 §5.1 的增益判据决定。重建侧读 `index.bin` 时以 bit0 为"该帧是否参与重建"的唯一依据，**不得**用 bit1（通过门限）替代——通过门限但无增益的帧 bit1 = 1 且 bit0 = 0（见 03 §5.1.1 的流程图）。

#### 5.3.2 索引操作

| 操作 | 复杂度 | 实现 |
|---|---|---|
| 按 `frame_id` 查 | O(log N) | `mmap` + 二分（记录按 `frame_id` 有序） |
| 按时间区间查 | O(log N + K) | 二分定位 + 顺序扫 |
| 追加 | O(1) | 顺序追加写，**不重写历史** |
| 断点恢复 | O(N) 一次 | 扫描尾部，截断到最后一个**完整**记录（校验 `frame_id` 连续性与 `rgb_offset + rgb_size ≤ frames.bin` 长度） |

#### 5.3.3 断点续算

| 项 | 规格 |
|---|---|
| 续算单元 | 关键帧级。`manifest.json` 中记录 `resume_cursor = { last_keyframe_frame_id, last_imu_index }` |
| 续算输入 | `frames.bin` + `index.bin` + `imu.bin` + `calib_used.json`，全部只读 |
| 校验 | 启动时校验 `manifest.json.sha256_of(index.bin)`；不匹配则拒绝续算并提示"数据不完整" |
| 写模式 | 续算输出写入新目录 `sessions/<id>_resume/`，**不修改**原目录 |

### 5.5 `frames.bin` 负载布局

每帧的负载按下列顺序连续排列：

```
[RGB 段][深度段][置信度段]
```

| 段 | 内容 | 长度 |
|---|---|---|
| RGB | `PixelFormat` 原生格式的像素行（stride 对齐） | `rgb_raw_size` |
| 深度 | `uint16` 毫米（沿光轴的 z 深度，与 00 §8.2 一致），行对齐 | `depth_size` |

| 约束 | 说明 |

| F-3 | 段之间**不做 4 字节对齐填充**，偏移由索引精确记录 |

### 5.6 异步写盘

#### 5.6.1 线程模型

| 线程 | 数量 | 职责 | 优先级 |
|---|---|---|---|
| 采集线程 | 1 | 收帧、入队、释放引用 | 高（见 §2.7） |
| 核心处理线程 | 1 | 时间同步 → 质量门限 → 关键帧判定 → 组帧入写盘队列 | 中 |
| 写盘线程 | 1 | 顺序追加写 `frames.bin` / `index.bin` / `imu.bin` | 低（`QOS_CLASS_UTILITY` / `THREAD_PRIORITY_BACKGROUND`） |

```
采集线程 --(无锁队列, 8)--> 核心线程 --(无锁队列, 64 帧)--> 写盘线程 --(顺序 append)--> 文件
```

| 约束 | 规格 |
|---|---|
| W-1 | 写盘线程**独占**帧负载的所有权，核心线程移交后不再访问像素 |
| W-2 | 写盘线程不得做任何解压/压缩/特征计算，只做 `memcpy` + `write()` |
| W-3 | 核心 → 写盘队列满（64 帧）时：**不阻塞核心线程**，改为把帧标记 `pending_flush` 并继续；队列深度监控，超过 48 帧触发 `RECON_ERR_WRITE_QUEUE_BACKLOG` |
| W-4 | 写盘队列最终满时（64 帧且写盘连续 2 s 未下降）：丢弃**非关键帧**并记 `frames_dropped_writer`；关键帧**不丢弃**，改为阻塞核心线程（此时采集仍在进行，写盘追平后释放） |
| W-5 | `write()` 使用 `pwrite` 指定偏移，避免维护独立文件指针；**按累计写入量 ≥ 4 MiB 且距上次 sync 的间隔 ≤ 200 ms** 两个条件中**先到者**触发一次同步：Linux/Android 用 `fdatasync()`，iOS 用 `fcntl(fd, F_FULLFSYNC)`（`F_FULLFSYNC` 会连设备缓存一起落盘，比 `fsync()` 更严格，是 iOS 上的正确选择）。**间隔上限 200 ms 的依据**：写入速率 115 ~ 263 MiB/s（见 §5.6.2），200 ms 对应 23 ~ 53 MiB 的未落盘窗口，超过手机闪存断电保护所需的持久化窗口；原"或 1 s"的表述在高速率下会拉长未落盘窗口到 115 ~ 263 MiB，风险过高，故收紧为 200 ms |
| W-6 | `index.bin` 与 `frames.bin` 顺序写，不修改历史字节；崩溃后按 §5.3.2 截断恢复 |
| W-7 | 落盘完成的帧，从核心层的 IMU 预积分窗口中释放对应的 IMU 样本引用 |

#### 5.6.2 写入带宽需求

| 配置 | 帧率 | RGB/帧（原生） | 深度+置信度/帧 | 合计写入速率（落盘口径） | BGRA8 上界（内存口径） |
|---|---|---|---|---|---|
| 1080p + ToF 640×480 | 30 | 2.97 MiB | 0.88 MiB | **115 MiB/s** | 263 MiB/s |
| 1080p 无深度 | 30 | 2.97 MiB | — | **89 MiB/s** | 237 MiB/s |
| 720p + ToF | 30 | 1.32 MiB | 0.88 MiB | **66 MiB/s** | 132 MiB/s |
| 720p 无深度 | 30 | 1.32 MiB | — | **40 MiB/s** | 105 MiB/s |

> **两列的含义**："落盘口径"按 §5.5 F-2 规定的**平台原生格式**计算（iOS YUV420 / Android NV21），这是实际写入 `frames.bin` 的字节数；"BGRA8 上界"是核心层内存口径的等价字节数（C ABI 要求 BGRA8，见 §2.2.2），**仅用于内存预算**，不用于磁盘估算。
>
> **需实测回填**：上表全部为理论值，真机实测写入带宽与 `fdatasync` 开销见 §7 的 U-10。

| 结论 | 规格 |
|---|---|
| B-1 | 1080p + ToF 需 **115 MiB/s** 持续写入（原生格式口径）；即使按 BGRA8 上界也只有 263 MiB/s。现代手机 UFS 3.1 顺序写 ≥ 1 500 MB/s，**带宽不是瓶颈** |
| B-2 | 瓶颈是**帧负载的内存拷贝**（115 MiB/s memcpy 约占用 1 个 CPU 核的 11%；BGRA8 上界 263 MiB/s 时约 25%）。写盘线程使用 `writev` 合并 RGB+深度+置信度为一次系统调用，减少调用次数 |
| B-3 | 若实测写入导致采集线程调度延迟 > 5 ms，优先把 RGB 存储分辨率降到 720p（**这是采集分辨率设定，不是对已采数据的降采样**，不违反 R-PREC-4） |

#### 5.6.3 磁盘空间预估

| 项 | 公式 | 算例（3 分钟，1080p + ToF，30 fps，5400 帧，原生格式口径） |
|---|---|---|
| RGB 总量 | `N × S_rgb` | 5400 × 2.97 MiB = **15.6 GiB** |
| 深度总量 | `N × (S_depth + S_conf)` | 5400 × 0.88 MiB = **4.6 GiB** |
| IMU | `T × 16 000 B` | 2.9 MB |
| 索引 | `N × 64 B` | 0.33 MB |
| 质量 CSV | `N × ~120 B` | 0.65 MB |
| **合计** | | **≈ 20.3 GiB** |

> **口径**：按 §5.5 F-2，落盘存**平台原生格式**（YUV420 / NV21），故 RGB 段按 2.97 MiB/帧计。若改为 BGRA8 落盘（当前不采用），总量将升至 ≈ 46.3 GiB。

> 5400 帧全量落盘在移动端不现实（典型手机可用空间 30–200 GB，且未压缩）。因此落盘策略**必须**与关键帧策略联动，见下。

#### 5.6.4 落盘粒度策略（与 03 关键帧联动）

| 层级 | 落盘对象 | 说明 |
|---|---|---|
| L0 全量层 | **不落盘** | 移动端默认关闭；桌面/调试模式可开 |
| L1 关键帧层 | 通过门限且满足关键帧增量判据的帧（03 文档定义） | **默认落盘**，空间可控 |
| L2 上下文层 | 每个关键帧前 1 帧 + 后 1 帧（用于 IMU 边界与时序复核） | 默认落盘 |

| 空间估算（L1 + L2，1080p + ToF，原生格式口径） | 数值 |
|---|---|
| 关键帧率（典型桌面物体，3 分钟） | 0.7–1.5 帧/s → 130–270 帧 |
| L1 空间 | 0.5–1.0 GiB |
| L2 空间（×3） | 1.5–3.0 GiB |
| **合计** | **2.0–4.1 GiB** |

#### 5.6.5 磁盘不足处理

| 剩余空间 | 动作 | 用户提示文案 |
|---|---|---|
| > 30% 预估总量 | 正常 | — |
| ≤ 30% 预估总量 | 提示一次 | 存储空间可能不足 |
| ≤ 10% 预估总量 | 停止写入 L2 上下文层 | 存储空间不足，已减少备份帧 |
| ≤ 5% 预估总量 | 停止写入新关键帧，保留已有数据，提示用户确认或取消 | 存储空间不足，无法继续保存 |
| 写入失败（ENOSPC） | 立即停止采集，保留已落盘数据，状态置 `RECON_ERR_DISK_FULL` | 存储已满，扫描已停止 |

| 约束 | 说明 |
|---|---|
| DS-1 | **不得**因为磁盘不足而静默删除已落盘的关键帧 |
| DS-2 | 磁盘不足时必须让用户明确选择：停止 / 降低后续采集分辨率 / 取消。UI 层提供纯文字按钮 |
| DS-3 | 采集开始前做预估校验：可用空间 < 预估总量 × 1.5 → 拒绝开始并提示 |

### 5.9 落盘完整性校验

| 时机 | 校验 |
|---|---|
| 会话结束 | `frames.bin` 中所有索引引用的字节区间均存在且不越界；`index.bin` 的 `frame_id` 连续 |

| 异常退出后启动 | 扫描 `sessions/*/manifest.json`，`state == "recording"` → 标记 `interrupted`，按 §5.3.2 截断 `index.bin`，**保留**已有数据供续算 |
