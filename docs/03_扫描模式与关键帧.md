## 2. 扫描模式总览

### 2.1 两种模式

| 模式 | 标识 | 默认 | 适用对象 | 核心差异 |
|---|---|---|---|---|
| 自由环绕扫描 | `MODE_FREE_ORBIT` | 否 | 大型物体、不规则物体、用户不愿跟随引导 | 无引导点位，UI 只报告覆盖度与异常 |
| 定点引导扫描 | `MODE_GUIDED` | **是** | 中小型物体、桌面物体、需要高完整度拓扑 | 16 点引导序列 + 逐点覆盖校验 + 确认前自检 |

#### 2.1.1 模式选择决策

| 条件 | 选定模式 | 依据 |
|---|---|---|
| 用户未显式选择 | `MODE_GUIDED` | 默认模式；引导模式对拓扑完整度（00 §2 优先级第 2 位）的增益最大 |
| 物体包围盒对角线 > 0.8 m | `MODE_FREE_ORBIT` | 引导点位距离超出可达范围（§6.1 距离上限） |
| 物体包围盒最长边 < 0.12 m | `MODE_GUIDED` | 小物体引导成本低，且需要底面处理流程（§4.7） |
| 用户中途切换 | 允许 | 切换时保留已有帧，**不清空**（切到引导模式时按当前覆盖度决定下一个引导点位） |
| 相机不支持平台追踪（无 ARKit/ARCore） | `MODE_FREE_ORBIT` 强制 | 引导模式依赖物体中心位姿估计，见 §4.5 |

> 模式切换**不丢弃任何已采帧**。切回引导模式时，按 §4.6.3 的覆盖度重算，跳过已覆盖点位。

### 2.2 会话状态机（与 09 文档对齐）

```
IDLE
 └─> CALIBRATING        能力探测 + 设备标定检查（02 §3.9.4）
      └─> PLACING        用户放置物体 / 框选初始位置
           └─> SCANNING  采集中（帧 → 02 同步 → 02 门限 → 本文关键帧判定）
                ├─> REVIEWING   用户触发确认 → 自检清单（§7.1）
                │     ├─> RECONSTRUCTING  （05 文档）
                │     └─> SCANNING         （用户返回继续扫）
                └─> CANCELLING   用户取消 → 清理（§7.2）
```

| 状态 | 允许的 UI 动作 | 采集是否进行 |
|---|---|---|
| `PLACING` | 设置初始方位（选定"正面"方向）、选择模式 | 否 |
| `SCANNING` | 切换模式、暂停/继续、请求确认、取消 | 是 |
| `REVIEWING` | 返回继续扫、确认、取消 | 否（冻结最后一帧） |

## 3. 自由环绕扫描（Free Orbit）

### 3.1 交互流程

| 步 | 用户动作 | 系统响应 | UI（纯文字 / 极简标记） |
|---|---|---|---|
| 1 | 选择「自由环绕」 | 进入 `PLACING` | 提示：请将物体放在画面中央 |
| 2 | 转动手机，使物体出现在画面中 | 平台位姿累积，物体中心估计启动 | 提示：绕物体走一圈 |
| 3 | 围绕物体移动 | 持续采帧、门限判定、关键帧写入 | 顶部显示覆盖方位百分比 + 唯一一条异常文案（02 §4.9） |
| 4 | 任意时刻 | 顶部显示盲区方位（如"左后方尚未覆盖"） | 纯文字，无箭头 |
| 5 | 点击确认 | 进入 `REVIEWING`，执行 §7.1 自检 | 见 §7.1 |

#### 3.1.1 自由环绕的覆盖度反馈（纯文字）

| 状态 | 文案 |
|---|---|
| 覆盖 < 20% | 覆盖度 12% |
| 20% ≤ 覆盖 < 50% | 覆盖度 34% |
| 50% ≤ 覆盖 < 80% | 覆盖度 61% |
| 覆盖 ≥ 80% 且无盲区 | 覆盖度 84% |
| 存在盲区 | 覆盖度 61% · 右后方未覆盖 |

| 规则 | 说明 |
|---|---|
| FO-1 | 覆盖度百分比**每 500 ms 更新一次**，不做数字滚动动画 |
| FO-2 | 覆盖度按 §4.6.2 的方位覆盖定义计算：**已覆盖方位 bin 数 / 总 bin 数**（bin 内累计**关键帧**数 ≥ 3 即视为已覆盖，36 个 10° bin）。该百分比与自检 S3 的判定线（85%）**同口径同数值** |
| FO-3 | 自由环绕模式**不显示**方向箭头（没有唯一正确方向），只显示盲区方位文字 |

### 3.2 自由环绕的采集策略

| 项 | 规格 |
|---|---|
| 关键帧判据 | 与引导模式完全一致（§5.1），模式不改变入库规则 |
| 帧率要求 | 建议 ≥ 20 fps；低于 15 fps 时 UI 提示"帧率偏低"（不阻断） |
| 环绕速度建议 | 角速度 10–40 °/s；超过 60 °/s 触发 02 §4.2 的"移动太快" |
| 姿态覆盖要求 | 方位 360° 全覆盖，俯仰覆盖见 §4.6.2 |

## 4. 定点引导扫描（Guided Fixed-Pose）

### 4.1 交互流程

| 步 | 用户动作 | 系统响应 | UI |
|---|---|---|---|
| 1 | 选择「定点引导」（默认） | 进入 `PLACING` | 提示：请将物体放在画面中央 |
| 2 | 转动手机直到物体居中稳定 1.5 s | 建立物体中心 `C`、初始方位（"正面" = 相机当前方位） | 提示：保持不动，正在定位物体 |
| 3 | 定位完成 | 生成 16 点引导序列（§4.3），从距当前位置最近且未覆盖的点位开始 | 显示目标方位文字 + 边缘箭头 |
| 4 | 移动到目标点位附近 | 实时计算位姿偏差 `Δ`（§4.4） | 文字随偏差在 3 档间切换（近/中/远），无动画 |
| 5 | 偏差进入容差且停留足够 | 采集该点位的关键帧，计数达到 N | 文字切换为"已完成 5/16" |
| 6 | 自动跳到下一点位 | 同上 | 同上 |
| 7 | 16 点完成 | 进入 `REVIEWING`，执行 §7.1 自检 | 列出未覆盖点位 |

### 4.2 引导的"无花哨动效"原则（硬约束）

| 编号 | 约束 |
|---|---|
| G-1 | **禁止**任何形式的动效：不做箭头旋转/摆动、不做呼吸缩放、不做颜色渐变、不做粒子/光效、不做震动 |
| G-2 | 引导指示只由两部分组成：**① 一行纯文字**（当前应去的方向），**② 预览画面上的一枚静态标记** |
| G-3 | 静态标记仅允许两种形态：(a) 预览边框上的一条 2 px 短线段；(b) 预览内一个 12 px 的等腰三角形箭头。不得使用发光、阴影、描边动画 |
| G-4 | 标记颜色：单一色 `#FFFFFF`，透明度固定 0.85；不使用多色区分状态 |
| G-5 | 文字内容与标记位置**必须一致**（同一数据源，见 §4.4.2），不允许出现"文字说右、箭头指左" |
| G-6 | 提示区固定在预览上方，宽度 = 预览宽度，最多 1 行；超长截断 |
| G-7 | 禁止使用 ARKit/ARCore 的世界坐标 3D 箭头作为引导（会引入透视动画与漂移，且不可控） |

#### 4.2.1 方向文字表

| 方位描述 | 文案 |
|---|---|
| 正前方 | 请移到物体正前方 |
| 右前方 | 请移到物体右前方 |
| 正右方 | 请移到物体正右方 |
| 右后方 | 请移到物体右后方 |
| 正后方 | 请移到物体正后方 |
| 左后方 | 请移到物体左后方 |
| 正左方 | 请移到物体正左方 |
| 左前方 | 请移到物体左前方 |
| 上方 | 请抬高手机俯视 |
| 下方 | 请放低手机仰视 |
| 顶部 | 请站到物体上方俯拍 |
| 底部 | 请将物体抬起并翻转底部朝向镜头 |

#### 4.2.2 偏差档位文案

| 档位 | 判据 | 文案后缀 |
|---|---|---|
| 远 | `Δ > 25°` 或距离偏差 > 30% | ·距离较远 |
| 中 | `10° < Δ ≤ 25°` | ·请再靠近一些 |
| 近 | `Δ ≤ 10°` 且距离偏差 ≤ 30% | ·保持稳定 |

### 4.3 引导点位集

#### 4.3.1 坐标系定义

| 项 | 定义 |
|---|---|
| 原点 | 物体包围盒中心 `C`（世界系） |
| 方位角 `az` | 水平面内，**0° = 正面方向**（用户在 `PLACING` 阶段面对物体的方向），顺时针为正，范围 [0°, 360°) |
| 俯仰角 `el` | 相对水平面，`+90°` = 正上方（俯视），`−90°` = 正下方（仰视），范围 [−90°, +90°] |
| 距离 `d` | 相机光心到物体中心的水平距离 |
| 极角 | `el = 90°` 为天顶，`el = −90°` 为天底 |

在标准 16 点基础上追加：

| ID | 名称 | az (°) | el (°) | 目标距离 (m) | 可达性 | 默认 |
|---|---|---|---|---|---|---|
| V17 | 顶视 | 0 | +82 | 0.35 | 需要站到物体正上方（脚下）或把物体放到低矮支架上并蹲下俯拍 | 关 |
| V18 | 底视 | 0 | −80 | 0.35 | **默认不可达**，见 §4.7 | 关（需显式开启"翻转模式"） |

| 项 | 规格 |
|---|---|

| V-8 | 用户可在参数面板（08 文档）开启/关闭 V17/V18；默认值遵循上表 |

#### 4.3.4 点位序列生成

```
输入: 物体中心 C, 初始正面方位 az0, 物体包围盒
1. 计算目标距离 d = clamp(1.6 × B, 0.30, 0.80)
2. 生成 16 点目标位姿: T_target(i) = Translate(C) · Rz(az_i) · Ry(−el_i) · Translate(0,0,−d)
   （相机看向原点，+Z 为相机前方）
3. 排序: 以当前相机位姿为起点，做最近邻 + 贪心（贪心代价 = 视线方位差 × 1.0 + 俯仰差 × 0.5）
   约束: 同一"上/下"层内优先连续，避免频繁上下移动
4. 已覆盖的点位（§4.6）从序列中剔除
5. 扩展点位 V17/V18 按开关与可达性追加到序列末尾
```

### 4.4 目标偏差计算与标记

#### 4.4.1 偏差量定义

| 量 | 定义 |
|---|---|
| 位置偏差 `Δp` | `‖p_cam − p_target‖`（m），`p_cam` 为相机光心世界坐标 |
| 姿态偏差 `Δθ` | 相机光轴（+Z）与 `→ C` 方向之间的夹角（deg） |
| 综合偏差 `Δ` | `Δ = max(Δθ / 10°, Δp / (0.3 · d))`，无量纲，1.0 表示"已到位" |

| 档位 | `Δ` |
|---|---|
| 远 | > 2.5 |
| 中 | 1.0 – 2.5 |
| 近 | ≤ 1.0 |

#### 4.4.2 标记位置计算

```
1. 将目标方向向量 v = normalize(C − p_cam) 转换到相机坐标系: v_cam = R_cw^T · v
2. 若 v_cam.z > 0（目标在前方半空间）:
      投影到成像平面: u = f_x · v_cam.x / v_cam.z + c_x,  v = f_y · v_cam.y / v_cam.z + c_y
      若 (u,v) 在预览矩形内 → 标记画在 (u,v) 处（等腰三角形，朝向目标）
      若在矩形外 → 标记画在从画面中心指向 (u,v) 的射线与预览边框的交点处（2 px 短线段）
3. 若 v_cam.z ≤ 0（目标在后方）→ 标记固定在画面中心（短线段），文字提示改为"请转回物体方向"
4. 文字方向描述由 (az_target − az_current) 归入 8 个扇区得到（§4.2.1 表）
```

| 约束 | 说明 |
|---|---|
| GM-1 | 文字与标记由**同一次计算**产生（§4.4.2 步骤 1–4 与 §4.4.2 步骤 4），保证 G-5 |
| GM-2 | 标记绘制在预览**之上、预览之外**（不遮挡中心物体区域） |
| GM-3 | 标记坐标每 100 ms 更新一次；不做插值动画 |

### 4.5 物体中心与初始方位估计

| 项 | 规格 |
|---|---|
| 依赖 | 需要平台位姿（ARKit `ARFrame.camera.transform` / ARCore `Camera.getPose()`）。**无平台追踪的设备强制走自由环绕模式** |
| 初始化 | `PLACING` 阶段：累积 1.5 s 的平台位姿，取均值作为初始相机位姿 `T0`；`C` 初值 = `T0` 位置 + 相机前向 × `clamp(1.6 × B_est, 0.30, 0.80)`，其中 `B_est` 为当前估计的物体包围盒最大边长 (m)；`B_est` 未知时按最小可达值 0.30 m 代入 |
| 持续更新 | 每采 10 帧，用已入库关键帧的相机位姿与 `C` 做一次一致性检查：若多数帧的观测方向指向偏离 `C` > 15°，则按残差最小原则更新 `C`（一步最小二乘，阻尼 0.3），并重算引导点位 |
| 更新频率 | 每 1 s 最多更新一次；更新过程中**不移动**已有已覆盖点位的判定（用旧 `C` 判过的结果保留） |
| 初始方位 | `az0` = 用户在 `PLACING` 结束时相机相对物体的方位；用户在 UI 上可选"以当前方向为正面"，缺省为该值 |

### 4.6 点位覆盖判定

#### 4.6.1 单点位覆盖判据

某引导点位 `i` 判定为**已覆盖**，当且仅当以下全部满足：

| 条件 | 阈值 | 说明 |
|---|---|---|
| C1 方位精度 | 关键帧相机方位角与目标 `az_i` 的差 `≤ 12°` | 该关键帧真实观测了目标方向 |
| C2 俯仰精度 | 关键帧相机俯仰角与目标 `el_i` 的差 `≤ 10°` | |
| C3 距离 | `abs(d_actual − d_target) / d_target ≤ 30%` | 距离过远会损失像素分辨率 |
| C4 数量 | 满足 C1–C3 的**关键帧数** `≥ 12` | 对应约 0.4 s @30 fps |
| C5 质量 | 这些关键帧的 `q_total` 中位数 `≥ 0.55` | 低于此值的帧数不计入 C4，但保留在库中 |
| C6 视角间距 | 相邻计入帧的观测方位间隔 `≥ 4°` | 防止 12 帧全在同一方向（此时实际只有 1 个视角）。**注意**：此处"计入帧"指**已入库关键帧**，与 §5.1.2 视角增量判据所用的**候选帧累计** bin 计数语义不同（见 §5.1.2 末尾说明） |

#### 4.6.2 全局覆盖度

| 层级 | 定义 | 阈值 |
|---|---|---|
| 方位覆盖 | 方位直方图（36 bin × 10°）中，累计关键帧数 ≥ 3 的 bin 占比 | **达标 ≥ 85%**（自检 S3 的判定线）。该百分比同时用于 `MODE_FREE_ORBIT` 的 UI 展示与自检阻断，**两者同口径同数值**（见 §3.1.1 FO-2 与 §7.1.1 S3） |
| 俯仰覆盖 | 俯仰直方图（18 bin × 10°，范围 [−90°, +90°)）中累计 ≥ 3 的 bin 占比 | **达标 ≥ 60%**（自检 S4 的判定线，低于则警告）；**目标 ≥ 70%**（理想值，UI 引导的目标方向） |
| 盲区 | 方位 bin 的 6° 邻域内累计计数为 0，且该 bin 两侧 ±20° 内的累计计数 < 5 | 判定为盲区扇区 |

| 约束 | 说明 |
|---|---|
| CV-1 | 直方图统计的对象是**关键帧**（不是所有通过门限的候选帧），保证与重建实际使用的观测一致。这与 §5.1.2 视角增量判据所用的**候选帧累计** bin 计数是**两套独立计数**，用途不同（后者判断"方向是否被观测过"，前者衡量"重建实际使用的观测是否充分"），不可互相替代 |
| CV-2 | 盲区判定沿用 02 §4.7 的方位/俯仰定义，扇区划分统一为 10°/bin，避免两处口径不一致 |
| CV-3 | 引导模式的目标覆盖度 = 已覆盖引导点数 / 参与引导的点数；默认要求 ≥ 15/16，扩展点位不计入分母 |

#### 4.6.3 覆盖度重算时机

| 触发 | 动作 |
|---|---|
| 每新增 10 个关键帧 | 重算点位覆盖与盲区 |
| `C` 更新后 | 重算并更新 UI 百分比 |
| 模式切换后 | 全量重算 |
| 进入 `REVIEWING` | 全量重算一次（用于自检清单） |

### 4.7 底部扫描的可达性与工程解法

#### 4.7.1 物理限制（不可消除）

| 事实 | 说明 |
|---|---|
| 限制 | 物体静止放在平面上时，其**底面**与支撑面贴合，相机无法看到底面 |
| 不可行方案 A | "请把手机放到物体正下方仰拍" → 手机无法被举到物体下方而不穿过支撑面，且用户无法稳定持机 3–5 s；相机与物体必然发生碰撞风险 |
| 不可行方案 B | 镜像合成 → 镜面反射的成像包含镜像几何、镜面平面未知时无法标定，反射像的视差与真实表面视差不一致，会在重建中产生**虚假几何**。**本产品不支持镜像方案** |
| 不可行方案 C | ARKit/ARCore 平面检测辅助 → 平面检测只能给出**支撑平面**，不能给出物体底面的**细节**（凹陷、凸起、纹理、边界倒角）。它可以提供底面**位置**的先验，不能提供底面的**观测** |

#### 4.7.2 工程解法（分两级，按可获得的信息量排序）

| 级别 | 方案 | 是否真实观测 | 质量 | 启用条件 |
|---|---|---|---|---|
| L1 **优先** | 翻转模式：提示用户抬起物体并翻转，使底面朝向相机 | **是**，真实多视角观测 | 高 | 用户显式开启「翻转模式」；引导点位 V18 替换为"翻转底面" |
| L2 **兜底** | 支撑平面先验填充：由平台平面检测（ARKit `ARPlaneAnchor` / ARCore `Plane`）给出支撑平面高度，把底面位置约束到该平面 | 否，几何先验 | 中低 | 平面检测可用且置信度足够 |
| L3 **兜底** | 侧向低角度补扫：把 `el` 压到 −55°（用户蹲下），至少看到底面边缘一圈 | 部分（仅边缘） | 中 | 物体下沿离地 > 0.02 m 时可部分实现 |
| L4 | 底面留白：不做任何推断，网格保留空洞，在导出元数据中标记"底面未观测" | 否 | — | 所有方案均失败时 |

#### 4.7.3 翻转模式（Flip Mode）规格

| 项 | 规格 |
|---|---|
| 提示文案 | 请将物体抬起并翻转底部朝向镜头 |
| 判据 | 物体底面法向（由支撑平面估计的法向反向）与视线方向的夹角 `< 35°`；相机到 `C` 的距离在 `[0.25, 0.80] m` |
| 采集 | 与普通点位相同：满足判据期间持续采帧，计入 `N_min = 12` |
| 序列位置 | 放在 16 点序列**之后**，避免打断主流程 |
| 与其他点的关系 | 翻转物体的过程中，其余 16 点已采的帧**仍然有效**（物体位姿变化由 05 文档的全局 BA 处理），但**不追加**新的侧面帧 |
| 平台要求 | 需要 ARKit/ARCore 支持物体位姿跟踪（`ARWorldTrackingConfiguration` 的场景理解）；否则 L1 不可用，退到 L2/L3/L4 |

#### 4.7.4 底面填充的诚实标注（硬约束）

| 编号 | 约束 |
|---|---|
| BS-1 | 若底面由 L2/L3/L4 兜底，导出时**必须**在 06 文档定义的 `recon_mesh_info.json` 中写入 `bottom_face_source = "ground_plane_prior" \| "edge_only" \| "unobserved"` |
| BS-2 | 网格中由先验填充的区域必须可被下游识别。实现路径：优先使用 06 文档 `mesh_input_point_weight_*` 构造的点权重承载（推断区权重上限 `mesh_input_point_weight_floor`），并在 `recon_mesh_info.json` 记录推断区包围盒与面积占比。**不新增顶点属性**——06 §3.1 已固定 GLB/OBJ/PLY 的顶点属性集合与顺序，新增属性会破坏导出零错误保证与 06 的 `export_check.py` 校验 |
| BS-3 | UI 在 `REVIEWING` 自检清单中**明确列出**"底面为推断填充，非真实观测"，不得省略 |
| BS-4 | 禁止把 L2/L3/L4 生成的底面当作实测数据参与精度验收（14 文档） |
| BS-5 | 泊松网格化（06 文档）会对未观测底面做隐式曲面延拓，其结果**不可控**，必须由上述标注隔离 |
| BS-6 | 若推断区在 06 的置信度分位数裁剪（§2.3）中被裁掉，视为**预期行为**，不得为了保留底面而放宽裁剪分位数 |

## 5. 关键帧采集策略

### 5.1 关键帧定义与增益判据

#### 5.1.1 两个概念的区分（**必须先读这一节**）

本文涉及两个**互不相同**的概念，全套文档统一按 00 §2 的新措辞区分：

| 概念 | 判定方 | 语义 | 失败后果 |
|---|---|---|---|
| **质量门限**（Quality Gate） | 02 §4 | 该帧**是否允许进入重建流程**。六类检测项的**否决**判据 | 该帧被拒 → 不进入重建。**这是必要条件** |
| **关键帧入选**（增益判定） | 本文 §5.1.2 | 该帧**相对已入库关键帧是否带来新的精度增益**（几何增量 / 视角增量 / 质量分） | 该帧通过门限但无增益 → **不成为关键帧，但不被丢弃、不被静默处理** |

**两个概念的关系**：

```
采集帧
  │
  ├─ 通过质量门限？──否──► 拒帧（不进重建，原始数据仍落盘供回溯）
  │                        ← 02 §4
  是
  ▼
进入关键帧增益评估（本文 §5.1.2）
  │
  ├─ 有增益？──是──► 成为关键帧，入库并参与重建
  │                 ← 本文 §5.1.2
  否
  ▼
不成为关键帧
  │
  └─► **不丢弃、不静默**：该帧的观测量（q_total、位姿增量、覆盖贡献）仍被记录，
       用于 §5.4 的优先级标注与 §4.6 的覆盖度统计；原始数据按 02 §5.6.4 的层级策略落盘。
```

> **明确表述**：**通过质量门限的帧都会被评估，不会被静默丢弃**（00 §2）。质量门限是帧进入重建的**必要条件**，但**不是**充分条件；是否为关键帧由本文 §5.1.2 的增益判据决定。

#### 5.1.2 增益判据（三选一即入选）

| 判据 | 定义 | 阈值 | 依据 |
|---|---|---|---|
| **几何增量** | 与**上一入库关键帧**的相对位姿增量 | 旋转 `Δθ ≥ 0.35°` **或** 平移 `Δt ≥ 0.8% × B`（B = 包围盒最大边长） | 低于此值时该帧对三角化约束的贡献量级接近噪声 |
| **视角增量** | 该帧的观测方位（相对 `C`）落在**尚未覆盖**的直方图 bin 内，或使该 bin 的累计帧数从 `< 3` 变为 `≥ 3` | 见 §4.6.2 | 覆盖新方向带来新的视差与约束 |
| **质量分** | `q_total ≥ 0.85` 且 与上一入库关键帧间隔 `≥ 250 ms` | — | 高质量帧即使几何增量小，也对纹理/去噪有益 |

> **这三项是增益判据，不是剔除判据。** 三个判据都不命中时，该帧**不成为关键帧**，但**不会被删除、不会被静默丢弃**（见 §5.1.1 的流程图与 §5.2.3 NP-1 ~ NP-5）。
>
> **03-L6（bin 计数的语义区分）**：本节"视角增量"判据用的 bin 计数是**候选帧累计观测方向**（对所有**通过质量门限**的候选帧累计，包括尚未入库的帧），其目的是判断"这个方向是否已经被观测过"；而 §4.6.1 C6 的 bin 间距判据与 §4.6.2 的全局覆盖度统计用的是**已入库关键帧**的计数，其目的是衡量"重建实际使用的观测是否充分"。两者统计对象不同，**不可互相替代**：候选帧计数可以领先于关键帧计数（某方向已被多个候选帧观测但都未入库），关键帧计数则只反映真正参与重建的观测。

| 项 | 规格 |
|---|---|
| KF-1 | 判据按顺序短路求值：**几何增量 → 视角增量 → 质量分**。命中即入库，不做后续检查 |
| KF-1b | 三个判据**都不命中**时，该帧不成为关键帧，但**不被丢弃**：其观测量仍参与 §5.4 的优先级标注与 §4.6 的覆盖度统计，原始数据按 02 §5.6.4 落盘 |
| KF-2 | "上一入库关键帧"指**上一次入库**的关键帧，不是上一帧采集帧 |
| KF-3 | 几何增量的相对位姿由 05 文档的 VIO/平台位姿提供；平台位姿不可用时，降级为"光流增量"判据（中位光流 ≥ 2.5 px @960 宽） |
| KF-4 | 初始帧（`frame_id = 1`）无条件入库 |
| KF-5 | 被质量门限拒绝的帧**一律不入库**，但原始数据仍落盘（02 §5.6.4 的 L1/L2 层级之外的调试保留），用于事后复核 |

#### 5.1.3 几何增量阈值的合理性（诚实说明）

| 项 | 当前取值 | 标定方法 | 偏差容忍 |
|---|---|---|---|
| 现状 | `Δθ = 0.35°`、`Δt = 0.8%·B` 是**工程经验初值**，未经大规模实测标定 | — | — |
| 影响 | 阈值偏大 → 关键帧稀疏 → 纹理区 MVS 深度出现空洞；阈值偏小 → 关键帧数量膨胀 → 落盘空间与 BA 规模上升 | — | — |
| 标定方法 | 用 14 文档的黄金数据集做扫描回放，测"关键帧数 vs 重建误差"曲线，取拐点 | **U-15** | 实测拐点与当前值相差 > 2 倍时，必须更新本文 §8 的参数表与 §5.1.2 的阈值，并纳入 14 文档回归基线 |

### 5.2 保留策略：不做基于质量分 / 帧间隔的事后剔除

#### 5.2.1 策略陈述

> **本产品不做任何形式的"事后剔除"**——即**不**在关键帧已入库后，再按质量分、帧间隔、优先级等理由把帧从库里删掉。所有通过质量门限且满足 §5.1.2 增益判据的帧全部保留、全部参与重建。
> 与 00 §1.1 的 **R-PREC-3** 一致：关键帧只要对精度有增益即全量保留。
>
> **与 §5.1 的关系**：§5.1.2 的增益判据是**入库前**的判定（"这一帧要不要成为关键帧"），判据不命中只意味着"它不是关键帧"，**不意味着**"它要被删掉"。本节禁止的是**入库后**的事后剔除。二者不矛盾。

#### 5.2.2 工程理由

| 编号 | 理由 | 具体说明 |
|---|---|---|
| RS-1 | **视差不可再生** | 被剔除的帧包含的基线视差信息无法由保留帧插值恢复。MVS 深度 = 视差/焦距，缺一帧就是缺一个独立的深度约束 |
| RS-2 | **剔除判据是启发式，不是误差判据** | 几何增量小不等于信息量小。慢速环绕时每帧增量都很小，但这些帧共同构成稠密的方位覆盖；按增量剔除会直接破坏覆盖度（§4.6） |
| RS-3 | **反射/透明面只在少数帧可解** | 镜面区域的正确几何只在特定视角/光照组合下可解（04/05 文档会说明）。这些帧的"增量"往往很小（相邻帧几乎重合），按增量剔除会恰好删掉唯一可用的帧 |
| RS-4 | **下游是可降维的** | 位姿图规模 O(N)，TSDF 融合是流式的。真正的成本在 BA 与稠密 MVS，而这两者都能通过**分块 + 流式 + 稀疏求解**控制，不需要靠丢数据（00 §1.2 R-PREC-5） |
| RS-5 | **误差不可预知** | 剔除发生时无法预知哪一帧在下游会造成几何错误。保留全部帧的代价是确定的（时间/空间），剔除的代价是不可确定的（精度），按 R-PREC-1 应选确定代价 |
| RS-6 | **用户可预期性** | 用户按引导点位采集，期望"扫过的地方都被重建"。自动剔除会让用户认为扫过却缺失的区域变成空洞，责任边界不清晰 |
| RS-7 | **不可逆** | 剔除发生在采集期，原始帧若未落盘则无法恢复。落盘保留（02 §5.6.4）虽留了 L2 上下文层，但只覆盖关键帧前后各 1 帧，不足以支撑"事后重新挑选" |

#### 5.2.3 明确不做的事

| 编号 | 禁止行为 | 原因 |
|---|---|---|
| NP-1 | 按 `q_total` 阈值剔除帧 | 质量分只用于排序与加权，不用于丢弃 |
| NP-2 | 按"帧间隔太密"剔除 | 密集帧是有益冗余 |
| NP-3 | 按"位姿增量太小"剔除 | 见 RS-2 |
| NP-4 | 为控制落盘空间而丢帧 | 空间不足的处理是"提示用户 + 停止/降分辨率"，不是静默丢弃（02 §5.6.5 DS-1） |
| NP-5 | 在 BA/TSDF 阶段按优先级跳过某些关键帧 | 优先级只用于排序、权重与早停，不用于跳过 |

### 5.3 数量上限的内存/存储保护

#### 5.3.1 问题的重新表述

R-PREC-3 禁止丢帧，R-PREC-5 要求用"分块 + 落盘 + 流式"控内存，00 §1.2 把"关键帧保留数量"列入**不可降级黑名单**。因此：

> **关键帧数量本身不得成为降级项。** 内存与存储的保护必须通过**组织方式**实现，而不是通过减少关键帧。

#### 5.3.2 分层存储策略

| 层 | 内容 | 常驻内存 | 落盘 |
|---|---|---|---|
| L0 采集缓冲 | 当前帧 + 队列 8 帧 | 63 MiB（02 §2.4.3） | 否 |
| L1 关键帧图像 | 全部关键帧的 RGB/深度 | **0**（采集期即落盘后释放引用） | 是（02 §5.6.4） |
| L2 关键帧元数据 | 位姿、内参、2D 特征点、深度图路径 | 关键帧特征点是主要占用，见 §5.3.3 | 是 |
| L3 位姿图 | 关键帧位姿 + 帧间相对约束 | 小 | 是 |
| L4 重建中间量 | TSDF 体素、深度图、BA 残差 | 由 13 文档分块管理 | 临时 |

#### 5.3.3 关键帧元数据的内存核算

| 项 | 单关键帧 | 1 000 帧 | 5 000 帧 |
|---|---|---|---|
| 位姿（4×4 矩阵 + 时间戳 + 协方差对角） | 176 B | 176 kB | 880 kB |
| 2D 特征点（平均 800 点 × (x,y,depth,view) 16 B） | 12.8 kB | 12.8 MB | 64 MB |
| 特征描述子（800 × 128 bit = 12.8 kB） | 12.8 kB | 12.8 MB | 64 MB |
| 深度图引用（指针 + 尺寸） | 64 B | 64 kB | 320 kB |
| 质量与统计 | 96 B | 96 kB | 480 kB |
| **合计** | **≈ 26.7 kB** | **26.6 MB** | **128.9 MB** |

| 结论 | 规格 |
|---|---|
| K-1 | 关键帧元数据在 5 000 帧规模下仅 ~129 MB，**不构成内存瓶颈**。真正的瓶颈是稠密深度图与 TSDF 体素（13 文档） |
| K-2 | 特征描述子在 BA 阶段不需要全程常驻；按 §5.3.5 分块加载 |
| K-3 | 若单次会话超过 10 000 关键帧（> 5 min 高帧率扫描），元数据超过 258 MB。此时按 §5.3.5 分块，**不删帧** |

#### 5.3.4 存储保护

| 项 | 规格 |
|---|---|
| SP-1 | 全部关键帧落盘（02 §5.6.4 L1），空间估算见 02 §5.6.4：4.1–8.4 GiB / 3 min |
| SP-2 | 空间不足时按 02 §5.6.5 分级处理，**不删已落盘帧** |
| SP-3 | 落盘是原始数据（RAW），重建时从盘读入，可重复重算 |
| SP-4 | 重建中途需要额外的临时空间（深度图、TSDF 分块），按 13 文档预算 |

#### 5.3.5 分块处理（不丢精度的唯一合法路径）

| 阶段 | 分块策略 | 关键帧是否丢失 |
|---|---|---|
| SfM 特征匹配 | 按**空间近邻**分块：把关键帧按 `C` 的方位/俯仰分成 24 个空间块，块内 + 相邻块做匹配，跨块匹配通过**位姿图 + 闭环检测**补充 | 否 |
| BA | **滑窗 BA + 全局 BA**：先做 8 帧窗口的局部 BA 收敛，再做全量全局 BA（全量 BA 的残差与块划分无关） | 否 |
| TSDF 融合 | 按体素空间分块（13 文档），块内融合后拼接 | 否 |
| 稠密 MVS | 按参考帧分块：每次处理 32 个参考帧，深度图增量落盘 | 否 |
| 网格化 | 按 06 文档流程，全量关键帧参与 | 否 |

| 约束 | 说明 |
|---|---|
| K-4 | 分块只改变**调度与内存组织**，不改变任何精度阈值（00 §1.2 R-PREC-4） |
| K-5 | 全局 BA 必须在所有关键帧上跑完（哪怕分批求解），否则剔除效应会以"优化不完全"的形式隐性发生 |
| K-6 | 分块边界的重叠区宽度 ≥ 2 个关键帧，避免接缝处约束断裂 |

### 5.4 帧优先级标注

#### 5.4.1 优先级定义

每个关键帧携带一个 `priority ∈ [0, 100]` 的整数标注。**该标注只用于排序、权重与调度，不用于丢弃（NP-5）。**

计算公式：

```
priority = 40 · q_total
         + 20 · w_cov      // 该帧对覆盖度的贡献
         + 20 · w_geom     // 该帧提供的几何增量质量
         + 20 · w_stab     // 该帧的位姿估计稳定性
```

| 分项 | 定义 | 范围 |
|---|---|---|
| `q_total` | 02 §4.1.1 的质量综合分 | [0, 1] |
| `w_cov` | 若该帧是某覆盖 bin 的**首帧**（使该 bin 计数 0→1）则 1.0；若是使 bin 计数 2→3 的帧则 0.6；其余 0.2 | [0, 1] |
| `w_geom` | `Δθ / 1.0°` 与 `Δt / (2%·B)` 的较大者，截断到 1.0 | [0, 1] |
| `w_stab` | 由该帧参与的位置/旋转约束的**后验残差**决定：残差小于阈值的帧记 1.0，超出记 0.3 | [0, 1] |

#### 5.4.2 优先级的用途

| 用途 | 规格 |
|---|---|
| PU-1 | **重建顺序**：SfM 增量式求解时先处理高优先级帧（先建立可靠的初始位姿），但最终仍处理全部帧 |
| PU-2 | **BA 收敛顺序**：全局 BA 的初值由高优先级帧优先的增量结果给出 |
| PU-3 | **权重**：MVS 深度融合时，低优先级帧的深度图以更低置信度参与（**降权不丢弃**，00 §8.2 同策略） |
| PU-4 | **纹理烘焙**：高优先级帧覆盖的表面在纹理选择中优先采样 |
| PU-5 | **早停提示**：当累计覆盖度与位姿收敛度都达标时，UI 提示"可以确认了" |

| 禁止 | 原因 |
|---|---|
| 按优先级跳过帧 | NP-5 |
| 按优先级丢弃帧 | NP-5 / R-PREC-3 |
| 优先级跨会话比较 | 优先级只在单次会话内有意义 |

#### 5.4.3 优先级的存储

| 项 | 规格 |
|---|---|
| 存储位置 | 02 §5.3.1 的 `index.bin` 记录中 `flags` 字段的 bit5–bit12（8 bit，priority/255 的近似） |
| 计算时机 | 采集期实时计算初值（不含 `w_stab`）；重建期在 BA 收敛后补算最终值并回写 `index.bin` 的优先级字节 |

## 6. 相机–物体交互约束

### 6.1 建议扫描距离区间

| 项 | 规格 |
|---|---|
| 推荐区间（= 可达性硬界） | `d ∈ [0.30, 0.80] m`（相机光心到物体中心）。超出此区间按 §4.3.2 V-3b 属"难以到达"，不是禁止而是提示 |
| 理想区间（= 理想推荐区） | `d ∈ [0.35, 0.60] m` |
| 缩放规则（理想推荐区） | `d_ideal = clamp(1.6 × B, 0.35, 0.60)`，`B` = 包围盒最大边长 (m)。**这是理想推荐区**，与 §4.3.2 V-3b 的**可达性硬界** `d = clamp(1.6 × B, 0.30, 0.80)` 是两条独立规则：硬界决定"能否到达"，理想区决定"落在哪里最好"。两者缩放系数同为 1.6，clamp 上下界不同 |
| 下限理由 | < 0.25 m 时近距离相机对焦/畸变严重、近裁剪面截断，且视野覆盖不足 |
| 上限理由 | > 0.80 m 时物体在 1080p 下像素高度不足，MVS 深度分辨率下降；`> 1.2 m` 时纹素数 < 40%，纹理重建明显劣化 |
| 像素覆盖判据 | 物体最大边在图像中的投影高度应占画面高度的 **35%–75%**；超出则提示调整距离 |
| 距离读取 | 优先用深度数据（BRANCH_RGBD）；BRANCH_MONO 用已知物体尺寸 + 视觉距离估计；无法估计时不提示距离，只提示角度 |

| 约束 | 说明 |
|---|---|
| IC-1 | 距离超界**只提示不阻断**（02 §4.2 的"移动过快"是唯一会拒帧的运动类提示，且是瞬时超速，不是距离本身） |
| IC-2 | 距离提示文案：太近"请稍微远离一些"，太远"请靠近一些" |

### 6.2 建议角度步长

| 项 | 阈值 | 理由 |
|---|---|---|
| 相邻关键帧观测方位差 | **≥ 4°** | 低于此值，新增视差不足以独立约束深度（对应 §4.6.1 的 C6） |
| 相邻关键帧观测方位差（理想） | 8°–20° | 兼顾视差量与特征可跟踪性 |
| 方位差上限（同一区域连续帧） | **≤ 35°** | 超过后 KLT 跟踪与 RANSAC 内点率骤降（02 §4.4 的 `cov` 阈值 0.35） |
| 俯仰差（相邻层） | ≤ 24° | §4.3.2 的 V-2 |
| 建议环绕角速度 | 10–40 °/s | > 60 °/s 触发"移动太快" |
| 引导点位间的方位跳变 | 45° 或 90° | 有意设置：让用户**移动**而非仅转头，保证视差 |

#### 6.2.1 角度步长的层级区分

| 层级 | 步长 | 目的 |
|---|---|---|
| 逐帧（关键帧之间） | 4°–20° | 保证深度可解 |
| 点位之间（引导） | 45°/90° | 保证基线充足 + 覆盖全方位 |
| 用户手动环绕 | 自由 | 自由模式下不强制，靠 `cov` 与"移动太快"提示约束 |

| 项 | 规格 |
|---|---|

| 每个引导点位有效采集窗口 | 0.5–1.5 s，超过 1.5 s 后该点位的边际增益显著下降，UI 提示"可以前往下一个位置" |

|---|---|

### 6.4 手抖补偿

#### 6.4.1 两条独立通道

| 通道 | 目标 | 实现 | 是否修改落盘数据 |
|---|---|---|---|
| **A. IMU 稳像** | 抑制**手持整体抖动**（低频、高频混合） | 陀螺角速度积分 + 一阶低通（截止 15 Hz）+ 零速修正（ZUPT） | **否** |
| **B. 特征运动估计** | 估计**残余的相对运动**（绕光轴旋转、轻微平移） | Shi-Tomasi 角点 + KLT 光流 + RANSAC 本质矩阵分解，取旋转分量 | **否** |

#### 6.4.2 硬约束

| 编号 | 约束 |
|---|---|
| SH-1 | **补偿结果只用于 UI 显示（预览稳定化）与质量分计算，不写回原始帧**。落盘帧必须是未经任何几何变换的原始像素。理由：任何重采样/旋转插值都会引入插值模糊，直接损害纹理与特征精度（违反 R-PREC-1） |
| SH-2 | 若为稳定预览而对预览做旋转插值，插值核固定为双线性，**不得**用于落盘帧 |
| SH-3 | 稳像的旋转量上限 ±12°，超出视为用户主动转动而非抖动，不做补偿 |
| SH-4 | 抖动补偿**不改变**关键帧的入选判据与质量门限阈值 |

#### 6.4.3 抖动量化指标

| 指标 | 定义 | 阈值 |
|---|---|---|
| 手持抖动幅度 | 补偿后残余角速度的 95 分位绝对值（°/s） | `< 8 °/s` 视为稳定 |
| 抖动致残位移 | 补偿后残余平移（px/frame @960 宽） | `< 3 px/frame` |
| 判定 | 任一超限 → 02 §4.3 的模糊检测自动提升为"运动模糊"判定 | — |

#### 6.4.4 IMU 稳像的信号链

```
陀螺角速度 ω(t)  [rad/s]
  └─ 1. 零偏补偿（02 §3.5 的 b_g）：ω̃(t) = ω(t) − b_g
  └─ 2. 低通 IIR 去噪（抑制高频传感器噪声）:
  │      y[n] = α·y[n-1] + (1-α)·ω̃[n],  α = 2π·f_c / (2π·f_c + f_s),  f_c = 15 Hz
  │      → y(t) 为"已去噪的角速度"
  └─ 3. 在 y(t) 上用滑动窗口回归估计**主动转动分量** r(t):
  │      窗口长度 W = 0.5 s（≈ 50 样本 @100 Hz），对窗口内的 y(t) 做
  │      一阶线性拟合 y(t) ≈ a + b·(t − t_center)，取 b·(t − t_center) 为 r(t)
  │      → r(t) 是"窗口内的平均转动速率"，即用户主动转动（低频）分量
  └─ 4. 抖动分量 = y(t) − r(t)（残差），积分得抖动角度 θ_jitter(t)，限制 ±12°
  └─ 5. 预览旋转补偿（双线性插值）
```

> **为什么是这个顺序**：抖动是**高频**成分、主动转动是**低频**成分。原方案"先低通 15 Hz 再高通 3 Hz 分离"的表述在物理上不成立——低通 15 Hz 已经把 > 3 Hz 的分量全部滤掉，残差里根本不存在 3 Hz 以上的抖动分量可分离；而主动转动（用户绕物体移动）恰恰落在 0 ~ 3 Hz 的低频段，会被低通完整保留。
>
> 正确做法是：**先低通去噪**，再在低通后的信号上用**滑动窗口回归**（而不是高通滤波）估计主动转动分量——窗口内的一阶拟合斜率 `b` 就是该窗口的平均转动速率，与抖动的高频起伏无关；残差 `y − r` 即为抖动分量。这样"分离"不依赖频率边界的硬切，而是依赖"主动转动在窗口内近似匀速"这一物理假设。
>
> | 项 | 规格 |
> |---|---|
> | 回归窗口长度 | 0.5 s（`scan_stab_imu_cutoff_hz` 只控制第 2 步的低通截止，不影响本步窗口长度） |
> | 窗口长度依据 | 需 ≥ 5 个手持抖动周期（最慢抖动约 10 Hz → 0.5 s 内有 5 个周期），否则斜率估计被抖动污染。**待实测标定**（列为 U-19 的一部分） |
> | 主动转动判据 | 残差 `θ_jitter` 超过 ±12°（`scan_stab_max_rotation_deg`）时判定为主动转动，不做补偿（§6.4.2 SH-3） |

| 项 | 规格 |
|---|---|
| IMU 采样率 | ≥ 100 Hz；不足则只用特征通道 B |
| 时间对齐 | 陀螺采样与相机帧的时间对齐按 02 §3.6 |
| 延迟 | 稳像链路延迟 ≤ 50 ms（预览可接受） |

#### 6.4.5 特征运动估计的规格

| 项 | 规格 |
|---|---|
| 特征 | Shi-Tomasi，上限 1000，`qualityLevel = 0.01`，`minDistance = 8`（960 宽） |
| 跟踪 | KLT 稀疏金字塔，层 3 |
| 双向一致性 | 反向跟踪误差 > 1.0 px 丢弃 |
| 估计 | RANSAC 本质矩阵（内点阈值 2.0 px，迭代 1000 次，置信度 0.999）→ 分解 → 取旋转分量 |

| 与 02 的关系 | 与 02 §4.4 的重叠度检测**共用同一份 KLT 结果**，不重复计算 |

### 6.5 反光与透明物体

#### 6.5.1 物理限制（必须诚实说明）

| 物体类型 | 物理事实 | 对重建的影响 |
|---|---|---|
| 镜面/高反光 | 表面反射的是**环境**而非自身几何。不同视角看到的环境不同，**视差与表面几何不一致** | 基于视差的多视图几何在该区域**必然出错**（不是精度下降，是错误几何） |
| 透明/半透明 | 光线穿透表面，相机看到的是**背景**，表面本身几乎不产生可匹配的特征 | 该区域无有效对应点，重建结果为**空洞**而非错误几何 |
| 金属（漫反射为主） | 正常，可重建 | — |
| 漫反射粗糙面 | 正常 | — |

#### 6.5.2 处理策略

| 步骤 | 动作 | 对应约束 |
|---|---|---|
| 1 | 检测：02 §4.5 的饱和比 + 过曝连通域 → 标记"疑似反光区" | — |
| 2 | 检测透明：无对应点区域。判定依据：某区域在多帧中特征点数稳定但 RANSAC 内点率低且光流残差大 | 标记"疑似透明区" |
| 3 | UI 提示（纯文字）：反光区 → "存在反光，请换个角度或避开强光"；透明区 → "透明区域无法重建，请换个角度" | 02 §4.9 |
| 4 | **网格化阶段**：疑似反光/透明区域在 TSDF 融合中**降权**（权重 ≤ 0.2），但**不丢弃**该区域的其它观测 | R-PREC-1：降权 ≠ 丢弃 |
| 5 | **导出元数据标注**：标记区域写 `recon_mesh_info.json` 的 `unreliable_regions` 数组，每项含 `{kind, bbox, area_ratio}`。`kind` 取值为 **`reflective` / `transparent` / `low_texture`** 三值枚举（`low_texture` 对应 02 §4.6 检测到的低纹理网格区，由 05 文档 §6.4 的 I3 接口产出）。该结构与 06 文档的 `recon_mesh_info.json` 对齐，**不新增** GLB/OBJ/PLY 顶点属性 | BS-2 同机制 |
| 6 | 泊松重建后由 06 文档 §2.6 的一致性校验与 §4.1 的 V6 校验检测法向异常；命中时 06 已产出 `W_MESH_NORMAL_FLIP_RATIO` / `W_MESH_NORMAL_INCONSISTENT` / `RECON_ERR_EXPORT_NORMAL_MISMATCH`。**03 文档不重复实现该检测**，仅在 `REVIEWING` 自检清单读取这些告警码并提示"反光区域可能产生几何伪影" | 06 文档提供检测算子 |

#### 6.5.3 缓解手段（用户可执行）

| 手段 | 说明 |
|---|---|
| 改变角度 | 从不同的入射角观察，反射方向随之改变，可找到"不反射直接光源"的视角 |
| 关闭闪光灯/强补光 | 避免点光源造成的尖锐高光 |
| 使用漫射环境光 | 均匀环境光下镜面反射区域仍存在但更分散，MVS 可解性略好 |
| 放置消光板 | 在物体旁放白色哑光纸板，用作人工补光与反射缓冲 |
| 分层采集 | 对强反光物体分多轮采集不同角度，05 文档的多视图融合可部分缓解 |

| 编号 | 禁止 |

### 7.2 取消的数据清理

#### 7.2.1 清理范围

| 对象 | 位置 | 动作 |
|---|---|---|
| 会话目录 | `sessions/<session_id>/` 全部文件 | 递归删除（`frames.bin`、`index.bin`、`imu.bin`、`events.jsonl`、`quality.csv`、`calib_used.json`、`manifest.json`、`logs/`） |
| 临时文件 | `tmp/` 下本次会话的中间文件 | 删除 |
| 内存 | 关键帧元数据缓存、位姿图、VIO 滑窗、预积分缓冲 | 释放并复位 |
| 平台资源 | 相机会话、传感器订阅、ARKit/ARCore session | 停止并释放 |
| GPU 资源 | Metal/Vulkan 缓冲、纹理、计算管线 | 释放 |

#### 7.2.2 清理顺序（保证中途崩溃也可恢复）

```
1. manifest.json 写 state = "cancelling"
2. 停止采集线程（先停相机，再停 IMU）
3. 停止写盘线程，等待队列排空（上限 5 s，超时则丢弃剩余并继续）
4. 停止核心处理线程
5. 释放平台资源与 GPU 资源
6. 删除 sessions/<session_id>/ 目录
7. manifest.json 删除（目录已删则此步跳过）
8. 内存状态复位到 IDLE
```

| 编号 | 约束 |
|---|---|
| CN-1 | 步骤 1 必须在任何删除之前完成。若在步骤 6 之前崩溃，下次启动时扫描到 `state ∈ {"cancelling", "recording"}` 的会话目录 → **直接删除**（用户已明确取消） |
| CN-2 | `state == "recording"` 且从未标记取消 → 标记为 `interrupted`，**保留**数据供续算（02 §5.3.3），不删除 |
| CN-3 | 取消**不删除**设备标定文件（`calib/`），标定与会话无关 |
| CN-4 | 取消不做任何网络请求（零网络，00 §1） |
| CN-5 | 清理必须在 2 s 内完成（不含相机/传感器停止的固有延迟）；超时记录 `RECON_ERR_CANCEL_TIMEOUT` 并继续 |

#### 7.2.3 取消的 UI

| 规则 | 说明 |
|---|---|
| CU-1 | 取消入口：采集页右上角"取消"文字按钮，**无图标动画** |
