## 1. 分支定位与能力声明

### 1.1 立场：BRANCH_RGBD 与 BRANCH_MONO 是平级分支，不是"高精度版"

本文档的第一性立场（与 00 §4.5.1 一致，此处给出工程落地口径）：

> **`BRANCH_RGBD` 与 `BRANCH_MONO` 是同一套精度主线的两种尺度来源，不是"高精度版"与"兼容版"。**
> 曲面精度的一阶决定因素是**多视图几何（MVS）的视差精度与像素分辨率**，不是深度传感器的存在与否。
> 深度传感器提供的是**尺度锚定**与**弱纹理区覆盖**两项增益，这两项在本分支由**深度帧自带米制**与**TSDF 补盲通道**分别承担；在 MONO 分支由**参照物标定**与**光照引导 + 泊松置信度标注**分别承担。
> **两分支共用同一份 `core/mvs/` 代码，因此两分支的曲面精度由同一段代码决定，误差主导项完全相同。**

三条支撑论据（量化口径见 §6）：

| # | 论据 | 量化依据 | 本文位置 |
|---|---|---|---|
| A1 | 曲面误差由 `δZ = Z²·δd/(f·B)` 决定，与是否有深度帧无关 | 手机典型参数下端到端 0.12–0.17 mm（标准档）；两分支共用 `core/mvs/` | §6.1.2 / §6.2.2 |
| A2 | 深度传感器自身精度**低于**高质量 MVS | ARKit `sceneDepth` 厘米级（10–30 mm）；ToF 2–8 mm；ALGO_DEPTH 相对 2%–5%。与 MVS 的 0.12–0.17 mm 相差 **1–2 个数量级** | §2.2 / §6.1.3 |
| A3 | 尺度是**标定问题**而非**传感问题** | 两分支均强制参照物复核（00 §5.2 末行注）；尺度相对误差验收口径同为 ≤ 1.0% | §5.4 |

**明确不成立的表述（禁止写入任何对外材料）**：

| 禁止表述 | 原因 |
|---|---|
| "有深度传感器 = 高精度机型" | 与 00 §4.5.1 立场冲突；深度传感器的单点精度低于 MVS |
| "TSDF 网格就是扫描产物" | 与 00 §4.2 关键工程决策冲突：TSDF 只做 ①尺度锚定 ②几何先验 ③低纹理区补全 |
| "深度传感器提供绝对精准尺度" | 与 00 §4.5.2 / 07 §1.3 冲突：厘米级 / 1%–5% 误差均超 1.0% 验收线 |
| "带深度的机型孔洞更少所以更准" | 孔洞少是**拓扑**优势，不等于**曲面精度**优势；两分支拓扑指标同口径验收（00 §4.6） |
| "ARKit LiDAR 深度可直接用于三维重建" | 与 00 §8.1 冲突：`ARMeshAnchor` 面向实时环境理解，不适合作为扫描产物 |

### 1.2 00 §4.6 精度能力矩阵在本分支的逐项落实

00 §4.6 规定：**两条分支共用同一套验收指标，任一分支达不到即判定为缺陷，不得以机型差异为由豁免。** 本分支逐项落实如下：

| 验收项 | 指标（00 §4.6 口径） | 本分支的实现路径 | 关键参数 | 达标判据 | 本文位置 |
|---|---|---|---|---|---|
| 相对几何误差 | 对称面重投影中位数 ≤ **0.5 px** | ① 帧对 ICP + 位姿图给出位姿初值（§5.1–§5.3）；② 全局优化在 05 §4.6 的 BA 主线上叠加深度因子（§5.5）；③ **对称面必须由 MVS 深度构造**——用硬件深度构造的对称面残差天然 ≥ 1 px（LiDAR 10–30 mm 噪声 ÷ 0.14 mm/px ≈ 70–210 px），必然不达标 | `rgbd_icp_convergence_trans`、`rgbd_icp_convergence_rot`、`rgbd_depth_mvs_median_max`、`rgbd_pose_graph_iterations` | BA/位姿图收敛后对称面重投影中位数 ≤ 0.5 px，P95 ≤ 2.0 px | §5.5 / §6.1.2 / §6.2.1 |
| 尺度相对误差 | 相对参照物真值 ≤ **1.0%** | 深度自带米制（初始 `s = 1`）→ 位姿图尺度自由度由深度边固定 → 采集结束后**强制**执行 07 §4 的三重复核（参照物反向验证 / 深度 vs MVS 交叉一致性 / 包围盒合理性）；偏差 > 5% 时以参照物为准覆盖深度尺度 | `rgbd_scale_anchor_enabled`、`rgbd_scale_anchor_sigma`、`rgbd_depth_mvs_median_max`、`rgbd_depth_mvs_consistency_min` | 复核后 `σ_s/s ≤ 0.01`；07 §4.2 的 `abs(δ) ≤ 0.02` 为合格线 | §5.4 / §6.1.5 |
| 尺度重复性 | 10 次独立扫描尺度标准差 ≤ **0.5%** | 深度尺度受温漂影响（ToF 0.5%–2%/10min，07 §1.3），故**每条用例采集时长 ≤ 10 min 且复核在采集结束后立即执行**（14 §3.3 口径）；本分支的重复性主要由**复核后的尺度**决定 | `rgbd_scale_anchor_sigma`、`calib_scale_prior_sigma` | `std(s)/s ≤ 0.005` | §5.4 / §6.1.5 |
| 拓扑完整性 | 非流形边数 = **0** | 与 06 分支共享泊松 + 修复流水线；本分支额外保证：补盲区点云进入 S0 时权重已按来源下调，不制造新的非流形 | `rgbd_hole_fill_depth_weight_scale`、`rgbd_hole_fill_mvs_conf_max` | 0 | §6.4（与 06 对齐） |
| 拓扑完整性 | 未闭合孔洞面积占比 ≤ **0.05%** | 本分支的**唯一优势项**：低纹理/反光区由深度补盲通道提供真实几何，而非 MONO 的泊松外推。但补盲区是**推断区**，必须标注 | `rgbd_hole_fill_mvs_conf_max`、`rgbd_hole_fill_transition_px`、`rgbd_reflective_reject_enabled` | ≤ 0.05%（按 14 §3.4 口径统计，扣除标注为推断区的部分后仍需达标） | §6.4 |
| 网格分辨率 | 泊松等效半径 ≤ **体素边长** | **口径分歧点**：本分支的最终几何由 MVS 主导（00 §4.2），TSDF 不形成最终曲面，因此"体素边长"不是最终网格分辨率的约束来源。本文按 06 §1.4 的字面口径执行（`h_ref = rgbd_tsdf_voxel_size`），并给出物理口径的修正建议（`h_ref` = MVS 点云等效间距，与 MONO 同）；14 §3.5 已用两条独立规则（实测半径上限 + 参数一致性）消解字面冲突，不阻塞验收 | `rgbd_tsdf_voxel_size`、`mesh_poisson_depth`、`mesh_poisson_depth_mode` | `r_mesh ≤ h_ref/8 × 1.2`（14 §3.5 规则 1）且 `mesh_poisson_depth_effective` 满足推导关系（规则 2） | §6.2.4 / §8.3 |
| 导出可用性 | Blender / Maya 打开零错误 | 与 06/10 共用导出校验器，两分支同口径 | `export_check_run` | 零错误 | 本文不重复（06 §4） |

**结论**：本分支在 §4.6 的 7 项验收中，**只有 2 项**（孔洞面积占比、拓扑稳健性）从深度通道获得增益，**其余 5 项与 MONO 分支走完全相同的判据与实现**。因此"带深度 = 更准"在验收口径上不成立。

### 1.3 已知能力边界（明确写出，不夸大）

以下四类是**物理限制或传感限制**，不是本产品的工程缺陷，也不是"降级"。两分支均受限，但受限方式与表现不同：

| 场景 | 物理/传感机理 | 本分支（RGBD）表现 | MONO 分支表现 | 规避路径 | 剩余风险 |
|---|---|---|---|---|---|
| **镜面 / 高反光材质** | 表面反射**环境**而非自身几何。ToF 首个/最强回波被反射路径替代 → 返回**伪距**；LiDAR 同理；ARKit `sceneDepth` 在镜面上无有效回波 | 该区域深度是**错的**（非空洞），必须**拒绝注入**补盲点云并标注 `reflective` | 该区域产生错误几何（非空洞），必须降权 + 标注 | ① 改变入射角避开直接光源（03 §6.5.3）；② 漫射环境光；③ 分层采集；④ 标注为不可靠区。**不得用对称性/先验填补**（03 §6.5.4 RS-11） | **无有效替代路径**。镜面区的几何在本产品中**不可信**，只能标注 |
| **透明 / 半透明材质** | 光线穿透表面，相机看到的是背景，表面本身几乎不产生可匹配特征。ToF 打在透明物上**穿透**，返回背景距离 | 深度图在透明区无效（返回背景深度）→ 该深度点与真实表面不符 → 拒绝注入 + 标注 `transparent` | 该区域**无对应点 → 空洞**（不是错误几何） | ① 换背景提高对比；② 换角度；③ 标注空洞区 | 空洞由泊松 + 06 §2.5 补片处理；补盲通道无法救（深度本身无效） |
| **纯色 / 哑光低纹理物体** | 表面无稳定可匹配特征，视差不可观测 | **深度可用**（ToF/LiDAR 不依赖纹理；ALGO_DEPTH 依赖纹理，**低纹理面不精确**，00 §8.2）→ TSDF 补盲通道可生成真实几何 | 强纹理区正常；低纹理区**深度空洞**，由泊松外推填补并标注为推断区 | ① 侧向补光制造纹理（05 §6.4）；② 换角度获取不同的高光/阴影结构；③ 白卡做纹理参照；④ 分多轮采集不同光照（03 §6.5.3） | 若设备只有 `ALGO_DEPTH`（Tier 1）且物体为纯色哑光，**补盲通道同样失效**，此时两分支表现相同 |
| **`ALGO_DEPTH` 需位移才可用** | ARCore 运动深度由运动视差求解，设备静止时无有效解 | 静止拍摄期深度无效 → 采集期必须强制环绕运动；静止帧的深度必须标记无效而非填零 | 不适用（无深度通道） | ① 采集期检测"无位移"并告警 `RECON_ERR_RGBD_DEPTH_NO_MOTION`（§8.2）；② 丢弃该帧深度（保留 RGB 与 IMU）；③ 03 的环绕引导（03 §4.6） | 若用户全程静置拍摄，`ALGO_DEPTH` 通道**完全不可用**，必须回退 MONO 或提示重拍 |

**边界的量化口径（写入 09 文档与导出元数据）**：

| 区域类型 | 判定方法 | 面积占比上限 | 超限处置 |
|---|---|---|---|
| 疑似反光区 | 02 §4.5 饱和比 + 过曝连通域 | ≤ 15%（03 §7.1 S13） | 警告："反光区域较多，可能有几何伪影"；该区深度点**拒绝注入** |
| 疑似透明区 | 多帧特征数稳定但 RANSAC 内点率低且光流残差大（03 §6.5.2 步骤 2） | ≤ 15%（同 S13） | 警告 + 空洞标注 |

> **诚实声明**：本分支在**纹理充分、非镜面、非透明**的物体上达到与 MONO 分支**同等的曲面精度**（同一份 MVS 代码，误差主导项相同，见 §6.2.2）；本分支的**唯一净优势**是弱纹理区的几何覆盖（真实几何 vs 泊松外推）。在上述受限场景中，本分支的受限程度**不低于** MONO 分支——镜面/透明对深度传感器同样无效，而 `ALGO_DEPTH` 还额外受"需位移"与"低纹理面不精确"两条限制。这一条必须原样呈现在 09 文档的能力说明中，不得省略。

| `kNone` | 0 | ↔ | `kNone` | 0 |

| `kHwTof` | 2 | ↔ | `kTof` | 2 |

### 2.3 ALGO_DEPTH 的光轴投影特性与转换公式（**易错点，实施前必须读完**）

#### 2.3.1 问题陈述

Google 与 Apple 的深度 API 均输出**沿相机主轴（principal axis，即相机系 z 轴）的投影距离**，而**不是**沿视线射线（ray）的欧氏距离。

02 §5.5 F-1 已把这一点固化为契约：

> F-1 深度单位固定为 **毫米（沿光轴 z）**，不沿视线射线；ARCore/ARKit 均为此语义。

而**几乎所有几何运算**（反投影、三角化、ICP、TSDF 投影）默认使用**射线距离**或**轴向距离**中的一种。**三者混用产生的误差随像点离主点的距离急剧增长，在图像边缘可达 30% 以上**，且表现为"边缘拉伸"，很容易被误判为内参标定错误或 MVS 失配。

#### 2.3.2 三个量的精确定义

设像点 `(u, v)`，深度图内参 `f_xd, f_yd, c_xd, c_yd`；归一化像坐标：

```
x = (u − c_xd) / f_xd
y = (v − c_yd) / f_yd
```

相机系中的视线方向（未归一化）：

```
d = (x, y, 1)ᵀ
```

| 量 | 定义 | 表达式 | 说明 |
|---|---|---|---|
| **轴向深度** `z_ax` | 沿光轴 z 的投影距离 | `z_ax = t`，其中 `P = t · d` | **ARKit / ARCore 的深度图给出此量** |
| **射线距离** `r` | 沿视线的欧氏距离 | `r = ‖P‖ = t · ‖d‖` | 三角化、ICP 残差、测距使用此量 |
| **视线夹角** `θ` | 视线与光轴的夹角 | `cos θ = (d · e_z) / ‖d‖ = 1 / ‖d‖` | `‖d‖ = sqrt(x² + y² + 1)` |

#### 2.3.3 转换公式与推导

**推导**：视线参数化为 `P(t) = t · d`。轴向深度定义为 `P` 的 z 分量：

```
z_ax = P_z = t · d_z = t · 1 = t
```

即 `t = z_ax`，代入射线距离：

```
r = ‖P‖ = t · ‖d‖ = z_ax · sqrt(x² + y² + 1)
```

又 `cos θ = 1/‖d‖ = 1/sqrt(x² + y²+1)`，故：

```
┌────────────────────────────────────────────────────────────┐
│  r  =  z_ax / cos θ  =  z_ax · sqrt(1 + x² + y²)          │
│  z_ax  =  r · cos θ  =  r / sqrt(1 + x² + y²)              │
└────────────────────────────────────────────────────────────┘
```

**反投影（三维点重建）**：

```
P_cam = z_ax · (x, y, 1)ᵀ          ← 轴向深度直接反投影，**不需要**任何转换
```

> 这是最重要的一条：**用轴向深度反投影时，`P = z_ax·(x,y,1)` 一步到位，不存在 cos θ 因子**。绝大多数实现错误来自在这里多除了一次 `cos θ`（把 `z_ax` 当成 `r` 用），导致三维点被**向光轴方向压缩**。

#### 2.3.4 混用误差的量化（图像边缘最危险）

相对误差（把轴向深度当成射线距离使用）：

```
ε_rel = r / z_ax − 1 = sqrt(1 + x² + y²) − 1
```

| 工况 | 归一化坐标 | `sqrt(1+x²+y²)` | 相对误差 | 后果 |
|---|---|---|---|---|
| 图像中心 | `x=0, y=0` | 1.0000 | **0 %** | 无误差（故中心区看不出问题） |
| 4K 采集（`f=2500`，`cx=1920`，`cy=1080`）图像边缘中点 | `x=−0.768, y=0` | 1.2611 | **+26.1 %** | 边缘深度被低估 21% |
| 4K 采集图像角点 | `x=−0.768, y=−0.432` | 1.3329 | **+33.3 %** | 角点深度被低估 25% |
| 4K 采集全图平均 | `⟨x²⟩ = 0.1966`，`⟨y²⟩ = 0.0622` | ≈ 1.129 | **+12.9 %** | 全局系统性尺度偏差 |
| 1080p 采集（`f=1250`，`cx=960`，`cy=540`）角点 | 同上（比值与分辨率无关） | 1.3329 | **+33.3 %** | 同上 |

> **注意最后一行**：比值只由**归一化像坐标**决定，与分辨率、FOV 无关。同一颗镜头在 1080p 与 4K 下的错误**完全相同**——因此"换分辨率后错误消失"的现象必然是误诊。

#### 2.3.5 本分支的三条硬规则

| 规则 | 内容 | 违反时的后果 |
|---|---|---|
| **RA-1** | **所有内部几何量统一到轴向深度 z**。深度帧、反投影、TSDF 投影、ICP 一律使用 `z_ax`；深度图存盘格式亦为 z（02 §5.5 F-1 已固化） | 若内部混用 `r` 与 `z_ax`，图像边缘产生 26%–33% 的深度错位，表现为"物体边缘被拉出尖刺"或"轮廓多出一圈" |
| **RA-2** | **ICP 与三角化的残差必须显式声明距离空间**。帧对 ICP 的点—面残差用**射线距离**空间（§5.1.2），TSDF 的轴向空间比较用 `z_ax`（§4.3.2） | 两端空间不一致 → 残差在图像边缘偏大 → 位姿估计被边缘区域拉偏 |
| **RA-3** | **驱动层必须核验深度语义**。`HW_TOF` 的部分厂商驱动直出**径向距离**而非轴向深度；`manifest.json` 必须记录 `capture.depth_semantics ∈ {axial_z, radial_range}`（**需回填 02 文档 §5.7**），核心层据此选择转换分支 | 把径向距离当轴向深度用 → 全图 12.9% 的系统性尺度偏差，表现为模型整体偏大 12.9%，且**不可能**用参照物复核发现（因为复核也用同一份错标深度） |

#### 2.3.6 实现层的双分支处理

```
if (depth_semantics == axial_z)      z_ax = raw / depth_scale_m
else /* radial_range */               z_ax = raw / depth_scale_m * cos(theta(u,v))
```

`cos(theta(u,v))` 由深度图内参逐像点预计算并缓存（`float32` 查找表，640×480 时 1.2 MB；4K 时 33 MB）。查找表在每次会话开始时构建一次，**不逐帧重算**。

### 2.4 置信度 → TSDF 权重的映射公式与阈值

#### 2.4.1 置信度的三个来源与优先级

| 深度源 | 平台逐像素置信度 | 本分支采用的置信度 `c` | 依据 |
|---|---|---|---|
| `ALGO_DEPTH` | **有**：ARCore 随深度图提供 16 bit 置信度图（0 = 无效，值越大越可信） | 平台置信度归一化后与**推导项取小** | 00 §8.2：低纹理面深度不精确 |
| `HW_LIFAR` / `HW_TOF` | **无**（ARKit `sceneDepth` 无逐像素置信度；`DEPTH16` 通常无伴随置信度图） | **完全由局部一致性推导**（§2.4.2） | 平台不提供就必须自建，否则无法做置信度加权 |

**归一化（平台置信度）**：

```
c_raw = clamp( conf_platform / 65535, 0, 1 )
c_plat = clamp( (c_raw − c_off) / (c_full − c_off), 0, 1 )
c_off  = 0.01      （ARCore 置信度直方图低端，保守）
c_full = 0.50      （保守：ARCore 文档未给量化口径，按实测分布取）
```

> `c_off` / `c_full` **必须实测标定**（§8.1 U-63）。当前取值是保守估计（把"看起来最好的一半"映射到 [0,1]），宁可低估置信度。

#### 2.4.2 推导置信度（无平台置信度时的唯一依据）

对像素 `p`，取 `w = rgbd_confidence_plane_window`（默认 5）的窗口内有效深度，用**最小二乘平面拟合**得到局部平面 `Π_p`，定义：

```
σ_p  = | d_p − Π_p(d_p) |              局部平面拟合残差（米）
g_p  = ‖ ∇d ‖                            局部深度梯度幅值（米/像素）
```

两个因子：

```
c_planar = exp( −(σ_p / σ_c)² )        平面一致性因子
c_edge   = 1 / (1 + (g_p / g_0)²)       边缘因子（深度梯度大 ⇒ 该像素恰在轮廓上，深度不可靠）
c_derive = c_planar · c_edge
```

其中 `σ_c = 2.5 · σ_z(tier)`（该档位的传感器噪声 2.5 倍），`g_0 = rgbd_confidence_edge_scale`（默认 0.02 m/px）。

> **为什么两个因子都要**：只有 `c_planar` 时，位于**平直但错误**区域（例如镜面伪距形成的大片"平坦"假面）的像素会得到高置信度；加入 `c_edge` 后，位于真实轮廓上的像素被系统性降权。而**低纹理平面上**两因子都高——这正是我们想要的（低纹理区的深度是可信的，只是 MVS 不可信）。

**平台置信度与推导置信度的合成**：

```
c = min( c_plat , c_derive )      （当平台置信度可用时）
c = c_derive                       （否则）
```

取 **min** 而非乘积或加权平均：任一环节判定不可信，则该像素不可信。乘积会过度惩罚（两个 0.5 相乘得 0.25），加权和需要额外权重参数且无法解释。

#### 2.4.3 置信度 → 基础可靠性 `ρ`

**原则（R-PREC-1 与 00 §8.2 的"降权不丢弃"）**：置信度低 → **权重低**，但**权重不得为 0**（除非该像素已被 §3.2/§3.3 判为无效像素）。因此 `ρ` 有一个严格为正的**地板**。

```
                ⎧ ρ_floor                                       ,  c ≤ c_low
  ρ(c) =       ⎨ ρ_floor + (1 − ρ_floor) · (c − c_low)/(c_high − c_low) ,  c_low < c < c_high
                ⎩ 1                                             ,  c ≥ c_high
```

| 符号 | 含义 | 默认（快/标/高） | 合法范围 | 依据 |
|---|---|---|---|---|
| `c_low` | 置信度下拐点 | 0.25 / 0.25 / 0.25 | [0.0, 0.9] | 保守：低于此值的样本只保留地板权重 |
| `c_high` | 置信度上拐点 | 0.75 / 0.75 / 0.75 | [0.5, 1.0] | 保守：高于此值的样本按满权重计 |
| `ρ_floor` | **可靠性地板**（严格正） | 0.05 / 0.05 / 0.03 | [0.0, 0.5] | 保证"降权不丢弃"；高精密档地板更低以抑制低置信样本的拖累 |

#### 2.4.4 深度不确定度 → 权重（完整映射链）

TSDF 样本的最终权重由三部分相乘：

```
┌──────────────────────────────────────────────────────────────────┐
│  w_i  =  ρ(c_i)  ×  w_unc,i  ×  w_cap                          │
│                                                                  │
│  w_unc,i = min( 1 , (σ_ref / σ_surface,i)² )                    │
│  σ_surface,i = σ_z(tier) / max( cos θ_inc,i , cos θ_min )       │
└──────────────────────────────────────────────────────────────────┘
```

| 符号 | 含义 | 默认 | 说明 |
|---|---|---|---|
| `σ_z(tier)` | 该深度源的单像素深度噪声（轴向） | ToF 2 mm / ALGO 0.03·z + 0.5 mm / LiDAR 12 mm | §2.2 表；需实测标定 |
| `σ_ref` | 参考噪声（权重归一化基准） | 2 mm（`rgbd_sigma_ref`） | 对应 ToF 标档，故 ToF 样本在标档法向入射下 `w_unc = 1` |
| `cos θ_inc` | 入射角余弦：视线与**局部表面法向**的点积绝对值 | 由深度图局部平面拟合的法向给出 | 掠射观测的深度不确定度按 `1/cos θ` 放大 |
| `cos θ_min` | 入射角余弦下限（防止 `1/cos` 爆炸） | 0.25 / 0.20 / 0.15 | 下限处 `σ_surface = σ_z/0.15 = 6.7 σ_z`，`w_unc = (2/13.3)² = 0.023` |
| `w_cap` | 相对权重上限（防止单帧/单源主导） | 2.0 / 4.0 / 8.0 | 高档放宽以允许多帧累积 |

**为什么用逆方差形式而不是固定权重**：`w_unc ∝ 1/σ_surface²` 使"噪声大的源自动少说话"，这是把 §2.2 的可信度分级落到数值的唯一自洽方式。用固定权重（例如"LiDAR 一律 0.5、ToF 一律 1.0"）会在 `ALGO_DEPTH` 的近距区（z = 0.2 m 处 σ_z 只有 6.5 mm，质量优于远距 ToF）给出错误判断。

**三条硬性规定**：

| 编号 | 规定 |
|---|---|
| **RW-1** | `w_i > 0` 恒成立（`ρ_floor > 0` 且 `w_cap > 0`）。置信度低 → 权重低，**永不置零** |
| **RW-2** | `w_unc` 的上限为 1，即**最可信的样本权重不超过 1**。权重是**相对量**，其绝对值由 §4.3.2 的 `W ≥ W_min` 判据解释 |
| **RW-3** | 权重下限 `w_floor = ρ_floor × w_unc,floor` 必须 ≥ 1e-4，否则在 float32 的运行均值累加中会被舍入吞掉 |

## 3. 深度预处理

### 3.1 总体流程与不可交换的顺序

```
┌──────────────────────────────────────────────────────────────────────┐
│ 输入：原始深度帧 d_raw (uint16, mm, 沿光轴 z)                        │
│       + 平台置信度 conf (uint8/uint16, 可空)                        │
│       + 深度相机内参 K_d                                            │
│       + 深度→RGB 外参 T_cd (可空)                                   │
└──────────────────────────────────────────────────────────────────────┘
   │
   ├─▶ ① 语义核验：单位/量纲/轴向语义（RA-3）          → §2.3
   │      失败 → RECON_ERR_CALIB_SCALE_OUT_OF_RANGE，中止
   │
   ├─▶ ② 置信度掩码：低置信 → 降权（不丢弃）           → §3.2
   │
   ├─▶ ③ 飞行点剔除：轮廓处的混合读数 → 置无效         → §3.3
   │
   ├─▶ ④ 双边最小区间估计滤波：保边去噪 + 最小分支恢复   → §3.4
   │
   ├─▶ ⑤ 深度 → RGB 对齐（仅用于颜色关联与交叉校验）    → §3.5
   │      ★ TSDF 几何使用**原生分辨率 + 深度内参**，不经此步
   │
   └─▶ ⑥ 保留原始深度副本（铁律）                      → §3.6
```

**顺序不可交换的理由**：

| 约束 | 理由 |
|---|---|
| ① 在 ② 之前 | 单位/语义错误时，后续所有计算无意义，且错误会以"深度噪声"的形式被置信度模型掩盖 |
| ② 在 ③ 之前 | 飞行点检测的判据依赖深度跳变统计；低置信像素会污染跳变统计，必须先降权 |
| ③ 在 ④ 之前 | 飞行点若不先剔除，会被双边滤波当成"合法的一致邻域"参与估计，把轮廓拉出斜面 |
| ④ 在 ⑤ 之前 | 滤波后的深度才可用于颜色关联；否则颜色会关联到被污染的深度上 |
| ⑤ 与 TSDF 并行 | TSDF 几何用原生深度；对齐图是**派生副本**，仅供颜色与交叉校验 |

### 3.2 置信度掩码

**目标**：把"不可信"编码进**权重**，而不是把像素删掉。

```
对每个有效深度像素 p：
    c_p = 置信度（§2.4.1 / §2.4.2）
    ρ_p = ρ(c_p)                                       （§2.4.3）
    w_p = ρ_p × w_unc(p) × w_cap                        （§2.4.4）
```

**附加规则**：

| 编号 | 规则 |
|---|---|
| **RM-1** | `rgbd_confidence_threshold`（08 G6，默认 0 = 不过滤）作为**硬门槛**保留：当用户显式设为 > 0 时，`c < threshold` 的像素被置为**无效**（不是降权）。默认 0，即**不硬删**，全部走降权路径 |
| **RM-2** | **平台明确标记无效的像素**（`conf = 0`，或深度值 0）**直接置为无效**。这不是"丢弃精度数据"，而是尊重传感器的无效标记——它本来就没有测量值 |
| **RM-3** | `ALGO_DEPTH` 的**无位移帧**整帧置无效（§1.3），并告警 `RECON_ERR_RGBD_DEPTH_NO_MOTION` |
| **RM-4** | 置信度掩码的**统计量必须落盘**：`mean(c)`、`P05(c)`、`valid_ratio`、按 16×16 网格的 `low_conf_ratio`，写入 `recon_mesh_info.json` 的 `depth` 节 |

### 3.3 飞行点剔除（flying pixel rejection）

#### 3.3.1 机理与检测判据

飞行点是**轮廓处**的深度像素：ToF 的一束光同时打到前景与背景，回波混合，读数落在两者之间，且**偏背景**（回波能量更强的一侧主导）。

**检测判据（两级）**：

```
一级：邻域深度跳变
    Δ_p = max over q ∈ N4(p) of | d_p − d_q |
    若 Δ_p > τ_eff  →  p 是"跳变候选"

二级：轮廓型判定（区分真实边缘与孤立噪声）
    设 p 的 4-邻域深度为集合 S = {d_q}
    设 m_lo = min(S), m_hi = max(S), m_md = median(S)
    p 是飞行点  ⟺  三条同时成立：
        (a) Δ_p > τ_eff                               （确有跳变）
        (b) m_hi − m_lo > τ_eff                       （跳变幅度显著，非噪声）
        (c) m_lo < d_p < m_hi                         （d_p 落在两侧之间 = 混合值）
                                                    且 d_p > m_lo + 0.5·(m_hi − m_lo)
                                                    （读数偏向背景侧，ToF 的典型特征）
```

**判据 (c) 的后半段是本分支的关键**：如果 `d_p` 落在两侧之间但**偏前景**（`d_p < m_lo + 0.5·Δ`），那不是 ToF 飞行点，而是**真实的表面**（例如一个刚好处于中间深度的真实小凸起）。把它误剔会丢失真实几何。

#### 3.3.2 阈值 `τ_eff`（噪声自适应）

08 G6 已有 `rgbd_flying_pixel_threshold`（快/标/高 = 4/2/1 mm）。**该值是"最小跳变幅度"语义**：低于此幅度的跳变视为真实曲率，高于则视为边缘候选。但**它必须随深度源噪声自适应**，否则在 `ALGO_DEPTH`（噪声 11 mm @0.35 m）下，几乎每个像素都是"跳变候选"，检测完全失效。

```
┌──────────────────────────────────────────────────────────────────┐
│  τ_eff = max( rgbd_flying_pixel_threshold , k · σ_z(tier) )      │
│  k = rgbd_flying_pixel_noise_k （默认 3.0）                       │
└──────────────────────────────────────────────────────────────────┘
```

| 深度源 | `σ_z` | `k·σ_z` | `rgbd_flying_pixel_threshold`（标档 2 mm） | **τ_eff（标档）** | 高档（1 mm） |
|---|---|---|---|---|---|
| `HW_TOF` | 2.0 mm | 6.0 mm | 2 mm | **6.0 mm** | 6.0 mm |
| `ALGO_DEPTH` @0.35 m | 11.0 mm | 33.0 mm | 2 mm | **33.0 mm** | 33.0 mm |
| `HW_LIDAR` | 12.0 mm | 36.0 mm | 2 mm | **36.0 mm** | 36.0 mm |

> **`rgbd_flying_pixel_threshold` 的语义修正（需回填 08 G6）**：当前备注为"飞行点检测阈值"，未说明与噪声的关系。应补注"本参数为**跳变幅度下限**，实际判据为 `max(本值, k·σ_z)`"。这与 08 §5.4 已列出的"`rgbd_tsdf_truncation` 默认系数需实测标定"属同类问题。

#### 3.3.3 剔除后的处理

| 步骤 | 动作 | 理由 |
|---|---|---|
| 1 | 判定为飞行点的像素 → **置为无效**（不是"平滑掉"） | 混合读数没有可恢复的真相，只有两侧之一可选，由 §3.4 的最小分支恢复 |
| 2 | 记录**飞行点掩码**与逐帧统计（`flying_ratio`） | 落盘；`flying_ratio > 0.05` 说明该深度源在该帧质量差 |
| 3 | `flying_ratio > 0.15` → 该帧深度整体降权 ×0.5，并记 `W_RGBD_DEPTH_FLYING_PIXEL_RATIO_HIGH` | 轮廓占比过高通常意味着深度分辨率不足或物体过于复杂 |
| 4 | 掩码本身**不参与 TSDF 融合**（`w = 0`），但**原始深度副本保留**（§3.6） | 保留可追溯性；用户可调阈值后重跑 |

> **与"降权不丢弃"的关系**：`00 §8.2` 的"降权不丢弃"针对的是**低置信区域**（降权但保留贡献）。飞行点是**无效测量值**（不是"低质量测量"），置无效不违反该原则——两者必须区分，否则会退化到"任何有噪声的像素都保留"，融合结果被污染。

### 3.4 双边最小区间估计滤波（BMRE）

#### 3.4.1 名称与定位

**双边最小区间估计滤波（BMRE, Bilateral Minimum-Range Estimation）** 是本项目自定义的深度预滤波，目标是**同时**做到两件互相冲突的事：

| 目标 | 传统方法的不足 |
|---|---|
| 平滑 ToF 的乘性散粒噪声 | 双边滤波只保边，不解决边缘处的混合读数 |
| 边缘处**恢复正确的表面**（选前景而非混合值） | 中值滤波会把边缘抹成斜面；双边滤波会把混合值保留下来 |

BMRE 的做法：**用双边权重限定"同一表面"的邻域集合，在该集合上做区间估计，并对边缘像素显式选择更近（前景）分支**。

#### 3.4.2 步骤 ①：双边权重

在窗口 `W(p)`（半径 `rgbd_bilateral_sigma_space` × 3，默认 σ_s = 4 px → 半径 12 px）内，对有效深度邻域 `q`：

```
w(p,q) = exp( −‖I_p − I_q‖² / (2 σ_c²) )  ·  exp( −‖p − q‖² / (2 σ_s²) )

σ_c = rgbd_bilateral_sigma_color （归一化到 [0,1] 的 RGB 空间，快/标/高 = 0.12/0.08/0.05）
σ_s = rgbd_bilateral_sigma_space （像素，快/标/高 = 6/4/3）
```

`I_p` 取**对齐后**的 RGB 颜色（§3.5）——这正是"双边"的意义：颜色相近才可能是同一表面。

#### 3.4.3 步骤 ②：最小区间估计

对每个邻域 `q`，构造"可信深度区间"：

```
A_q = [ d_q − τ_eff , d_q + τ_eff ]        （τ_eff 见 §3.3.2）
```

取**双边支持度 ≥ `rgbd_bilateral_support_ratio`（默认 0.50）** 的邻域集合 `S_50`（按 `w(p,q)` 归一化累计），对 `S_50` 的区间求交：

```
I_p = ⋂_{q ∈ S_50} A_q = [ max_{S_50}(d_q) − τ_eff ,  min_{S_50}(d_q) + τ_eff ]
```

| 情形 | 判定 | 处理 |
|---|---|---|
| `I_p` **非空**（`max(d_q) − min(d_q) ≤ 2 τ_eff`） | 邻域一致，无真实断层 | **d̂_p = clamp(d_p, I_p)`**（把 d_p 拉进一致区间；不改动已一致的像素） |
| `I_p` **为空**（`max(d_q) − min(d_q) > 2 τ_eff`） | 存在真实深度断层 | **不做平滑**，`d̂_p = d_p`，并把该像素的置信度乘以 `rgbd_bilateral_edge_confidence`（默认 0.5） |
| `S_50` 为空（所有邻域权重都低于支持比） | 颜色/空间邻域无有效支持 | `d̂_p = d_p`，置信度乘以 `rgbd_bilateral_edge_confidence` |

**为什么是"区间"而不是直接加权平均**：加权平均在断层处会把前景与背景平均成一个**不存在的中间深度**，且这个中间深度落在两侧之间，会被后续的表面重建当成真实几何。区间求交在断层处直接判定为"不一致"并放弃平滑，这是**保守且正确**的行为。

#### 3.4.4 步骤 ③：最小分支恢复（仅对被判为边缘的像素）

对于步骤 ② 中"区间为空"的像素 `p`，其邻域被深度分成两组：

```
F = { q ∈ N4(p) : d_q < d_p }        前景组（更近）
B = { q ∈ N4(p) : d_q > d_p }        背景组（更远）
```

**前景组的判定不能只看深度**（否则斜面上的近端邻域会被误判为前景）。追加**颜色判据**：前景组还必须满足颜色与 `p` 的相似度高：

```
前景有效性：  median_{q ∈ F} ( w_color(p,q) )  ≥  w_color_fg_min
w_color(p,q) = exp( −‖I_p − I_q‖² / (2 σ_c²) )
w_color_fg_min = 0.35（固定常量，随 σ_c 一致缩放；**需回填 08 G6 为显式参数**）
```

**恢复规则**：

```
d̂_p = median_{q ∈ F_valid} d_q          （取前景分支的中位数）
若 |F_valid| < 2  →  d̂_p = d_p（前景组样本不足，不恢复）
```

`rgbd_bilateral_min_branch_median`（默认 1）控制是否用中位数（1）还是最小值（0）替代中位数。用**中位数**而非最小值的原因：中位数对残余噪声稳健；用最小值会系统性偏向最前景的孤立噪声点。

#### 3.4.5 BMRE 的完整公式汇总

```
输入：d_raw（§3.2 掩码后）, I_rgb（对齐后颜色）, τ_eff, σ_c, σ_s, w_sup, w_edge, w_fg_min
输出：d_filt, c_filt, edge_flag

for each p with valid d_raw[p]:
    w(p,q) = w_color(p,q) · w_space(p,q)                       ∀q ∈ W(p)
    S_50   = { q : w(p,q) ≥ w_sup · max_q' w(p,q') }
    if S_50 ≠ ∅ and (max_{S_50} d_q − min_{S_50} d_q) ≤ 2 τ_eff:
        I_p = [ max_{S_50} d_q − τ_eff ,  min_{S_50} d_q + τ_eff ]
        d_filt[p] = clamp(d_raw[p], I_p)
        c_filt[p] = c_raw[p]
    else:
        edge_flag[p] = 1
        c_filt[p] = c_raw[p] · w_edge
        F_valid = { q ∈ N4(p) : d_q < d_raw[p] and w_color(p,q) ≥ w_fg_min }
        if |F_valid| ≥ 2 and rgbd_bilateral_min_branch_median:
            d_filt[p] = median_{F_valid} d_q
        else:
            d_filt[p] = d_raw[p]
```

#### 3.4.6 BMRE 的参数与效果

| 参数 | 快/标/高 | 作用 | 调大 / 调小的后果 |
|---|---|---|---|
| `rgbd_bilateral_sigma_color` | 0.12 / 0.08 / 0.05 | 颜色相似度尺度 | 调大 → 跨表面误加权；调小 → 只在极相似颜色间平滑，保边更强但噪声残留多 |
| `rgbd_bilateral_sigma_space` | 6 / 4 / 3 | 空间尺度（像素） | 调大 → 平滑范围大、噪声压得好，但边缘混合更严重 |
| `rgbd_bilateral_support_ratio` | 0.50 / 0.50 / 0.50 | 邻域支持比 | 调大 → 要求更一致的邻域，更多像素落入"边缘"分支 |
| `rgbd_bilateral_edge_confidence` | 0.50 / 0.50 / 0.50 | 边缘像素置信度折扣 | 调小 → 边缘像素在 TSDF 中几乎不贡献（更保守） |
| `rgbd_bilateral_min_branch_median` | 1 / 1 / 1 | 前景分支用中位数 | 0 → 用最小值（更激进，易被孤立噪点带偏） |

> **BMRE 的诚实定位**：它是**降噪 + 边缘恢复**手段，不是精度提升手段。它把 ToF 的随机噪声从 σ = 2 mm 压到约 σ = 2/√N_eff mm（N_eff = 窗口内一致邻域数，典型 8–20），但**不改变** §2.2 表中的系统误差（温漂、多径、尺度偏差）。这些系统误差只能靠 §5.4 的复核与 §2.3 的语义核验处理。

### 3.5 深度图 → RGB 相机对齐

#### 3.5.1 为什么需要对齐，以及对齐到什么程度

**需要对齐的用途（仅两项）**：

| 用途 | 说明 |
|---|---|
| 颜色关联 | TSDF 的颜色融合需要 RGB 颜色；深度图本身不带颜色（02 §5.5：深度段只有 uint16 毫米 + uint8 置信度） |
| 深度–MVS 交叉一致性 | 07 §4.3 的 `r(x) = (d_mvs − d_hw)/d_hw` 需要**同像素**比较 |

**不需要对齐的用途**：TSDF 的几何积分。理由：

| 理由 | 说明 |
|---|---|
| 上采样不产生新信息 | 深度原生分辨率（ToF 典型 640×480 = 0.31 Mpx）远低于 RGB（4K = 8.3 Mpx）。上采样到 RGB 分辨率只做插值，**不增加任何几何信息** |
| 插值会制造虚假深度 | 双线性上采样会生成**原图中不存在**的深度值，违反 00 §1.2 黑名单"深度图平滑替代原始深度"的精神 |
| 精度由原生分辨率决定 | 深度点云的空间采样间距 = `Z / f_d`。4K RGB + 640×480 深度时 `f_d ≈ 520 px`，`Z = 0.35 m` → 深度点间距 **0.67 mm**，是 MVS 点间距（0.14 mm）的 4.8 倍。**上采样到 4K 不会改变 0.67 mm 的实际采样间距** |

> **铁律的推论**：**TSDF 几何积分在深度原生分辨率上进行**，使用深度相机内参 `K_d` 与深度→世界变换。对齐到 RGB 的图是**派生副本**（`derived = 1`），仅供颜色关联与交叉校验。

#### 3.5.2 重投影映射公式（一般情形：深度相机与 RGB 相机不同心）

**输入**：深度像点 `(u_d, v_d)`，轴向深度 `z_ax`；深度内参 `K_d = [f_xd, f_yd, c_xd, c_yd]`；深度→RGB 外参 `T_cd = (R_cd, t_cd)`（**深度相机 → RGB 相机**）；RGB 内参 `K_c`。

**步骤**：

```
① 深度相机系归一化：
     x_d = (u_d − c_xd) / f_xd
     y_d = (v_d − c_yd) / f_yd

② 轴向深度反投影（RA-1：直接用 z_ax，无 cos θ 因子）：
     P_d = z_ax · (x_d, y_d, 1)ᵀ                    ∈ ℝ³（深度相机系）

③ 外参变换到 RGB 相机系：
     P_c = R_cd · P_d + t_cd

④ 透视投影到 RGB 像平面：
     若 P_c.z ≤ 0            → 无效（相机后方）
     u_c = f_xc · P_c.x / P_c.z + c_xc
     v_c = f_yc · P_c.y / P_c.z + c_yc
     若 (u_c, v_c) 越界       → 无效

⑤ 对齐后深度值 = P_c.z
     （注意：不是 z_ax。存在基线时 RGB 相机系的轴向深度与深度相机系不同）
```

**第 ⑤ 步是最容易出错的一步**：对齐图的深度值必须记为 `P_c.z`（在 RGB 相机系中的轴向深度），而不是原始的 `z_ax`。当深度相机与 RGB 相机同心同轴时二者相等；存在基线时二者相差 `t_cd.z` 量级。

#### 3.5.3 退化情形：同光心（ARKit / ARCore 路径）

ARKit `sceneDepth` 与 ARCore Depth API 的深度与彩色图像**同光心、同光轴**（深度是相对于彩色相机的），此时 `R_cd = I`、`t_cd = 0`，映射退化为纯内参重标定：

```
x_c = (f_xc / f_xd) · x_d
y_c = (f_yc / f_yd) · y_d
u_c = f_xc · x_d + c_xc = f_xc · (u_d − c_xd)/f_xd + c_xc
v_c = f_yc · y_d + c_yc = f_yc · (v_d − c_yd)/f_yd + c_yc
对齐后深度值 = z_ax（不变）
```

**同光心时的分辨率适配**：ARKit 的 `sceneDepth` 分辨率可能低于彩色图像（如 256×192 vs 1920×1440），此时需要**从深度分辨率内参换算到彩色分辨率内参**：

```
若深度图内参未由平台给出，按彩色分辨率内参等比缩放：
    f_xd' = f_xd · (W_c / W_d) ,  f_yd' = f_yd · (H_c / H_d)
    c_xd' = (c_xd + 0.5) · (W_c / W_d) − 0.5
    c_yd' = (c_yd + 0.5) · (H_c / H_d) − 0.5
```

> 主点的 `+0.5 / −0.5` 偏移必须加上（02 §3.9.1 C-1 明确要求）。这是标定界的经典陷阱：直接按比例缩放主点会引入 **0.5 px 的系统偏差**，在 4K 下相当于 0.07 mm 的深度偏差，在 0.35 m 处又折算为 0.5 px 的重投影偏差——**恰好是 00 §4.6 验收线的量级**。

#### 3.5.4 z-buffer 消解与空洞处理

多个深度像点可能映射到同一个 RGB 像点（深度分辨率低于 RGB 时必然发生）。**保留最近者**（最小 `P_c.z`）：

```
对每个 RGB 像点 (u,v)：  D_align[u,v] = min { P_c.z : 投影到 (u,v) 的所有深度像点 }
```

**空洞处理（硬规定）**：

| 编号 | 规定 |
|---|---|
| **RA-4** | 对齐后的**空洞（无任何深度像点覆盖）必须保持无效**，**禁止**用邻域均值/最近邻填补。空洞必须以 `derived = 0, valid = 0` 标记 |
| **RA-5** | 对齐图**只用于颜色关联与交叉校验**；任何进入 TSDF 几何的深度必须来自原生分辨率路径（§3.5.1） |
| **RA-6** | 对齐后的每个像点携带 `derived` 标记与**折扣后置信度**：`c_align = c_src × rgbd_align_derived_conf_scale`（默认 0.5）。折扣原因是 RGB 像元对应的深度是**多个深度像元的加权覆盖**，其几何位置对应的是**覆盖区域的某个统计量**，不是精确的表面点 |
| **RA-7** | 交叉一致性统计（07 §4.3）**必须**在有效覆盖率 ≥ `rgbd_depth_mvs_consistency_min`（默认 0.40）的区域内计算；覆盖率不足时该统计量标记为"不可用"，并按 §5.4 触发"深度通道不可信"处置 |

#### 3.5.5 深度–RGB 基线合理性硬校验

07 §1.3 原因 1 指出：深度–RGB 外参标定错误 `Δb` 会表现为"近处放大 / 远处缩小"，且**与尺度误差难以区分**。本分支在每次会话开始时执行硬校验：

| 检查 | 判据 | 不满足时 |
|---|---|---|
| 基线量级 | `‖t_cd‖ ≤ rgbd_align_max_baseline`（默认 0.05 m = 50 mm，手机深度相机与 RGB 相机的典型基线 3–15 mm） | 告警 `W_RGBD_ALIGN_BASELINE_SUSPICIOUS`；外参视为不可用，退化为同光心假设并记录 |
| 一致性 | 深度 vs MVS 的 `median(r)`（07 §4.3），在 0.4–1.0 m 深度段统计 | `abs(median(r)) > rgbd_depth_mvs_median_max`（默认 0.03）→ 告警 `W_RGBD_DEPTH_MVS_MEDIAN_BIAS` |
| 包围盒比值 | 深度直接测得的包围盒 vs 重建包围盒，比值 `abs(ratio − 1) > 0.10` | 告警（07 §4.4） |

### 3.6 铁律：保留原始深度副本

> **00 §1.2 黑名单原文**：`深度图降采样、深度图平滑替代原始深度` 属于**禁止降级**项。
> **00 §4.2 关键工程决策**：`※保留原始深度副本，不做降采样`。

本分支把这条铁律落成**六条可检验的工程规定**：

| 编号 | 规定 | 检验方法 |
|---|---|---|
| **IR-1** | **原始深度帧按原生分辨率、原生单位（uint16 毫米）逐帧落盘**，与 RGB 帧、置信度帧一同写入 `frames.bin` 的深度段与置信度段（02 §5.5）。不得重采样、不得转码为 float32、不得丢帧 | 14 文档 IT-7：落盘深度帧与采集期内存副本逐字节相等 |
| **IR-2** | **TSDF 几何积分使用原生分辨率深度 + 深度内参**，不经过 RGB 分辨率上采样（§3.5.1） | 14 文档 IT-8：TSDF 输入深度图的分辨率 == 平台深度分辨率 |
| **IR-3** | **滤波结果 `d_filt` 与原始 `d_raw` 分离存储**，二者都落盘（`d_raw` 必需，`d_filt` 可选重建）。`d_filt` **不得**覆盖 `d_raw` | 14 文档 IT-7：`d_raw` 校验和与采集期一致 |
| **IR-4** | **BMRE 的输出不被当作"更准的深度"**。`d_filt` 只用于融合，其**系统误差不因此改变**；§2.2 表中的精度数字对 `d_raw` 与 `d_filt` 同时成立 | 文档评审检查：§2.2 精度列未因滤波而下调 |
| **IR-5** | **阈值可重跑**：置信度阈值、飞行点阈值、BMRE 参数全部是用户可调或专家可调（§7.1），修改后**从原始深度副本重跑预处理**，不要求重新采集 | 14 文档 CT-9：参数改写白名单扫描；`rgbd_*` 的预处理参数在白名单内 |
| **IR-6** | **置信度帧与深度帧一一对应落盘**，不丢弃置信度为 0 的帧（只丢弃深度本身为无效的**像素**） | 14 文档 IT-7：置信度帧数量 == 深度帧数量 |

## 4. TSDF 融合

### 4.1 体素网格定义

#### 4.1.1 坐标与网格

| 项 | 定义 |
|---|---|
| 世界系 | **Y-up 右手系，单位米**（06 §0.1），与 05 的 MVS 输出、MVS 融合点云完全一致 |
| 网格原点 | `o = (o_x, o_y, o_z)`，由关键帧深度范围 + 1.5 × 物体尺度确定（05 §5.5.2 同款口径） |
| 体素索引 | `i = ⌊(p − o).x / h⌋`，`j`、`k` 同理 |
| 体素中心 | `c(i,j,k) = o + (i + 0.5)·h·(1, 1, 1)` |
| 稀疏存储 | 哈希表（`unordered_map` / 自研开放寻址哈希），键 = `(i,j,k)` 的 64 bit 打包（各 21 bit） |
| 块结构 | `rgbd_voxel_block_size`（快/标/高 = 32/64/128 体素/边），块间**重叠 1 层体素 halo**，块淘汰与落盘由 13 §3.2.1 定义 |

#### 4.1.2 每体素的数据布局

| 字段 | 类型 | 字节 | 含义 |
|---|---|---|---|
| `S` | float32 | 4 | **TSDF 加权累加器** `Σ w_i · t_i` |
| `W` | float32 | 4 | **权重累加器** `Σ w_i` |
| `C` | uint8 × 3 | 4 | 颜色累加器（§4.5） |
| 哈希索引 | uint32 | 4 | 开放寻址的桶内索引（13 §2.5 口径） |
| **合计** | | **16 B** | 与 13 §2.5 一致 |

> **字段语义的修正（需回填 13 §2.5）**：13 §2.5 把第一个字段记作 "TSDF f32(4)"。本分支明确该字段为**加权累加器 `S`**（不是已经归一化的 TSDF 值），有效 TSDF = `S / max(W, ε)`。选择累加器形式而非运行均值形式（`TSDF ← (TSDF·W + w·t)/(W+w)`）有三条理由：
>
> 1. **数值稳定性**：加权均值的闭式 `S/W` 避免了运行均值在 `W` 很大时的反复舍入累积；`S` 与 `W` 同步增长时相对误差不放大。
> 2. **GPU/CPU 可比对性**：CPU 参考实现与 GPU 实现都用同一累加器形式、同一定点标度（§4.6.4），两者的差异**只来自定点量化**（`2⁻²² ≈ 2.4e-7`），因此 14 文档单元测试要求的"差 < 1e-6"可达。运行均值形式的 GPU/CPU 差异会随帧数累积而放大。
> 3. **块划分无关性**：体素归属采用**不相交所有权**（§4.6.2），同一帧的数据无论被拆到几个块，每个体素收到的样本集合完全相同 → 无论用哪种形式，结果都与分块方式无关。
>
> 数值范围检查：`t ∈ [−1, 1]`，单帧每体素 1 个样本（体素中心式，§4.6.2），`w ≤ w_cap = 8`，100 帧累积 → `|S| ≤ 100 × 8 × 1 = 800`（float32 相对误差 < 1e-5，无溢出风险）；`W ≤ 800`，`W ≥ W_min = 1.0` 判据见 §4.3.6。

#### 4.1.3 三档体素边长预设（与 08 G6 一致）

| 档位 | `rgbd_tsdf_voxel_size`（主网格 `h_voxel`） | `rgbd_tsdf_truncation`（μ） | μ/h | 主网格体素数（`L_max` = 0.3 m） | 主网格内存（16 B/体素） |
|---|---|---|---|---|---|
| 快 | **4 mm** | 16 mm | 4 | 4.22e5 | **6.7 MB** |
| 标 | **2 mm** | 8 mm | 4 | 3.375e6 | **54 MB** |
| 高 | **0.5 mm** | 2 mm | 4 | 2.16e8 | **3 456 MB** |

> 与 13 §2.5 的表完全一致（6.7 / 54 / 432 / 3456 MB），本文不重复其推导。**高档的 3.4 GB 必须走分块 + 落盘**（13 §3.2.1），且 `rgbd_tsdf_voxel_size` 是**黑名单参数**，内存不足时**永不**自动调大（00 §1.2、13 §2.5）。

### 4.2 截断距离与体素边长的关系

#### 4.2.1 关系式与取值

```
┌──────────────────────────────────────────────────────────────────┐
│  μ  =  k_μ · h_voxel ,      k_μ = rgbd_tsdf_truncation_ratio    │
│  默认 k_μ = 4  （与 08 G6 的三档取值 16/8/2 mm 完全一致）       │
└──────────────────────────────────────────────────────────────────┘
```

#### 4.2.2 为什么是 4 而不是别的值

| 约束 | 推导 | 结论 |
|---|---|---|
| **下界：零交叉可被插值定位** | 截断带内至少要有 **2 个体素**跨越零交叉，否则插值点落在带外，等值面出现断裂 | `μ ≥ 2h`（08 §3.2 L2 强制 `μ ≥ 2h`） |
| **下界：跨帧带一致性** | 深度噪声 σ_z 引起的带中心抖动 `Δ_d ~ N(0, σ_z)`。若 `2μ ≲ Δ_d`，则第 k 帧写入的带与第 k+1 帧写入的带**不重叠**，融合后出现"雾状"多带 | `μ ≳ 2 σ_z` → 见 §4.2.3 的分档处理 |
| **上界：自由空间雕刻过厚** | 带内的体素被置为"自由空间"，过厚的带会把相邻表面之间的空间也雕刻掉，造成**表面变胖**、缝隙闭合 | `μ ≤ 12h`（经验上界；4h 远低于此） |
| **上界：MVS 主导下的残余影响** | 主网格只用于融合去噪与补盲点生成，其误差不进入最终曲面；但过大的 μ 会让补盲点向"最近观测面"吸附，位置偏差增大 | `μ ≤ 8h` 为宜（4h 满足） |

#### 4.2.3 跨帧带一致性的分档处理（**关键工程处理**）

由上表，`μ ≥ 2σ_z` 与 `μ = 4h` 在高档（`h = 0.5 mm` → `μ = 2 mm`）下**直接冲突**：`2σ_z(ToF) = 4 mm > 2 mm`。三种处理：

| 方案 | 做法 | 评价 |
|---|---|---|
| A | 把 `μ` 提到 `2σ_z` | 高档 `μ` 从 2 mm 提到 4 mm（ToF）/ 24 mm（LiDAR）。但**高档的 `μ/h` 从 4 变成 8**，融合工作量翻倍；且 LiDAR 的 `μ = 24 mm` 相对 `h = 0.5 mm` 是 48 层体素，**完全不可行** |
| B | 保持 `μ = 4h`，接受"雾状多带" | 高档的 TSDF 表面质量下降。但由于**主网格只做融合去噪与补盲，最终曲面由 MVS 决定**（00 §4.2），影响被限制在补盲区 |
| C | **分级承载**（本分支采用） | 按深度源的角色分流：能进主网格的源用主网格 + `μ = 4h`；不能进的源用**先验网格**（粗体素，`μ` 随 `h_prior` 放大，带一致性自动满足） |

**方案 C 的先验网格定义**：

```
h_prior = max( 4 · h_voxel , h_prior_min )      h_prior_min = 8 mm（固定下限）
μ_prior = 4 · h_prior
```

由 `h_prior ≥ 8 mm` → `μ_prior ≥ 32 mm ≥ 2σ_z`（ToF 4 mm、ALGO 22 mm、LiDAR 24 mm **全部满足**）。带体素层数恒为 4，与主网格一致。

**先验网格的内存代价（可忽略）**：

| 档位 | `h_prior` | 体素数（`L_max` = 0.3 m） | 内存 |
|---|---|---|---|
| 快 | 16 mm | 6.6e4 | 1.1 MB |
| 标 | 8 mm | 5.27e5 | 8.4 MB |
| 高 | 8 mm | 5.27e5 | 8.4 MB |

> 相比主网格的高档 3.4 GB，先验网格的 8.4 MB 是 **0.24%**。这是本分支最重要的一个成本优化：**用 0.24% 的额外内存，把 LiDAR / ALGO_DEPTH 彻底从"必须很大 μ"的困境中解脱出来。**

#### 4.2.4 三档 × 三源的最终承载分配

| 深度源（Tier） | 承载网格 | `h` | `μ` | `μ/h` | 本档是否满足 `μ ≥ 2σ_z` | `rgbd_lidar_role` 生效值 |
|---|---|---|---|---|---|---|
| `HW_TOF`（Tier 2） | **主网格** | `h_voxel` | `4h_voxel` | 4 | 快 16 ≥ 4 ✓ / 标 8 ≥ 4 ✓ / 高 **2 < 4 ✗** | **2**（TSDF 主输入） |
| `ALGO_DEPTH`（Tier 1） | 先验网格 | `h_prior` | `4h_prior` | 4 | ✓（全部档） | **1**（08 L10 强制） |
| `HW_LIDAR`（Tier 3） | 先验网格 | `h_prior` | `4h_prior` | 4 | ✓（全部档） | **1**（00 §4.2 强制） |

**`HW_TOF` 在高档（`h = 0.5 mm`, `μ = 2 mm`）的不满足项处置**：

| 项 | 处置 |
|---|---|
| 现象 | `2 μ = 4 mm < 2σ_z = 4 mm`（ToF @标档噪声 2 mm）→ 恰好在边界，融合带会出现轻微"雾化" |
| 影响范围 | **仅影响主网格的融合去噪质量**（补盲点的位置误差在 §6.1.3 中已按 2 mm 计，雾化不改变系统误差） |
| 对最终曲面的影响 | **零**。最终曲面由 MVS 决定（00 §4.2），主网格不形成最终曲面 |
| 工程处置 | 高档默认 `rgbd_lidar_role` 对 ToF 仍为 2，但 §4.7 规定：主网格的融合结果**只用于补盲点与置信度调制**，不参与最终曲面的直接构造。若用户显式要求 ToF 在高档下作"主几何"（违反 00 §4.2），必须先提高 `rgbd_tsdf_truncation`，而这会触发 08 §3.2 L2 的联动检查 |
| 记录 | `recon_mesh_info.json` 的 `tsdf.band_consistency_margin = 2μ − 2σ_z`（负值即雾化风险），落盘供 14 文档分析 |

### 4.3 加权 TSDF 融合公式（Kurz & Rusinkiewicz 扩展）

#### 4.3.1 基础形式回顾（Curless–Levoy）

对体素 `v`（世界坐标 `p_v`）与第 `i` 帧：

```
P_c = R_i · p_v + t_i                    变换到相机系
(u, v) = π_K(P_c)                        投影到像平面
d(u,v)                                  该像素的深度（无效则跳过）
s = d(u,v) − P_c.z                       轴向有符号距离（RA-1：轴向空间）
t = clamp(s / μ, −1, 1)                  截断后的 TSDF 值
```

**符号约定**：`s > 0` 表示体素在**表面之前**（相机到体素的路程比到表面的路程长），即体素在自由空间；`s < 0` 表示体素在表面之后（在物体内部）。

#### 4.3.2 空间选择的严格规定（**关键**）

上面的 `s = d − P_c.z` 是**轴向**有符号距离。它与**射线距离**有符号距离的关系是：

```
s_ray = r_sensor(u,v) − ‖P_c‖ = (d(u,v) − P_c.z) · sqrt(1 + x² + y²) = s_ax · sec θ
```

| 融合类型 | 必须使用的空间 | 原因 |
|---|---|---|
| **TSDF 融合**（本节） | **轴向** `s_ax` | `d(u,v)` 与 `P_c.z` 同为轴向量，直接相减即得轴向有符号距离；且**零交叉位置 `P_c.z = d` 恰好等价于"轴向深度等于观测轴向深度"，与 §2.3.3 的反投影公式完全一致**，不存在 `sec θ` 的畸变 |
| **帧对 ICP 残差**（§5.1） | **射线** `s_ray` | 点—面残差 `n·(P_t − P_{t−1})` 是三维欧氏量；用轴向空间会使图像边缘的残差被系统性缩小 `cos θ` 倍 |

> **RA-2 的具体化**：这两处空间不一致**不是错误**，因为它们各自在正确的空间里工作。真正要禁止的是"在同一处混用"。本文把该规定写成 RA-2。

#### 4.3.3 加权更新公式（完整）

```
┌────────────────────────────────────────────────────────────────────────────────────┐
│  ① 投影与取值                                                                  │
│     P_c = R_i · p_v + t_i                                                        │
│     (u,v) = π_K(P_c)          若 P_c.z ≤ 0 或越界 → 跳过                        │
│     d = D_i(u,v)              若该像素无效 → 跳过                                │
│     n = N_i(u,v)              深度图局部平面法向（§4.3.5）                     │
│                                                                                    │
│  ② 距离与截断（轴向空间，RA-1）                                                 │
│     s_ax = d − P_c.z                                                             │
│     t    = clamp(s_ax / μ, −1, 1)                                                │
│                                                                                    │
│  ③ 权重（§2.4.4 完整映射链）                                                    │
│     c      = C_i(u,v)                  置信度（平台 + 推导）                     │
│     ρ      = ρ(c)                                                             │
│     cosθ_inc = | n · d̂ |                 入射角余弦（d̂ = P_c/‖P_c‖）           │
│     σ_surface = σ_z(tier) / max(cosθ_inc, cosθ_min)                              │
│     w_unc   = min(1, (σ_ref / σ_surface)²)                                       │
│     w_i     = ρ × w_unc × w_cap                                                   │
│                                                                                    │
│  ④ 加权累加（顺序无关形式）                                                     │
│     S(v) ← S(v) + w_i · t                                                        │
│     W(v) ← W(v) + w_i                                                            │
│     C(v) ← C(v) + w_i · c_i        （§4.5）                                       │
│                                                                                    │
│  ⑤ 有效 TSDF                                                                    │
│     TSDF(v) = S(v) / max(W(v), ε) ,  ε = 1e-6                                     │
└────────────────────────────────────────────────────────────────────────────────────┘
```

#### 4.3.4 相对 Curless–Levoy 的三处扩展（Kurz & Rusinkiewicz 式）

| 扩展 | Curless–Levoy | 本分支 | 依据 |
|---|---|---|---|
| **E1：不确定度加权** | 全部样本权重相同（等权平均） | 权重 = `ρ(c) × w_unc × w_cap`，其中 `w_unc` 按 `1/σ_surface²` 归一 | Kurz & Rusinkiewicz 的不确定度加权融合思想；本分支把传感器噪声模型（§2.2）与置信度模型（§2.4）接入该框架 |
| **E2：累加器形式（顺序无关）** | 运行均值 `TSDF ← (TSDF·W + w·t)/(W+w)` | 存 `S = Σ w·t` 与 `W = Σ w`，`TSDF = S/W` | 满足 14 文档 "分块融合与单块融合结果一致（差 < 1e-6）" |
| **E3：入射角因子** | 无 | `w_unc` 含 `1/max(cosθ_inc, cosθ_min)` | 掠射观测的深度不确定度按 `1/cosθ` 放大（与 05 §5.5.3 的 `w_ang = cos θ` 方向相反、作用点不同：05 用于**视图选择**，本文用于**单样本不确定度**） |

#### 4.3.5 局部表面法向 `N_i(u,v)` 的估计

融合时需要该像素处的表面法向（用于入射角因子与后续补盲点的法向）。**不使用 TSDF 自身的梯度**（首帧尚无梯度），而用**深度图局部平面拟合**：

```
取 (2w+1)² 窗口（w = rgbd_icp_plane_window，默认 5）的有效深度，
最小二乘拟合平面 a·u + b·v + c = d，
法向 n = normalize(−a, −b, 1) ，指向相机（深度增大的方向为负）
取 n 的方向使其满足 n · P_c < 0（朝向相机）
```

拟合点数 < 6（有效样本不足）时，退化用**中心差分法向**：

```
n ∝ ( d(u+1,v) − d(u−1,v), d(u,v+1) − d(u,v−1), −2h_px )
```

其中 `h_px` 为该像素在深度图上的等效物理间距 `= P_c.z / f_d`。

#### 4.3.6 体素有效性判据

| 判据 | 条件 | 不满足时 |
|---|---|---|
| 权重下限 | `W(v) ≥ rgbd_tsdf_min_weight`（默认 1.0） | 该体素标记为**未充分观测**，其 `TSDF` 不用于生成补盲点（§6.4） |
| 带内一致性 | `σ_S(v) = sqrt(max(0, S²/W − (S/W)²)) / W ≤ rgbd_tsdf_dispersion_max`（默认 0.10） | 该体素降权 ×0.5 并记录 `W_TSDF_DISPERSION_HIGH` |
| 支撑视图数 | `N_support(v) ≥ rgbd_tsdf_min_views`（默认 2） | 不足以判定为"多帧一致"，仅在 `W` 很高时仍可使用 |

> `σ_S` 用**加权**标准差（`E[w²t²]/W − (E[wt]/W)²` 的形式）度量体素内不同帧观测的离散度。ToF 的乘性噪声在融合后仍残留约 `σ_z/√N_eff`，若 `N_eff` 不足则离散度偏大 → 正确地触发降权。

### 4.4 深度不确定度 → 权重的完整映射（汇总）

§2.4.4 已给出映射链，此处给出**端到端算例**（标档、ToF、4K 采集、0.35 m、f_d = 520）：

| 场景 | `c` | `ρ` | `cosθ_inc` | `σ_surface` | `w_unc` | `w_i`（`w_cap` = 4） |
|---|---|---|---|---|---|---|
| 法向入射、强纹理、满置信 | 0.90 | 1.00 | 1.00 | 2.0 mm | 1.000 | **4.00** |
| 法向入射、中等置信 | 0.50 | 0.51 | 1.00 | 2.0 mm | 1.000 | **2.04** |
| 法向入射、低置信（仍有效） | 0.20 | 0.05 | 1.00 | 2.0 mm | 1.000 | **0.20** |
| 掠射 60°、强纹理 | 0.90 | 1.00 | 0.50 | 4.0 mm | 0.250 | **1.00** |
| 掠射 80°、强纹理 | 0.90 | 1.00 | 0.17 | 11.8 mm | 0.029 | **0.12** |
| 低纹理平面上（ToF，深度可信） | 0.85 | 0.97 | 1.00 | 2.0 mm | 1.000 | **3.88** |

**关键观察**（这决定了 §6.4 的补盲策略能成立）：

> **低纹理平面上，ToF 的深度权重与强纹理区几乎相同**（3.88 vs 4.00）。深度传感器不依赖纹理，因此低纹理区的**深度是可信的**。这正是本分支相对 MONO 的核心优势：**MVS 在低纹理区失效，但深度不失效**，补盲通道因此能提供真实几何而非推断几何。
>
> 反之，`ALGO_DEPTH` 在低纹理面上**由运动视差求解**，本身就不精确——其低置信度由 §2.4.2 的 `c_planar` 因子捕捉（`ALGO_DEPTH` 的低纹理区深度跳变大 → `c_edge` 降低 → `ρ` 降低）。因此 **Tier 1 的补盲能力显著弱于 Tier 2/3**，这是 00 §8.2 限制的直接落地。

### 4.5 颜色融合

#### 4.5.1 权重

颜色累加使用**与几何同一套权重** `w_i`（保证颜色与几何的支撑一致），但**视角权重**额外叠加：

```
w_color,i = w_i · w_view,i
w_view,i  = cos^n( θ_i ) / max_i' cos^n( θ_i' )        （归一化到 [0,1]，n = rgbd_tsdf_color_view_weight_exp）
```

| 符号 | 含义 | 默认（快/标/高） |
|---|---|---|
| `θ_i` | 视线方向与该体素表面法向的夹角 | — |
| `n` | 视角权重指数 | 1.5 / 2.0 / 3.0 |

`w_view` 的作用：正对表面的视角颜色最准（无透视压缩、无掠射高光畸变）；掠射视角的颜色被压缩并可能带高光，降权。

#### 4.5.2 累加与归一

```
C(v) ← C(v) + w_color,i · c_i          （c_i ∈ [0,1]³，来自对齐后的 RGB，§3.5）
```

最终颜色：

```
color(v) = C(v) / max(Σ w_color,i , ε)
```

`Σ w_color,i` 需要单独累加（或由 `W` 近似）。为节省 4 B/体素的存储，**本分支用 `W` 近似**（视角权重归一化后其和 ≈ `W`），偏差 < 5%，对低频底色无影响。

> **重要边界（对齐 06 §1.6 的"颜色渗染"缺陷）**：TSDF 的颜色只是**低频底色**，不作为最终纹理来源。最终纹理由 06 §2.9 的多视图投影 + 烘焙产生。TSDF 颜色仅用于：(a) 补盲区的顶点初始颜色（烘焙在该区可能覆盖不足）；(b) `recon_mesh_info.json` 的诊断对比。

### 4.6 GPU 实现

#### 4.6.1 Metal / Vulkan 算法映射

两端使用**同一套算法描述**（`shaders/common/tsdf_fusion.h` 风格的伪代码），分别编译为 `.metal` 与 `.comp`（00 §3.2）。映射与 05 §5.9.1 同款：

| 算法 | Metal | Vulkan | 备注 |
|---|---|---|---|
| 计算管线 | `MTLComputePipelineState` + `MTLComputeCommandEncoder` | `VkPipeline` + `VkCommandBuffer` + descriptor set | |
| 分派 | `dispatchThreadgroups(x, y, z)` | `vkCmdDispatch(x, y, z)` | |
| workgroup | `threadgroup_size` 声明 | `local_size_x/y/z` 声明 | 统一 8×8 = 64 线程 |
| 共享内存 | `threadgroup` 变量 | `shared` 变量 | 本算法**不需要**共享内存（每个体素独立） |
| 采样 | `texture2d<float, access::read>` | `texture2D` + `sampler`（`imageLoad` 更优，无滤波） | 深度图必须用**最近邻**采样 |
| 原子操作 | `atomic_compare_exchange_weak` | `atomicCompareExchangeWeak` | 体素中心式下**仅块分配需要**（§4.6.2 / §4.6.4） |
| 屏障 | `memoryBarrier` | `memoryBarrierShared` / `barrier()` | 本算法**无需**屏障（无共享内存、无跨线程协作） |

#### 4.6.2 融合的并行结构：体素中心式（voxel-centric）

TSDF 融合有两种并行化方向，它们的**原子操作需求与显存模型完全不同**。本分支选定 **体素中心式（voxel-centric）**：

| 方案 | 并行单元 | 每个线程处理 | 原子操作需求 | 结论 |
|---|---|---|---|---|
| **体素中心式**（本分支采用） | **体素** | 一个体素：投影 → 查深度 → 算 `s` → 更新自己 | **S/W 的更新无需原子**（每体素仅被一个线程写）；**仅块分配需要原子** | ✅ 采用 |
| 像素中心式（point-centric） | 深度像素 | 一个像素：反投影 → 沿射线遍历体素 → 逐体素累加 | S/W/颜色三者**全部需要浮点原子累加** | ❌ 不采用（Metal/Vulkan 无浮点原子，见 §4.6.4） |

**体素中心式的完整流程（每个体素一次）**：

```
对块 b 中的每个体素 v（世界坐标 p_v）：
    ① P_c = R_i · p_v + t_i                 变换到相机系
    ② (u,v) = π_K(P_c)                      投影
       若 P_c.z ≤ 0 或越界 → 跳过（体素不在相机前方）
    ③ d = D_i(u,v)                          查深度（最近邻采样）
       若该像素无效 → 跳过
    ④ 早退判定：|d − P_c.z| > μ → 跳过
       （体素距表面超过截断距离，不产生有效观测）
       ★ 该早退把 99% 的体素在第 ④ 步剔除，是体素中心式的性能关键
    ⑤ s = d − P_c.z ;  t = clamp(s/μ, −1, 1)
    ⑥ 算权重 w（§2.4.4 完整映射链）
    ⑦ 更新自身：S(v) += w·t ;  W(v) += w ;  C(v) += w·c
       ★ 体素 v 在本帧只被"包含 v 的那个块"的一个线程处理，
         因此这三个更新**不需要原子操作**
```

**块分配的原子需求**（唯一需要原子的地方）：新块进入稀疏哈希时，多个线程可能同时发现"块 (i,j,k) 不存在"并试图创建。用 CAS（compare-and-swap）抢占：

```
Metal：atomic_compare_exchange_weak
Vulkan：atomicCompareExchangeWeak
```

| 步骤 | 线程 A | 线程 B | 结果 |
|---|---|---|---|
| 1 | CAS(hash[slot], EMPTY → CLAIMED) 成功 | — | A 获得创建权 |
| 2 | — | CAS(hash[slot], EMPTY → CLAIMED) 失败 | B 退化为"读已存在的块"（自旋等待或直接跳过本帧） |
| 3 | A 分配块内存、清零、标记 READY | B 重试读取 | 一致 |

> **本设计相对点云式的一个额外收益**：体素中心式天然满足 §4.1.2 的"块划分无关性"——每个体素的样本集合与其所在的块无关，因此 14 文档单元测试"分块融合与单块融合结果一致（差 < 1e-6）"**自动成立**，不需要额外的顺序控制。

#### 4.6.3 分派层次与命令缓冲区

```
层次 1：帧级 dispatch
   每个深度帧一次命令缓冲区录制
层次 2：块级 dispatch
   一个块（64³ 或 128³ 体素）一次 dispatch
层次 3：体素级
   每线程处理一个体素（§4.6.2 的 6 步）
```

**命令缓冲区编排（标档、4K RGB + 640×480 ToF 深度）**：

| 命令缓冲区 | 内容 | 数量 | 备注 |
|---|---|---|---|
| CB-1 | 深度输入准备：法向图生成（§4.3.5）、置信度归一化 | 1 | 逐像素并行，无原子 |
| CB-2 | 主网格融合：块级 dispatch，逐块 | `n_blocks_main` | 体素中心式，无原子（除块分配） |
| CB-3 | 先验网格融合（role ≥ 1 的源） | `n_blocks_prior` | 同上 |
| CB-4 | 归一化与统计（`TSDF = S/W`、颜色归一、`W`/`σ_S` 统计） | 1 | 逐体素并行，无原子 |
| CB-5 | 补盲点提取（可选，见 §6.4.2） | 1 | 零交叉检测，逐体素并行 |

> **CB-1 的法向图生成**是逐像素操作（每个深度像素拟合一个局部平面），每个像素独立 → **无原子**。这是把法向从"逐体素现算"（需要在 GPU 上再查一次邻域深度）改为"预先算好一张法向图"（每像素一次）的原因：法向图只占 `640×480×3×4 = 3.5 MB`，而逐体素现算会让每个体素多做 4 次深度采样。

#### 4.6.4 原子操作需求与定点化

**结论先行**：**体素中心式融合的 S/W/C 更新不需要任何原子操作**（§4.6.2）。Metal 与 Vulkan 无浮点原子这一限制在本设计下**不构成障碍**。

| 操作 | 原子需求 | Metal | Vulkan |
|---|---|---|---|
| 块分配（哈希槽抢占） | **需要**（CAS） | `atomic_compare_exchange_weak` | `atomicCompareExchangeWeak` |
| S/W/C 更新 | **不需要**（每体素单写者） | — | — |
| 法向图生成 | **不需要**（逐像素独立） | — | — |
| 归一化与统计 | **不需要**（逐体素独立） | — | — |

**定点化的唯一用途**：块分配时的哈希槽状态标记（`EMPTY`/`CLAIMED`/`READY`），用 `atomic_uint` 即可，无精度问题。

**如果将来改用点云式（point-centric）**，则需要定点化方案，预留如下（**本分支不采用，仅作设计备案**）：

```
定点标度：  TSDF  t_fixed = round(t · 2²²)      t ∈ [−1,1] → ±4 194 304
            权重  w_fixed = round(w · 2¹⁶)      w ≤ 8    → ≤ 524 288
            颜色  c_fixed = round(c · 2¹⁶)      c ∈ [0,1] → ≤ 65 536

溢出分析（点云式，单帧单体素最多累积 M 个样本）：
    M 的上界 = 一个体素在单帧内被多少深度像素的射线穿过。
    对 h_voxel = 2 mm、f_d = 520 px、Z = 0.35 m 的工况，
    单个深度像素在物体表面的覆盖面积为 (h·f/Z)² = (0.002×520/0.35)² = 8.8 像素²；
    一个体素在深度图上的投影面积为 (2h·f/Z)² = 35.3 像素²，
    故单帧单体素的样本数上界 M ≈ 35 / 8.8 ≈ 4（保守取 8）。
    |S_fixed| ≤ 8 × 8 × 4 194 304 = 2.68e8  < 2³¹ = 2.15e9   ✓
    |W_fixed| ≤ 8 × 8 × 65 536      = 4.19e6  < 2³¹          ✓
    颜色每通道独立累加，同样 ≤ 4.19e6                             ✓
    ⚠ 若改用 h_voxel = 0.5 mm 且 Z 更近，M 会显著上升（∝ 1/h²），
      届时必须改用两级缓冲（单帧定点累加 → 归约为 float32 持久累加器）
      或改回体素中心式。
```

### 4.7 TSDF 与 MVS 的职责边界与贡献权重策略

这是 00 §4.2 关键工程决策的**落地章节**，也是本分支最容易做错的地方。

#### 4.7.1 职责边界表

| 职责 | 承担者 | 权重/参数 | 硬性规定 |
|---|---|---|---|
| **曲面几何（主）** | **MVS**（05 §5，共用代码） | `rgbd_mvs_fusion_weight`（快/标/高 = 0.6/0.75/0.9） | 在 **MVS 有效区**，TSDF/深度**位置权重恒为 0**。深度点**不得**进入 MVS 有效区的点云 |
| **低纹理/失效区几何** | **TSDF 补盲通道** | `1 − rgbd_mvs_fusion_weight` × `C_tsdf` | 仅在 MVS 失效区注入（§6.4） |
| **融合去噪** | **TSDF**（主网格，role = 2 源） | `w_i` | 提供多帧融合后的深度估计，作为补盲点的来源 |
| **几何先验** | **TSDF**（先验网格，role = 1 源） | `w_i`（LiDAR 相对权重 0.028） | 参与 §5.5 全局优化中的深度先验项，**权重极低**，只做"不能完全无视"的软约束 |
| **尺度锚定** | **深度（帧对 ICP 的平移量）** | §5.4 | 深度边的**长度**就是米制，尺度自由度被消除 |
| **颜色** | **RGB**（06 §2.9 烘焙） | — | TSDF 颜色仅作低频底色 |

#### 4.7.2 权重策略的数值化

`rgbd_mvs_fusion_weight`（`w_mvs`）在最终点云中的体现：

```
点云来源仲裁（逐像素/逐表面点）：
    MVS 有效（C_mvs ≥ rgbd_hole_fill_mvs_conf_max）
        →  该点来自 MVS，权重 = w_mvs · C_mvs
        →  TSDF 点在此区权重 = 0（不注入）

    MVS 失效（C_mvs < rgbd_hole_fill_mvs_conf_max，或该像素无 MVS 深度）
        →  该点来自 TSDF，权重 = (1 − w_mvs) · C_tsdf
        →  其中 C_tsdf = 补盲点的 TSDF 置信度（由 W(v)、σ_S(v)、来源角色共同决定）
```

**为什么是"互斥仲裁"而不是"加权平均"**：这是本分支最关键的设计决策，理由如下：

| 若采用加权平均 | 后果 |
|---|---|
| MVS 点（误差 0.17 mm，权重 0.75）与深度点（误差 12 mm，权重 0.25）在同一位置平均 | 合成误差 ≈ `√((0.75×0.17)² + (0.25×12)²)` ≈ **3.0 mm**，比纯 MVS 差 **17 倍** |
| 且该误差是**系统性**的（LiDAR 偏差不随帧数衰减），无法被多帧融合抵消 | 违反 00 §8.3 "稠密重建精度上限由 MVS 决定" |

> **结论**：深度点与 MVS 点**不得在同一位置做位置平均**。深度只在 MVS 无覆盖处**接管**几何。这是 00 §4.2 "LiDAR 深度只用于 ①尺度锚定 ②TSDF 几何先验 ③低纹理区补全" 的唯一自洽实现。

**`rgbd_mvs_fusion_weight` 的实际作用**：控制**补盲区点云在泊松中的相对权重**。
- `w_mvs = 0.9`（高）→ 补盲点权重 0.1 → 泊松在补盲区更倾向于外推 MVS 的边界（即更保守、更接近推断）
- `w_mvs = 0.6`（快）→ 补盲点权重 0.4 → 泊松更信任深度提供的补盲几何

> 该参数**不改变** MVS 有效区的任何几何（那里深度权重恒为 0），**不改变**最终曲面的精度上限（00 §8.3），只改变**补盲区与推断区的边界位置**。

#### 4.7.3 与 06 §1.5 的对接

06 §1.5 把 Marching Cubes（TSDF 等值面）列为**辅路径**："仅在 RGBD 分支作为 TSDF 先验网格参与全局优化，不作为最终产物"。本分支的落地：

| 06 的表述 | 本分支的落地 |
|---|---|
| TSDF 先验网格参与全局优化 | §5.5 的全局优化含深度先验项（权重来自 §2.4.4 的 `w_i`，极低） |
| 不作为最终产物 | 最终曲面 100% 来自 MVS 深度 + 泊松；TSDF 等值面**不提取为最终网格** |
| TSDF 的补盲用途 | 补盲点从 TSDF 的**零交叉体素**提取（§6.4），作为点云的一部分进入 06 §2.1 的 S0 |

> **零交叉点的提取方式**：不用 Marching Cubes（会生成三角形网格，与"点云输入泊松"的流程不匹配），改用**体素零交叉 + 三线性插值定位**：对体素 `(i,j,k)`，检查 12 条棱上的 TSDF 符号变化，符号变化处用线性插值定位等值面点，法向取 TSDF 梯度（`∇TSDF`，中心差分），颜色取 §4.5 的累加颜色，权重取 §6.4 的补盲权重。

## 5. RGBD 里程计与全局优化

### 5.1 帧对 ICP（深度图对深度图）

#### 5.1.1 为什么用"深度图对深度图"而不是"点云对点云"

| 方案 | 数据关联方式 | 特点 |
|---|---|---|
| **点云对点云 ICP** | 需要显式最近邻搜索 | 需建 kd-tree；大场景下慢；在低纹理区因深度噪声导致错误关联 |
| **深度图对深度图 ICP**（本分支采用） | **直接利用像素网格**：把帧 `t` 的深度反投影为点，投影到帧 `t−1` 的像平面，读取该处的深度值 | ① 免去最近邻搜索（关联是 O(1) 的双线性/最近邻采样）；② 天然利用**深度图的规则结构**；③ 每个像素都有对应点，关联密度高 |

这是 RGB-D 里程计的经典做法（如 Depth-ICP / RGBD-odometry 系列），在纹理缺失时依然可用——**这正是深度通道的价值所在**。

#### 5.1.2 残差定义（射线空间，RA-2）

设帧 `t` 与 `t−1` 的相对位姿 `T_rel = (R, t)`（把帧 `t−1` 的相机系变换到帧 `t` 的相机系）。

```
① 帧 t 的像素 p（有效深度 d_t(p)）反投影：
     x = (p_u − c_x)/f_x ,  y = (p_v − c_y)/f_y
     P_t = d_t(p) · (x, y, 1)ᵀ                    （相机系 t，轴向深度，RA-1）

② 变换到帧 t−1 的相机系：
     P_{t−1} = R · P_t + t

③ 投影到帧 t−1 的像平面：
     若 P_{t−1}.z ≤ 0 → 跳过
     q = ( f_x · P_{t−1}.x/P_{t−1}.z + c_x ,  f_y · P_{t−1}.y/P_{t−1}.z + c_y )
     若 q 越界 → 跳过

④ 读取帧 t−1 在 q 处的深度 d_{t−1}(q)（双线性插值；越界或无效 → 跳过）
     反投影得到对应点：
     P'_{t−1} = d_{t−1}(q) · ( (q_u−c_x)/f_x , (q_v−c_y)/f_y , 1 )ᵀ

⑤ 法向：帧 t−1 在 q 处的局部平面法向 n（§4.3.5）

⑥ 点到面残差（射线空间的三维欧氏量）：
     r = nᵀ · ( P_t − P'_{t−1} )
```

**点—点残差（补充通道）**：

```
     r_pp = P_t − P'_{t−1}   ∈ ℝ³
```

#### 5.1.3 点—面为主、点—点为辅的理由

| 项 | 点—面 | 点—点 |
|---|---|---|
| 对**法向方向**的约束 | 强（直接沿法向） | 弱 |
| 对**切向**的约束 | 无（切向滑动不产生残差） | 有 |
| 对深度的依赖 | 只需法向（来自局部平面拟合，比深度本身更平滑） | 需精确的三维点 |
| 低纹理/大倾角面 | 法向估计不稳 → 需点—点补充 | — |

因此：**主残差点—面，辅以小权重点—点**，权重 `rgbd_icp_point_to_point_weight`（快/标/高 = 0.3/0.3/0.4）。

#### 5.1.4 权重与鲁棒核

```
w_p = w_conf(p) × w_ang(p) × w_geom(p)

w_conf(p) = ρ(C_{t−1}(q))                     帧 t−1 该处的置信度（§2.4.3）
w_ang(p)  = max( |n · d̂_{t−1}| , 0.1 )        入射角因子
w_geom(p) = 1 / (1 + (σ_S(q) / σ_ref)² )      帧 t−1 该体素的融合离散度惩罚
```

鲁棒核：**Huber**，`δ = rgbd_icp_huber_delta_scale × σ_z(tier)`（默认 `k` = 2.5 → ToF `δ` = 5 mm、ALGO `δ` = 27.5 mm、LiDAR `δ` = 30 mm）。

> `δ` 随深度源噪声放大是必要的：`δ` 若固定为 5 mm，在 LiDAR 上会把**所有**观测都判为外点（噪声 12 mm > δ）；若固定为 30 mm，在 ToF 上又会放过真正的外点。

#### 5.1.5 求解与收敛判据

| 项 | 规格 |
|---|---|
| 求解器 | **Gauss–Newton + LM 阻尼**（6 自由度：3 旋转 + 3 平移），自研（`core/rgbd/icp.cpp`）；不用 Ceres——单帧 6 变量的求解开销远大于 Ceres 的初始化与调度开销 |
| 线性化 | 点—面残差对位姿的雅可比 `J = nᵀ · [ −[P_t]ₓ , I ]`（`[·]ₓ` 为反对称矩阵）；点—点残差的雅可比 `J = [ −[P_t]ₓ , I ]` |
| 迭代上限 | `rgbd_icp_max_iterations`（快/标/高 = 12/20/30） |
| 收敛（平移） | `‖Δt‖ < rgbd_icp_convergence_trans`（快/标/高 = 1e-4/1e-5/1e-6 m） |
| 收敛（旋转） | `‖Δθ‖ < rgbd_icp_convergence_rot`（快/标/高 = 1e-4/1e-5/1e-6 rad） |
| 对应点数量下限 | `N_corr ≥ rgbd_icp_min_correspondences`（默认 200）→ 不足则该帧对判定为**退化**，跳过并记录 `W_RGBD_ICP_DEGENERATE` |
| 深度范围 | `[rgbd_icp_min_depth, rgbd_icp_max_depth]`（快/标/高 = 0.08–1.0 / 0.05–1.5 / 0.03–2.0 m），超出范围不参与（抑制背景与远景干扰） |
| 采样步长 | `rgbd_icp_sample_stride`（快/标/高 = 2/1/1），像素级步长；步长 > 1 时按固定网格偏移采样（保证确定性） |

#### 5.1.6 帧对 ICP 的精度量级（**理论下界，需实测**）

对含 `N` 个对应点、目标横向尺度 `L`（物体半宽，米）、深度噪声 `σ_d` 的情形：

```
σ_rot  ≈ σ_d / ( L · sqrt(N) )             （绕垂直于基线轴的旋转）
σ_trans ≈ σ_d / sqrt(N)                   （沿视线方向）
```

代入标档典型值（`σ_d` = 2 mm、`L` = 0.15 m、`N` = 50 000）：

```
σ_rot   ≈ 0.002 / (0.15 × 224) = 5.95e-5 rad = 0.0034°
σ_trans ≈ 0.002 / 224 = 8.9e-6 m = 0.009 mm
```

**这是理论下界**，实际被系统项主导：深度偏差（多径、温漂）、基线外参误差、低纹理区的错误对应、法向估计噪声。**实测值必须显著大于该下界**（§8.1 U-82，容忍 ±50%）。作为对照，05 §6.1.2 第 4 级的位姿旋转残差为 0.02°（BA 后），本分支的帧对 ICP 旋转精度**理论上更好**，但由于缺少 SfM 的全局约束，其**漂移累积更快**——这正是 §5.3 位姿图存在的原因。

### 5.2 与 IMU 的紧耦合

#### 5.2.1 紧耦合结构

帧对 ICP 单独使用会在**旋转**上漂移（深度的旋转可观测性弱：绕光轴的旋转在近似平面上不改变深度）。IMU 提供高频的旋转与平移约束。

```
┌─────────────────────────────────────────────────────────────────────┐
│ 状态（滑窗 N_w = 8 帧）：                                           │
│   帧 t−1 的位姿 T_{t−1} ∈ SE(3)                                     │
│   帧 t   的位姿 T_t     ∈ SE(3)                                     │
│   陀螺零偏 b_g ∈ ℝ³（窗口内共享）                                   │
│   加计零偏 b_a ∈ ℝ³（窗口内共享）                                   │
└─────────────────────────────────────────────────────────────────────┘
残差：
   ① 帧对 ICP 残差（§5.1.2）：r_c，权重 w_p（§5.1.4），Huber δ（§5.1.4）
   ② IMU 预积分残差（02 §3.5 / 05 §3.3）：r_i，9 维
        r_i = [ R_iᵀ(p_{i+1} − p_i − v_i Δt − ½ g Δt²) − Δp̂
                R_iᵀ(v_{i+1} − v_i − g Δt)          − Δv̂
                Log(R_iᵀ R_{i+1} · Exp(−Δθ̂)) ]
        协方差 Σ_i 取 02 §3.5.4 的预积分协方差（**需按 05 §3.3.4 的密度域口径修正**，
        见 §8.3 的回填清单）
   ③ 零偏软先验：r_b = [ b_g ; b_a ]，权重 1/σ_bg²、1/σ_ba²
```

**求解**：Ceres 2.x（BSD-3，`third_party/ceres`），`SPARSE_SCHUR` 关闭（状态维数小，稠密 Schur 更快），`TRUST_REGION` + `LM`，`num_threads = perf_thread_pool_size`（白名单可降级）。数值类型 double。

|---|---|---|
| `rgbd_imu_prior_weight` | 0.5 / 1.0 / 2.0 | IMU 预积分残差的乘性权重 |
| `rgbd_imu_rotation_sigma_deg` | 1.5 / 1.0 / 0.5 | IMU 旋转约束的等效 σ（角点残差的白化尺度） |

#### 5.2.3 与平台位姿先验的关系

ARKit / ARCore 提供的位姿（02 §2.1 `pose_is_metric`）在本分支的处理：

| 项 | 规定 |
|---|---|
| 角色 | **弱先验**，权重远低于 ICP 与 IMU（05 §2.1 的"仅作弱先验（旋转 0.5° 权重）"口径在 RGBD 分支放宽到 `rgbd_platform_prior_weight`） |
| 原因 | 平台位姿在**有 LiDAR/ToF 的设备上**通常质量良好，但其尺度与本分支重建的米制可能有偏差（ALGO_DEPTH 尤其明显），过强先验会把尺度拉偏 |
| 度量检查 | 平台位姿的**平移长度**与深度测距的一致性：`|‖t_platform‖ − ‖t_depth‖| / ‖t_depth‖ > 0.10` → 告警 `W_RGBD_PLATFORM_SCALE_BIAS`，该先验权重降为 1/10 |
| 不可用时 | 无平台位姿（纯 CameraX + ToF 直出）→ 该先验项整体关闭，其余不变 |

### 5.3 位姿图优化与闭环检测

#### 5.3.1 位姿图结构

```
节点：关键帧 i（03 §5.1 产出），位姿 T_i ∈ SE(3)
边：
  ① 帧间边 (i, i+1)：由 §5.1 + §5.2 的滑窗结果给出相对位姿 T_{i,i+1}
       信息矩阵 Ω_ij = Hessian of the residuals（6×6），由 Ceres 输出
  ② 回环边 (i, j)：由 §5.3.3 的闭环验证给出
       信息矩阵 Ω_ij = Hessian × rgbd_loop_info_scale
  ③ 尺度锚定边：见 §5.4
Gauge 固定：
  G-1  第 0 个关键帧的位姿全固定（6 自由度）
  G-2  第 1 个关键帧的旋转固定（3 自由度）
  G-3  剩余 3 个 gauge 自由度由**深度尺度边**固定（§5.4）—— 这是 RGBD 与 MONO
       的关键差异：MONO 由参照物尺度先验固定（05 §4.6.1），RGBD 由深度边固定
```

#### 5.3.2 位姿图目标函数

```
E_pose(T) = Σ_{(i,j) ∈ E_seq}  ρ_o( ‖ r_ij^odom ‖²_{Ω_ij} )
          + Σ_{(i,j) ∈ E_loop} ρ_o( ‖ r_ij^loop ‖²_{Ω_ij} )
          + Σ_{i ∈ W}        w_p · ρ_p( ‖ r_i^plat ‖²_{Σ_p} )
          + w_s · ( (s − 1) / σ_depth )²
```

| 项 | 说明 |
|---|---|
| `r_ij^odom = Log(T_i⁻¹ T_j T_{i,j}⁻¹)` | 帧间边的相对位姿残差（SE(3) 上的对数映射，6 维） |
| `r_ij^loop` | 回环边残差，形式同上 |
| `ρ_o` | Huber（`rgbd_pose_graph_loss`） |
| `w_p` | 平台位姿先验权重（§5.2.3） |
| `w_s`、`σ_depth` | 尺度锚定项（§5.4） |

**尺度自由度**：位姿图中**不设自由尺度变量**。深度边的平移长度本身就是米制，尺度由数据固定（gauge G-3）。`s` 在式中的含义是"**深度尺度的相对偏差**"（相对于深度自身的米制），取值范围受限（`|s − 1| ≤ 0.10`），超限直接触发 §5.4 的复核流程。

#### 5.3.3 闭环检测

| 环节 | 做法 | 与 05 的共享 |
|---|---|---|
| 候选生成 | **DBoW2 词袋**（`third_party/dBow2`，BSD-3）+ LSH 轻量指纹（`sfm_lsh_bits` / `sfm_lsh_hamming`） | **完全共用 05 §4.5.1** |
| 几何验证 | ① 尺度一致性检查（§5.4）：闭环推导出的平移长度必须与深度测距一致，容差 `rgbd_loop_scale_consistency_max`（快/标/高 = 0.08/0.05/0.03）—— **RGBD 分支特有的第一道门槛**，因为深度让尺度变成可观测量，回环若隐含尺度变化，说明有一方的深度有问题；② 深度 ICP 验证（用 §5.1 的帧对 ICP 在回环位姿上算残差中位数，`rgbd_loop_max_reproj_px`）；③ 05 §4.5.2 的重投影验证 | 共享 05 §4.5 的框架 |
| 接受判据 | `median_reproj ≤ rgbd_loop_max_reproj_px`（快/标/高 = 2.5/1.5/1.0 px）且 尺度一致性通过 且 内点数 ≥ `rgbd_loop_min_inliers`（30/50/80） | — |
| 拒绝处置 | **拒绝该回环**，不改尺度，记 `W_RGBD_LOOP_SCALE_INCONSISTENT`；若因尺度被拒的回环数 > 总回环数的 30%，触发 §5.4 的**全局尺度复核** | — |

> **RGBD 分支回环检测的特殊价值**：在 MONO 分支，回环的主要风险是**尺度漂移**（回环把两个不同尺度的子图拉到一起，导致模型被拉伸）；在 RGBD 分支，尺度由深度固定，回环只会修正**位姿漂移**，不会引入尺度错误——**前提是尺度一致性检查被执行**。因此 RGBD 分支的闭环接受率应当**高于** MONO 分支，且接受后的位姿改善更可靠。

### 5.4 尺度锚定机制

#### 5.4.1 三层尺度来源

| 层 | 来源 | 相对不确定度 | 作用 |
|---|---|---|---|
| **L-1 初始** | 深度自带米制（`s = 1`） | ToF 1%–2% / ALGO 2%–5% / LiDAR 厘米级 | 位姿图的 gauge 固定（G-3）；**不是**最终尺度 |
| **L-2 锚定** | 深度边的平移长度在位姿图中的一致性 | 同上 | 保证长程尺度不漂移（尺度漂移被度量的可观测性约束住） |
| **L-3 复核（强制）** | 07 §4 的三重复核 | 0.3%–0.5%（参照物多视角联合） | **最终尺度的唯一达标来源** |

#### 5.4.2 为何仍需参照物复核（引用 07）

07 §1.3 列出了深度设备尺度仍需复核的**六个原因**，全部在本分支成立：

| # | 07 §1.3 的原因 | 在本分支的具体表现 | 本分支的对策 |
|---|---|---|---|
| 1 | 深度与 RGB 的外参标定误差 | 深度重采样到 RGB 平面时基线 `Δb` 标错 → "近处放大 / 远处缩小"，与尺度误差难以区分 | §3.5.5 的基线硬校验 + 07 §4.4 的包围盒比值 |
| 2 | 边缘飞行像素 | 轮廓处深度系统性偏移 | §3.3 剔除（阈值噪声自适应） |
| 3 | 多径与镜面反射 | 局部深度偏大 | §6.4 拒绝注入 + 标注 |
| 4 | 温漂 | 慢速尺度漂移 0.5%–2%/10min | 采集 ≤ 10 min + 采集后立即复核（14 §3.3） |
| 5 | `ALGO_DEPTH` 的绝对偏差 | 尺度虽米制但有 2%–8% 偏差，且继承 IMU 的 5%–10% | **强制**参照物复核，不允许"深度即真值" |
| 6 | 单位/量纲转换错误 | 1000 倍灾难性错误 | §3.1 ① 的语义核验 + 07 §4.4 的包围盒硬校验 |

**结论（必须写入 09 文档与导出元数据）**：

> **深度传感器提供的是"尺度的可观测性"与"尺度的初值"，不是"尺度的真值"。**
> 参照物复核在**全机型**上均为强制步骤（00 §5.2 决策表末行注）。在 `BRANCH_RGBD` 中，深度把尺度误差从 MONO 的 **5%–10%（IMU）**压到 **1%–5%（深度）**，但 00 §4.6 的验收线是 **≤ 1.0%**，因此**仍必须由参照物标定提供最终尺度**。

#### 5.4.3 尺度锚定残差（进入位姿图与全局优化）

```
r_scale = ( s − 1 ) / σ_depth ,   σ_depth = rgbd_scale_anchor_sigma （默认 0.02）
```

| 深度源 | `σ_depth` 的实际取值 | 说明 |
|---|---|---|
| `HW_TOF` | 0.02（2%） | 07 §1.3 表 |
| `ALGO_DEPTH` | 0.05（5%） | 07 §1.3 表（含 IMU 继承误差，取上界） |
| `HW_LIDAR` | 0.10（10%） | 厘米级 @0.3 m 物体的相对量级；仅作弱锚定 |

**残差的物理含义**：`s` 是"重建结果的米制与深度米制之间的相对偏差"。位姿图在优化位姿的同时最小化该项，实质是要求**位姿图的长度与深度测距保持一致**。若位姿图为了闭合而需要拉伸，残差会增大并被压制。

#### 5.4.4 复核流程与触发条件（本分支定义，07 §4 为权威）

```
阶段 1：会话内一致性检查（重建中）
   ① 深度 vs MVS 交叉一致性（07 §4.3）：
        r(x) = (d_mvs(x) − d_hw(x)) / d_hw(x)
        在覆盖率 ≥ rgbd_depth_mvs_consistency_min（0.40）的区域内统计：
            median(r)  > 0.03  → 告警 W_RGBD_DEPTH_MVS_MEDIAN_BIAS
            std(r)     > 0.05  → 告警 W_RGBD_DEPTH_INCONSISTENT
            P95(|r|)   > 0.15  → 告警 W_RGBD_DEPTH_INCONSISTENT
   ② 包围盒合理性（07 §4.4，硬校验）：
        重建包围盒与深度直接测得的包围盒比值 |ratio − 1| > 0.10 → 告警
        三轴均须 > 1 mm 且 < 100 m，否则 RECON_ERR_CALIB_SCALE_OUT_OF_RANGE
   ③ 跨时间漂移：会话首尾同一区域深度中值 drift > 0.02 → 告警 W_RGBD_DEPTH_DRIFT

阶段 2：采集后立即复核（07 §4.2，强制）
   参照物反向验证：|δ| ≤ 0.02 通过；0.02~0.05 可疑；> 0.05 异常
   → 异常时按 07 §5.2 的回退链处置，本分支的动作：
      ① 不改深度、不改位姿（保持几何自洽）
      ② 以参照物标定的尺度为准（07 §3.3 仲裁：手动 > 参照物 > 深度锚定 > IMU）
      ③ 记录 W_CALIB_DEPTH_SCALE_MISMATCH（07 §4.2）
      ④ 在 recon_mesh_info.json 中记录 depth_scale_confidence = "low"
```

#### 5.4.5 尺度重复性

14 §3.3 规定 10 次独立扫描的尺度标准差 ≤ 0.5%。本分支的重复性来源分解：

| 来源 | 对重复性的影响 | 处置 |
|---|---|---|
| 深度温漂 | 0.5%–2%/10min，**直接超 0.5% 的验收线** | 采集 ≤ 10 min；复核在采集后立即执行；用参照物复核的尺度（0.3%–0.5%）而非深度原值作为最终尺度 |
| 深度随机噪声 | 深度尺度是**单次测量**，不随帧数平均（尺度是全局量） | 不可通过多帧平均消除 → 必须靠参照物 |
| 参照物标定本身的重复性 | 卡片检测稳定性（05 §6.3 FM-2） | 与 MONO 分支完全相同 |

> **诚实结论**：本分支的**尺度重复性并不优于** MONO 分支，甚至因温漂而更差。05 §6.2.1 已指出"MONO 优于 RGBD（无温漂项）"。**两分支最终都靠参照物标定，故最终口径相同。**

### 5.5 全局优化目标函数（完整）

#### 5.5.1 优化变量

| 变量 | 维度 | 参数化 | 说明 |
|---|---|---|---|
| 关键帧位姿 `T_i` | 6 / 关键帧 | `R_i` 四元数 + `ceres::Manifold`；`t_i` 加性 | 全部关键帧参与（R-PREC-3） |
| 3D 点 `X_j` | 3 | 加性 | 满足 `sfm_min_track_length` 的稀疏点（与 05 共用） |
| 陀螺零偏 `b_g` | 3 | 加性 | 全局共享（与 05 §4.6.1 的"BA 中零偏必须逐帧"**不同**——本分支的 BA 复用 VIO 的全局零偏估计，故只需一组） |
| 加计零偏 `b_a` | 3 | 加性 | 同上 |
| 重力 `g_W` | 3 | 加性 + 软约束 | 与 05 §3.2.3 一致 |
| 深度尺度偏差 `s` | 1 | `s = exp(σ)` | 见 §5.3.2 的说明，范围受限 |

**Gauge 固定**：G-1（第 0 帧位姿）、G-2（第 1 帧旋转）、G-3（深度尺度边）。

#### 5.5.2 目标函数（完整形式）

```
E(X) =  Σ_{(i,j) ∈ Ω_sparse}  w_v · ρ_v( ‖ r^v_{ij} ‖²_{Σv} )        ← 稀疏视觉重投影（05 §4.6.2.1）
      + Σ_{i ∈ W}             w_i · ρ_i( ‖ r^i_i ‖²_{Σi} )              ← IMU 预积分（05 §4.6.2.2）
      + Σ_{(i,j) ∈ Ω_dense}   w_d · ρ_d( ‖ r^d_{ij} ‖²_{Σd} )          ← 深度一致性（新增，见 §5.5.3）
      + Σ_{(i,j) ∈ Ω_seq}      w_o · ρ_o( ‖ r^o_{ij} ‖²_{Ω_ij} )       ← 帧对 ICP 相对位姿因子（新增）
      + Σ_{(i,j) ∈ Ω_loop}     w_l · ρ_l( ‖ r^l_{ij} ‖²_{Ω_ij} )       ← 回环因子
      + Σ_{i ∈ W}             w_p · ρ_p( ‖ r^p_i ‖²_{Σp} )              ← 平台位姿弱先验（§5.2.3）
      + w_s · ( (s − 1) / σ_depth )²                                  ← 深度尺度锚定（§5.4.3）
      + w_g · ( ‖g_W‖ − 9.80665 )²                                    ← 重力
      + w_b · ( ‖b_g‖²/σ_bg² + ‖b_a‖²/σ_ba² )                        ← 零偏弱先验
```

#### 5.5.3 深度一致性因子 `r^d_{ij}`（本分支新增）

```
r^d_{ij} = ( Z_d(i, j) − Z_mvs(i, j) ) / Z_mvs(i, j)
```

| 项 | 规格 |
|---|---|
| `Z_d(i,j)` | 关键帧 `i` 的深度（原生分辨率，轴向）经位姿 `T_i` 变换到世界系后，在关键帧 `j` 的视线方向上的投影距离 |
| `Z_mvs(i,j)` | 关键帧 `j` 的 MVS 深度图给出的对应距离（05 §5.10） |
| `Σ_d` | `σ_d² I`，`σ_d = rgbd_depth_consistency_sigma`（快/标/高 = 0.05/0.03/0.02，相对量） |
| `w_d` | `rgbd_depth_consistency_weight`（快/标/高 = 0.2/0.5/1.0） |
| `ρ_d` | Huber，`δ = 2.0`（白化后） |
| 有效区域 | 仅在 **MVS 有效**（`C_mvs ≥ rgbd_hole_fill_mvs_conf_max`）且深度**有效**的像素上计算——**MVS 失效区不算该因子**（那里深度才是权威） |

**因子的作用机理**：

| 作用 | 说明 |
|---|---|
| 把尺度/外参误差暴露到优化里 | 若深度与 MVS 系统性偏离 5%，该因子会推动位姿向"让两者一致"的方向移动，从而**把深度的尺度偏差转化为可观测的位姿调整**，进而被 §5.4 的复核捕获 |
| 抑制位姿的深度方向漂移 | 深度对**沿视线方向**的平移极其敏感（`δZ ≈ δt·cosθ`），是比 RGB 更强的平移约束 |
| 不主导几何 | `w_d` 远小于视觉项（`w_v = 1/σ_v²`，`σ_v` = 0.8 px → `w_v ≈ 1.56`；`w_d ≈ 0.5`，且该因子数量远少于视觉观测） |

> **为什么权重不能太大**：深度的绝对精度（LiDAR 12 mm、ALGO 11 mm）远低于 MVS（0.17 mm）。若 `w_d` 与 `w_v` 同量级，优化会把 MVS 深度拉向厘米级的深度测量，**直接把 05 文档辛苦建立的 0.17 mm 曲面精度毁掉**。这是本分支最危险的参数，`rgbd_depth_consistency_weight` 默认 0.5（标档）已经偏保守，**高档 1.0 仍比视觉项小一个数量级**。

## 6. 精度保障与失败诊断

### 6.1 精度预算表

#### 6.1.1 误差分级与口径

本分支沿用 05 §6.1.1 的三级口径（**不可混用**）：

| 级别 | 名称 | 定义 | 度量方式 | 对应 00 §4.6 验收项 |
|---|---|---|---|---|
| L-A | **形状误差** | 曲面相对于真实形状的偏差（已扣除全局尺度与刚体变换） | 与高精度参考（激光扫描 / CMMS）比对，扣除最佳拟合相似变换后的 RMS 偏差 | "相对几何误差" |
| L-B | **尺度误差** | 整体尺寸的相对偏差 | 与参照物真值比对 | "尺度相对误差 ≤ 1.0%"、"尺度重复性 ≤ 0.5%" |
| L-C | **局部噪声** | 单点深度的不确定度 | 深度图自身的方差 | 无直接验收项，由 L-A 吸收 |

| 机制 | 定量 |
|---|---|
| 深度点**不注入** MVS 有效区 | §4.7.2 的互斥仲裁：该区 TSDF 权重恒为 0 |
| 深度一致性因子只影响**位姿**，不影响曲面 | `w_d` 比视觉项小一个数量级（§5.5.3），其作用是把尺度偏差暴露到 §5.4 的复核，而非改动曲面 |
| 深度对位姿的约束不引入新的曲面偏差 | 位姿精度的改善只体现在第 4/5 级（位姿误差）的**取值**上，不新增误差项 |

> **第 4/5 级取"与 05 相同"的理由**：本分支的位姿估计虽与 MONO 不同（帧对 ICP + 位姿图 vs VIO + BA），但**全局优化后的位姿精度指标口径必须相同**——00 §4.6 的验收项是"对称面重投影中位数 ≤ 0.5 px"，它约束的是**优化后的自洽性**，而不是估计器的类型。若本分支的位姿精度显著优于 05，则 05 的第 4 级应被复核；反之若显著更差，则本分支不达标。**因此第 4/5 级按"同一验收口径下的目标值"取相同数值**，并由 14 文档的实测回填（§8.1 U-85）。
>
> 若实测显示 RGBD 分支的位姿旋转残差为 0.01°（优于 05 的 0.02°），第 4 级贡献降为 0.025 mm，总计降至 **0.146 mm**；这是**允许的**（更优），但**不得**据此声称"RGBD 曲面精度更高"——该差异（0.025 mm）在 0.5 px 验收口径（隐含 0.070 mm 深度上限）下不可区分。

**结论（标准档，MVS 主导区）**：

```
L-A 形状误差 ≈ 0.171 mm RMS（强纹理区域）   ← 与 05 §6.1.2 完全相同
             ≈ 0.25 – 0.45 mm（中等到弱纹理区域，δd 劣化到 0.25 px 时）  ← 同 05
```

### 6.2 与 MONO 分支的精度对齐论证

#### 6.2.1 00 §4.6 七项验收的逐项对照

| 验收项（00 §4.6） | 指标 | RGBD 分支的达成路径 | MONO 分支的达成路径 | 对齐性 |
|---|---|---|---|---|
| **相对几何误差** | 对称面重投影中位数 ≤ 0.5 px | 位姿图 + 全局 BA（含深度一致性因子）；对称面**必须由 MVS 深度构造**——用硬件深度构造时噪声 12 mm ÷ 0.14 mm/px ≈ 86 px，**必然不达标** | 稀疏点由 BA 统一优化，对称面重投影中位数可做到 ≤ 0.5 px | **对齐**（前提：对称面用 MVS 深度，与 05 §6.2.1 的同一前提） |
| **尺度相对误差** | ≤ 1.0% | 深度锚定 + **强制参照物复核**（07 §4），多视角联合路径 0.79% | 参照物多视角联合标定，1.04% | **对齐**（均为参照物口径；RGBD 略优 0.25 个百分点） |
| **尺度重复性** | 10 次扫描标准差 ≤ 0.5% | 深度温漂 0.5%–2%/10min 是**本分支的劣势项**；采集 ≤ 10 min + 采集后立即复核 + 参照物复核的尺度 | 参照物标定的重复性取决于卡片检测稳定性 | **MONO 优于 RGBD**（无温漂项）——与 05 §6.2.1 一致 |
| **拓扑完整性** | 非流形边数 = 0 | 06 共享；补盲区点云权重已下调，不制造新的非流形 | 06 共享 | **对齐** |
| **拓扑完整性** | 孔洞面积占比 ≤ 0.05% | **RGBD 优于 MONO**（唯一净优势项）：低纹理区由深度提供真实几何（2.5–9.5 mm），MONO 靠泊松外推（不可量化） | 弱纹理区孔洞依赖泊松外推 → 需引导补光 | **RGBD 优于 MONO** |
| **网格分辨率** | 泊松等效半径 ≤ 体素边长 | 06 §1.4 的 8× 关系（体素 0.5–4 mm）；口径分歧见 §6.2.4 | 无 TSDF 体素，改为"MVS 点云等效间距" | **口径需统一**（见 §6.2.4） |
| **导出可用性** | 零错误 | 06/10 共用导出校验器 | 同左 | **对齐** |

#### 6.2.2 "带深度不降级"的量化依据（四条论证）

**论证 1：曲面精度由 MVS 决定，两分支共用同一份代码**

| 指标 | RGBD（LiDAR） | RGBD（ToF） | RGBD（ALGO） | MONO |
|---|---|---|---|---|
| **深度/曲面误差（源）** | 10–30 mm | 2–8 mm | 3.7%（≈11 mm @0.35 m） | — |
| **MVS 曲面误差（两分支共同的上限）** | 0.12–0.17 mm | 0.12–0.17 mm | 0.12–0.17 mm | 0.12–0.17 mm |
| **MVS 主导区实际曲面误差** | **0.171 mm** | **0.171 mm** | **0.171 mm** | **0.171 mm** |
| **补盲区实际曲面误差** | 9.45 mm | **2.47 mm** | 5.45 mm | **不可量化**（泊松外推） |

**数值来源**：00 §8.1（ARKit sceneDepth 厘米级）、00 §8.2（ToF 2–8 mm）、00 §8.8（MVS 0.2–0.5 mm）、本文 §6.1.2（0.171 mm）、本文 §6.1.3（补盲区）。

**结论**：两分支在 **MVS 主导区**的最终曲面误差由**同一份 MVS 代码 + 同一组 MVS 参数**决定，**因此相等**（§6.1.2 的第 0–13 级逐级相同，BUD-5 强制）。深度传感器的精度**不进入** MVS 主导区的曲面误差——这是 00 §4.2 关键工程决策的直接后果。**唯一的差异区域是补盲区**，且差异方向对 RGBD 有利。

**论证 2：验收口径完全共用**

00 §4.6 明文："两条分支共用同一套验收指标，任一分支达不到即判定为缺陷，不得以机型差异为由豁免。"本分支逐项落实（§1.2），且**没有一项依赖"有深度帧"**（唯一依赖深度的两项——孔洞面积占比与拓扑稳健性——都是 RGBD **更优**的方向）。

**论证 3：唯一劣势项有明确的工程解法，且劣势范围可界定**

| 劣势项 | 差距 | 解法 | 剩余风险 |
|---|---|---|---|
| **尺度重复性**（温漂） | 深度温漂 0.5%–2%/10min vs MONO 无此项 | ① 每条用例采集 ≤ 10 min（14 §3.3 已规定）；② 复核在采集结束后**立即**执行；③ 最终尺度取参照物复核值（0.35%–1.04%），不取深度原值 | 若用户在 10 min 内连续扫描 10 次且每张都独立复核，重复性受参照物标定支配（与 MONO 相同）；若不复核，**超标** |
| **补盲区标注负担** | 补盲区是推断区，需标注 | §6.4 的区域标注机制（与 06 §1.6.2 的泊松外推区标注同源） | UI 需展示补盲区占比（09 U-07） |

这是**能力边界**（00 §4.5.5 已列明），不是能力分级。

**论证 4：尺度口径统一，不存在"有深度 = 有尺度"**

| 尺度来源 | 相对不确定度 | 达标 |
|---|---|---|
| IMU/VIO 尺度先验 | 5%–10% | ✗（仅作初值与交叉校验） |
| **深度自带米制** | 1%–5%（ToF 最好） | ✗（**不达标**——见 §6.1.5） |
| **参照物多视角联合标定** | **0.35%–1.04%** | ✓（达标来源） |

**参照物标定是全机型统一的尺度来源**（00 §5.2 决策表末行注："两条分支的尺度均须经参照物复核"）。在尺度维度上，RGBD **不比** MONO 差。

#### 6.2.3 论证的边界（不夸大）

| 不可声称的内容 | 原因 |
|---|---|
| "RGBD 在所有场景都优于 MONO" | 尺度重复性上 MONO 更优（无温漂）；补盲区的标注负担更重 |
| "深度传感器提供了绝对精准尺度" | §6.1.5 算出 1.71%–2.02%，超 1.0% 验收线；00 §4.5.2 / 07 §1.3 一致 |
| "TSDF 网格的精度就是模型精度" | 00 §8.3：稠密重建精度上限由 MVS 决定，不由 TSDF 决定 |
| "带 LiDAR 的机型精度更高" | §6.2.2 论证 1：MVS 主导区的曲面误差两分支**相同** |
| "补盲区的几何是精确的" | 补盲区误差 2.5–9.5 mm，是 MVS 主导区的 15–55 倍；**必须标注为推断区** |
| "ALGO_DEPTH 的精度与 LiDAR 相当" | §2.2：ALGO 相对误差 2%–5% 且继承 IMU 的 5%–10%；LiDAR 为厘米级但不受距离影响 |
| "两分支的几何可以逐点完全一致" | 14 §3.6 的 IT-9 给出的是"对齐后差值 ≤ 0.05 mm"，不是逐点相同；且位姿估计器不同，必然有亚 0.1 mm 的差异 |

#### 6.2.4 网格分辨率口径的分歧与建议（**需回填 06 / 14**）

**分歧陈述**：

| 来源 | 口径 |
|---|---|
| 00 §4.6 | "泊松等效半径 ≤ **体素边长**"（`r_mesh ≤ h_voxel`） |
| 06 §1.4 | 解释为**更严格的 8×**：`r_mesh = h_voxel / 8`；MONO 分支换算为 `r_mesh ≤ h_mvs / 8` |
| 14 §3.5 | 给出**两条独立规则**：① 实测等效半径 ≤ `h_ref/8 × 1.2`；② 参数一致性（推导关系正确即可，不强制 `D` 等于推导值） |

**问题的实质**：06 §1.4 的 8× 绑定，其物理理由是"泊松网格分辨率必须比 **TSDF 体素**细 8 倍，否则网格会继承体素阶梯（staircase）误差"。这条理由**在 MONO 分支不成立**（无 TSDF），在 **RGBD 分支也不完全成立**——因为 00 §4.2 已确定"最终网格由 MVS 深度主导"，**网格继承的是 MVS 点云的采样误差（0.14 mm @4K/0.35 m），不是 TSDF 的体素阶梯**。

**本分支的建议（需 06 §1.4 与 14 §3.5 回填）**：

```
RGBD 分支的 h_ref 应与 MONO 分支统一：
    h_ref(RGBD) = h_ref(MONO) = MVS 点云等效间距 = Z_mean / f_px × 1 px
理由：两分支的最终几何都由 MVS 产生，网格分辨率的约束来源相同。
TSDF 体素边长的约束应改为作用于「TSDF 自身的贡献量」，
即：TSDF 补盲点的位置误差 ≤ h_voxel / 2（保证补盲点不引入体素阶梯），
而不是约束最终网格的分辨率。
```

**当前的执行口径（本文不改写 06/14 的权威表述）**：

| 项 | 本文的执行 |
|---|---|
| 参数一致性 | `rgbd_tsdf_voxel_size` 与 `mesh_poisson_depth` 的推导关系按 06 §1.4 的 `from_voxel` 模式校验，`mesh_poisson_depth_effective` 必须满足 `r ≤ h_voxel/8` 的推导关系 |
| 实测半径 | 按 14 §3.5 规则 1：`r_mesh ≤ h_ref/8 × 1.2` |
| `mesh_poisson_depth_mode` 的建议取值 | **`literal`**（默认，08 G7）——避免 `from_voxel` 在 `L_max` = 1.0 m、`h_voxel` = 0.5 mm 时推导 `D = 15`（超 `mesh_poisson_depth_max` = 14） |
| 分歧的处置 | 14 §3.5 已用两条独立规则消解字面冲突，**不阻塞验收**。本条的物理口径建议记录在 §8.3 的回填清单中，由 06/14 文档的作者裁决 |

### 6.4 低纹理与反光区：深度可用但 MVS 弱 → 融合策略

这是本分支**唯一的能力优势区**，也是最容易做错的地方（做错会导致 3 mm 的深度点污染 0.17 mm 的 MVS 曲面）。

#### 6.4.1 MVS 失效的判据

| 判据 | 阈值 | 来源 |
|---|---|---|
| 逐像素 MVS 置信度 | `C_mvs(p) < rgbd_hole_fill_mvs_conf_max`（快/标/高 = 0.35/0.30/0.25） | 05 §5.10 的 `C_r` |
| 该像素无有效 MVS 深度 | `D_mvs(p)` 为 NaN | 05 §5.10 |
| 几何一致性未通过 | `N_support < mvs_min_view_consistency` | 05 §5.5.4 |

#### 6.4.2 补盲点云的生成

```
对每个被判为 MVS 失效的像素 p：
  ① 在 TSDF 主网格 / 先验网格中定位对应的体素 v
     （把该深度像素反投影为 3D 点，用 §2.3.3 的公式，再查最近体素）
  ② 检查体素有效性：
       W(v) ≥ rgbd_tsdf_min_weight
       σ_S(v) ≤ rgbd_tsdf_dispersion_max
       N_support(v) ≥ rgbd_tsdf_min_views
     不满足 → 该像素不产生补盲点（留洞，由泊松外推并标注）
  ③ 取体素的零交叉点（沿 12 条棱线性插值定位）
  ④ 法向 = TSDF 梯度 ∇TSDF（中心差分）
  ⑤ 颜色 = §4.5 的累加颜色（低频底色）
  ⑥ 权重：
       w_hole = (1 − rgbd_mvs_fusion_weight) · C_tsdf(v) · rgbd_hole_fill_depth_weight_scale
       C_tsdf(v) = clamp( W(v) / rgbd_tsdf_confidence_ref , 0 , 1 ) × (1 − min(1, σ_S(v)/rgbd_tsdf_dispersion_max))
  ⑦ 写入点云，标记 region_kind = "hole_filled"
```

| 参数 | 快/标/高 | 说明 |
|---|---|---|
| `rgbd_hole_fill_mvs_conf_max` | 0.35 / 0.30 / 0.25 | MVS 失效判据 |
| `rgbd_hole_fill_transition_px` | 12 / 12 / 16 | MVS 有效区与补盲区之间的**过渡带宽度**（像素） |
| `rgbd_hole_fill_depth_weight_scale` | 1.0 / 1.0 / 1.0 | 补盲点权重的整体缩放 |
| `rgbd_tsdf_confidence_ref` | 8.0 | 补盲置信度的参考支撑权重（`W` 达到此值即满置信） |
| `rgbd_tsdf_min_weight` | 1.0 | 体素有效性的权重下限 |
| `rgbd_tsdf_min_views` | 2 | 体素有效性的支撑视图数下限 |
| `rgbd_tsdf_dispersion_max` | 0.10 | 体素内加权深度的离散度上限 |

#### 6.4.3 过渡带（避免接缝）

补盲区与 MVS 主导区的边界**不能是硬切换**——否则会出现可见的"台阶"（FM-R14）。采用**线性过渡带**：

```
在过渡带内（宽度 W_t = rgbd_hole_fill_transition_px 像素，围绕判据边界）：
    MVS 点权重   = C_mvs_smooth · w_mvs        （C_mvs_smooth 在带内从 1 线性降到 0）
    补盲点权重  = (1 − C_mvs_smooth) · (1 − w_mvs) · C_tsdf
```

这样在带内**总权重连续**，泊松不会看到台阶。过渡带内的几何**由两者共同决定**，是**推断程度最高的区域**，必须在标注中体现（见 §6.4.4）。

#### 6.4.4 区域标注（三层，与 05 §6.4.3 对齐）

| 层级 | 判据 | 标注内容 | 呈现位置 |
|---|---|---|---|
| **顶点级** | `region_kind = "hole_filled"` 且 `w_hole < 0.5 · w_mvs` | 顶点标记为"深度补全（低置信）" | `recon_mesh_info.json` 的 `hole_fill` 节；导出模型的顶点色 alpha（可选） |
| **区域级** | 补盲区的连通域（按 16×16 网格聚类） | `unreliable_regions[]` 增加 `kind = "low_texture_filled"`（**需回填 03 §6.5.2 枚举**），含 `bbox` / `area_ratio` | 09 U-07 的统计区 + 导出元数据 |
| **推断区级** | 补盲区 + 过渡带 + 泊松外推区（06 §1.6.2） | 全部合并为**推断区**并标注 | 09 U-07 + 03 §7.1 S12 |

> **强制要求（对齐 00 §4.5.4）**：**补盲区与过渡带必须标注为推断区**，无论其置信度多高。这与"底面由泊松外推填补的区域必须标注"是同一条产品义务。补盲区的几何虽然来自**真实传感器测量**（优于泊松外推），但它**不是被直接观测验证过的曲面**（没有多视图一致性确认），因此在产品语义上仍属推断。

#### 6.4.5 置信度不达标的处置链

| 条件 | 处置 |
|---|---|
| 全局 `hole_filled_ratio > 0.40` | 重建成功但 UI 显著提示"较多区域依靠深度补全，细节可能不足"；**建议补光后重拍** |
| `hole_filled_ratio > 0.60` | **提示"请补光或换角度后重拍"**，给出具体低纹理网格的位置（05 §6.4.5 同款口径，但本分支给出具体网格图） |
| 某网格全程低纹理且补盲点也不可信（体素 `W < rgbd_tsdf_min_weight`） | 该网格留洞 → 泊松外推 → 标注为推断区 |
| 反光/透明区的深度点 | **拒绝注入**（`rgbd_reflective_reject_enabled`），该区由 MVS 或泊松外推处理，并标注 |

#### 6.4.6 补盲通道的诚实边界

| 限制 | 说明 |
|---|---|
| 补盲区的精度上限是深度源的精度 | 2.5 mm（ToF）到 9.5 mm（LiDAR），见 §6.1.3 |
| 补盲区**无法**恢复 MVS 也无法恢复的细节 | 若深度也失效（镜面、透明），补盲无效 |
| Tier 1（ALGO_DEPTH）的补盲能力弱 | 低纹理面上 ALGO_DEPTH 本身不精确（00 §8.2），且需设备位移 |
| 补盲区**不参与**最终曲面的精度声明 | 它被标注为推断区，精度声明（0.171 mm）只适用于 MVS 主导区 |
