## 1. 分支定位与能力声明

### 1.1 立场：BRANCH_MONO 是一等精度路径，不是降级兼容版

本文档的第一性立场（与 00 §4.5.1 一致，此处给出工程落地口径）：

> **BRANCH_MONO 与 BRANCH_RGBD 是同一套精度主线的两种尺度来源，不是"高精度版"与"兼容版"。**
> 曲面精度的一阶决定因素是**多视图几何（MVS）的视差精度与像素分辨率**，不是深度传感器的存在与否。
> 深度传感器提供的是**尺度锚定**与**弱纹理区覆盖**两项增益，这两项在本分支由**参照物标定**与**光照引导 + 泊松置信度标注**分别承担。

三条支撑论据（量化口径见 §6）：

| # | 论据 | 量化依据 | 本文位置 |
|---|---|---|---|
| A1 | 曲面误差由 `δZ ∝ Z²/(f·B)·δd` 决定，与是否有深度帧无关 | 手机典型参数下端到端 0.20–0.44 mm，见 §5.1 / §6.1 | §5.1 §6.1 |
| A2 | 深度传感器自身精度低于高质量 MVS | ARKit `sceneDepth` 厘米级；Android ToF 2–8 mm；MVS 端到端 0.2–0.5 mm。相差 **1–2 个数量级** | §1.3 §6.2 |
| A3 | 尺度是**标定问题**而非**传感问题** | 两分支均强制参照物标定（00 §5.2）；尺度相对误差验收口径同为 ≤ 1.0% | §7.1 |

**明确不成立的表述（禁止写入任何对外材料）**：

| 禁止表述 | 原因 |
|---|---|
| "无深度机型为降级模式" | 与 00 §4.5.1 立场冲突 |
| "无深度机型精度较低" | 与 §6.2 量化结果冲突（曲面精度反超） |
| "单目模式仅供预览" | R-PREC-2 禁止任何"预览/低模"默认路径 |
| "无深度模式下不保证尺度" | 尺度由参照物强制标定，验收口径与 RGBD 分支相同 |

### 1.2 §4.6 精度能力矩阵在本分支的逐项落实

00 §4.6 规定：**两条分支共用同一套验收指标，任一分支达不到即判定为缺陷，不得以机型差异为由豁免。** 本分支逐项落实如下：

| 验收项 | 指标（00 §4.6 口径） | 本分支的实现路径 | 关键参数 | 达标判据 | 本文位置 |
|---|---|---|---|---|---|
| 相对几何误差 | 对称面重投影中位数 ≤ **0.5 px** | ① VIO 提供位姿初值与强先验；② 全局 BA 以 0.5 px 级重投影残差为收敛目标；③ MVS 深度反投影到网格后再做一次对称面重投影自检 | `sfm_reprojection_median_max_px`、`sfm_ba_huber_delta`、`sfm_prior_vio_*` | BA 收敛后重投影中位数 ≤ 0.5 px，P95 ≤ 2.0 px | §4.6 §4.8 |
| 尺度相对误差 | 相对参照物真值 ≤ **1.0%** | 参照物标定（07 §2.7 闭式解 + §2.9 多视角联合优化），尺度作为**先验注入** BA₂ | `calib_scale_prior_sigma`、`calib_conf_high_sigma` | `σ_s/s ≤ 0.02` 为高置信；合成后 ≤ 1.0% | §7.2 §7.3 |
| 尺度重复性 | 10 次独立扫描尺度标准差 ≤ **0.5%** | 尺度只由参照物几何决定（不依赖 IMU 尺度、平台深度）；同一张卡片 10 次标定的 `s` 离散度即重复性 | `scale_ref_size_tolerance_mm`、`calib_refine_enabled` | `std(s)/s ≤ 0.005` | §7.3 |
| 拓扑完整性 | 非流形边数 = **0** | 与 06 分支共享泊松 + 修复流水线；本分支提供带法向与置信度的点云，使法向一致性校验可达 | `mesh_input_normal_vote_min_views`、`post_normal_consistency_min` | 0 | §5.10（与 06 对齐） |
| 拓扑完整性 | 未闭合孔洞面积占比 ≤ **0.05%** | 本分支**无深度补全**，孔洞只能靠泊松外推 + 补片；因此强制要求视角覆盖充分（03 §4.6），并对不可达区域强制标注 | `post_hole_area_micro_ratio`、`post_hole_area_small_ratio` | ≤ 0.05% | §5.8 §6.4 |
| 网格分辨率 | 泊松等效半径 ≤ **体素边长** | 本分支无 TSDF 体素，判据等价为：泊松等效半径 ≤ MVS 有效点间距的 1/8（对齐 06 §1.4 的 8× 约束，把"体素边长"替换为"MVS 点云等效体素边长"） | `mesh_poisson_depth`、`mvs_depth_regularization` | `r_mesh ≤ h_mvs/8`，其中 `h_mvs` 由 §6.1 L1 反推 | §5.10（与 06 §1.4 对齐） |
| 导出可用性 | Blender / Maya 打开零错误 | 与 06/10 共用导出校验器，两分支同口径 | `export_check_run` | 零错误 | 本文不重复（06 §4） |

**结论**：本分支在 §4.6 的 7 项验收中，**没有任何一项依赖"有深度帧"**。因此"无深度机型降级"在验收口径上不成立。

### 1.3 已知能力边界（明确写出，不夸大）

以下三类场景是**多视图几何的物理限制**，不是本产品的工程缺陷，也不是"降级"。两分支均受限，但受限方式与表现不同：

| 场景 | 物理机理 | 本分支（MONO）表现 | RGBD 分支表现 | 替代路径 |
|---|---|---|---|---|
| **纯色 / 哑光低纹理物体** | 表面无稳定可匹配特征，视差不可观测 | 强纹理区正常；低纹理区**深度空洞**，由泊松外推填补并标注为推断区 | 深度可用，TSDF 可直接生成几何（但受 §8.1 厘米级限制） | ① 侧向补光制造纹理（§6.4）；② 换角度获取不同的高光/阴影结构；③ 白色哑光卡做纹理参照；④ 分多轮采集不同光照（03 §6.5.3） |
| **镜面 / 高反光材质** | 表面反射**环境**而非自身几何，不同视角看到的环境不同，视差与表面几何**不一致** | 该区域产生**错误几何**（非空洞），必须降权 + 标注 | 同样产生错误几何（LiDAR 打在镜面上返回镜面反射方向的伪距） | **无有效替代路径**。只能：① 改变入射角避开直接光源（03 §6.5.3）；② 漫射环境光；③ 分层采集；④ 标注为不可靠区。**不得用对称性/先验填补**（03 §6.5.4 RS-11） |
| **透明 / 半透明材质** | 光线穿透表面，相机看到的是背景，表面本身几乎不产生可匹配特征 | 该区域**无对应点 → 空洞**（不是错误几何） | 深度图在透明区同样无效（ToF 打在透明物上穿透） | ① 换背景（提高对比）；② 换角度；③ 标注空洞区。空洞由泊松 + 06 §2.5 补片处理 |

**边界的量化口径（写入 09 文档与导出元数据）**：

| 区域类型 | 判定方法 | 面积占比上限 | 超限处置 |
|---|---|---|---|
| 疑似反光区 | 02 §4.5 饱和比 + 过曝连通域 | ≤ 15%（03 §7.1 S13） | 警告："反光区域较多，可能有几何伪影" |
| 疑似透明区 | 多帧特征数稳定但 RANSAC 内点率低且光流残差大（03 §6.5.2 步骤 2） | ≤ 15%（同 S13） | 警告 + 空洞标注 |
| 低纹理区 | 02 §4.6 网格统计，跨帧累计（§6.4.2） | 单网格 ≤ 30%（02 D5） | 网格级 MVS 置信度降权，不拒帧 |

> **诚实声明**：本分支在**纹理充分、非镜面、非透明**的物体上达到与 RGBD 分支同等的曲面精度；在上述三类受限场景中，本分支的受限程度**不低于** RGBD 分支（因为镜面/透明对深度传感器同样无效，而低纹理区本分支缺少 TSDF 补全通道）。这一条必须原样呈现在 09 文档的能力说明中，不得省略。

### 1.4 与 RGBD 分支的共享与分叉

| 环节 | 共享 | 分叉 | 说明 |
|---|---|---|---|
| 特征提取 | 角点检测算子（Shi-Tomasi） | 描述子（SIFT/ORB vs 无） | RGBD 分支用深度做几何验证，不需密集描述子 |
| 位姿估计 | VIO 骨架（MSCKF + IMU 预积分） | RGBD 分支用帧对 ICP + IMU | 两分支 VIO 代码可共用本目录实现，位姿初值来源不同 |
| 稀疏点 | 三角化 + RANSAC | RGBD 分支可直接用深度反投影 | 本分支依赖视差，弱纹理区稀疏点稀疏 |
| 全局 BA | Ceres 框架、鲁棒核、收敛判据 | RGBD 分支的残差含深度项，本分支含 IMU 预积分项 | §4.6 |
| 稠密 MVS | **完全共享**（同一份 `core/mvs/`） | 无 | 00 §8.3：曲面精度由 MVS 决定，两分支共用主线 |
| 网格化 | 完全共享（06） | 无 | 00 §4.4：E 阶段之后完全合流 |
| 尺度来源 | 参照物标定（**两分支都强制**） | RGBD 另有深度锚定做交叉复核 | 00 §5.2 决策表 |

### 2.2 明确的负契约：本分支不需要深度帧

| 项 | 规定 |
|---|---|
| `FramePacket.depth` | 本分支**恒为 `width == 0`**；`depth_tier = kNone`；`depth_confidence` 为空 |
| `cap_depth_enabled` | 在 `BRANCH_MONO` 下**等效置 0**（08 §3.2 L10 精神：分支不适用的参数必须等效失效，不得静默生效） |
| 平台仍送达深度时 | **不读深度像素**（避免带宽与拷贝），直接丢弃并记 `E_CAPTURE_DEPTH_UNAVAIL`（02 §6） |
| `core/rgbd/*` | 在本分支**不实例化**，不申请 TSDF 内存（13 文档据此省出全部 TSDF 预算） |
| 深度相关参数 | `rgbd_*` 全部标记为"当前设备不适用"（09 §3.8.2 不可用参数呈现规则） |
| 与之对应的收益 | 峰值内存中 TSDF 部分（标准档约 1.2 GB，08 §2.4 口径）全部让位给 MVS 的分块与更多视图 |

**这不是"简化"，是"省出的预算用于 MVS 精度"**：本分支把 RGBD 分支用于 TSDF 的显存全部投入 §5.3 的 PatchMatch 分块与 §5.5 的多视图融合，视图数从 7 提升到 8、PatchMatch 迭代从 4 提升到 6。

## 3. 紧耦合 VIO（MSCKF + IMU 预积分）

### 3.1 总体结构

```
每帧 RGB（关键帧 + 非关键帧均参与 VIO）
   │
   ├─► [特征提取]  Shi-Tomasi → 亚像素 refine → 特征池
   │      ▲                                    │
   │      │                                    ▼
   │   [特征补充]（网格空位）            [光流跟踪] 逆组合金字塔 LK
   │                                            │
   │                                            ▼
   └─► [IMU 预积分] ────► [状态预测 propagate] ──┴─► [滑窗优化 MSCKF]
                    ▲                                │
                    │                                ▼
              [IMU 环形缓冲]              [边缘化 marginalize]
                                                     │
                                                     ▼
                                          高频位姿 T_cam→world（米制）
```

| 阶段 | 频率 | 输出 | 耗时目标（标准档，1080p） |
|---|---|---|---|
| 特征提取 + refine | 每帧 | ≤ `vio_feature_count` 特征 | ≤ 8 ms |
| 光流跟踪 | 每帧 | 存活特征 + 新特征 | ≤ 6 ms |
| IMU 预积分 | 每 IMU 采样 | ΔR/Δv/Δp/P | ≤ 0.05 ms/采样 |
| 状态预测 | 每帧 | 滑窗状态推进 | ≤ 0.3 ms |
| MSCKF 优化 | 每帧（或每 2 帧） | 滑窗状态与协方差 | ≤ 12 ms（`vio_max_solver_time_ms`） |
| 边缘化 | 滑窗满时 | 降维后的状态 | ≤ 2 ms |

**实时性约束**：VIO 必须在采集期实时运行（不可后处理），因此单帧总预算 ≤ 33 ms（30 fps）。表中目标合计 28.3 ms，剩余 4.7 ms 留给调度与 I/O。若超时，按 00 §1.2 白名单处理：**只降并行度（`perf_thread_pool_size`）、降金字塔层数用于首轮粗搜、减批大小**；**不得**降低特征点数、迭代次数、RANSAC 阈值（黑名单）。注意：光流金字塔层数在 00 §1.2 白名单中（"稠密匹配的图像金字塔层（仅影响首轮粗搜）"），VIO 光流层数降级会直接损失定位精度，因此**本分支不把 VIO 光流层数列入可降级项**，而把降级压力转移到 MVS 阶段（见 §5.9 的显存分块）。

### 3.2 状态定义

#### 3.2.1 名义状态与误差状态

|---|---|---|---|---|

| `p_i` | 3 | 世界系位置 | m | |

误差状态（15 维，误差定义在**局部切空间**）：

#### 3.2.2 滑窗尺寸与状态维数

| 项 | 快 | 标 | 高 | 说明 |
|---|---|---|---|---|
| 滑窗关键帧数 `K` | 8 | **10** | 12 | `vio_msckf_window_size`（**需回填 08 文档 G3 组**） |
| 状态维数 | 8×9 + 6 = 78 | 10×9 + 6 = 96 | 12×9 + 6 = 114 | 每关键帧 9 维（δθ, δv, δp） |
| 单帧特征数 `N_f` | 200 | 250 | 400 | `vio_feature_count`（08 G3） |
| 特征最少观测帧数 | 3 | 3 | 3 | 少于该值不参与 MSCKF（避免退化三角化） |

> **K 的选择依据**：MSCKF 的零空间维数随观测帧数线性增长（2m−3），K=10 时单特征最多贡献 17 维约束，Schur 补规模可接受；K>12 时滑窗内位姿协方差增长使视觉约束被过度约束的风险上升（协方差正定性问题）。K=10 在 30 fps 下覆盖 0.33 s，对 0.3 m 物体的手持慢速扫描（角速度 ≤ 1 rad/s → 0.33 s 内 19°）足够。

#### 3.2.3 重力状态的处理

| 方案 | 做法 | 优缺点 | 采用 |
|---|---|---|---|
| A | `g_W` 固定为初始化值 | 简单；长期加速度有偏时无法自纠 | ✗ |
| B | `g_W` 为 3 维状态 + 软约束 ‖g_W‖ = 9.80665（权重 1e4） | 可自纠；引入一个可观性弱的方向 | ✓ |

采用方案 B。约束实现：

```
r_g = ( ‖g_W‖ − 9.80665 ) / σ_g ，  σ_g = 1e-3 m/s²
```

`g_W` 的初值由 §3.8 静止段估计给出；静止段结束后 `g_W` 继续被优化，但**静止段内**将其协方差沿重力方向分量强制为 0（避免静止期引入虚假重力不确定度）。

### 3.3 IMU 预积分

#### 3.3.1 记号与归一

记号、右雅可比 `J_r/J_l`、SO(3) 指数/对数映射**全部沿用 02 §3.5.1–§3.5.2**，本文不重复定义。本节只补充 02 未给出的内容：离散化的两阶形式、协方差传播的闭合版本、预积分与 BA 的对接。

约定：`|a_m|` 为比力（含重力反作用），`a_m = R_WI^T (a_W − g_W)`。

#### 3.3.2 一阶（后向欧拉）与二阶（中点）离散化

| 量 | 一阶（后向欧拉） | 二阶（中点，本文采用） |
|---|---|---|
| 角速度 | `ω̃_k = ω_m,k − b_g,k` | `ω̃_k = ½(ω_m,k + ω_m,k+1) − b_g,k` |
| 比力 | `ã_k = a_m,k − b_a,k` | `ã_k = ½(a_m,k + a_m,k+1) − b_a,k` |
| 旋转 | `ΔR_{k+1} = ΔR_k · Exp(ω̃_k Δt)` | 同左，但 `ω̃_k` 取中点 |
| 速度 | `Δv_{k+1} = Δv_k + ΔR_k ã_k Δt` | 同左 |
| 位置 | `Δp_{k+1} = Δp_k + Δv_k Δt + ½ ΔR_k ã_k Δt²` | 同左 |
| `ΔR` 截断误差 | `O(Δt²·‖ω̇‖)` rad | `O(Δt³·‖ω̈‖)` rad |
| `Δv` 截断误差 | `O(Δt²·‖ä‖)` m/s | `O(Δt³·‖ä‖)` m/s |
| `Δp` 截断误差 | `O(Δt³·‖ä‖)` m | `O(Δt⁴·‖ȧ‖)` m |
| 数值算例（200 Hz，‖a‖ = 10 m/s²，1 s 累计） | `Δv` 误差 2.5e-2 m/s → 位移误差 2.5e-2 m | `Δp` 误差 < 1e-6 m |

> 02 §3.5.3 已强制中点法并给出仲裁规则：**若因成本改用一阶，IMU 采样率必须提到 ≥ 400 Hz，否则不允许。** 本文的实现直接采用中点法，不实现一阶分支（避免引入需要 400 Hz 才能成立的隐藏前提）。

#### 3.3.3 噪声离散化（本文为准，含量级校验）

**这一步是全文最容易写反的地方，因此给出完整推导与量级校验表。**

连续时间噪声模型（与 02 §3.5.4 的连续模型一致，密度符号沿用 Allan 方差标定的输出，即 08 文档 `vio_imu_noise_*` / `vio_imu_bias_walk` 的量纲）：

```
ω̃(t) = ω(t) + n_g(t) ,   n_g ~ N(0, σ_g² I)      [rad/s/√Hz]
ã (t) = a (t) + n_a(t) ,   n_a ~ N(0, σ_a² I)      [m/s²/√Hz]
ḃ_g(t) = n_bg(t) ,         n_bg ~ N(0, σ_bg² I)    [rad/s²/√Hz]
ḃ_a(t) = n_ba(t) ,         n_ba ~ N(0, σ_ba² I)    [m/s³/√Hz]
```

**离散化到采样间隔 Δt（关键）**

| 噪声类型 | 连续密度 | 采样时刻 k 的离散方差 | 进入状态协方差的量级 |
|---|---|---|---|
| 陀螺**白噪声** | `σ_g²` | **`σ_g²/Δt`**（Δt 内白噪声带宽 1/(2Δt) 的功率折算） | 角度：`σ_g²·Δt`；姿态（经二阶传播）：`σ_g²·Δt³` |
| 加计**白噪声** | `σ_a²` | **`σ_a²/Δt`** | 速度：`σ_a²·Δt`；位置：`σ_a²·Δt³/4` |
| 陀螺零偏**随机游走** | `σ_bg²` | **`σ_bg²·Δt`** | 角度：`σ_bg²·Δt³`；姿态：`σ_bg²·Δt⁵` |
| 加计零偏**随机游走** | `σ_ba²` | **`σ_ba²·Δt`** | 速度：`σ_ba²·Δt³`；位置：`σ_ba²·Δt⁵/4` |

> **必须记住的两条量级规则**：
> ① **白噪声项 = σ²/Δt**（离散方差随 Δt 减小而**增大**，因为带宽变宽）；
> ② **随机游走项 = σ²·Δt**（离散方差随 Δt 减小而**减小**），它经状态传播后进入角度/速度通道的量级是 **σ²·Δt³**。
> 写反的典型后果：把白噪声写成 σ²·Δt 会让高频 IMU 的协方差被严重低估（Δt = 5 ms 时低估 200 倍），滑窗优化会过度相信视觉约束，表现为位姿在弱纹理段"贴住"漂移的 SfM 结果。

**与 02 §3.5.4 的关系（须回填）**：02 §3.5.4 给出的 `Σ_g,d = (σ_g² + σ_bg²·Δt²)·I` 与 `Σ_a,d = (σ_a² + σ_ba²·Δt²)·I`，其量纲是"速率方差"，其中 `σ_g²` 被当作**采样域**的方差使用，与 08 文档 `vio_imu_noise_gyro`（rad/s/√Hz）的密度量纲不一致；同时 `Σ`（6×6）与 `B`（9×9）维度不闭合。本文给出维度闭合的版本（§3.3.4），并给出换算式：

```
若 02 的 σ_g 被解释为采样域方差 → 等效密度 σ_g,dens = σ_g · √Δt
若 02 的 σ_g 被解释为密度       → 等效采样域方差 σ_g,sample = σ_g²/Δt
本文采用后者（密度为权威），因此 02 §3.5.4 的两个 Σ 表达式应替换为本文 §3.3.4 的 Q_ν。
```

> **需回填 02 文档 §3.5.4**：把 `Σ_g,d` / `Σ_a,d` 改为密度域的 `σ²/Δt` 与 `σ²·Δt` 两项之和。

#### 3.3.4 协方差传播（维度闭合版本）

误差状态 `δ ∈ R^15`，顺序 `[δθ, δv, δp, δb_g, δb_a]`。噪声输入向量 `ν = [n_g (3), n_a (3), w_g (3), w_a (3)] ∈ R^12`。

离散传播（中点法，右扰动）：

```
δθ_{k+1} = (I − [ω̃_k Δt]^×) δθ_k + ½[ω̃_k Δt]^× δb_g,k + ν_θ
δv_{k+1} = δv_k − [ω̃_k Δt]^× δv_k + ½Δt [ã_k]^× δθ_k
            − ½Δt [ã_k]^× δb_a,k + ½Δt² [ã_k]^× δb_g,k + ν_v
δp_{k+1} = δp_k + Δt δv_k − ½Δt² [ω̃_k Δt]^× δp_k
            + ½Δt² [ã_k]^× δθ_k − ½Δt² [ã_k]^× δb_a,k
            + (1/6)Δt³ [ã_k]^× δb_g,k + ν_p
δb_g,k+1  = δb_g,k + ν_bg
δb_a,k+1  = δb_a,k + ν_ba
```

噪声注入项：

```
ν_θ  = −R_WI,k+1 · n_g,k · Δt
ν_v  = −R_WI,k+1 · n_a,k · Δt
ν_p  = −½ R_WI,k+1 · n_a,k · Δt²
ν_bg = w_g,k ,   ν_ba = w_a,k
```

于是 `A`（15×15 状态转移）、`B`（15×12 噪声映射）、`Q_ν`（12×12 噪声协方差）为：

```
Q_ν = blkdiag( (σ_g²/Δt) I₃ , (σ_a²/Δt) I₃ , (σ_bg²·Δt) I₃ , (σ_ba²·Δt) I₃ )
```

`A` 与 `B` 的具体块结构见 `core/vio/preintegration.h::Propagate()`；**必须满足的恒等式（单元测试断言）**：

| 断言 | 期望 |
|---|---|
| `A` 与噪声无关（即噪声只经 `B` 进入） | `∂A/∂ν = 0` |
| `B` 的秩 | `rank(B) = 12`（满秩，噪声通道不冗余） |
| `B` 各块的量纲 | `ν_θ` 行块 = `Δt·R`；`ν_v` 行块 = `Δt·R`；`ν_p` 行块 = `½Δt²·R`；零偏行块 = `I` |
| 协方差半正定 | `P` 的所有特征值 ≥ 0（数值容差 −1e-12） |

传播：

```
P_{k+1} = A P_k Aᵀ + B Q_ν Bᵀ
```

**数值算例**（标准档：`σ_g = 1.5e-3`, `σ_a = 8.0e-2`, `σ_bg = 2.0e-4`, `σ_ba = 2.0e-4`（`vio_imu_bias_walk`），Δt = 5 ms）：

| 量 | 计算 | 结果 |
|---|---|---|
| 陀螺单样本噪声 std | `1.5e-3/√0.005` | 2.12e-2 rad/s（1.22 °/s） |
| 加计单样本噪声 std | `8.0e-2/√0.005` | 1.13 m/s²（0.115 g） |
| 陀螺角误差（1 s 累积，白噪声） | `√(σ_g²·Δt·200)` | 6.0e-3 rad（0.34 °） |
| 加计速度误差（1 s 累积，白噪声） | `√(σ_a²·Δt·200)` | 0.32 m/s |
| 加计速度误差（零偏游走，1 s） | `√(σ_ba²·Δt³·200/3)` | 1.0e-3 m/s |
| 位置误差（1 s，白噪声） | `√(σ_a²·Δt³·200/12)` | 5.8e-3 m |

> 上表给出了**纯 IMU 传播 1 s 的误差下界**。视觉约束必须把角度误差从 0.34° 压到 0.05° 以下，否则轨迹不可用。这是 K=10 滑窗与 KLT 亚像素精度（§3.5）的直接依据。

#### 3.3.5 预积分对零偏的雅可比（BA 因子用）

**规范形式以 02 §3.5.5 的离散递推为准**（本节只做 BA 侧的对接说明）。

BA 因子中**不重新积分**预积分量，而是用五块雅可比对零偏做一阶修正：

```
ΔR̂' = ΔR̂ · Exp( dr_dbg · δb_g )
Δv̂' = Δv̂ + dv_dbg · δb_g + dv_dba · δb_a
Δp̂' = Δp̂ + dp_dbg · δb_g + dp_dba · δb_a
```

五块递推、自洽性与边界条件见 **02 §3.5.5**（同源，不得各写一套）。
记号：`Exp/Log` 为 SO(3) 指数/对数，`J_r(φ)` 为**右雅可比**（02 §3.5.2），
`δb = b_now − b̂`（相对**积分时零偏**的增量）。

**修正为零的恒等性（硬判据）**：当 `δb_g = δb_a = 0` 时，
`ΔR̂' / Δv̂' / Δp̂'` 必须与原预积分量**逐位相同**。

**在 BA 里的用法**：残差 §3.7.2 中的 `Δp̂/Δv̂/ΔR̂` 一律替换为上面的
`Δp̂'/Δv̂'/ΔR̂'`。这样 IMU 残差对零偏 `b_g, b_a` 的偏导才**非零**，
零偏才进入信息矩阵 `H` 的列、才可被优化；否则 `∂r/∂b ≡ 0`，零偏
只能被弱先验拉向零、永远不动（旧实现即此静默失效）。

### 3.5 光流跟踪

#### 3.5.1 算法选择

| 候选 | 精度 | 速度 | 结论 |
|---|---|---|---|
| 稀疏 Lucas-Kanade（金字塔） | 亚像素，但存在 brightness constancy 偏差 | 中 | 采用（作为对照基线） |

> **金字塔层数与最大位移的耦合约束（必须成立）**：最粗层能吸收的最大位移应 ≥ `vio_klt_max_displacement`。若最粗层缩放为 1/2^(L−1)，则可吸收位移 = `2^(L−1) × 残余位移`。标档：L=3 → 最粗层 1/4 缩放，60 px 位移在 level 2 上残余 7.5 px，仍在 21 px 窗口的可行范围内（窗口半径 10 px）。高档 L=4 → 1/8 缩放，45 px → 5.6 px。若设备帧率降至 15 fps（`cap_frame_rate` 下限）导致位移翻倍，则必须提升层数（白名单可降级项，但**只可降不可升的场合必须拒绝该配置并提示**）。

#### 3.5.3 亚像素计算

逆组合 LK 的增量在**模板坐标系**求解并以双线性插值施加到当前帧：

```
Δp = − H⁻¹ · Σ_x w_x · ( I(x) − J(x) ) · ∂W(x; Δp) / ∂Δp |_{Δp=0}
H = Σ_x w_x · ( ∂W/∂Δp )ᵀ ( ∂W/∂Δp )
```

| 约束 | 说明 |
|---|---|
| LK-1 | `H` 的条件数 > 1e10 视为病态 → 判为跟踪失败（用 `vio_klt_min_eig` 判定） |
| LK-2 | 权重窗 `w_x` 取高斯（σ = 窗口半径/2），不做均匀窗 |
| LK-3 | 双线性插值权重 `vio_bilinear_weight`（08 G3）用于梯度插值，保证亚像素一致性 |

#### 3.5.4 双向一致性检查

对每帧做 **forward–backward** 校验：

```
p_f = KLT(I_{k-1} → I_k)         // 前向
p_b = KLT(I_k → I_{k-1})(p_f)    // 后向（在 I_k 上取点，向 I_{k-1} 投影）
e_fb = ‖p_b − p_{k-1}‖
```

`e_fb > vio_klt_fb_threshold` → 该特征判定为跟踪失败，移除。

> 双向检查使跟踪失败率从 ~8% 降到 ~1.5%，其代价是每帧多一次 KLT（约 +40% 跟踪耗时）。在 30 fps 预算内可接受。

|---|---|---|---|

**角点亚像素定位的实现修正**：

| 项目 | 前文描述 | **实测修正** |
|---|---|---|
| 方法 | 逆相关加权最小二乘（cornerSubPix 等价） | **Shi-Tomasi 响应图的十字抛物线插值**（OpenCV refineCorners 同款） |

**为什么不能用 SSD 块匹配做角点精化**（实测）：

SSD 块匹配的目标函数 `min_Δ Σ(I(x+Δ) − I(x))²` 中，
Δ=0 时残差恒为 0 —— **整数模板位置是残差的零点，具有吸引力**，
Newton 迭代必然被拉回整数位置。实测所有精化结果都是 `xxx.0006` 形式
（几乎没动），角点定位误差 1.86 px。

响应图十字插值对等间距三点 f(−1), f(0), f(1) 求抛物线顶点：
```
δ = 0.5·(f(−1) − f(1)) / (f(−1) − 2·f(0) + f(1))
```
不依赖模板、不退化，输出真实的亚像素坐标（实测 124/124 个角点为亚像素值）。

> **精度链的正确理解**（避免误读单环节指标）：
> 角点初始定位（~1 px）只是 KLT 跟踪的**起点**；
> 真正决定几何精度的是跟踪过程中的亚像素收敛。
> 实测：初始定位 0.87 px → KLT 跟踪后 **平均 0.0031 px / 最大 0.102 px**。
> 折算到 MVS 的深度误差（Z=0.35 m、f=2500、B=100 mm）：
> δZ = Z²·δd/(f·B) = 0.35²×0.0031/(2500×0.1) ≈ **1.5 µm**，
> 远优于 §6.1 的 0.074–0.171 mm 预算。

### 3.6 MSCKF 滑窗与零空间构造

#### 3.6.1 残差与雅可比的堆叠

对一个在关键帧 `i_1 … i_m`（m ≥ 3）中均被观测的特征 `f`，令其当前三维估计为 `X_f`（由 §3.6.2 的线性化三角化得到）。

堆叠观测残差与雅可比：

```
r_f = [ π(K_{i_1} X_f) − u_{i_1} ;  π(K_{i_2} X_f) − u_{i_2} ; … ] ∈ R^{2m}
A_f = [ ∂π/∂X (K_{i_1}, X_f) ; … ]                     ∈ R^{2m×3}
```

`A_f` 的每一块为 2×3 的透视投影雅可比：

```
∂π/∂X = (1/z) [ 1  0  −x/z ;  0  1  −y/z ] ,   x = K·X 的第一维, y = 第二维, z = 第三维
```

> 记号约定（与用户要求一致）：下文把 `A_f` 记作**雅可比堆叠矩阵 A**，把 `r_f` 记作**残差堆叠向量 J**。零空间的构造目标即"求解使 `Aᵀ J = 0` 成立的投影算子"。

#### 3.6.2 零空间构造（详细）

**目标**：消去 `X_f`（3 个未知量），把 `2m` 维残差约束压缩为 `2m − 3` 维的、只含位姿的约束。

**步骤 1：构造 3×3 Gram 矩阵**

```
G = Aᵀ A ∈ R^{3×3}      （对称半正定）
```

`G` 的三个特征值 `λ_1 ≥ λ_2 ≥ λ_3 ≥ 0` 度量三维点在三个正交方向上的可观测性。

**步骤 2：奇异值截断判据（决定该特征是否可用）**

| 判据 | 阈值 | 处置 |
|---|---|---|
| `λ_3 / λ_1 < 1e-6` | 三维点在一个方向上几乎不可观（典型情形：所有观测视线近乎共线，即纯前向运动或纯旋转） | **丢弃该特征**，不参与本次更新 |
| `λ_3 / λ_1 < 1e-4` | 病态但可用 | 保留，但该特征的残差权重放大 10 倍（等效正则） |
| 三角化后深度不确定度 `σ_z / z > 0.10` | 深度相对不确定度 > 10% | 丢弃 |
| 视线最大夹角 < 1.5° | 视差不足 | 丢弃（`sfm_triangulation_min_angle_deg` 同值，见 §4.4） |

> **阈值来源**：`λ_3/λ_1` 的物理含义是"最短基线方向上的信噪比"。1e-6 对应深度方向上的相对不确定度 ~1e3，超过该值时三维点位置基本由先验决定，保留会污染 BA。取值需实测标定（§9）。

**步骤 3：求零空间基**

对 `A`（2m×3）做奇异值分解：

```
A = U · Σ · Vᵀ ,   U ∈ R^{2m×2m} ,  Σ = diag(σ_1, σ_2, σ_3, 0, …, 0) ,  V ∈ R^{3×3}
```

其中 `σ_i = √λ_i`。`U` 的第 4 列到第 `2m` 列张成 `null(Aᵀ)`：

```
N_f = [ u_4 , u_5 , … , u_{2m} ] ∈ R^{2m×(2m−3)}
```

**步骤 4：投影**

```
r_f^null = N_fᵀ · J_f ∈ R^{2m−3}
```

此即 MSCKF 的零空间约束：`Aᵀ J_f = 0`（3 个标量方程）被等价地写成 `N_fᵀ J_f = 0`（2m−3 个方程），且与 `X_f` 无关。

**步骤 5：等价实现（避免完整 SVD）**

由于 `A` 只有 3 列，`V` 与 `λ` 可由 `G = AᵀA` 的 3×3 特征分解直接得到（`V` 的列 = `G` 的特征向量，`σ_i = √λ_i`）。而 `N_f` 需要 `U` 的后 2m−3 列。工程上采用等价的**两段式消元**：

```
A = [ A_1 ; A_2 ]        把 2m 行分为两组（各 ≥ 3 行）
对 A_1 做 QR： A_1 = Q_1 R_1 (3×3 上三角)
A_2 = Q_2 R_2 (3×3)
A = [Q_1 Q_2] [R_1; R_2]
```

记 `C = [R_1; R_2] ∈ R^{6×3}`（列主序的前 3 列为 `C_1`）。零空间可由 `C_1` 的右奇异向量补齐：

```
令 S = I₆ − C_1 (C_1ᵀ C_1)⁻¹ C_1ᵀ ∈ R^{6×6}   （投影到 C_1 的零空间）
N_f = [Q_1 Q_2] · S ∈ R^{2m×(2m−3)}
```

该实现只需求 3×3 的逆，数值稳定性优于显式求 `U` 的零空间。

**步骤 6：权重与鲁棒核**

零空间投影后残差的协方差不再是对角的，因此：

| 项 | 规格 |
|---|---|
| 权重 | 白化 `r_f^null ← (Σ_f^null)⁻¹ᐟ² r_f^null`，其中 `Σ_f^null = N_fᵀ Σ_J N_f`，`Σ_J = σ_v² I_{2m}`（`σ_v = 0.8 px`） |
| 鲁棒核 | Cauchy（`ρ(x) = log(1 + x/δ²)`），`δ = 1.0 px`（快 1.5，高 0.7），`vio_visual_huber_delta`（**需回填 08 G3**） |
| 核的选择理由 | Cauchy 对大残差的抑制比 Huber 更强，适合"错误三角化"这类成片外点；Huber 在残差分布接近高斯时效率更高，故 SfM 全局 BA 用 Huber（`sfm_ba_loss_function`），VIO 在线用 Cauchy |

#### 3.6.3 边缘化（marginalization）

滑窗满（`|W| = K`）时，边缘化最旧的关键帧 `i_1`：

```
① 收集滑窗内所有状态的雅可比（相机位姿 + 零偏 + 重力）：
   H = [ ∂r/∂x_1 , ∂r/∂x_2 , … , ∂r/∂x_n ]   （全部残差块，含零空间残差与 IMU 残差）
② 分离被边缘化状态 x_1（9 维）与保留状态 x_2：
   H = [ H_1 , H_2 ] ,   P = [ P_11 P_12 ; P_21 P_22 ]
③ Schur 补更新：
   P_22 ← P_22 − P_21 P_11⁻¹ P_12
   x_2 ← x_2 − P_21 P_11⁻¹ (r(x_1) + H_1 x_1)
④ 特征处理：
   - 仅在 i_1 中被观测、其余帧无观测的特征 → 直接移除
   - 在 i_1 与剩余帧中都被观测的特征 → 保留，但其零空间约束需用**剩余帧重新构造**
     （新的观测数 m' = m−1；若 m' < 3 则该特征降级为 2 帧约束并把权重降低 50%；
      若 m' < 2 则移除）
⑤ 预积分量：滑窗内相邻关键帧间的预积分量保留；被边缘化帧与其前一帧之间的预积分量丢弃
⑥ 零偏不边缘化（全局单例）；若零偏协方差超过阈值（‖b_g‖ > 0.05 rad/s 或 ‖b_a‖ > 0.5 m/s²）
   → 执行 bias reset（§3.3.6）
```

| 约束 | 说明 |
|---|---|
| MG-1 | 边缘化必须使用 **Schur 补**，不得用"直接丢弃"或"投影到零空间"近似 |
| MG-2 | 边缘化后滑窗状态维数必须严格回到 `K×9 + 6`（内存不允许增长） |
| MG-3 | 特征在剩余帧中重新构造零空间时，必须使用**更新后的位姿估计**重新线性化三角化 |
| MG-4 | 边缘化产生的数值不可逆性（信息损失）通过 `P` 的**膨胀**补偿：被边缘化状态的协方差通过 Schur 补已经计入剩余状态，不需要额外膨胀（这一点与 EKF 的平方根形式等价，**不得**再额外膨胀，否则协方差会被重复计入） |

### 3.7 残差定义与鲁棒核

#### 3.7.1 视觉残差（零空间投影后）

```
r_f^null = N_fᵀ ( π(K_i X_f) − u_i )_stacked ,  维度 2m−3
```

白化与核：

```
r̃_f = (Σ_f^null)⁻¹ᐟ² r_f^null
E_f = ρ_cauchy( ‖r̃_f‖² ) ,  ρ(x) = log(1 + x/δ²) , δ = 1.0 px
```

#### 3.7.2 IMU 残差（相邻关键帧之间）

对滑窗内相邻的关键帧 `i` 与 `i+1`（时间差 `Δt = t_{i+1} − t_i`），使用 §3.3 累积的预积分量：

```
r_imu,i = [  R_iᵀ ( p_{i+1} − p_i − v_i Δt − ½ g_W Δt² ) − Δp̂_i
             R_iᵀ ( v_{i+1} − v_i − g_W Δt )              − Δv̂_i
             Log( R_iᵀ R_{i+1} · Exp(−Δθ̂_i) )                     ] ∈ R^9
```

| 块 | 单位 | 权重来源 |
|---|---|---|
| 位置块 | m | 预积分协方差 `P(15×15)` 中对应块（已包含零偏不确定性） |
| 速度块 | m/s | 同上 |
| 姿态块 | rad | 同上 |

白化：`r̃_imu = P_preint⁻¹ᐟ² r_imu`，其中 `P_preint` 是预积分量自身的 15×15 协方差（对零偏边缘化后的 9×9 分块）。

**尺度一致性（关键）**：`r_imu` 的位置块单位是**米**。当 BA 的世界系是尺度未定的 SfM 系（ru）时，必须用尺度因子 `s` 缩放位置块（07 §2.9.3）：`r_p' = s · r_p`。本文的做法是**在 BA 中直接把世界系定义为米制**，尺度由 §7 的参照物标定注入（见 §4.6），因此 `r_imu` 无需缩放。

**IMU 残差的鲁棒核**：Huber，`δ = 2.0`（作用在白化后的残差范数上，即 2σ）。理由：IMU 残差的外点主要来自时间同步异常（02 §3.6.3 的 `E_SYNC_RESIDUAL_REJECT`），这类外点应被**拒绝而非降权**——实现上，`|r_t| > 10σ_t` 的帧已在预积分阶段被排除出 IMU 约束（02 §3.6.3），因此残差层面只需轻度鲁棒。

#### 3.7.3 总代价

```
E(x) = Σ_f E_f^visual  +  Σ_i E_i^imu  +  E_g^gravity  +  E_b^bias
```

| 项 | 形式 | 权重 |
|---|---|---|
| 视觉 | §3.7.1 | 白化 + Cauchy δ=1.0 px |
| IMU | §3.7.2 | 白化 + Huber δ=2.0 |
| 重力 | `(‖g_W‖ − 9.80665)² / σ_g²`，`σ_g = 1e-3 m/s²` | 硬约束（权重 1e6） |
| 零偏 | `‖b_g‖²/σ_bg² + ‖b_a‖²/σ_ba²` | `σ_bg = 2.0e-4`, `σ_ba = 2.0e-4`（弱先验，防止零偏漂到不合理值） |

### 3.8 初始化流程

#### 3.8.1 静止检测与重力方向估计

| 项 | 规格 | 参数键名 |
|---|---|---|
| 判据 1（加速度） | `\| ‖a_m‖ − g \| < 0.1 m/s²` | `vio_static_accel_tolerance`（**需回填 08 G3**） |
| 判据 2（角速度） | `‖ω_m‖ < 0.05 rad/s` | `vio_static_gyro_tolerance`（**需回填 08 G3**） |
| 持续时长 | ≥ 2.0 s（快 2.5 s） | `vio_static_window_ms`（**需回填 08 G3**） |
| 采样数 | 2.0 s × 30 fps = 60 帧（400 Hz IMU 时 800 样本） | — |
| 失败处置 | 3 s 内未通过 → 判为初始化失败，提示"请保持手机静止"，并允许**运动初始化**降级路径（§3.8.4） | — |

**重力方向估计**：

```
静止时： a_m = R_WIᵀ ( a_W − g_W ) = −R_WIᵀ g_W  （a_W = 0）
⇒ ā_m ≈ −R_WIᵀ g_W
⇒ ĝ_W = −R_WI(ā_m) · ā_m / ‖ā_m‖    （把测得的比力方向映射到世界系）
```

初始化旋转：

```
R_WI(0) = Rot( ẑ → ā_m/‖ā_m‖ )     （世界系 Z 轴对齐到测得的比力反方向）
```

即令 `R_WI(0) · (ā_m/‖ā_m‖) = ẑ`，从而 `g_W(0) = (0, 0, −9.80665)`。**偏航角（yaw）不可由重力观测**，取第一帧的主视方向为 yaw 零参考，后续由视觉跟踪修正。

**零偏初值**：

```
b_g(0) = mean(ω_m)   over 静止窗口
b_a(0) = mean(a_m) − R_WI(0)ᵀ g_W(0)   over 静止窗口
```

| 数值校核 | 计算 | 结果 |
|---|---|---|
| 静止段加速度均值的噪声 | `σ_a/√(N)`（N = 400 样本 @200 Hz） | `8.0e-2/20 = 4.0e-3 m/s²` |
| 判据 1 的裕度 | `0.1 / 4.0e-3` | **25 σ**（判据宽裕，不会误判；代价是真实的匀速平移（`\|a\|` 与 g 差 0）也能通过 → 需靠判据 2 与加速度方差补充，见下） |
| 静止段角速度均值噪声 | `σ_g/√N` | `1.5e-3/20 = 7.5e-5 rad/s` |
| 判据 2 的裕度 | `0.05 / 7.5e-5` | 667 σ |

> **静止判据的补充条件（必要）**：单纯用均值判据会把"匀速直线平移"误判为静止（此时加速度也恰为纯重力）。必须叠加**方差判据**：

| 补充判据 | 阈值 | 说明 |
|---|---|---|
| 加速度标准差 | `std(‖a_m‖) < 0.15 m/s²` | 排除"匀速直线平移 + 手抖" |
| 角速度标准差 | `std(‖ω_m‖) < 0.02 rad/s` | 同上 |
| 光流中位速度 | `< 2.0 px/frame @960 宽` | 与 02 §4.4 的 `cov` 判据联合使用（02 KF-3 的降级判据同源） |

#### 3.8.2 尺度可观性检查（初始化阶段）

初始化阶段必须立即判定"本次采集的**运动形态**是否有望定出尺度"，因为尺度退化一旦在整段采集中持续存在，事后无法补救（§3.9）。

**判据（基于 IMU 加速度序列的方向多样性）**：

定义窗口内（最近 2.0 s）去除重力后的世界系加速度：

```
a_W,k = R_WI,kᵀ ( a_m,k − b_a ) + g_W        （水平分量为 a_h,k）
```

计算两个指标：

| 指标 | 定义 | 物理含义 |
|---|---|---|
| `σ_a` | `std( a_h,k )` 的模长均值（m/s²） | 加速度**大小**的变化程度 |
| `ρ_dir` | 方向一致性：`‖ (1/N) Σ û_k ‖`，`û_k = a_h,k/‖a_h,k‖` | 1 = 完全同向（直线）；0 = 各向均匀（圆周/8 字） |

判定：

| 条件 | 结论 | 处置 |
|---|---|---|
| `σ_a < 0.05 m/s²` 且 `ρ_dir > 0.95` | **尺度退化**（近似匀速/匀加速直线运动） | 标记 `W_VIO_SCALE_DEGENERATE`；尺度先验不可用（σ 放大到 0.30）；触发 §3.9.3 的引导 |
| `σ_a < 0.20 m/s²` 或 `ρ_dir > 0.85` | 尺度弱可观 | 尺度先验 σ 放大到 0.20 |
| 其他 | 尺度可观 | σ = 0.10（`scale_imu_prior_relative_sigma`） |

> **判定阈值的物理依据**：`σ_a` 衡量的是加速度的大小变化，匀速直线时 `σ_a ≈ 0`（即使有恒定加速度，加速度**大小**不变时 `ρ_dir = 1` 也可判出）；匀加速直线时 `σ_a = 0` 且 `ρ_dir = 1`。圆周运动时加速度方向持续变化，`ρ_dir` 低。8 字运动时加速度在两个象限交替，`ρ_dir ≈ 0.3~0.5`。因此 `ρ_dir` 是主判据，`σ_a` 是辅助。

#### 3.8.3 初始速度估计

| 情形 | 做法 |
|---|---|
| 静止初始化 | `v_0 = 0`（严格） |
| 运动初始化（静止检测失败但已积累 ≥ 1 s 有效帧） | 用最近 5 帧的 VIO 位姿差分给出 `v_0` 的方向，量级由 IMU 积分给出：`v_0 ≈ (p_N − p_{N−5}) / Δt`，并按 §3.8.4 的尺度因子缩放；若此时尺度不可观，`v_0` 的**量级**不可信，只保留方向，标 `v_0_magnitude_unknown = true` |

#### 3.8.4 运动初始化降级路径

当 3 s 内未通过静止检测（用户手持晃动），但光流与 IMU 均可用时：

| 步骤 | 动作 |
|---|---|
| 1 | 用 `exp(…)` 累积的陀螺积分给出初始姿态（gyro-only 姿态积分），重力方向用前 1 s 的加速度均值给出 |
| 2 | 跳过零偏精估计，`b_g` 用出厂先验（`σ_bg` 对角） |
| 3 | 尺度标记为 `unknown`，`s_imu` 不输出，尺度先验 σ = 1.0（视为无信息） |
| 4 | 记录 `W_VIO_INIT_MOTION`；UI 提示"请保持手机静止" |
| 5 | 后续采集中若出现 ≥ 2 s 的静止段（用户放手机不动），**在线补做静止重初始化**：重估零偏与重力，并重置滑窗（清空预积分与协方差，保留 SfM 已建立的位姿作为初值） |

### 3.9 尺度可观性检查（核心）

#### 3.9.1 问题陈述

单目 + IMU 的尺度可观性来自加速度计提供的米制参考，但该参考与视觉平移的耦合方式决定了它何时可解：

- **退化情形**：相机做**匀速或匀加速的直线运动**。此时加速度计只能给出"重力 + 常量水平力"，积分结果为 `p(t) = v₀ t + ½ a t²`，其中 `v₀` 的大小未知。视觉给出的相对位移与 `v₀` 成正比，因此 `s`（尺度因子）与 `v₀` 的大小**完全混淆**，尺度不可观测。
- **非退化情形**：运动轨迹弯曲（转弯、圆周、8 字）或加速度大小发生变化。加速度计的比力方向随时间变化，使得"米制加速度积分"与"任意尺度的视觉平移"之间的等式只能在唯一的 `s` 处成立。

> 这与 00 §8.7 的实测一致：直线运动尺度误差 9.2%、圆周 6.4%、8 字 4.8%。

#### 3.9.2 可检测判据（阈值）

| 编号 | 指标 | 定义 | 退化 | 弱 | 正常 |
|---|---|---|---|---|---|
| D1 | 方向一致性 `ρ_dir` | `‖ (1/N) Σ û_k ‖`，`û_k` = 水平加速度单位向量 | > 0.95 | 0.85 – 0.95 | < 0.85 |
| D2 | 加速度幅值变化 `σ_a` | `mean_k std(‖a_h,k‖)` over 滑动 0.5 s | < 0.05 m/s² | 0.05 – 0.20 | > 0.20 m/s² |
| D3 | 旋转激励 `Θ_total` | 窗口内累计旋转量（度） | < 15° | 15° – 45° | > 45° |
| D4 | 累计平移 `L_total` | 窗口内 IMU 积分路程（m） | < 0.05 m | 0.05 – 0.15 | > 0.15 m |
| D5 | 尺度漂移（离线，见 §3.9.4） | 分段尺度比的最大偏差 | > 0.10 | 0.05 – 0.10 | < 0.05 |

**综合判定规则**（按顺序短路）：

```
if (D1 退化) or (D2 退化 and D3 退化)  →  SCALE_DEGENERATE
elif (D1 弱) or (D2 弱) or (D3 弱)    →  SCALE_WEAK
else                                    →  SCALE_OBSERVABLE
```

| 结论 | 尺度先验 σ | 对 BA 的影响 | UI 提示 |
|---|---|---|---|
| `SCALE_DEGENERATE` | 0.30（不可用） | 不注入尺度先验（`r_scale` 权重置 0） | 触发 §3.9.3 引导文案 |
| `SCALE_WEAK` | 0.20 | 注入但权重低（`sfm_prior_scale_weight` × 0.2） | 提示但可继续 |
| `SCALE_OBSERVABLE` | 0.10 | 正常注入 | 无 |

| 级别 | 主文案（≤ 14 汉字） | 补充文字（可选） | 触发条件 | 消失条件 |
|---|---|---|---|---|
| 提示 | `请绕物体画圈移动` | `直线移动无法确定真实尺寸` | `SCALE_DEGENERATE` 且已采集 < 30 s | 判定变为 `SCALE_WEAK` 以上 |
| 提示 | `请走8字轨迹` | `多方向移动才能确定真实尺寸` | 同上，且用户已按提示移动但 `ρ_dir` 仍 > 0.95 | 同上 |

#### 3.9.4 尺度一致性检验（离线，BA 前执行）

在 §4 的 SfM 完成后、§4.6 的全局 BA 之前执行，用以最终裁定 IMU 尺度的可用性：

```
① 取关键帧轨迹的世界系平移 {t_i}（IMU 轨迹，米制）与 {t'_i}（SfM 轨迹，任意单位）
② 求最优尺度（仅平移，旋转固定为 SfM 的旋转）：
   s* = argmin_s Σ_i ‖ t_i − s · R_i t'_i ‖²
   s* = ( Σ_i (R_i t'_i)ᵀ t_i ) / ( Σ_i ‖R_i t'_i‖² )
③ 残差比：ρ_res = rms_i ‖ t_i − s* R_i t'_i ‖ / rms_i ‖ t_i − mean(t) ‖
④ 分段尺度：把轨迹等分为 5 段，各段独立求 s_k，计算 s̄ 与 max|s_k/s̄ − 1|
```

| 判据 | 阈值 | 结论 |
|---|---|---|
| `ρ_res` | > 0.05 | VIO 位姿与 SfM 结构不一致 → 尺度不可信，记 `W_VIO_SCALE_INCONSISTENT` |
| `max\|s_k/s̄ − 1\|` | > 0.10 | 尺度沿轨迹漂移（"VIO 尺度会漂"的可检测形式），记 `W_VIO_SCALE_DRIFT` |
| `s*` 与 07 文档参照物标定值 `s_ref` 的偏差 | > 0.30 | 尺度源冲突，记 `W_SCALE_SOURCE_CONFLICT`（07 §1.2 规定的 30% 阈值） |

| `imu_preint`（关键帧间） | ΔR, Δv, Δp, P | — | §4.6 的 IMU 因子 |

**时间戳是每关键帧的第一等输出量**（对齐 §2.3 的输入语义）：语义是**曝光中点**（`t_exposure_center_ns`，02 §3.3.2），不是 PTS。下游一律按**时间**而非按序号对齐 —— 因为关键帧是从逐帧流里**抽取**的子序列，序号会因丢帧/降采样而失去连续含义。实现上，VIO 在挂载关键帧时把本帧时间戳写入 `KeyframeState.timestamp_ns`，编排层再用一条**与位姿/内参/下标同长同序**的平行数组 `key_timestamps_ns_` 透传（`CameraPose` 是纯几何量、不含时间字段，故不能依赖它携带时间）。

**坐标系约定**：世界系为 **Y-up 右手系、单位米**（与 06 §0.1 一致）。VIO 内部可用 Z-up 重力对齐系，但**导出到重建世界系前必须完成 Y-up 转换**，转换在 §4 的 SfM 初始化时统一执行一次（并记入 `recon_mesh_info.json` 的坐标约定字段）。

## 4. 稀疏 SfM 与全局 BA

### 4.1 与 COLMAP 增量式 SfM 的关系：取舍与结论

#### 4.1.1 逐项对比

| 能力 | COLMAP 稀疏模块 | 本产品需求 | 差距 |
|---|---|---|---|
| 特征提取（SIFT） | 有 | 需要 | 无差距 |
| 穷举/词袋匹配 | 有（ANN + vocab） | 需要 | 无差距 |
| 两视图几何（F/E/H + RANSAC） | 有（LO-RANSAC） | 需要 | 无差距 |
| 增量式注册与三角化 | 有（成熟） | 需要 | 无差距 |
| **注入外部位姿先验（VIO）** | **无接口** | 必须（核心要求 M3） | **需改造** |
| **IMU 预积分残差因子** | **无** | 必须 | **需改造** |
| **尺度作为优化变量 + 参照物先验** | **无**（COLMAP 是纯 SfM，尺度 gauge 自由） | 必须 | **需改造** |
| **闭环边的尺度一致性检查** | **无** | 必须（防止闭环拉偏尺度） | **需改造** |
| **输出逐帧对称重投影误差**（03 S14 回填） | **无直接接口** | 必须 | 需新增 |
| CGAL 依赖 | 默认 ON（GPL 传染点，00 §8.4） | 必须 OFF | 构建约束 |
| 移动端内存 | 特征库常驻内存设计 | 描述子 1.2 GB 级必须分块 | 需改造 |

#### 4.1.2 结论（明确）

> **结论：复用 COLMAP 的稀疏模块作为「几何原语层」，自研「求解层」与「调度层」。**

具体拆分：

| 层 | 归属 | 内容 |
|---|---|---|
| 几何原语层 | **复用 COLMAP**（`third_party/colmap`，构建参数 `-DCGAL_ENABLED=OFF -DGUI_ENABLED=OFF -DONNX_ENABLED=OFF -DCUDA_ENABLED=OFF -DMVS_ENABLED=OFF -DFETCH_*=OFF`，00 §8.4） | SIFT 提取与匹配、LO-RANSAC（F/E/H）、本质矩阵分解、DLT 三角化、增量式注册策略（`IncrementalMapper` 的"选下一对 + 定位 + 三角化"逻辑） |
| 求解层 | **自研** `core/sfm/global_ba.cpp` | 全局 BA（含 VIO 先验 + IMU 因子 + 尺度先验），Ceres Solver 2.x |
| 调度层 | **自研** `core/sfm/mapper.cpp` | 关键帧选择、内存分块与落盘（03 §3.5.5）、闭环策略、失败处置 |

**理由（量化）**：

| # | 理由 | 量化 |
|---|---|---|
| R1 | COLMAP 的 BA 是纯 SfM，尺度 gauge 完全自由；要注入参照物尺度必须重写代价函数与参数化 | 改造量 ≈ 400 行（代价函数 + 尺度参数化 + 因子注册） |
| R2 | VIO 先验与 IMU 因子在 COLMAP 中无任何挂载点 | 改造量 ≈ 300 行（自定义 Factor + 参数块） |
| R3 | COLMAP 的 DBoW2 闭环在**弱纹理**下召回率低（词袋对低区分度描述子失效），且不做尺度一致性检查 | 改造量 ≈ 250 行（见 §4.5） |
| R4 | COLMAP 的特征库与描述子全常驻内存；本产品描述子预算 0.46–1.84 GB，必须分块 | 改造量 ≈ 200 行 |
| R5 | 自研 BA 后，COLMAP 的 `BundleAdjuster` 可完全不用，避免两套 BA 语义 | 简化收益 ≈ 800 行被删除的胶水代码 |

**风险与回退**：

| 风险 | 缓解 | 回退条件 |
|---|---|---|
| COLMAP 稀疏模块在移动端编译困难（依赖链长） | 只编译 `src/colmap/sfm`、`src/colmap/feature`、`src/colmap/mvs` 子集中的 `feature` + `estimators` + `sfm` 三部分，禁用 `mvs`/`ui`/`pybind` | 若子集编译在 NDK/Xcode 上不可行（预计工作量 > 3 人日），则**自研几何原语**（OpenCV `findFundamentalMat` / `findEssentialMat` / `recoverPose` + 自研 DLT 三角化），工作量增加约 400 行但零外部耦合 |
| COLMAP 的 LO-RANSAC 与本文的 RANSAC 阈值口径不一致 | 统一改为 OpenCV RANSAC 实现，阈值由本文参数控制 | — |
| 描述子分块后跨块匹配的实现复杂度 | 匹配图构建用**空间分块**（03 §3.5.5）：关键帧按物体中心 `C` 的方位/俯仰分 24 块，块内 + 相邻块匹配 | — |

#### 4.1.3 明确不做的事

### 4.2 特征提取与描述子选型

#### 4.2.1 描述子对比

| 描述子 | 类型 | 维度 | 提取耗时（1080p，12k 点） | 匹配（12k×12k） | 弱纹理区分度 | 尺度/旋转不变 | 许可 |
|---|---|---|---|---|---|---|---|
| **SIFT** | float32 | 128 | 420 ms | L2 暴力 12k² = 1.44e8 × 128 flops ≈ 1.8e10 → FLANN 约 90 ms | 高 | 好 | BSD-3（OpenCV 4.4+ 主仓库） |
| **SIFT + rootSIFT** | uint8 | 128 | 420 ms | 汉明 + FLANN 约 35 ms | 高（比 SIFT 更好） | 好 | 同上 |
| **ORB** | binary | 256 | 55 ms | 汉明 FLANN 约 8 ms | 中 | 中（旋转 30° 内可用） | BSD-3 |
| **BRISK** | binary | 1024 / 64 | 130 ms | 汉明约 15 ms | 中高 | 好 | BSD-3 |

#### 4.2.2 分档预设的选择与理由

| 档 | 描述子 | 理由 |
|---|---|---|
| 快 | **ORB**（256 bit） | 匹配耗时是 SIFT 的 1/11；本档定位是"快速可用"，且 ORB 在 60 fps 高帧率下的描述子数量需求较低。**明确代价**：弱纹理区区分度下降，误匹配率上升，因此快档的 `sfm_match_ratio_threshold` 收紧到 0.90（08 G4 已有） |
| 标 | **SIFT + rootSIFT（uint8）** | rootSIFT 归一化把欧氏距离转成余弦相似度，匹配质量比裸 SIFT 提升；uint8 存储把描述子内存降到 1/4，使分块加载可行 |
| 高 | **SIFT + rootSIFT（uint8）**，特征数 20000 | 与标准档同描述子，靠**特征数**与 BA 迭代提升精度，不换描述子（换描述子会同时改变匹配统计特性，需重新标定阈值） |

| 项 | 快 | 标 | 高 | 参数键名 |
|---|---|---|---|---|
| 描述子类型 | ORB | rootSIFT | rootSIFT | `sfm_descriptor_type`（**需回填 08 G4**：枚举 0=ORB, 1=rootSIFT） |
| 描述子位数 | 256 bit | 128 byte | 128 byte | — |
| 每帧特征数 | 8000 | 12000 | 20000 | `sfm_feature_count`（08 G4 已有） |
| SIFT 首层边缘阈值 | 不适用 | 10.0 | 8.0 | `sfm_feature_edge_threshold`（08 G4 已有，ORB 下无效） |
| ORB FAST 阈值 | 20 | 不适用 | 不适用 | `sfm_orb_fast_threshold`（**需回填 08 G4**） |
| 描述子内存（每帧） | 2.0 MB | 1.5 MB | 2.6 MB | — |
| 描述子内存（300 关键帧全驻留） | 614 MB | 461 MB | 768 MB | 超出移动端预算 → **必须分块** |

#### 4.2.3 描述子内存预算与分块策略

| 项 | 快 | 标 | 高 |
|---|---|---|---|
| 单帧描述子 | 8000 × 32 B = 256 KB | 12000 × 128 B = 1.5 MB | 20000 × 128 B = 2.5 MB |
| 300 关键帧全驻留 | 77 MB | 461 MB | 768 MB |
| 可用常驻上限（按 13 文档预算的 25% 分配给 SfM） | 512 MB | 512 MB | 1024 MB |
| 结论 | 可全驻留 | **必须分块**（每次 80 帧） | **必须分块**（每次 120 帧） |

分块策略（沿用 03 §3.5.5）：关键帧按物体中心 `C` 的方位/俯仰分 24 个空间块，块内 + 相邻块做匹配；跨块匹配通过位姿图 + 闭环检测补充。**不删帧**（R-PREC-3）。

### 4.3 特征匹配与几何验证

#### 4.3.1 匹配图构建策略（穷举 vs 词袋 vs 混合）

| 策略 | 匹配对数 | 描述子比较次数 | 弱纹理召回 | 结论 |
|---|---|---|---|---|
| 穷举（全对全） | `N(N−1)/2` | N=300 → 44850 对 × 1.44e8 = 6.5e12 次 → 不可行 | 最高 | 仅 N ≤ 40 时启用 |
| 纯词袋（DBoW2） | 每帧 top-k（k=10） | 300 × 10 × 1.44e8 = 4.3e11 → 仍然很高，但可先用**词袋分数粗筛 + top-200 描述子对** | 中（低纹理下召回差） | 作为**闭环候选**源，不作为主匹配 |
| **混合（本文采用）** | ① 序列邻接必配对；② 空间近邻（方位差 < 45°）配对；③ 词袋 top-k | 邻接 2N + 空间近邻 ~4N + 词袋 10N ≈ 16N 对 | 高（邻接链保证连通） | ✓ |

| 编号 | 规则 |
|---|---|
| MM-1 | **序列邻接边**：关键帧 `i` 与 `i+1..i+3` 必配对（保证 SfM 主链连通，这是 03 §4.6 覆盖度策略的直接要求） |
| MM-2 | **空间近邻边**：由 03 §4.7 的方位/俯仰直方图算出两帧的方位差，< 45° 的帧对进入候选（上限 `sfm_max_num_neighbors` = 80） |
| MM-3 | **词袋候选**：DBoW2 top-10 |
| MM-4 | 匹配图的对数上限 16N；超过时按"角点数量 × 空间距离"的评分排序截断（**不删帧**，只删边） |
| MM-5 | 匹配策略枚举 `sfm_matching_strategy`（**需回填 08 G4**）：0=穷举, 1=混合（默认）, 2=纯词袋 |

#### 4.3.2 描述子匹配与过滤

| 步骤 | 规格 | 参数键名 |
|---|---|---|
| 最近邻搜索 | FLANN（rootSIFT 用 L2 on uint8 归一化向量）/ BRISK-FAST（ORB 用汉明） | `sfm_matcher_type`（**需回填 08 G4**） |
| 比值检验 | `d_1 / d_2 ≤ ratio` | `sfm_match_ratio_threshold`（08 G4：0.90/0.85/0.82） |
| 双向一致性 | 互为最近邻（mutual NN） | `sfm_cross_check_enabled`（**需回填 08 G4**，默认 1） |
| 交叉检验比值 | 双向最近邻的距离比 ≤ 0.90 | `sfm_cross_check_ratio`（**需回填 08 G4**） |
| 匹配上限 | 每帧最多 8000 对（标） | `sfm_max_matches_per_image`（**需回填 08 G4**） |

> **双向一致性为什么必须**：纯 ratio test 在重复纹理（织物、格栅）上会产生大量"互为最近邻但都错"的匹配。加互为最近邻后，重复纹理的错误匹配率从 ~12% 降到 ~2%，代价是匹配召回降低 ~8%。几何验证（RANSAC）只能剔除**空间分布随机**的外点，无法剔除**系统成片**的外点（重复纹理的外点也成片），因此双向一致性不可省。

#### 4.3.3 几何验证（RANSAC）

| 步骤 | 规格 | 阈值（快/标/高） | 参数键名 |
|---|---|---|---|
| 模型选择 | 优先 E（已标定内参）；若内点率 < 30% 退化到 H（平面场景）；再退化到 F | — | — |
| **F 矩阵** RANSAC | Sampson 距离（像素单位） | 2.0 / **1.5** / 1.2 px | `sfm_two_view_f_threshold_px`（**需回填 08 G4**） |
| **E 矩阵** RANSAC | Sampson 距离（像素单位） | 1.5 / **1.0** / 0.8 px | `sfm_two_view_e_threshold_px`（**需回填 08 G4**） |
| **H 矩阵** RANSAC | 对称转移距离（像素单位） | 3.0 / **2.0** / 1.5 px | `sfm_two_view_h_threshold_px`（**需回填 08 G4**） |
| RANSAC 迭代上限 | — | 5000 / **10000** / 30000 | `sfm_ransac_max_iterations`（08 G4，黑名单） |
| 提前终止置信度 | — | 0.99 / **0.999** / 0.9999 | `sfm_ransac_confidence`（08 G4） |
| 最小内点数 | — | 20 / **30** / 50 | `sfm_ransac_min_inliers`（08 G4，黑名单） |
| 最小内点率 | — | 0.15 / **0.25** / 0.35 | `sfm_two_view_min_inlier_ratio`（**需回填 08 G4**） |
| 正深度检验 | cheirality：三角化后所有点在相机前方（`z > 0`） | 100% | — |
| 视角夹角 | 三角化的两视线夹角 > 1.5° | — | `sfm_triangulation_min_angle_deg`（**需回填 08 G4**） |

> **阈值依据**：E 矩阵的 Sampson 阈值与光流残差同量级。§3.5.5 定的光流残差上限是 1.0 px（标），因此 E 的 1.0 px 与之自洽；F 因未归一化相机内参，在宽幅图像上误差放大 1.3–1.8 倍，故取 1.5 px；H 用于平面场景，其噪声敏感度更高，取 2.0 px。
> **RANSAC 迭代数校核**：内点率 p = 0.25、要求置信度 0.999 时，所需迭代数 `log(1−0.999)/log(1−0.25²) ≈ 41`。即 10000 次远超需求，RANSAC 迭代数在此不是瓶颈（黑名单保护的对象是"内点阈值"与"内点数"，见 00 §1.2）。

#### 4.3.4 相对位姿估计与验证

| 步骤 | 规格 |
|---|---|
| E 分解 | 4 种候选解（四种 cheirality 组合），按正深度点数最多者 |
| 尺度归一 | E 分解给出单位旋转 + 单位平移（尺度不可观测，见 §3.9） |
| PnP 验证 | 用第三个视角做 PnP + RANSAC（阈值 4.0 px = `sfm_ransac_max_error_px`，08 G4），验证相对位姿 |
| 三角化 | DLT 齐次解 + RANSAC（重投影 ≤ 2.0 px，内点率 ≥ 0.6） |

### 4.4 增量式注册与三角化

#### 4.4.1 注册调度

```
候选图像对（来自匹配图）
   → 对每个候选对：几何验证（§4.3.3）→ 相对位姿 + 三角化点
   → 按"新增三角化点数 / 计算代价"排序
   → 取最优对 → 用 PnP + RANSAC 把新帧注册到已建地图（内点阈值 4.0 px）
   → 注册成功 → 三角化该帧与已建地图之间的对应点
   → 触发局部 BA（窗口 `sfm_local_ba_window` = 8）
   → 满足 `sfm_ba_min_num_images`（5 帧）或每新增 10 帧 → 触发全局 BA
```

| 项 | 规格 | 参数键名 |
|---|---|---|
| 局部 BA 窗口 | 8 帧（快 6，高 12） | `sfm_local_ba_window`（**需回填 08 G4**） |
| PnP RANSAC 内点阈值 | 4.0 px（快 6.0，高 3.0） | `sfm_ransac_max_error_px`（08 G4） |
| 三角化重投影上限 | 2.0 px（快 3.0，高 1.5） | `sfm_triangulation_max_reproj_px`（**需回填 08 G4**） |
| 最小轨迹长度 | 3（快 3，高 2） | `sfm_min_track_length`（08 G4） |
| 增量式 BA 开关 | 开启 | `sfm_incremental_ba_enabled`（08 G4） |

#### 4.4.2 三角化的数值实现

| 项 | 规格 |
|---|---|
| 方法 | 线性 DLT（6 方程/点）+ RANSAC 外点剔除 + 非线性精化（3 维点的 Levenberg，5 次迭代） |
| 世界系 | 尺度未定的 ru（重建单位），尺度由 §7 注入 |
| 数值条件 | DLT 的 A 矩阵做 QR 预条件化；`cond(A) > 1e9` → 弃用该点 |
| 深度过滤 | `z < 0` 或 `z > 10 × 场景尺度` → 弃用 |
| 视角夹角 | < 1.5° → 弃用（`sfm_triangulation_min_angle_deg`） |
| 相对深度不确定度 | `σ_z/z > 0.10` → 弃用（与 §3.6.2 的零空间判据同源） |

### 4.5 闭环检测

#### 4.5.1 两种方案

| 方案 | 机制 | 召回 | 计算量 | 适用 |
|---|---|---|---|---|
| **轻量方案**（默认） | 描述子 LSH 指纹 + 汉明距离 + 几何验证 | 中（对强纹理好） | 极低（每帧一次 64 bit 指纹 + 候选对几何验证） | 通用，**默认开启** |
| **完整方案** | DBoW2 词袋（随 App 打包 10k 词词典） + 几何验证 | 高（对纹理变化鲁棒） | 中（词典查询 O(log W)） | 弱纹理或长会话，**与轻量方案并行运行**，取并集 |

**轻量方案的指纹构造**：

```
① 每帧取响应最强的 512 个描述子
② 每个描述子做 8 次随机超平面投影 → 8 bit（0/1）→ 拼成 64 bit 指纹
   （随机投影矩阵由固定种子生成，随 App 发布，保证跨会话一致）
③ 两帧指纹的汉明距离 < 12 → 进入几何验证
```

| 项 | 规格 | 参数键名 |
|---|---|---|
| 指纹位数 | 64 bit | `sfm_lsh_bits`（**需回填 08 G4**） |
| 汉明距离阈值 | 12（快 16，高 10） | `sfm_lsh_hamming`（**需回填 08 G4**） |
| 参与描述子数 | 512 | — |
| 候选对上限 | 每帧 20 个 | `sfm_loop_max_candidates`（**需回填 08 G4**） |

#### 4.5.2 闭环的几何验证

| 步骤 | 规格 | 阈值（快/标/高） |
|---|---|---|
| 描述子匹配 | 与主链相同的 ratio + 双向一致性 | ratio 0.90/0.85/0.82 |
| 最小匹配对数 | 20 / **30** / 40 | `sfm_loop_min_matches`（**需回填 08 G4**） |
| 两视图几何 | E 矩阵 RANSAC，阈值放宽到 2.0 px | `sfm_two_view_e_threshold_px` 的 2 倍 |
| 内点数 | 20 / **30** / 50 | `sfm_loop_min_inliers`（08 G4） |
| 内点率 | ≥ 0.30 | `sfm_loop_min_inlier_ratio`（**需回填 08 G4**） |
| 视角夹角 | > 15°（闭环必须有大视角变化才有约束价值） | `sfm_loop_min_angle_deg`（**需回填 08 G4**） |
| 重投影中位数 | ≤ 2.5 / **1.5** / 1.0 px | `sfm_loop_reproj_median_px`（**需回填 08 G4**） |
| **尺度一致性** | 闭环推导的相对平移长度与当前地图的对应长度之比，偏离 > 0.10 → **拒绝该闭环**并告警 | `sfm_loop_similarity_scale_tolerance`（08 G4，0.15/0.10/0.05） |

> **为什么闭环不做 Sim(3) 尺度自由**：本产品的尺度由 §7 的参照物标定唯一确定。如果闭环引入尺度自由度，尺度会在每次闭环时重新调整，导致"尺度反复漂移"，且与 00 §4.6 的"尺度相对误差 ≤ 1.0%、重复性 ≤ 0.5%"直接冲突。因此闭环只优化 **SE(3)**（旋转 + 平移），尺度变化量被显式检测并作为**拒绝条件**。这是与 COLMAP 的关键差异之一。

#### 4.5.3 闭环拒绝与告警

| 情况 | 处置 | 告警码 |
|---|---|---|
| 几何验证不通过 | 丢弃候选 | — |
| 尺度一致性超限 | 丢弃候选，**不改尺度** | `W_SFM_LOOP_SCALE_INCONSISTENT` |
| 与已有闭环边冲突（同对帧已有一条边） | 保留内点数更多的一条 | — |
| 闭环导致全局 BA 残差上升 > 20% | 回滚该闭环边 | `W_SFM_LOOP_REJECTED` |

### 4.6 全局 BA（SfM 位姿以 VIO 为强先验）

#### 4.6.1 优化变量

| 变量 | 维度 | 参数化 | 说明 |
|---|---|---|---|
| 相机位姿 `T_i`（每关键帧） | 6 | `R_i` 用四元数 + `ceres::Manifold`（02 §3.10.4 同款）；`t_i` 加性 | 全部关键帧参与（R-PREC-3） |

| 重力 `g_W` | 3 | 加性 + 软约束 | 与 §3.2.3 一致 |
| **全局尺度 `s`** | 1 | `s = exp(σ)`（保证正性，避免跨数量级时雅可比病态） | 见 §4.6.2 的尺度项 |

**Gauge 固定**：

| 约束 | 说明 |
|---|---|

#### 4.6.2 代价函数（完整形式）

```
E(X) =  Σ_{(i,j) ∈ Ω}  w_v · ρ_v( ‖ r^v_{ij} ‖²_Σv )
      + Σ_{i ∈ W}      w_i · ρ_i( ‖ r^i_i ‖²_Σi )
      + Σ_{i ∈ W}      w_p · ‖ r^p_i ‖²_Σp
      + w_s · ( s / s_ref − 1 )² / σ_prior²
      + w_g · ( ‖g_W‖ − 9.80665 )²
      + w_b · Σ_i ( ‖b_g,i‖²/σ_bg² + ‖b_a,i‖²/σ_ba² )
```

#### 4.6.2.1 视觉重投影残差

```
r^v_{ij} = π( K_i · ( R_i X_j + t_i ) ) − u_{ij} ∈ R²
```

| 项 | 规格 |
|---|---|
| 投影 | 针孔 + 畸变模型（`BROWN_CONRADY` 或 `RADIAL_KANNALA_BRANDT`，02 §3.9.2）；畸变在**归一化像平面**上施加 |
| `Σ_v` | `σ_v² I₂`，`σ_v = 0.8 px`（快 1.2，高 0.5） |
| `w_v` | `1/σ_v²`（相对权重，隐含在 `Σ_v` 中） |
| `ρ_v` | Huber（`sfm_ba_loss_function` = 1），`δ = sfm_ba_huber_delta` = 1.5 px（快 2.0，高 1.0） |
| 权重调整 | 02 §4.5 标记的 `highlight_cells`（反光网格）内的观测，权重 × 0.2（**降权不丢弃**，02 §4.5.2）；低纹理网格内的观测，权重 × 0.5 |

#### 4.6.2.2 IMU 预积分残差

与 §3.7.2 完全相同的形式，但**在 BA 中是"两帧之间"的因子**：

```
r^i_i = [ R_iᵀ ( p_{i+1} − p_i − v_i Δt − ½ g_W Δt² ) − Δp̂_i
          R_iᵀ ( v_{i+1} − v_i − g_W Δt )              − Δv̂_i
          Log( R_iᵀ R_{i+1} · Exp(−Δθ̂_i) )                     ] ∈ R^9
```

| 项 | 规格 |
|---|---|
| `Σ_i` | 预积分量 9×9 协方差（对零偏边缘化后），来自 §3.3.4 的 `P_preint` |
| `w_i` | `sfm_prior_imu_weight`（**需回填 08 G4**，默认 1.0，快 0.5，高 2.0） |
| `ρ_i` | Huber，`δ = 2.0`（白化后） |
| 尺度耦合 | `s` 作用在 `p`、`v` 上：`p = s · p_ru`，`v = s · v_ru`，因此 IMU 位置/速度残差对 `s` 的雅可比**不为零**——这正是尺度可观性的代数体现 |
| 零偏 | `b_g, b_a` 作为优化变量，与预积分量的偏置雅可比（§3.3.5）耦合 |

#### 4.6.2.3 VIO 位姿先验残差（强先验）

```
r^p_i = [ Log( R^vio_iᵀ R_i ) ;  R^vio_iᵀ ( t_i − t^vio_i ) ] ∈ R^6
```

| 项 | 规格 | 参数键名 |
|---|---|---|
| `Σ_p` | `diag( σ_θ² I₃ , σ_t² I₃ )`，`σ_θ = 1.0°`（快 1.5，高 0.5°），`σ_t = 3 mm`（快 5，高 1.5） | `sfm_prior_vio_rotation_sigma_deg`、`sfm_prior_vio_translation_sigma_m`（**需回填 08 G4**） |
| `w_p` | `sfm_prior_vio_weight`（**需回填 08 G4**，默认 1.0，快 0.5，高 2.0） | — |
| 尺度处理 | `t^vio_i` 是**米制**，`t_i` 是 `s · t_ru`。因此先验项实际写为 `R^vio_iᵀ ( s·t_i^ru − t^vio_i )`。**这使得 VIO 先验同时约束位姿与尺度**，是"VIO 作为强先验"的核心机制 | — |
| 降权保护 | 若 `‖r^p_i‖ > 5σ`，该帧的先验权重 × 1/10（`sfm_prior_downgrade_factor`，**需回填 08 G4**，默认 10），并记 `W_SFM_VIO_PRIOR_REJECTED`。防止 VIO 失效时把 BA 拉偏 | — |

> **为什么是"强先验"而不是"弱正则"**：VIO 的位姿精度（1 s 内 0.34° 量级，见 §3.3.4 算例）远好于纯 SfM 在弱纹理段的精度。若 VIO 先验权重过低（弱正则），BA 会在弱纹理区被 SfM 的漂移带走，先验形同虚设。若过强，则 BA 无法纠正 VIO 的系统偏差。取 `σ_θ = 1.0°` 的含义是：**允许 BA 在 1° 量级上修正 VIO，但不允许它跑到几度之外**。该值需实测标定（§9）。

#### 4.6.2.4 尺度约束残差

```
r_s = ( s / s_ref − 1 ) / σ_prior ,   σ_prior = calib_scale_prior_sigma = 0.02
```

| 项 | 规格 |
|---|---|
| `s_ref` | 07 文档的参照物标定结果（m/ru）；置信度低（`σ_s/s > 0.05`）时不注入 |
| `w_s` | `sfm_prior_scale_weight`（**需回填 08 G4**，默认 1.0）。`vio_scale_observability = SCALE_DEGENERATE` 时 `w_s = 0` |
| 与 IMU 项的竞争 | IMU 项本身也约束 `s`（通过 `b_a` 的耦合）。二者竞争的结果是：`s` 被拉向 `s_ref`（σ=2%）而 IMU 项的残差通过 `b_a` 吸收大部分差异。**这是正确的行为**：因为 `b_a` 本身的不确定度远大于 2%（`σ_ba` 量级），它有足够自由度吸收 |
| 冲突检测 | 若优化后 `s` 与 `s_ref` 偏差 > 0.30（07 §1.2 阈值）→ 告警 `W_SCALE_SOURCE_CONFLICT` |

#### 4.6.2.5 各项权重汇总

| 项 | 权重 | 快 | 标 | 高 |
|---|---|---|---|---|
| 视觉重投影 `w_v` | `1/σ_v²`，`σ_v` = 1.2 / 0.8 / 0.5 px | — | — | — |
| IMU 预积分 `w_i` | `sfm_prior_imu_weight` | 0.5 | **1.0** | 2.0 |
| VIO 位姿先验 `w_p` | `sfm_prior_vio_weight` | 0.5 | **1.0** | 2.0 |
| 尺度先验 `w_s` | `sfm_prior_scale_weight` | 1.0 | **1.0** | 1.0 |
| 重力 `w_g` | 硬约束 | 1e6 | 1e6 | 1e6 |
| 零偏弱先验 `w_b` | `1/σ_bg²`, `1/σ_ba²` | — | — | — |

> **权重的相对关系是本节的核心**：视觉项数量远多于 IMU 项（每帧数千观测 vs 每帧 1 个 IMU 因子），若不做尺度归一，IMU 与先验会被淹没。因此 `w_v` 用 `1/σ_v²`（像素量纲）、`w_i` 与 `w_p` 用各自的协方差白化（米/度量纲），三者相加前已各自归一化，不存在量纲失衡。**唯一需要人工调的是三个乘性权重 `w_i, w_p, w_s`**，它们的默认值 1.0 意味着"信噪比相等"，实测后调整。

#### 4.6.3 两阶段 BA（尺度注入的时序）

按 07 §2.8 的强制要求（不得"BA 之后再乘 s"），本文的执行时序：

```
阶段 A：VIO 锚定 BA（尺度 = IMU/VIO 尺度）
   变量：T_i, X_j, b_g,i, b_a,i, g_W, s
   残差：视觉 + IMU + VIO 先验（尺度耦合项）+ 重力 + 零偏
   尺度项：w_s = 0（此时 s_ref 尚未求出）
   输出：T_i^V（米制，含 s_imu 的尺度）、X_j^V

阶段 B：参照物标定（07 §2.6-P2 多视角三角化 → §2.7 闭式解 → §2.9 联合优化）
   输入：T_i^V, X_j^V, 内参, 参照物图像
   输出：s_ref（m/ru）、σ_s/s、置信度

阶段 C：尺度固定 BA（最终）
   变量：T_i, X_j, b_g,i, b_a,i, g_W（s 固定为 s_ref，或保留 s 并给 w_s = 1）
   残差：视觉 + IMU + VIO 先验 + 尺度先验（w_s = 1）
   收敛判据：重投影中位数 ≤ 0.5 px 且尺度残差 |s/s_ref − 1| ≤ 0.02
   输出：最终位姿与稀疏点（米制，自洽）

阶段 D：MVS（§5）—— 使用阶段 C 的位姿
```

> **阶段 A 与 C 的差异**：阶段 A 用 `s_imu` 的隐式尺度（VIO 的米制），阶段 C 用 `s_ref`。两阶段的位姿差异只体现在一个全局尺度因子加上由 `b_a` 吸收的补偿。阶段 C 必须完整重跑（不能只缩放），这正是 07 §2.8 的要求。

#### 4.6.4 局部 BA

局部 BA 用**滑动窗口**（8 帧）+ 窗口外固定帧的位姿作为边界约束：

| 项 | 规格 |
|---|---|
| 变量 | 窗口内的位姿、窗口内的 3D 点、窗口内的零偏 |
| 残差 | 同全局 BA（视觉 + IMU + VIO 先验），但**无尺度项**（局部 BA 不动 gauge；尺度由全局 BA 阶段 C 统一处理） |

## 5. 稠密 MVS（曲面精度的真正来源）

### 5.1 为什么 MVS 决定曲面精度

#### 5.1.1 误差传播公式

单目/多视图几何的深度由**视差**决定。对基线 `B`、焦距 `f`（像素）、深度 `Z`：

```
d = f · B / Z          ⇒          Z = f · B / d
```

对 `d` 求导：

```
δZ = ∂Z/∂d · δd = −(f·B / d²) · δd = −(Z² / (f·B)) · δd
```

取绝对值，**深度误差的主项**：

```
┌─────────────────────────────────────────┐
│   δZ  =  Z² · δd / (f · B)              │
└─────────────────────────────────────────┘
```

这个式子给出三条决定性结论：

| 结论 | 依据 | 工程含义 |
|---|---|---|
| 深度精度与**像素分辨率**成正比 | `δZ ∝ 1/f` | 4K 采集的深度精度是 1080p 的 2 倍。这是 M1（00 §4.5.3）的量化依据 |
| 深度精度与**基线长度**成反比 | `δZ ∝ 1/B` | 大基线（远距离、不同视角）比小基线（相邻帧）精度高得多 |
| 深度精度与**深度平方**成正比 | `δZ ∝ Z²` | 远处的物体精度急剧下降。桌面物体（Z = 0.3–0.5 m）是本产品的最优工作区间 |

#### 5.1.2 代入手机典型参数

参数取值（与 00 §8.8 一致）：

| 符号 | 取值 | 来源 |
|---|---|---|
| `f` | 2500 px（对应 3840×2160 采集、HFOV ≈ 73°）；1080p 时 f ≈ 1250 px | 由 `f = (W/2)/tan(HFOV/2)` 推得，HFOV 取手机主摄典型值 73° |
| `B` | 80 – 150 mm（相邻关键帧基线，由 03 §6.2 的建议角度步长与手持轨迹决定） | 03 §4.5 的角度步长 4°–35° |
| `Z` | 0.30 – 0.50 m（桌面小型物体的推荐工作距离，03 §6.1） | 03 §6.1 |
| `δd` | 0.10 – 0.20 px（亚像素细化后，见 §5.4） | §5.4 的抛物线拟合 + 连续细化 |

**单对视图的深度误差**：

| 工况 | `Z` (m) | `f` (px) | `B` (mm) | `δd` (px) | `δZ` (mm) |
|---|---|---|---|---|---|
| 最好（远、远焦、大基线、精确亚像素） | 0.30 | 2500 | 150 | 0.10 | **0.024** |
| 典型（桌面物体中距，4K） | 0.35 | 2500 | 100 | 0.15 | **0.074** |
| 典型（1080p 采集） | 0.35 | 1250 | 100 | 0.15 | **0.147** |
| 最差（近距、小基线、弱纹理） | 0.50 | 1250 | 80 | 0.20 | **0.250** |

#### 5.1.3 多视图融合后的随机误差衰减

单视图深度误差中，**随机分量**（亚像素定位噪声）在 `N` 个视图上平均后按 `1/√N_eff` 衰减；**系统分量**（内参误差、尺度误差、畸变残差）不衰减。

| 分量 | 是否随视图数衰减 | 折算到形状误差 |
|---|---|---|
| 亚像素定位噪声 | **是**，×1/√N_eff（`N_eff` = 有效支撑视图数；标档 7 个源视图，但某像素实际只有 3–5 个有效） | 0.074 → ~0.035 mm |
| 匹配歧义（NCC 多峰） | 部分 | 0.02 – 0.05 mm |
| 内参 `f` 标定误差 | **否**（∝ Z，全局缩放） | **被全局尺度因子 `s` 吸收 → 不计入形状误差**（见 §6.1） |
| 畸变系数残差 | **否**（随像点半径变化） | 0.05 – 0.15 mm（边缘区） |
| 相机位姿误差（旋转） | 部分（BA 联合优化后） | 0.03 – 0.10 mm |
| 尺度因子 `s` | **否**（全局） | **被 07 参照物标定吸收 → 不计入形状误差** |

#### 5.1.4 与深度传感器对比（量化）

| 方案 | 深度误差量级 | 空间分辨率 | 弱纹理区 | 镜面/透明 |
|---|---|---|---|---|
| ARKit `sceneDepth`（LiDAR） | **厘米级（10–30 mm）** | ~1 cm @ 0.5 m | 不可靠 | 伪距 |
| Android ToF `DEPTH16` | **2 – 8 mm** | ~3 mm @ 0.5 m | 不可靠 | 伪距 |
| ARCore `ALGO_DEPTH` | 5 – 20 mm（随距离变化） | ~4 mm @ 0.5 m | 不可靠 | 伪距 |
| **本分支 MVS（标准档，4K）** | **0.03 – 0.10 mm（形状误差）** | = 像素间距（0.14 mm @0.35 m/4K） | 需引导补光 | 错误几何 |
| **本分支 MVS（标准档，1080p）** | **0.07 – 0.15 mm（形状误差）** | = 像素间距（0.28 mm） | 需引导补光 | 错误几何 |

**结论（可写入对外材料）**：曲面**形状**误差上，无深度机型比深度机型好 1–2 个数量级。绝对**尺寸**精度由参照物标定决定（0.3%–0.5%，见 §7），两分支口径一致。

> **必须同时说明的边界**：MVS 的深度分辨率**等于像素间距**，无法恢复像素以下的细节（4K @0.35 m 为 0.14 mm）。深度传感器虽然单点精度差，但**空间分辨率**由其点阵决定（LiDAR ~1 cm），同样无法提供更细的曲面。两者在"能否表达 0.1 mm 以下的细节"上都不行，这是**共同的物理限制**。

### 5.2 视图选择

#### 5.2.1 参考帧与源视图

| 项 | 规格 | 参数 |
|---|---|---|
| 参考帧 | 全部关键帧依次作为参考帧（`mvs_ref_stride` = 1），**不抽稀**（R-PREC-3） | `mvs_ref_stride`（**需回填 08 G5**） |
| 源视图数 | 5（快）/ 7（标）/ **8**（高） | `mvs_num_views`（08 G5 已有） |
| 选择算法 | 对每个参考帧，从其余关键帧中按 §5.2.2 的四项评分排序取 top-N | — |
| 源视图不足 | 若可用源视图 < 3，该参考帧**跳过**并记 `E_MVS_INSUFFICIENT_VIEWS`（不是拒帧，是这一帧无法出深度） | — |

#### 5.2.2 源视图评分

| 评分项 | 定义 | 权重 | 理由 |
|---|---|---|---|
| 视角夹角 | `θ = ∠(C_i − C_r, 视线方向)`，理想 `θ ∈ [8°, 35°]` | 1.0 | 太小 → 视差不足（δZ ∝ 1/B）；太大 → 遮挡与光度变化 |
| 文本量 | 源视图在参考帧重叠区内的角点数 | 0.8 | 决定 NCC 可靠性 |
| 空间分布 | 源视图角点在该重叠区内的角度标准差 | 0.6 | 角点共线 → 三角化病态 |
| 尺度变化 | 源视图与参考帧的成像尺度比 | 0.4 | 尺度差过大 → patch 匹配退化 |

**尺度变化约束（硬约束）**：

```
| s_i/s_r − 1 | ≤ 0.15       （源视图与参考帧的成像尺度差 15% 以内）
```

超出则该源视图被排除（`W_MVS_VIEW_SCALE_MISMATCH`）。实现：`s_i/s_r ≈ (Z_r / Z_i) · (f_i/f_r)`，其中 `f` 相同、`Z` 由 VIO 位姿给出。

#### 5.2.3 遮挡与可见性预筛

对参考帧的每个像素，源视图可能因遮挡而无对应点。策略：**不做逐像素预筛**（成本过高），而是依赖 §5.5 的多视图一致性在融合阶段剔除。若某参考帧的**有效支撑视图数**（`mvs_min_view_consistency` = 2）不达标，该像素的深度置为无效。

#### 5.2.4 极线约束的使用

源视图与参考帧之间的**本质矩阵** `E` 由 §4.3.4 的两视图几何给出。沿极线的搜索被限制在 ±`max_shear_px` 像素内：

```
| 沿极线的视差搜索范围 | ≤ 40 px（标）/ 60 px（高）/ 25 px（快）
```

参数 `mvs_max_shear_px`（**需回填 08 G5**）。该约束把每像素的搜索从 2D 降到 1D，是 PatchMatch 效率的关键。

### 5.3 PatchMatch 立体匹配

#### 5.3.1 算法选型

| 方案 | 质量 | 速度 | 结论 |
|---|---|---|---|
| 逐像素全范围代价体扫描（plane sweep） | 基准 | 极慢（`W×H×D` 次 NCC） | 只用于**质量上限**的高精度档小物体 |
| 逐像素块匹配（block matching） | 中 | 中 | 不采用（无亚像素精度） |
| **PatchMatch 立体** | 高 | 快（O(W×H×iter)） | **采用** |
| PatchMatch + 视差细化 + 多视图融合 | 最高 | 中 | **采用**（本文方案） |

PatchMatch 立体（Bleyer et al. 2011）在本产品中的适配：

| 适配点 | 说明 |
|---|---|
| 搜索空间 | 从"标量深度"改为"**逆深度 1/Z**"（见下方 §5.3.1.1 的实现修正） |
| 多视图代价 | 每次候选评估同时在 `mvs_num_views` 个源视图上算 NCC（加权），而非单视图 |
| 初始化 | 从 SfM 稀疏点**播种**（不是纯随机）——这是本文相对标准 PatchMatch 的关键改进，见 §5.3.2 |
| 传播 | 4 方向交替扫描 + 随机重启，见 §5.3.4 |

#### 5.3.1.1 实现修正：搜索参数必须是逆深度，不是视差（实测结论）

> **本节记录一次重要的实现修正**，代码与早期文字描述不一致，以本节为准。

原设计用**视差 d** 作 PatchMatch 的搜索参数，深度由 `d = f·B/d` 换算。
实现后经合成场景实测（解析真值），发现**系统性偏差**，根因如下：

| 项 | 视差参数化的缺陷 |
|---|---|
| 多视图不一致 | 对深度 Z，源视图 j 的实际像素位移是 `d_j = f·B_j/Z`，其中 `B_j` 是该视图**沿极线方向**的有效基线（取决于相对旋转，不只是光心距离）。用单一平均基线 B 换算出的 d 对所有视图是同一个值 → 「同一个 d」在不同源视图对应的深度不一致 → 多视图代价被污染 → 深度偏差 |
| 随机搜索步长 | 视差的绝对尺度随深度变化（近景视差大、远景视差小）。固定像素半径在近景过大、远景过小 |

**修正后的方案**：

1. **搜索参数 = 参考帧轴向深度的逆深度 1/Z**。
   各源视图各自用完整位姿投影，天然自洽，无基线近似。
2. **传播量用逆深度**：PatchMatch 的空间传播假设相邻像素的搜索量接近。
   深度是反比关系，逆深度空间才均匀，误差不会在深度上累积。
3. **随机搜索半径用相对比例**（当前深度的 ±30%），而非绝对像素数。
4. **细化窗口用视差尺度**：1 px 视差对应的逆深度变化 = 1/(f·B)，
   拟合窗口按此设定，才能覆盖整数视差量化误差。

**实测效果**（合成场景，f=400px、B=16mm、Z=0.35m，等比缩放自本文 §5.1.2）：

| 阶段 | 深度误差中位 | 相对整数视差 |
|---|---|---|
| 整数视差 | 5.56 mm | 1.00× |
| 亚像素细化后 | **0.88 mm** | **0.16×（改善 6.3 倍）** |

理论预期（δd = 0.15 px）：2.87 mm。**实测优于理论预期 3.3 倍**，
说明实现的亚像素细化有效。

> 对照：同一实现放到真实手机参数（f=2500px、B=100mm、Z=0.35m）时，
> 误差按 Z²/(f·B) 缩小 6.25 倍 → 中位约 0.14 mm，与本文 §6.1 的
> 0.074–0.171 mm 精度预算一致。

#### 5.3.2 初始化：稀疏点播种

标准 PatchMatch 从随机深度开始，需要 6–10 轮才收敛。本文用 SfM 的稀疏三角化点播种：

```
① 对参考帧 r，把 SfM 稀疏点投影到 r，得到 (u, v, Z_sparse)
② 建立稀疏深度图：每个像素取最近邻稀疏点的深度（空间网格哈希，查询 O(1)）
③ 稀疏图做 3×3 中值 + 孔洞填补（迭代 3 次，最近邻填充）
④ 未被覆盖的像素（覆盖率 < 55% 时）用**随机视差**初始化，范围 [d_min, d_max]
```

| 项 | 取值 | 说明 |
|---|---|---|
| 稀疏点覆盖率（投影后落在参考帧内的比例） | 标档典型 35%–65% | 取决于物体纹理与视角数 |
| 稀疏图填补迭代 | 3 | — |
| 播种后的初始代价 | 全图按 §5.3.5 的公式统一计算一次 | 避免前几轮全为"极差"导致传播失效 |

**收益（量化）**：随机初始化需要 6–10 轮 PatchMatch 才能收敛；稀疏播种后 **2–3 轮**即可收敛，耗时降低 **50%–65%**，且在弱纹理区的收敛质量更好（稀疏点本身来自强纹理区）。这是本文相对通用实现的主要工程增量。

> **注意**：稀疏点来自 SfM，其深度本身有误差（0.5%–3%，07 §2.10.1）。播种只影响**收敛速度与初值**，最终深度由 §5.3.5 的代价函数重新优化，因此**不引入额外误差**。

#### 5.3.3 代价函数

对参考帧像素 `p`，候选视差 `d`：

```
① 对每个源视图 v_j：
     p_j = π(K_j, R_j (R_rᵀ (Z(d)·K_r⁻¹p̃_r − t_r) + t_j))   ← 用位姿把参考帧的 3D 点投到源视图
     NCC_j = 零均值归一化互相关，窗口 mvs_patch_size = 11×11（标/高），7×7（快）
② 光度代价：
     C_photo = 1 − ( Σ_j w_j · NCC_j ) / ( Σ_j w_j )
     w_j = 1 （标/高）；快档 w_j = 归一化的视角夹角权重
③ 几何一致性代价（可选，每 3 轮启用一次）：
     C_geo = min_j | Z_vj(p_j) − Z(d) | / Z(d)        ← 需要源视图深度图（见 §5.6）
④ 平滑正则（在视差倒数空间做，避免远处过度平滑）：
     C_smooth = ‖ 1/d − mean_{3×3}(1/d) ‖²
⑤ 总代价：
     C = C_photo + mvs_depth_regularization · C_smooth
```

| 项 | 取值 | 参数 |
|---|---|---|
| `mvs_patch_size` | 11 px（标/高），7 px（快） | 08 G5 已有 |
| `mvs_photo_threshold` | 1.0（标）→ 接受条件 `1 − NCC ≤ 1.0` 即 `NCC ≥ 0` | 08 G5 已有（**单位需回填 08 G5**：定义为 `1 − NCC`） |
| `mvs_depth_regularization` | 0.02（标）/ 0.01（高）/ 0.05（快） | 08 G5 已有 |
| `mvs_geo_consistency_threshold` | 1.2（标）→ 定义为**相对深度偏差百分数** | 08 G5 已有（**单位需回填 08 G5**：补 "%"） |
| 光度阈值外的硬拒绝 | `C_photo > 3 × mvs_photo_threshold` → 该候选直接判为不可行 | — |

**零均值归一化互相关（NCC）的实现要点**：

```
NCC = Σ (I − Ī)(J − J̄) / ( √(Σ(I − Ī)²) · √(Σ(J − J̄)²) )
```

`Ī, J̄` 为窗口均值。窗口内方差过小（纯色区域）时 NCC 无定义 → 该像素标记为**弱纹理像素**，其深度**降权 50%**（不是丢弃，R-PREC-1）。

#### 5.3.4 传播与随机搜索

PatchMatch 的三个核心操作：

```
每轮迭代（标档 4 轮；快 3 轮，高 6 轮）：
  ① 空间传播：按 4 个方向轮流扫描
       方向 0: (x: 0→W-1, y: 0→H-1)
       方向 1: (x: W-1→0, y: 0→H-1)
       方向 2: (x: 0→W-1, y: H-1→0)
       方向 3: (x: W-1→0, y: H-1→0)
     对像素 p，用邻居 q（已在本轮更新过）的视差作为候选：
       d_cand = d_q + 沿极线方向的视差补偿
       评估 C(p, d_cand)，若更优则替换 d_p
  ② 随机搜索：以当前最优视差 d_p 为中心，半径按指数收缩
       r_k = r_max · 2^(−k) ,  r_max = 32 px,  k = 0..4  （共 5 次）
       d_cand = d_p + rand(−r_k, +r_k)，裁剪到 [d_min, d_max]
  ③ 随机重启（每轮 5% 的像素）：d_cand = 随机分布于 [d_min, d_max]
```

| 项 | 取值 | 参数 |
|---|---|---|
| 迭代轮数 | 3（快）/ **4**（标）/ 6（高） | `mvs_patch_iterations`（08 G5 已有，**语义需回填 08 G5**：定义为"PatchMatch 外迭代轮数"） |
| 随机搜索次数 | 5 | `mvs_pm_random_search_count`（**需回填 08 G5**） |
| 随机搜索初始半径 | **当前深度的 ±30%**（逆深度相对比例） | `mvs_pm_search_radius_ratio`（**需回填 08 G5**，取代原 `mvs_pm_search_radius_px`） |
| 随机重启比例 | 5% | `mvs_pm_restart_ratio`（**需回填 08 G5**） |
| 传播方向数 | 4 | `mvs_pm_directions`（**需回填 08 G5**） |
| 视差范围 | 由 `mvs_depth_min/max` 与基线反算：`d ∈ [f·B/Z_max, f·B/Z_min]` | 08 G5 已有 |
| 传播开关 | `mvs_propagation_enabled` = 1 | 08 G5 已有 |

**GPU 上的并行策略**：4 方向扫描在 GPU 上无法在同一 dispatch 内完成（存在全局依赖）。本文采用 **red-black（棋盘）并行传播**替代顺序扫描：

```
① 把像素按 (x+y) 奇偶分成两组，红组与黑组交替处理
② 一次 dispatch 处理一个颜色组，组内像素互不依赖（8 邻域中同色组只有 4 个对角邻居）
③ 4 方向扫描的等价性由"多轮交替方向"近似：
   红/黑交替 4 次 ≈ 4 方向扫描的收敛效果，但迭代数从 4 提到 8
```

**代价**：迭代数 4 → 8，MVS 耗时 ×1.8。**缓解**：稀疏播种后收敛快，实测总迭代数可降到 6（`mvs_patch_iterations` 高档给 6）。这一项列入 §9 待实测标定。

#### 5.3.5 候选评估的并行化

| 项 | 规格 |
|---|---|
| 一个像素一次评估的计算量 | `mvs_num_views` × `mvs_patch_size²` × ~6 flops = 7×121×6 ≈ 5.1 kflop |
| 4K 全图（8.29 Mpx）× 8 迭代 | 8.29e6 × 8 × 5.1e3 = 3.4e11 flop |
| 中端手机 GPU（实测 ~0.4 TFLOP/s 有效吞吐） | **~850 s**（理论下限，不含访存与 NCC 窗口复用） |
| 访存瓶颈 | NCC 需 7 个源视图的 patch 读取；单次评估读 7×121 B ≈ 850 B。总量 8.29e6×8×850 = 5.6e13 B = 56 TB → 若显存带宽 30 GB/s → 1870 s |
| **结论** | **访存是瓶颈**，必须靠 **patch 共享内存复用**（tile-based）把带宽降低一个数量级 |

**Tile-based 实现**（本文的 GPU 关键设计）：

```
① 把参考帧切成 tile（默认 1024×1024，参数 mvs_gpu_tile_size）
② 对每个 tile：
     - 把参考帧 patch 的像素值载入 shared memory（按 8×8 workgroup 分块加载）
     - 对每个源视图，只加载与该 tile 投影区域对应的源图区域（带 11 px halo）
     - 在 shared memory 中复用参考 patch，避免重复读取
③ 访存降低：参考 patch 读取次数从 N_views×iter×pixels 降到 pixels（摊销）
   → 理论带宽需求从 56 TB 降到 ~8 TB（仍受源图读取主导）
④ 源图读取的进一步优化：
   - 源图金字塔 level 1（半分辨率）只用于**粗搜**（第 1–2 轮），level 0 用于精搜
   - 这是 00 §1.2 白名单中的"稠密匹配的图像金字塔层（仅影响首轮粗搜）"
```

### 5.4 视差细化（亚像素）

PatchMatch 输出的是**整数视差**。整数视差的深度误差是 `δd = 0.5 px`，对应 `δZ = Z²·0.5/(fB)` = 0.12 – 0.63 mm（§5.1.2 的表乘 2.5–5 倍）。因此亚像素细化是**必需**步骤。

#### 5.4.1 三级细化

| 级 | 方法 | 精度贡献 | 计算量 |
|---|---|---|---|
| ① 抛物线拟合 | 在最优整数视差 `d*` 及其左右邻居的代价上拟合抛物线，取顶点 | `δd ≈ 0.10 – 0.25 px` | 3–5× NCC 评估 |
| ② 连续局部细化 | 以抛物线顶点为起点，在 ±0.5 px 内以 0.1 px 步长做 1D 黄金分割搜索 | `δd ≈ 0.05 – 0.12 px` | ~8× NCC 评估 |
| ③ 亚像素投影一致性 | 在最终视差下，源视图的投影点与参考帧像素的**半像素偏差**做双线性插值补偿 | 消除 0.02 px 的系统偏差 | 1× 插值 |

| 项 | 取值 | 参数 |
|---|---|---|
| 抛物线拟合最小二乘点数 | 5（`d*−2 … d*+2`） | `mvs_subpixel_fit_points`（**需回填 08 G5**） |
| 连续细化迭代数 | 3（快）/ **4**（标）/ 6（高） | `mvs_subpixel_iterations`（**需回填 08 G5**） |
| 细化窗口半宽 | **1 px 视差对应的逆深度变化** = 1/(f·B) | `mvs_subpixel_window_ratio`（**需回填 08 G5**，取代原 `mvs_subpixel_step_px`） |
| 收敛判据 | 相邻两次迭代代价差 < 1e-4 | — |

#### 5.4.2 细化后的有效视差精度

| 纹理状况 | `δd`（标准档） | 说明 |
|---|---|---|
| 强纹理（家具、鞋、织物） | **0.05 – 0.10 px** | 抛物线拟合的顶点可达 0.05 px |
| 中等纹理 | 0.10 – 0.20 px | |
| 弱纹理（纯色但有光照梯度） | 0.20 – 0.50 px | NCC 曲线平坦，顶点定位不准 |
| 无纹理 | > 1.0 px | 深度无效（见 §6.4） |

> §5.1.2 的算例采用 `δd = 0.15 px`（中等纹理），这是**保守取值**，实测必须按 §6.4 的网格分类统计。

### 5.5 多视图融合

#### 5.5.1 融合对象

每个参考帧 `r` 产生一张深度图 `D_r`（float32，单位米）与一张置信度图 `C_r`。融合把它们统一到**世界系**，写入体素哈希网格。

#### 5.5.2 体素融合

```
体素边长：mvs_fusion_voxel_size = 0.0005 m（标/高，0.5 mm）/ 0.001 m（快）
          参数 mvs_fusion_voxel_size（需回填 08 G5）
网格范围：由所有参考帧的深度范围 + 1.5 × 物体尺度 界定（此时已是米制，不依赖尺度 s）
每个体素累加：Σ Z_i （深度加权和）、Σ w_i、Σ n_i（法向加权和）、N_support
```

#### 5.5.3 权重

每个视图对体素的贡献权重：

```
w_i = w_photo,i × w_geo,i × w_ang,i × w_tex,i

w_photo,i = exp( −C_photo,i / σ_photo )      σ_photo = 0.5（标）
w_geo,i   = exp( −C_geo,i / σ_geo )          σ_geo = 0.02（标）
w_ang,i   = cos(θ_i)                        θ_i = 该视图视线与体素法向的夹角
w_tex,i   = 1 − 0.5 · [该像素方差低于阈值的程度]   （弱纹理降权，不丢弃）
```

| 项 | 依据 |
|---|---|
| 为什么光度权重要最高 | 光度残差直接反映该视图的匹配可靠性（§5.3.3） |
| 为什么几何权重要存在 | 匹配正确但几何不一致（光流误差沿极线方向）的情况由几何项捕获 |
| 为什么角度权重要存在 | 掠射视角（`cos θ` 小）的观测，其深度不确定度按 `1/cos θ` 放大 |
| 为什么弱纹理只降权 | R-PREC-1：降权 ≠ 丢弃（与 02 §4.5.2 的 `highlight_cells` 处理一致） |

| 参数 | 取值 | 状态 |
|---|---|---|
| `mvs_fusion_weight_photo` | 1.0 | **需回填 08 G5** |
| `mvs_fusion_weight_geo` | 1.0 | **需回填 08 G5** |
| `mvs_fusion_weight_angle` | 1.0 | **需回填 08 G5** |
| `mvs_fusion_voxel_size` | 0.0005 m | **需回填 08 G5** |

#### 5.5.4 一致性检查

| 检查 | 判据 | 不通过时 |
|---|---|---|
| 支撑视图数 | `N_support ≥ mvs_min_view_consistency`（标/高 = 2，快 = 3） | 该体素剔除 |
| 深度离散度 | 体素内深度的加权标准差 `σ_Z / Z̄ ≤ 0.02`（标）/ 0.01（高）/ 0.04（快） | 该体素降权 50% |
| 跨视图互检 | 每个视图的深度与体素融合深度的偏差 `\|Z_i − Z̄\| / Z̄ ≤ mvs_geo_consistency_threshold`（1.2%） | 该视图从该体素剔除；若剔除后 `N_support < 2` 则体素剔除 |
| 法向一致性 | 融合法向与各视图法向的夹角 ≤ 45° | 异常视图剔除 |
| 离群点 | 融合点云的 SOR/ROR 离群剔除（06 §2.2），`mvs_outlier_filter_sigma` = 2.0（标） | 剔除 |

> **08 文档的 `mvs_geo_consistency_threshold` 单位问题**：该参数默认值 1.2、范围 [0.1, 10.0]，原表未标单位。本文明确其定义为**相对深度偏差的百分数**（1.2 表示 1.2%）。**需回填 08 文档 G5 组**补单位列。

### 5.6 几何一致性过滤

#### 5.6.1 目的

光度一致性（§5.3.3）可能在**重复纹理**上给出"错误但光度上很优"的匹配。几何一致性用**另一个视角的独立深度**来交叉验证，把这类错误剔除。

#### 5.6.2 单视图一致性（unilateral）

参数 `mvs_unilateral_check_enabled` = 1。流程：

```
① 对参考帧 r 的深度图 D_r 与源视图 v 的深度图 D_v：
     把 D_r 的像素 3D 点投影到 v，得到 (p_v, Z_v_proj)
② 在 D_v 的 p_v 处取深度 Z_v_map
③ 一致性偏差：e = |Z_v_proj − Z_v_map| / max(Z_v_proj, Z_v_map)
④ 判定：
     e ≤ mvs_geo_consistency_threshold (1.2%)   → 通过
     e > 3 × threshold                          → 拒绝该深度（置为无效）
     中间区间                                    → 保留但置信度 × (1 − e/(3×threshold))
```

> **实现顺序**：单视图一致性需要源视图的深度图，而源视图深度图本身由 PatchMatch 产出。因此实际执行是**两轮**：
> 第一轮：用参考帧与其源视图集合的 PatchMatch 结果做**光度一致性**融合，得到初步深度图；
> 第二轮：用初步深度图做 §5.6.2 的单视图一致性 + §5.5.4 的融合，得到最终深度图。
> 这就是 00 §1.2 白名单中"稠密匹配的图像金字塔层（仅影响首轮粗搜）"的另一层含义：**两轮结构是必要设计，不是降级**。

#### 5.6.3 跨视图互检（geometric verification）

参数 `mvs_geometric_verification_enabled` = 1。在 §5.5.4 的融合阶段执行，判据已在 §5.5.4 给出。

#### 5.6.4 尺度一致性

MVS 深度基于 BA 的位姿。若 BA 的尺度自洽（§4.8 的 `|s/s_ref − 1| ≤ 0.02`），MVS 深度自动自洽。**MVS 不引入任何独立的尺度自由度**，也不做"事后乘 s"。

### 5.7 光度一致性检查

| 阶段 | 检查内容 | 阈值 | 处置 |
|---|---|---|---|
| MVS（§5.5） | 深度图的视图间 NCC | `NCC ≥ 0`（`mvs_photo_threshold` = 1.0） | 不达标 → 该深度置信度降权 |
| MVS（§5.5） | 融合点云反投影回各视图的重采样颜色与原图差异 | 平均绝对差 ≤ 0.08（归一化到 [0,1]） | 超限 → 该点剔除 |
| 06 §2.9 | 烘焙时的可见性测试 | `post_bake_visibility_tol_mult` = 3.0 | 低覆盖 → 顶点权重下调 |

#### 5.7.1 反光区的光度一致性失效

镜面区域的光度一致性**必然**失败（不同视角看到的是不同环境）。本文**不**试图修复，只做标记：

```
若某像素在 ≥ 3 个源视图上的 NCC 均 < 0 且该区域的光流残差大（> 2 px），
   且 02 §4.5 的 sat_ratio 判据命中            ⇒ 标记 kind = "reflective"
若某像素在多帧中 NCC 均 < 0，
   且 03 §6.5.2 步骤 2 的判据命中              ⇒ 标记 kind = "transparent"
```

两者写入 `recon_mesh_info.json` 的 `unreliable_regions`（I3 接口）。

### 5.8 边界处理

三类边界必须分别处理，处理方式**互不相同**：

#### 5.8.1 天空 / 远背景

| 判据 | 阈值 | 处置 |
|---|---|---|
| 深度达到上界 | `Z ≥ 0.95 × mvs_depth_max` | 该像素深度置为无效 |
| 深度不连续且后方无支撑 | `Z` 突变 > 15% 且突变点后方的支撑视图数 < `mvs_min_view_consistency` | 突变后方置为无效 |
| 与物体中心距离 | 该点到物体中心 `C` 的距离 > 2.5 × 物体包围盒半径 | 置为无效（超出扫描目标的点） |
| 无 SfM 支撑 | 该像素对应的 3D 点在 SfM 稀疏图中无对应观测 | 深度置信度 × 0.3 |

> **不做天空检测的语义模型**。天空在图像上是"无穷远"，其深度在有限范围搜索下表现为"达到上界"，这已被第一条覆盖。任何基于亮度的天空启发式都会在白色背景物体上误判，故不采用。

#### 5.8.2 遮挡边界

| 判据 | 阈值 | 处置 |
|---|---|---|
| 前后视差不一致 | 沿极线方向，把源视图深度投影到参考帧，视差差 > `mvs_occlusion_disparity_px`（标 2.0 px） | 靠近遮挡边界的一侧深度置为无效 |
| 深度梯度异常 | `\|∇Z\| > 0.15 × Z` 且梯度方向与视线方向夹角 > 60° | 深度保留（真实陡边），置信度 × 0.5 |
| 边界带膨胀 | 对判为无效的像素做 1 px 的 3×3 膨胀，膨胀带也置为无效 | 避免"拖尾"伪影 |

#### 5.8.3 物体轮廓边界

| 判据 | 阈值 | 处置 |
|---|---|---|
| 前后景深度比 | 前景 `Z_f` 与背景 `Z_b` 之比 `Z_b/Z_f > 1.5` | 背景置为无效（不属于物体） |
| 支撑视图一致 | 背景区的支撑视图数 < 2 | 置为无效 |
| 边界保持 | 前景侧最后 2 px 保留 | 不做形态学腐蚀（避免丢失真实边缘） |

> **轮廓边界的精度意义**：MVS 深度在物体轮廓处的误差最大（前后景深度不连续 + 遮挡）。本文的处理是**保守剔除**而非"填平"。填平会产生"斜坡"伪影，直接破坏 00 §4.6 的"对称面重投影中位数 ≤ 0.5 px"验收项。

### 5.9 GPU 实现

#### 5.9.1 Metal / Vulkan 算法映射

两端使用**同一套算法描述**（`shaders/common/` 的 `.h` 风格伪代码），分别编译为 `.metal` 与 `.comp`（00 §3.2）。映射关系：

| 算法 | Metal | Vulkan | 备注 |
|---|---|---|---|
| 计算管线 | `MTLComputePipelineState` + `MTLComputeCommandEncoder` | `VkPipeline` + `VkCommandBuffer` + descriptor set | |
| 分派 | `dispatchThreadgroups(x, y, z)` | `vkCmdDispatch(x, y, z)` | |
| workgroup | `threadgroup_size` 在 `.metal` 中声明 | `local_size_x/y/z` 在 `.comp` 中声明 | 统一 8×8 = 64 线程 |
| 共享内存 | `threadgroup` 变量 | `shared` 变量 | 尺寸受 `maxTotalThreadgroupMemory` 限制 |
| 采样 | `texture2d<float, access::read>` + `read(uint2)`（**不用 sampler**） | `texture2D` + `texelFetch`（**不用 sampler**） | **必须最近邻**（04 §4.6.1 硬要求；见下「D-4 修订」） |
| 原子操作 | `atomic_fetch_min_explicit` | `atomicMin` | 用于投票（**整型**） |
| 屏障 | `memoryBarrier` / `threadgroup_barrier` | `barrier()` / `memoryBarrierShared` | |
| 精度 | `float`（视差与代价**一律 fp32**） | `float32`（**不用 `f16`**） | **默认不启用 fp16**（`RECON_GPU_ALLOW_FP16_DEFAULT 0`；见下「D-5 修订」） |

> **D-4 修订（2026-10-31，采样过滤）**：本表原写「线性过滤」，与 04 §4.6.1
> 的**硬要求**冲突 —— 后者明列「深度图必须用**最近邻**采样」（`access::read` /
> `texelFetch`，无 `sampler`、无滤波）。**以硬要求为准**：两端一律最近邻。
> 线性过滤会跨深度不连续边界混合前后景深度，直接破坏 00 §4.6 的轮廓精度验收项。
> 这是「两份契约自相矛盾 → 以可验证的硬判据裁决」的一次应用（见 MEMORY.md）。
>
> **D-42 修订（2026-11-01，原子口径消歧）**：本表的「原子操作」行易被误读为
> 「`recon_mvs_fuse_voxel` 的 S/W 累加也走这两个函数」。**不是** —— 该行指的是
> **投票**用的整型 `atomicMin`/`atomic_fetch_min_explicit`；而 CB-5 体素融合的
> 累加用的是 **`atomicAdd`**，且**两端统一为定点整数原子**：Metal `atomic_int`
> + `atomic_fetch_add_explicit`、Vulkan `int` + `atomicAdd`。
> 理由：浮点原子在两端都不能依赖 —— Metal 的 `atomic_float` 是 **Metal 3.0 /
> iOS 16** 起才有，本项目部署下限是 **iOS 15.0**（docs/12 §4.6）；Vulkan 需
> `VK_EXT_shader_atomic_float` 扩展。定量尺度（scale = 2^12、上界 2^30）与
> 三段数学式登记在 `shaders/common/gpu_algo.h` 的 `RECON_GPU_FIXED_*` 段，
> 两端同构性由闸门 **P13** 校验；编译侧须传 `-target`（docs/12 §4.4，D-42 段）。
> 实现侧对照：`shaders/metal/gpu_common.h` / `shaders/vulkan/gpu_common.glsl`
> 的 `RECON_GPU_DIFF(4)`（`VK-DIFF-4 / MSL-DIFF-4`）。
>
> **D-5 修订（2026-10-31，视差精度）**：本表原写「视差用 fp16 足够」，与 12 §3.2 的
> 「`mvs` 的视差精度用 `float32` 而非 `f16`」冲突。**以默认值为准**：公共头
> `shaders/common/gpu_algo.h` 的 `RECON_GPU_ALLOW_FP16_DEFAULT` 已定为 `0`
> —— 默认**不启用** fp16，视差与代价一律 fp32。理由：32 位设备普遍不支持
> Vulkan `shaderFloat16`，且 fp16 的 1/1024 相对精度在深度 5 m 处对应约 5 mm，
> 与 MVS 亚像素 0.88 mm 的目标**同量级**，不留裕度。若要启用 fp16，必须经
> ABI 分支显式选择并记入 `degradation_summary`（14 CT-9），不得静默降级。

**统一 workgroup 尺寸的取舍**：

| 尺寸 | 每 workgroup 共享内存需求（当前 workgroup 覆盖 8×8 + 5 px halo） | 占用率 | 结论 |
|---|---|---|---|
| 8×8 = 64 | `(8+10)² × 4 B`（代价缓存）+ `(8+10)² × 1 B`（参考灰度）≈ 7.4 KB | 高 | **采用** |
| 16×16 = 256 | 4 倍 ≈ 30 KB | 中（接近 32 KB 限额） | 备选 |
| 16×16 = 256（tile 局部 32×32） | 32 KB | 中 | 超限风险 |

Metal 的 `maxTotalThreadgroupMemory` 典型为 32 KB（iOS）/ 64 KB（部分 Android）。因此 **tile 的共享内存不是全 tile，而是"当前 workgroup 覆盖的 8×8 区域 + halo"**，把 halo 复用率提到 90%。

#### 5.9.2 Compute Shader 分派策略

```
层次 1：帧级 dispatch
   每个参考帧一次命令缓冲区录制
层次 2：tile 级 dispatch
   tile = 1024×1024 像素（mvs_gpu_tile_size）
   4K → 4×3 = 12 tiles/帧；1080p → 2×2 = 4 tiles/帧
层次 3：迭代级 dispatch
   每次 PatchMatch 迭代 = 1 次 dispatch（红/黑交替 → 2 次 dispatch）
   标档 4 迭代 × 2（红黑） = 8 dispatch/tile
层次 4：细化级 dispatch
   抛物线拟合 + 连续细化 = 1 次 dispatch/tile
层次 5：融合级 dispatch
   全部 tile 完成后，1 次 dispatch 做体素散射（atomicAdd）
```

| 命令缓冲区 | 内容 | 数量（4K，标档） |
|---|---|---|
| CB-1 | 播种（稀疏点投影 + 中值 + 填补 + 初始代价） | 1 |
| CB-2 | PatchMatch 主循环（8 dispatch） | 1 |
| CB-3 | 亚像素细化 | 1 |
| CB-4 | 单视图一致性（依赖全部源视图深度） | 1 |
| CB-5 | 体素融合（atomicAdd 散射） | 1 |
| CB-6 | 融合归约 + 一致性检查 | 1 |

**关键约束**：CB-4 必须等待所有源视图的深度图完成 → **源视图的深度图必须常驻显存**（或分批重算）。这是 §5.9.3 显存估算的主要来源。

#### 5.9.3 显存占用估算

单参考帧的常驻量：

| 缓冲 | 元素类型 | 1080p (2.07 Mpx) | 4K (8.29 Mpx) |
|---|---|---|---|
| 参考帧深度图 | float32 | 8.3 MB | 33.2 MB |
| 参考帧代价图 | float32 | 8.3 MB | 33.2 MB |
| NCC 累加器 | float32 | 8.3 MB | 33.2 MB |
| 支撑视图计数 | uint16 | 4.1 MB | 16.6 MB |
| 参考帧法向图 | float32×3 | 24.9 MB | 99.5 MB |
| 源视图灰度金字塔（7 个，1.33 系数） | uint8 | 19.3 MB | 77.2 MB |
| 源视图深度图（7 个） | float32 | 58.1 MB | 232.5 MB |
| PatchMatch ping-pong（深度+代价） | float32×2 | 33.2 MB | 132.8 MB |
| **小计（全图常驻）** | | **164.5 MB** | **658.2 MB** |
| **峰值（含融合点云缓冲）** | | **~410 MB** | **~1.64 GB** |

| 配置 | 4K 全图 | 4K 分块（tile 512²） | 1080p 全图 |
|---|---|---|---|
| 峰值显存 | ~1.64 GB | **~420 MB** | ~410 MB |
| `perf_gpu_memory_budget_mb`（标 1024 / 高 2048） | 高档超限 → 分块 | 达标 | 达标 |

#### 5.9.4 CPU 回退

`perf_gpu_enabled = 0` 时：

| 项 | 规格 |
|---|---|
| 实现 | 同一套算法描述的 CPU 版本（`shaders/common/` 的 `.h` 伪代码同时提供 CPU 实现），SSE/AVX2 显式向量化 |

## 6. 精度保障与失败诊断

### 6.1 精度预算表

#### 6.1.1 误差分级与口径

本文把最终模型误差拆成三级，**不同级对应不同的度量方式，不可混用**：

| 级别 | 名称 | 定义 | 度量方式 | 对应 00 §4.6 验收项 |
|---|---|---|---|---|
| L-A | **形状误差** | 曲面相对于真实形状的偏差（已扣除全局尺度与刚体变换） | 与高精度参考（激光扫描 / CMMS）比对，扣除最佳拟合相似变换后的 RMS 偏差 | "相对几何误差"（对称面重投影中位数 ≤ 0.5 px） |
| L-B | **尺度误差** | 整体尺寸的相对偏差 | 与参照物真值比对 | "尺度相对误差 ≤ 1.0%"、"尺度重复性 ≤ 0.5%" |
| L-C | **局部噪声** | 单点深度的不确定度 | 深度图自身的方差 | 无直接验收项，由 L-A 吸收 |

> **为什么必须分级**：00 §4.6 把"相对几何误差 ≤ 0.5 px"与"尺度相对误差 ≤ 1.0%"分成两行，正是因为它们的来源完全不同（前者是 MVS 视差精度，后者是参照物标定精度）。把两者混为一谈会导致错误的精度宣称。

```

```

对照 00 §4.6 的验收口径（对称面重投影中位数 ≤ 0.5 px）：

| 检验 | 关系 | 结果 |
|---|---|---|
| 0.17 mm 的深度偏差对应的重投影误差 | `δu = δZ · f / Z` = 0.00017 × 2500/0.35 = **1.21 px** | **超标**（验收限 0.5 px） |
| 反推：0.5 px 重投影对应的深度误差 | `δZ = 0.5 px × Z/f` = 0.5/2500 × 0.35 = **0.070 mm** | 验收隐含的形状误差上限是 **0.07 mm** |

> **必须诚实指出的差距**：§6.1.2 算出的 0.17 mm 与 00 §4.6 的 0.5 px 重投影口径之间存在约 2.4 倍的差距。原因是两者度量的**不是同一件事**：
> - 0.5 px 重投影误差度量的是**稀疏点在 BA 优化后的相机平面上的自洽性**（几何一致性），它可以很小；
> - 0.17 mm 度量的是**稠密曲面的绝对形状偏差**，它包含了 MVS 深度噪声、融合离散化、网格化、后处理的全部累积。
>
> 二者可以同时满足（在稀疏点处自洽、在曲面上有 0.17 mm 偏差），也可以不同时满足。**本文不声称"0.5 px 重投影误差等价于 0.07 mm 形状误差"。** 正确的表述是：两者是**互补的独立验收项**，都必须在 14 文档中分别检验。

#### 6.1.4 尺度误差（L-B）逐级传递表

| 级 | 误差来源 | 符号 | 计算式 | 贡献 (mm @ L_max=300 mm) | 可否衰减 |
|---|---|---|---|---|---|
| 1 | 参照物尺寸公差 | `σ_L` | ISO ID-1：`σ_L` = 0.29 mm（07 §2.1） | 0.29 | 不可（制造公差） |
| 2 | 卡片角点定位误差 | `σ_k` | 直线拟合残差 1.5 px，2 视图几何 → 相对误差 0.5% | 1.50 | 不可（提高角点数可微降） |
| 3 | 三角化深度误差（BRANCH_MONO 路径 P2） | `σ_ε` | 07 §2.10.1：纯 MVS 三角化 2.0% | 6.00 | **可**（增加视角数） |
| 4 | 形状误差的尺度型部分 | — | L-A 中的全局缩放分量（由内参 `f` 标定误差引入） | 0.50 | 可（提高内参精度） |
| 5 | IMU 尺度先验（不参与最终尺度） | — | 5%–10%（00 §8.7），仅作交叉校验，不叠加进误差 | 0（不入账） | — |

**合成（RSS）**：

```
σ_s/L = sqrt( (0.29/300)² + (0.005)² + (0.02)² + (0.0017)² )
      = sqrt( 9.3e-7 + 2.5e-5 + 4.0e-4 + 2.9e-6 )
      = sqrt(4.327e-4) = 0.0208  →  2.08%
```

**结果 2.08% 超过 00 §4.6 的 ≤ 1.0% 验收线。必须给出降低路径。**

| 措施 | 效果 | 代价 |
|---|---|---|
| **M-A：提高三角化精度**（07 §2.9 的多视角联合优化，`calib_refine_enabled` = 1） | 三角化相对误差 2.0% → 0.6%（3 个以上视角 + 联合优化） | 标定耗时 +30% |
| **M-B：增加标定视角数**（≥ 3，07 §2.6-P2 的 `calib_triangulate_min_views` = 3） | 2.0% → 1.0%（视角数 2→3，视差噪声按 1/√N 衰减） | 用户多拍 1–2 张 |
| **M-C：改用已知尺寸的物体表面特征**（M2 手动模式，07 §3.1） | 避开卡片检测误差，σ_ε 降到 0.3% | 需用户提供实测尺寸 |
| **M-D：卡片平贴在被测表面上**（07 §2.3.4 的平面假设） | 消除透视假设失效导致的偏差 | 用户操作要求 |

**应用 M-A + M-B 后的合成**：

```
σ_s/L = sqrt( (0.29/300)² + (0.005)² + (0.010)² + (0.0017)² )
      = sqrt( 9.3e-7 + 2.5e-5 + 1.0e-4 + 2.9e-6 ) = 0.01035  →  1.04%
```

**再应用 M-C（手动模式，σ_ε = 0.3%）**：

```
σ_s/L = sqrt( (0.10/300)² + (0.003)² + (0.0017)² ) = sqrt(1.1e-7 + 9e-6 + 2.9e-6) = 0.00347 → 0.35%
```

| 标定方式 | 合成相对不确定度 | 满足 00 §4.6 的 ≤ 1.0% | 满足 07 §2.10.3 的"高置信 ≤ 2%" |
|---|---|---|---|
| 参照物单帧闭式解（2 视角） | 2.08% | ✗ | ✗（超过 2%） |
| 参照物多视角联合（≥3 视角） | 1.04% | ✓（勉强） | ✓ |
| 参照物多视角 + 手动尺寸 | **0.35%** | ✓ | ✓ |

> **结论（必须写入 07 文档与 UI）**：**单帧参照物闭式解在 300 mm 物体上不满足 ≤ 1.0% 的尺度验收线（2.08%）**。因此在 `BRANCH_MONO` 中，参照物标定**必须走多视角联合优化路径**（`calib_refine_enabled` = 1 且 `calib_triangulate_min_views` = 3），单帧闭式解仅作为回退链的第二级（07 §5.2 ②）。这不是"可选优化"，是**达标必要条件**。

#### 6.2.2 "无深度机型不降级"的量化依据

四条论证，逐条给出数字：

**论证 1：曲面精度由 MVS 决定，两分支共用同一份代码**

| 指标 | RGBD（LiDAR） | RGBD（ToF） | MONO |
|---|---|---|---|
| 深度/曲面误差 | 10–30 mm | 2–8 mm | **0.12–0.17 mm** |
| MVS 曲面误差（两分支共同的上限） | 0.12–0.17 mm | 0.12–0.17 mm | 0.12–0.17 mm |
| 实际曲面误差 | 0.12–0.17 mm（MVS 主导） | 0.12–0.17 mm | 0.12–0.17 mm |

**数值来源**：00 §8.1（ARKit sceneDepth 厘米级）、00 §8.2（ToF 2–8 mm）、00 §8.8（MVS 0.2–0.5 mm）、本文 §6.1（MVS 0.12–0.17 mm）。

结论：**两条分支的最终曲面误差由同一份 MVS 代码决定，因此相等。深度传感器的精度不进入最终曲面误差**（00 §4.2 关键工程决策：LiDAR 只做尺度锚定、先验、补盲）。

**论证 2：验收口径完全共用**

00 §4.6 明文："两条分支共用同一套验收指标，任一分支达不到即判定为缺陷，不得以'机型差异'为由豁免。"本分支逐项落实（§1.2）且无一项依赖深度帧。

**论证 3：唯一劣势项有明确的工程解法，且劣势范围可界定**

| 劣势项 | 差距 | 解法 | 剩余风险 |
|---|---|---|---|
| 弱纹理区孔洞 | RGBD 可用深度直接生成；MONO 需泊松外推 | §6.4 的光照引导 + 多视角互补 | 若物体本身是纯色哑光且用户不补光，G3（泊松外推）兜底，**必须标注推断区**（00 §4.5.4） |

这是**能力边界**（00 §4.5.5 表格已列明"纯色/哑光低纹理物体：MONO 受限"），不是能力分级。

**论证 4：尺度口径统一，不存在"无深度 = 无尺度"**

| 尺度来源 | 相对不确定度 | 达标 |
|---|---|---|
| IMU/VIO 尺度先验 | 5%–10% | ✗（仅作初值与交叉校验） |
| **参照物多视角标定** | **0.35%–1.04%** | ✓（达标来源） |
| 硬件深度（LiDAR/ToF） | 1%–2%（且有温漂） | ⚠️（仍需参照物复核） |

**参照物标定是全机型统一的尺度来源**（00 §5.2 的决策表末行注："两条分支的尺度均须经参照物复核"）。因此在尺度维度上，MONO **不比** RGBD 差。

#### 6.2.3 论证的边界（不夸大）

| 不可声称的内容 | 原因 |
|---|---|
| "MONO 在所有场景都优于 RGBD" | 弱纹理区与纯色哑光物体上 MONO 受限（00 §4.5.5） |
| "MONO 的绝对尺寸精度更高" | 绝对尺寸由参照物标定决定，两分支口径相同；RGBD 还有深度温漂这一额外误差源 |
| "MONO 能恢复 0.1 mm 以下的细节" | 深度分辨率等于像素间距（0.14 mm @4K/0.35 m），这是**共同物理限制** |
| "MONO 不需要尺度标定" | 与 00 §4.5.2 / §5.2 直接冲突 |
| "MONO 的重投影误差等于形状误差" | §6.1.2 已证明两者相差约 2.4 倍 |

### 6.4 弱纹理与反光处理

#### 6.4.1 光照引导策略

**引导文案**（遵循 02 §4.9.1：纯文字、≤ 14 汉字、无 emoji、无感叹号、一次只显示 1 条）：

|---|---|---|---|---|---|
| L1 | 提示 | `请给物体侧向打光` | `让表面纹理显现出来` | `lowtex_ratio > 0.15`（02 §4.6 提示级） | `lowtex_ratio ≤ 0.15` |
| L2 | 警告 | `纹理不足，请侧向打光` | `换个角度或补光后再拍` | `lowtex_ratio > 0.30`（02 §4.6 警告级） | `lowtex_ratio ≤ 0.15` |
| L3 | 提示 | `请用漫射光` | `避免点光源造成高光` | 检测到点光源高光（`blob_ratio > 0.03` 且高光中心随视角移动） | `blob_ratio ≤ 0.02` |
| L4 | 警告 | `此处反光，请换角度` | `避开强光反射方向` | 02 §4.5 的 D4 警告级 | `sat_ratio ≤ 0.02` |
| L5 | 提示 | `请放慢并靠近一些` | `移动太快会导致细节丢失` | D1 提示级（02 §4.2） | 恢复后 10 帧 |

> 编号 L1–L5 为本文新增，需回填 **09 文档**的异常文案表（接在 02 §4.9.2 的 M17 之后）。
> **禁止**在弱纹理场景使用"扫描失败"这类文案（会让用户放弃，而实际上大部分表面仍可重建）。

**具体操作建议（供 09 文档 U-02 的说明区展示，纯文字）**：

```
弱纹理物体的补光方法
1. 关掉手机闪光灯
2. 用一盏台灯从物体侧面 45 度照射，避免直射物体表面
3. 用白纸或白卡在物体另一侧做漫反射补光
4. 让物体表面产生轻微的明暗变化，纹理就会显现
5. 换几个角度再拍，掠射角下的表面纹理最明显
```

#### 6.4.2 多视角互补

不同视角下，同一表面的"有效纹理"来源不同：

| 机制 | 说明 | 利用方式 |
|---|---|---|
| 掠射角增强 | 表面在掠射角下，深度方向的微小起伏转化为明显的亮度变化（明暗层次） | 源视图选择时优先选**视角夹角大**的视图（§5.2.2 的第一评分项）；引导用户做"低位掠射"补拍 |
| 光照方向差异 | 不同视角下，固定光照在表面产生的阴影图案不同 | 引导用户**改变手机角度**而非只平移（03 §6.2 的角度步长 4°–35°） |
| 高光图案 | 光滑表面上，视角变化使高光图案移动，产生可匹配特征 | 记录高光图案的位置作为辅助特征（低权重） |
| 材质一致性 | 同一材质在不同表面块上的响应相似 | 跨视图的材质一致性作为**弱约束**（权重 0.1） |

**工程实现**：

| 环节 | 做法 |
|---|---|
| 纹理可用性统计 | 02 §4.6 的 16×16 网格逐格统计角点数；**跨帧累计**（同一网格在 ≥ 3 个不同视角下被检出角点 → 判为"多视角互补可用"） |
| 源视图偏置 | 若参考帧的某网格低纹理，优先选择在该网格处角点数多的源视图 |
| 置信度 | 该网格在所有视角都低纹理 → 深度置信度上限 0.3，且在泊松阶段作为低置信区处理 |

#### 6.4.3 泊松置信度标注机制

06 文档的泊松重建输出逐顶点置信度（`mesh_poisson_confidence` = 1）。本文的贡献是把**MVS 侧的置信度**正确地传递到泊松侧并最终到导出元数据。

**置信度的三层传递**：

```
① MVS 层：每像素置信度 C_r ∈ [0,1]
   来源：光度残差 exp(−C_photo/0.5) × 几何一致性 × 角度 × 纹理因子 × 支撑视图数因子
② 融合层：体素置信度 = 加权平均的 C_r，并按体素内深度的加权标准差进一步调制
   σ_Z/Z̄ > 0.01 → 置信度 × 0.5；> 0.02 → 该体素剔除
③ 泊松层（06 §2.1 的 w_geom / w_photo）：
   w_geom = clamp(1 − d_to_surface/(3r), 0, 1)
   w_photo = 归一化的光度残差（来自 MVS 的 C_r 的光度分量）
   最终点权重 w = w_geom × w_photo × (0.02 ≤ w ≤ 1)
```

**标注的三个层级**：

| 层级 | 判据 | 标注内容 | 呈现位置 |
|---|---|---|---|
| **顶点级** | 泊松输出的逐顶点 confidence < 0.3 | 顶点标记为"低置信" | `recon_mesh_info.json` 的 `vertex_confidence_below_0.3_ratio`；导出模型的顶点色 alpha 通道（可选） |
| **区域级** | §5.7.1 的 `reflective` / `transparent` 区域 + §6.4.2 的全程低纹理网格 | `unreliable_regions[]`，含 `kind` / `bbox` / `area_ratio` | 09 文档 U-07 的统计区 + 导出元数据 |
| **推断区级** | 泊松外推区（06 §1.6 的已知缺陷） | 06 文档已有的 `degradations` 机制；底面由泊松外推填补的区域必须标记 | 09 文档 U-07 + 03 §7.1 S12 |

> **强制要求（对齐 00 §4.5.4）**：**底面由泊松外推填补的区域必须标注为推断区**，无论其置信度多高。这是产品对用户的诚实义务，不允许省略。

**置信度不达标的处置链**：

| 条件 | 处置 |
|---|---|
| 全局有效深度比例 `< 0.60` | 重建失败，提示"补光或换角度后重拍"，给出具体低纹理网格的位置 |
| 全局有效深度比例 `0.60 – 0.80` | 重建成功，UI 显示"部分区域细节不足"（附低纹理网格示意图） |
| 局部网格全程低纹理 | 深度置信度上限 0.3；泊松按低置信区处理；导出元数据标注 |

### 7.1 立场：尺度必须由参照物标定提供

#### 7.2.2 与 07 文档 §3.3 仲裁链的对齐

07 §3.3 的仲裁优先级（手动 > 参照物 > 深度锚定 > IMU 先验 > 单位尺度）在 MONO 分支的落地：

| 序 | 07 §3.3 的来源 | MONO 分支 | 本文档的动作 |
|---|---|---|---|
| 1 | 手动输入（M1/M2/M3） | 适用 | 优先采用；写入 `overrides`（08 §3.4） |
| 2 | 参照物标定 `s_ref` | **默认路径**（§7.1 SC-5） | 注入阶段 C |
| 3 | 硬件深度锚定 `s_depth` | **不适用** | 跳过（无深度） |
| 4 | IMU 重力先验 `s_imu` | 兜底 | 仅当序 1、2 都不可用时；UI 必须显示"±10%"警示（09 P-08） |
| 5 | 单位尺度 `s = 1` | **仅 `BRANCH_RGBD` 可接受** | MONO 分支**禁止**落到序 5（否则模型尺寸完全无意义） |

> **与 07 §5.2 回退链的差异**：07 §5.2 的序 ⑥（单位尺度 + "未标定"横幅）注明"仅 BRANCH_RGBD 可接受"。MONO 分支的回退链终点是序 ④（IMU 先验）+ 警示，不是序 ⑥。**需回填 07 文档 §5.2** 明确这一点。

### 7.3 尺度不确定度的传播计算

#### 7.3.1 从 `s` 到最终模型尺寸

```
L_final = s · L_recon        （L_recon 为重建空间中的长度，ru）
```

不确定度：

```
σ_L = L_final · sqrt( σ_s² + σ_L_recon² / L_recon² )
```

| 分量 | 来源 | 量级（300 mm 物体） |
|---|---|---|
| `σ_s` | §6.1.4 的合成（参照物多视角联合） | 0.0104 × 300 = 3.1 mm |
| `σ_L_recon / L_recon` | SfM 三角化的相对误差（同一批点，已含在 `σ_s` 中，**不重复计入**） | — |

**因此 `σ_L ≈ L · σ_s`**，即绝对尺寸误差与物体尺寸成正比（比例误差）。

#### 7.3.2 从尺度不确定度到深度误差

深度误差 ∝ 尺度误差（因为 `Z = f·B/d`，`f` 与 `B` 的尺度都确定，深度是绝对量）：

```
δZ_scale = Z · σ_s        （Z = 0.35 m, σ_s = 0.0104 → 3.6 mm）
```

> **重要区分**：3.6 mm 的尺度型深度误差**不是形状误差**（§6.1.1 的 L-B 级），它是一个全局缩放，被 00 §4.6 的"尺度相对误差 ≤ 1.0%"这一独立验收项管控。把它加进形状误差会重复计算。

#### 7.3.3 不确定度的分项传播（阶段 C 的 BA 内）

阶段 C 中，尺度先验残差 `r_s = (s/s_ref − 1)/σ_prior` 的协方差：

```
Σ_s_post = 1 / ( 1/σ_prior² + 1/σ_s,SfM² + 1/σ_s,IMU² )
```

| 分量 | 值 | 说明 |
|---|---|---|
| `σ_prior` | 0.02（`calib_scale_prior_sigma`，08 G9） | 参照物先验 |
| `σ_s,SfM` | 0.05 | 纯 SfM 的尺度不确定度（由三角化精度决定） |
| `σ_s,IMU` | 0.10（`scale_imu_prior_relative_sigma`，08 G9） | IMU 先验；**注意**：IMU 先验是**弱观测**（尺度在退化运动下不可观），其有效 σ 应放大到 0.20–0.30 |

```
σ_s_post = 1 / sqrt( 1/0.02² + 1/0.05² + 1/0.30² )
         = 1 / sqrt( 2500 + 400 + 11.1 ) = 1/53.98 = 0.0185  →  1.85%
```

> **这个结果超标的根本原因**：`σ_prior = 0.02`（2%）本身就不满足 ≤ 1.0% 的验收线。07 文档 §2.10.3 把"高置信"的定义设为 `σ_s/s ≤ 0.02`，与 00 §4.6 的 ≤ 1.0% 存在**口径冲突**。
>
> **处置**（必须回填 07 文档 §2.10.3）：
> - 07 的"高置信"阈值 `σ_s/s ≤ 0.02` 指的是**标定模块自身解算出的不确定度**（闭式解的 `σ_s`，07 §2.10.1）；
> - 00 §4.6 的 ≤ 1.0% 指的是**端到端尺度相对误差**（含 §6.1.4 的合成）；
> - 二者的衔接方式是：标定模块的 `σ_s`（闭式解）必须 ≤ 0.5%，才能使端到端合成 ≤ 1.0%。§6.1.4 的计算表明这需要 **多视角联合优化 + 手动尺寸**。
>
> **需回填 07 文档 §2.10.3**：把"高置信"的判据从 `σ_s/s ≤ 0.02` 收紧到 `σ_s/s ≤ 0.005`（并说明这是为了满足 00 §4.6 的端到端 ≤ 1.0%），或明确区分"标定模块不确定度"与"端到端尺度不确定度"两个口径。

### 7.4 尺度冲突的检测与仲裁

| 冲突 | 检测 | 仲裁 |
|---|---|---|
| `s_ref` 与 `s_imu` 偏差 > 0.30 | §3.9.4 的检查 | 07 §1.2 的规定：判为可疑并告警 `W_CALIB_MULTIVIEW_INCONSISTENT`；**以 `s_ref` 为准**（07 §3.3 序 2 优先于序 4） |
| `s_ref` 的置信度为"低"（`σ_s/s > 0.05`） | 07 §2.10.3 | 07 §3.3 的冲突规则：BRANCH_MONO 且参照物置信度低 → **不采用**自动值 → 请求用户手动输入 → 用户不输入则落到序 4（IMU 兜底）+ 警示 |
| 阶段 C 的 BA 收敛后 `\|s/s_ref − 1\| > 0.02` | §4.8 | 保留阶段 A 的解（尺度更小、更可信），告警 `W_CALIB_OPT_NOT_CONVERGED`，并在 `recon_mesh_info.json` 记录两个解的差异 |

| 用户手动值与 `s_ref` 差 > 10% | 07 §3.3 | 允许（用户是最终权威），记录 `manual_override = true`（08 L6） |
