### 1.3 depth 与最终网格分辨率的量化关系

设：

| 符号 | 含义 | 来源 |
|---|---|---|
| `L_max` | 点云轴对齐包围盒最长边长度 | 单位 m，由输入点云实测 |
| `s` | `mesh_poisson_scale` | 默认 1.1 |
| `D` | `mesh_poisson_depth` | 八叉树深度（整数） |
| `r` | 最终网格特征边长（等效分辨率） | 计算量 |

**关系式（唯一权威）**

```
2^D  = ceil( s * L_max / r )          （向上取整到 2 的幂）
r    = s * L_max / 2^D                （实际生效分辨率，m）
D    = ceil( log2( s * L_max / r_target ) )
```

- 八叉树根节点覆盖一个边长 `s * L_max` 的立方体，沿最长轴被 `2^D` 等分，因此最细层单元边长 = `s * L_max / 2^D`。
> **硬约束：`r` 必须不小于点云采样间距**（2026-10-30 实测补入）
>
> 本模块的八叉树采用**稀疏化**实现：活跃单元只取「点云支撑的单元 + 一环邻域」。
> 因此当单元边长 `r` **远小于点云采样间距**时，点云之间没有场值支撑 →
> 等值面**断裂成碎片**，网格只覆盖点云所在区域的一小部分。
>
> 实测（球面 R = 50 mm，20000 点，采样间距 1.18 mm）：
>
> | `D` | `r` (mm) | 网格覆盖球面面积 | 边界环数 |
> |---|---|---|---|
> | 9 | 0.215 | **7.3%** | 4.2 万 |
> | 8 | 0.430 | 30.7% | 4.2 万 |
> | 7 | 0.859 | **87.9%** | 3.0 万 |
> | 6 | 1.719 | 107.9%（含外扩区） | 0.9 万 |
>
> **上述限制已被「切平面致密化」解除**（2026-10-30 第二轮实测）：`PoissonReconstruct`
> 内部会把点云沿切平面展开到「等效间距 ≤ r」，让活跃单元连成片。
> 致密化后的实测（同一球面）：
>
> | `D` | `r` (mm) | 致密化 k | 网格覆盖球面面积 | 实际边长 / r |
> |---|---|---|---|---|
> | 7 | 0.859 | 2 | **107.4%** | 1.02 |
> | 9 | 0.215 | 6 | **88.8%**（裁剪后 87.0%） | 1.03 |
>
> 因此 `D` 可以按精度需求自由选取，不再受点云密度硬限制。
> **但必须如实理解其代价与边界**：
> - 致密化把点数放大 k² 倍（k 上限 6 → 36 倍）。实测 depth=9 用例：
>   点云 20000 → 72 万，活跃单元 135 万，MC 产出 181 万三角形，
>   `poisson` 单测耗时 9.4 s → 81 s。
> - **虚拟点是插值出来的，不增加任何几何信息** —— **形状精度的上限仍是
>   原点云的采样密度**。切平面平坦化误差 ≈ (k·r)²/(2R)：R=50 mm、
>   k·r=1.18 mm 时仅 0.014 mm。
> - 因此「网格分辨率 r 更细」不等于「形状更准」；`r` 更细带来的是**更好的
>   三角形质量与 UV 均匀度**，以及不再出现碎片化网格。
>
> 仍保留两个接口供上层按实测点云密度选择 `D`（不静默改用户参数，R-PREC-6）：
>
> ```
> double EstimatePointSpacing(const OrientedPointCloud&);   // 最近邻中位数 × 2
> int    PoissonDepthForPointSpacing(double L_max, double s, double spacing);
>         // = ceil( log2( s * L_max / spacing ) )
> ```
>
> **与 §1.4 的冲突（如实声明，重要）**：§1.4 要求 `r_mesh = h_voxel/8`，
> 即网格单元比 TSDF 体素细 8 倍。若体素间距与 MVS 点云间距同量级，
> 该约束**在当前的稀疏化八叉树实现下不可达** —— 要同时满足「细 8 倍」与
> 「铺满曲面」，必须把八叉树改为**自适应深度**（粗层填满空白、细层只出现在
> 点云附近，即 PoissonRecon 的 Depth + Level 双参数机制）。
> **这是当前实现已知的最重要的架构级缺口**，已列入下一步任务。

- **反推公式的取整口径（唯一权威）**：目标分辨率 `r_target` 是**上界** —— 取到的 `D` 必须满足 `r = s·L_max/2^D ≤ r_target`，即 `D = ceil(log2(s·L_max/r_target))`。
  **不可**按最近整数取整：那样会偏小一档，导致网格分辨率粗于目标，违背 §1.4 的「网格分辨率 ≤ 体素/8」绑定关系（§1.4 已给出同一口径）。
  推论：速查表里的 `r` 是**达成分辨率**；把它当 `r_target` 反推时，若表值是四舍五入后的数（例：`L=0.30, D=10 → 0.322`，实际达成 `0.32227`），保守取整会落到 `D=11`（`0.16113`）—— 这是**正确行为**，因为目标 0.322 mm 比 D=10 的达成值更严。
- 泊松输出的三角形特征边长与该单元边长同量级（实测比值 0.8 ~ 1.2，取决于曲率），故 `r` 即等效网格分辨率。
- **`r` 与包围盒尺寸成正比**：同一 `D` 下，大物体的实际分辨率比小物体粗。这是八叉树方法的固有性质，不可通过参数绕过，只能通过提高 `D` 补偿。

**表面单元数（内存驱动量）**

```
N_cells ≈ SurfaceArea / r^2
```

例：`L_max`=0.3 m、球形表面积 0.28 m²、`D`=10 → `r`=0.322 mm → `N_cells` ≈ 2.7e6。

**内存估算口径（全文唯一）**：泊松内部每个活跃节点持有梯度/法向/约束数组，按**单节点 220 B** 计（与 §6 待实测表同口径）：

```
M_peak = N_cells × 220 B
```

代入上例：`2.7e6 × 220 B = 5.94e8 B ≈ 0.59 GB`。

> **需实测回填**：220 B/节点为经验估算值，必须在目标机型上实测峰值 RSS 曲线后回填至 §6 与 `docs/14_验收测试.md`。回填前，本文所有内存数字均按本口径给出，不再出现第二种估算区间。

> **`N_cells` 与 `L_max` 的关系（重要）**：在形状不变、仅等比放大的前提下，`area ∝ L_max²` 而 `r = s·L_max/2^D ∝ L_max`，故 `N_cells = area / r²` **与 `L_max` 无关**，只由 `D` 与物体的**形状因子**（表面积 / 最大边长²）决定：`N_cells ≈ 2.7e6 × 4^(D−10)`（球形近似）。也就是说：物体变大不增加内存，**提高 `D` 才增加内存**（每 +1 层 ×4）。
>
> **形状因子的影响**：细长物体（棒状、薄板）的形状因子小于球形，`N_cells` 更小；表面极度起伏的物体（花菜、绒毛）形状因子更大，`N_cells` 可达球形的 2~3 倍。下表的 `N_cells` 是**球形下界**，实際峰值需按实测形状因子放大后再套 220 B/节点。这决定了 §1.7 的分块触发判据。

### 1.4 与 TSDF 体素边长的绑定关系（承接 00 文档 §4.2 E）

00 文档中的表述「泊松，深度 = 体素边长×8」在本项目中被实现为**线性比值 8**：

```
r_mesh = h_voxel / 8
```

即泊松网格分辨率必须比 TSDF 体素边长细 8 倍。原因：RGBD 分支的最终几何由 MVS 深度主导（见 00 §8.3），TSDF 体素只承担融合去噪与先验职责。若泊松分辨率不细于体素，网格将继承体素阶梯（staircase）误差，违背「几何建模精准度优先」。

> **口径声明**：00 文档 §4.2 E 的原文「深度 = 体素边长×8」在"深度"指八叉树层数时是无量纲的（层数不能等于 mm×8）。本项目将其解释为**网格分辨率是体素边长的 1/8**，即 `r_mesh = h_voxel / 8`，并按下式换算为八叉树深度。此解释已在 08 文档的 `mesh_poisson_depth_mode` 参数中固化为两种模式。
>
> **关于 §1.3 硬约束的处置（2026-10-30 第二轮更新）**：切平面致密化已让
> `r < 点云间距` 可用（不再碎裂），因此 `r_mesh = h_voxel/8` **在执行层面可行**。
> 但必须同时声明：**形状精度不会因此提高**（上限仍由点云密度决定，
> 见 §1.3 的三条代价说明）。`from_voxel` 模式可正常使用。
>
> ~~历史记录：与 §1.3 旧硬约束的冲突~~：`r_mesh = h_voxel/8`
> 意味着网格单元比体素细 8 倍，而 §1.3 实测表明 **`r` 必须不小于点云采样间距**
> 才能铺满曲面。若 `h_voxel` 与 MVS 点云间距同量级，两者不可兼得。
> 根因是本模块的八叉树为**固定深度 + 稀疏活跃单元**实现 —— 点云之间的空隙
> 没有任何单元。解法是改为**自适应深度八叉树**（粗层填满空白、细层只出现在
> 点云附近），这是下一步的架构级任务。在那之前，`from_voxel` 模式推导出的
> `D` 必须再经过 §1.3 的点云密度约束校正，否则网格会碎成大量孤立片。

换算为 `depth`：

```
D = ceil( log2( s * L_max * 8 / h_voxel ) )
```

**`h_voxel` × `L_max` → `D` 对照表（`s` = 1.1）**

下表按上式 `D = ceil( log2( s · L_max · 8 / h_voxel ) )` **逐格重算**（`L_max` 与 `h_voxel` 先统一到米）：

| `L_max` (m) \ `h_voxel` (mm) | 4.0 | 2.0 | 1.0 | 0.5 |
|---|---|---|---|---|
| 0.10 | 8 | 9 | 10 | 11 |
| 0.12 | 9 | 10 | 11 | 12 |
| 0.20 | 9 | 10 | 11 | 12 |
| 0.30 | 10 | 11 | 12 | 13 |
| 0.50 | 11 | 12 | 13 | 14 |
| 1.00 | 12 | 13 | 14 | 15（超上限 14） |

**取整规则说明（保守口径）**：`ceil(log2(·))` 取到的是满足

```
r = s · L_max / 2^D  ≤  h_voxel / 8
```

的**最小整数 `D`**。因此本表等价于"按 `r ≤ h_voxel/8` 取更保守的 `D`"，而不是按最近整数取整（后者会偏小一档，导致网格分辨率粗于体素/8，违背 §1.4 的绑定关系）。

**触顶与超限处理**：

| 情形 | 处置 |
|---|---|
| `D ≤ 14`（表中绝大多数格） | 直接取该 `D` |
| `D = 15`（`L_max`=1.00 m、`h_voxel`=0.5 mm） | 超出 `mesh_poisson_depth_max` = 14。按 §1.7 走**分块泊松**（块内 `D_block` 自适应，块间分辨率与全局一致），**不得**为了塞进 14 而牺牲全局分辨率（R-PREC-4） |

**分支化说明：MONO 分支没有 TSDF 体素，绑定基准换算**

00 文档 §4.2 E 的「深度 = 体素边长×8」只对 `BRANCH_RGBD` 有定义（TSDF 融合产生等效体素网格）。`BRANCH_MONO` 没有 TSDF 融合阶段，**不存在"体素边长"**：

| 分支 | 绑定基准 `h_ref` | 说明 |
|---|---|---|
| `BRANCH_RGBD` | `h_voxel` = `rgbd_tsdf_voxel_size` | TSDF 体素边长。本节全部公式按此代入 |
| `BRANCH_MONO` | **MVS 点云等效间距** | 由 MVS 深度图的采样密度决定：`h_ref = Z_mean / f_px · 1 px`（单像素视差对应的深度增量），按 §1.7 的分块策略取该量的**中位数**作为代表值 |

因此 `BRANCH_MONO` 的"网格分辨率 ≤ 体素/8"应读作"**网格分辨率 ≤ MVS 点云等效间距 / 8**"，其绝对数值随拍摄距离变化（典型桌面物体 0.3–0.5 m、f ≈ 2500 px 时约 0.12–0.2 mm）。实现时由 MVS 阶段实测 `h_ref` 并写入 `recon_mesh_info.json` 的 `mesh_resolution_reference`，本文的 `h_voxel` 对照表在该分支下按 `h_ref` 代入。

**两种深度模式**

| 模式 | 行为 | 适用 |
|---|---|---|
| `literal` | 直接使用 `mesh_poisson_depth`（预设 9 / 10 / 11） | 默认。深度由用户与预设直接控制，与 00 文档的档位语义一致 |
| `from_voxel` | 运行时由实测 `L_max` 与 `h_voxel` 按上式推导 `D`，并夹取到 `[mesh_poisson_depth_min, mesh_poisson_depth_max]` | 需要严格满足"分辨率 = 体素/8"时使用；推导值写入 `recon_mesh_info.json` 的 `poisson_depth_effective` |

> **约束边界**：按 §1.3 的 `N_cells ≈ 2.7e6 × 4^(D−10)`，`D`=11 时 `N_cells` ≈ 1.08e7（峰值内存 ≈ 2.4 GB，仍可行）；`D`=12 时 `N_cells` ≈ 4.3e7（峰值内存 ≈ 9.5 GB），移动端不可行。此时按 §1.7 启用分块泊松，**不得**降低 `D`（R-PREC-4）。`mesh_poisson_depth_max` 缺省 **11（快速）/ 12（标准）/ 14（高精度，配合分块泊松）**。

### 1.5 为何选泊松而非 Marching Cubes / Ball Pivoting

| 维度 | 泊松（Poisson） | Marching Cubes（TSDF 等值面） | Ball Pivoting |
|---|---|---|---|
| 拓扑封闭性 | **输出必为闭合流形曲面**（隐式函数零等值面无边界），除非点云分布导致多分量 | 仅当 TSDF 体素网格完全被填满时才闭合；未观测区域产生破面 | **不封闭**，依赖采样密度，孔洞由半径参数决定 |
| 对未观测区域 | 生成**外推曲面**（有形状但无数据支撑），需裁剪 | 生成"空洞"，边界处终止 | 不生成几何（真空洞） |
| 噪声抑制 | 指示函数 + 全局梯度正则 → 天然平滑，孤立噪点被 `min_samples` 与 sharpness 抑制 | 噪声原样体现为面片抖动，需要额外 TV/双边滤波 | **对噪声极敏感**，采样不均直接产生破面 |
| 边角规整 | `sharpness` 控制锐边保留，正交投影约束（`bType`）改善角部法向 | 阶梯效应明显（体素分辨率即上限），需 dual contouring 改善 | 三角形尺寸不均，薄结构易退化 |
| 分辨率上限 | 由 `2^D` 决定，与输入点密度无关 | **硬上限 = 体素边长** | 由采样密度决定 |
| 尺度度量 | 隐式解本身是度量的，但输出顶点需再做尺度归一 | 天然度量（体素网格） | 天然度量 |
| 内存/耗时 | 高（见 §1.7） | 中 | 低 |
| 本项目结论 | **主路径**：负责拓扑完备 + 平滑 + 锐边 | **辅路径**：仅在 RGBD 分支作为 TSDF 先验网格参与全局优化，不作为最终产物 | **不采用** |

> **工程约束**：泊松不创造数据。它无法恢复未被观测到的表面，只会把"无数据区"填成一张合理的猜测曲面。因此 §2.3 的裁剪阶段是必需环节，不是可选优化。

### 1.6 已知缺陷与规避手段

| 缺陷 | 现象 | 根因 | 规避手段（按执行顺序） |
|---|---|---|---|
| **内存爆炸** | OOM、`std::bad_alloc` | 活跃八叉树节点数 `N_cells ≈ S / r²`，`D` 每 +1 内存 ×4 | §1.7 分块泊松 / 分位数裁剪 / 落盘 |
| **法向方向不一致** | 局部区域翻转、面片穿插 | 泊松求解要求输入法向**全部朝外**且相互一致 | §1.6.1 |
| **外推区域虚假面** | 物体周围出现"蛛网"状悬浮薄壳 | 梯度场在无数据区被外推求解 | §1.6.2 |
| **薄结构丢失** | 细杆/毛发/线缆被抹掉 | `min_samples` 与梯度正则对高频结构的惩罚 | `mesh_poisson_min_samples` 保持 1~2；`mesh_poisson_sharpness` 提升；必要时对该区域改用 Ball Pivoting 局部补 |
| **等距面偏移** | 整体尺寸偏大/偏小 | `scale` 参数化与 `sharpness` 改变零等值面位置 | 交付前用标定参照物做一次尺寸复核（07 文档 §4） |
| **颜色渗染** | 顶点色跨越几何边界 | 顶点色在八叉树节点上做低通 | 纹理烘焙阶段以图像为准重写（§2.9），顶点色仅作低频底色 |

#### 1.6.1 法向方向一致性

要求：输入点云法向**全部朝外**且邻域一致。

| 步骤 | 算法 | 参数 |
|---|---|---|
| 1 | 相机可见性投票：每点取贡献该点的所有关键帧，用 `sign(dot(n_pca, dir_to_camera))` 投票，得分票数 > 0 则翻转 | 投票最少帧数 `mesh_input_normal_vote_min_views` = 2 |
| 2 | 稀疏区（票数不足）用 PCA 法向（`k`=16 邻域，最小特征值方向），再与已定向邻居对齐 | 邻域 `k` = 16 |
| 3 | 邻域一致性传播：对 kNN 图做符号传播，消除小簇反向 | 迭代上限 5 轮 |
| 4 | 输出前检查：统计 `dot(n, p - centroid) < 0` 的点占比 | > 5% 记警告日志 `W_MESH_NORMAL_FLIP_RATIO`，不阻断 |

> 法向错误是泊松产生"翻转面片"的第一主因，必须在 `poisson_in.cpp` 阶段解决，泊松之后无法可靠修复。

#### 1.6.2 外推区虚假面裁剪

三重裁剪，缺一不可：

| 裁剪器 | 判据 | 参数（快 / 标 / 高） |
|---|---|---|
| 置信度分位数裁剪 | 保留 `confidence` 最高的前 `p` 分位顶点及其面 | `p` = 0.995 / 0.999 / 0.9995 |
| 输入点云距离场裁剪 | 顶点到最近输入点的距离 > `τ` → 删除 | `τ` = 3·r / 2.5·r / 2·r（r = §1.3 分辨率） |
| 视锥裁剪 | 顶点投影到任何关键帧的相机视锥外 → 删除 | 视锥外扩 `mesh_frustum_margin` = 0.02 / 0.01 / 0.005（比例于 `L_max`） |

裁剪后必须重新计算连通分量，丢弃体积占比 < 0.5% 的孤岛（防止残留碎片）。

### 1.7 内存爆炸的具体解法

**问题**：`N_cells` 只随 `D` 增长（每 +1 层 ×4，见 §1.3），与 `L_max` 无关。按 `N_cells ≈ 2.7e6 × 4^(D−10)` 与单节点 220 B 口径：

| `D` | `N_cells`（球形近似） | 峰值内存（220 B/节点） | 移动端可行性 |
|---|---|---|---|
| 9 | 6.7e5 | ≈ 0.15 GB | 可行 |
| 10 | 2.7e6 | ≈ 0.59 GB | 可行 |
| 11 | 1.08e7 | ≈ 2.4 GB | 中端机勉强可行，高端机可行 |
| 12 | 4.3e7 | ≈ 9.5 GB | **不可行**，必须分块泊松 |
| 13 | 1.7e8 | ≈ 38 GB | **不可行**，必须分块泊松 |

因此**分块的触发点是 `D ≥ 12`**（而非 `L_max` 达到某个值）。`D`=11 在 6 GB 机型上已接近峰值上限，需按 §1.7 决策流程评估。

**三条解法（按优先级）**

#### 方案 A：分块泊松（首选，保持分辨率）

原理：把点云按空间切成带重叠的块，逐块独立做泊松，再缝合。

| 步骤 | 算法 | 关键参数 |
|---|---|---|
| A1 | 沿最长轴做 1D 切分，切块边长 `L_block`，块间重叠 `m` | `L_block` 由内存预算反推；`m` = `4·r` |
| A2 | 每块独立计算 `D_block`，**使分辨率与全局一致** | `D_block = ceil(log2(s * L_block / r_target))`，因此 `D_block ≤ D`，但 `r` 不变 → **分辨率不降**，符合 R-PREC-4 |
| A3 | 逐块泊松求解，块结果落盘（`.npz` 形态的自定义二进制） | 落盘粒度 = 1 块 |
| A4 | 缝合：重叠带内做 ICP 对齐（点到面，阈值 `0.2·r`），合并顶点（容差 `0.05·r`） | — |
| A5 | 接缝带二次修复：重叠带重跑一次局部泊松（`D` 同全局），或缝合并做切向平滑 | — |

> **诚实披露**：分块泊松**不是全局一致解**。数学上隐式函数的拉普拉斯方程在块边界不再成立，接缝处法向与曲率可能不连续，接缝带还可能出现轻微错位。因此分块泊松仅在内存硬约束下启用，启用时必须在 `recon_mesh_info.json` 记录 `poisson_chunked: true` 与块数，且接缝带必须经过 §2.4 非流形修复 + §2.6 法向矫正复核。若缝隙闭合后仍存在开口，按 §2.5 补洞。

#### 方案 B：分位数裁剪（降低活跃面数，不改 `D`）

| 步骤 | 算法 | 参数 |
|---|---|---|
| B1 | 泊松输出 confidence 后，先做 §1.6.2 三重裁剪 | — |
| B2 | 对 confidence 做分位数统计，取 `q` 分位阈值 | `mesh_trim_conf_quantile` = 0.995 / 0.999 / 0.9995 |
| B3 | 低于阈值的顶点与相邻两面删除 | — |

实测该步骤对典型物体可削减 5% ~ 25% 的顶点数量，但**不解决 `N_cells` 主导的内存峰值**（峰值出现在求解期而非输出期）。方案 B 只能与方案 A 组合使用。

#### 方案 C：落盘 + 流式（配合 A）

| 步骤 | 内容 |
|---|---|
| C1 | 八叉树构建阶段按层序列化到磁盘（`mesh_cache/octree_L{k}.bin`），求解器按层读回 |
| C2 | 求解完成后立即释放求解器，仅保留输出网格 |
| C3 | 峰值常驻内存降至 `N_cells` 的 1/3 ~ 1/5 |

#### 决策流程

```
读取设备内存预算 mem_budget (MB)
估算 N_cells = SurfaceArea / r^2
估算 peak    = N_cells * bytes_per_cell(实测标定, 默认 220 B)
if peak <= mem_budget * 0.6:      单块泊松
elif L_max <= 0.35:               提高 D（若 D+1 仍可行），单块泊松
else:                             分块泊松 + 落盘，D 不变
```

> **禁止路径**：不得为了省内存降低 `mesh_poisson_depth` 或 `mesh_poisson_scale`（R-PREC-4 黑名单）。不得以"降采样预览"名义走简化路径（R-PREC-2）。

## 2. 完整后处理流水线

### 2.0 阶段总览与执行顺序

```
S0  输入准备（法向定向、权重、颜色）
S1  离群点剔除
S-  网格净化（退化面 / 重复面 / 孤立顶点）        ← 实现新增，见 §2.5.1 (4)
S2  泊松重建
S3  网格裁剪（外推区 / 视锥 / 孤岛）
S4  非流形边与顶点修复
S5  孔洞缝合
S4' 兜底非流形修复 + S5' 兜底补洞（成对迭代，≤ 4 轮） ← 实现新增，见 §2.5.1 (3)
S6  法向统一矫正 + 逐顶点法向重算
S7  三角面规整（狭长面处理 + 顶点重分布）
S8  UV 展开（xatlas）
S9  纹理烘焙（多视图投影 + 融合）
S10 纹理质量校验
S11 几何简化（可选，仅用户显式触发）
```

**顺序不可交换的理由**

| 约束 | 原因 |
|---|---|
| S0 在 S2 前 | 泊松要求法向已定向一致，事后不可修 |
| 净化在 S4/S5 前 | 退化面与重复面被剔除时会撕开新的边界；若在补洞之后才产生，就再也没人填它们（实测球面用例有 523 个退化面、3 个重复面） |
| S4 与 S5 成对 | S4 的顶点分裂必然改变至少两条边的身份 —— 若那条边原本有 2 个面，拆分后变成 1 个面 → 撕开一个洞。S4 排在 S5 之前时撕开的洞由 S5 填上；但补洞本身可能再造出非流形边，于是需要「再拆一次 → 再补一次」迭代到收敛 |
| S3 在 S4 前 | 先剔除虚假面，避免为虚假面做无用的拓扑修复 |
| S4 在 S5 前 | 非流形边会干扰孔洞边界环识别（边界环定义依赖每边恰有 1 面） |
| S5 在 S6 前 | 补洞产生新面，其法向需一并纳入统一矫正 |
| S6 在 S7 前 | 规整操作会改变面朝向，需在最后重算法向 |
| S7 在 S8 前 | UV 展开依赖稳定的面邻接与顶点重分布结果 |
| S11 在 S8/S9 前 | 简化改变三角形数量，UV 与纹理须在最终分辨率上生成，避免二次烘焙 |

**通用回退原则（贯穿全部阶段）**

1. 任一阶段失败**不中断整条流水线**，而是降级到该阶段的"保守输出"并在 `recon_mesh_info.json` 记录 `stage_status[stage] = "degraded"` + 原因。
2. 降级后模型**仍必须通过 §4 导出校验**；若降级导致无法通过校验，则该格式导出被拒绝并返回明确错误码。
3. 用户在 UI 上必须能看到降级提示（R-PREC-6：不静默回退）。

### 2.1 S0 输入准备

| 项 | 内容 |
|---|---|
| 输入 | MVS 融合点云 或 TSDF+深度融合点云（含 RGB、置信度） |
| 输出 | `OrientedPointCloud`：`position(float3, m)` / `normal(float3, 朝外)` / `color(uchar3)` / `weight(float ≥ 0)` |
| 实现 | `core/mesh/poisson_in.cpp` |
| 失败回退 | 点云为空 → 阶段失败，终止流水线，返回 `RECON_ERR_MESH_EMPTY_INPUT` |

**逐点权重 `w` 的构造（`mesh_input_point_weight_*`）**

```
w = w_geom * w_photo * w_depth
w_geom  = clamp(1 - d_to_surface / (3 * r), 0, 1)      # 到 MVS 深度面的距离一致性
w_photo = clamp(1 - photo_residual / (2 * photo_sigma), 0, 1)
w_depth = clamp(depth_confidence / 255, 0, 1)
```

| 参数 | 快 | 标 | 高 | 说明 |
|---|---|---|---|---|
| `mesh_input_point_weight_photo_sigma` | 0.25 | 0.20 | 0.15 | 光度残差归一化阈值 |
| `mesh_input_point_weight_depth_enabled` | false | true | true | 是否使用深度置信度通道 |
| `mesh_input_point_weight_floor` | 0.02 | 0.02 | 0.01 | 权重下限，避免低权点被完全丢弃 |

### 2.2 S1 离群点剔除

两类剔除器，串联执行。

| 剔除器 | 算法 | 参数 | 快 | 标 | 高 |
|---|---|---|---|---|---|
| 统计离群点（SOR） | 对每点求 k 近邻平均距离 `d̄`，剔除 `d̄ > μ + α·σ` | `post_outlier_knn_k` | 16 | 24 | 32 |
| | | `post_outlier_sor_alpha` | 2.5 | 2.0 | 1.8 |
| 半径离群点（ROR） | 半径 `r` 内邻居数 < `m` 则剔除 | `post_outlier_radius_mult`（× 平均点间距） | 2.0 | 1.6 | 1.4 |
| | | `post_outlier_radius_min_nbr` | 4 | 5 | 6 |

| 项 | 内容 |
|---|---|
| 输入 | `OrientedPointCloud` |
| 输出 | 剔除后的 `OrientedPointCloud` |
| KNN 实现 | `third_party/nanoflann/`（BSD-3-Clause），KD 树建索引 `O(n log n)` |
| 失败回退 | 若 SOR 剔除了 > 40% 的点（疑似阈值过严），**放弃 SOR 结果**、仅保留 ROR 结果，并记录 `W_MESH_OUTLIER_OVER_PRUNE` |

### 2.3 S2 + S3 泊松重建与裁剪

参数见 §1.2。裁剪参数见 §1.6.2。

| 项 | S2 泊松 | S3 裁剪 |
|---|---|---|
| 输入 | S1 输出 | 泊松原始网格 |
| 输出 | `PoissonMesh`（含 confidence） | `TrimmedMesh` |
| 失败回退 | `bad_alloc` → 触发 §1.7 方案 A 重试一次（分块）；仍失败 → `RECON_ERR_MESH_POISSON_OOM` | 裁剪后顶点 < 100 → 判为失败，回退到"不裁剪"并记录 `W_MESH_TRIM_DEGENERATE` |

### 2.4 S4 非流形边与顶点修复

**检测方法**

| 缺陷 | 检测算法 | 判据 |
|---|---|---|
| 非流形边 | 边-面邻接表计数 | 邻接面数 > 2 |
| 非流形顶点 | 取该顶点所有关联面，构造边-面邻接图 | 关联面不能构成单一环（邻接图有 > 2 个连通分支，或某分支出现两次） |
| 边界环断裂 | 边-面邻接计数 == 1 的边 | 端点度数 != 2 → 边界环不闭合 |
| 重复面 | 三角形顶点三元组哈希 | 完全相同的三元组出现 > 1 次 |

**修复策略与优先级**

| 优先级 | 策略 | 具体动作 | 参数 |
|---|---|---|---|
| 1 | **坍缩边**（collapse） | 对非流形边 `(u,v)`：取该边关联面中二面角最小的 1 组（2 面）保留，另一组的面改为连接到合并后顶点 `m = (u+v)/2`；随后把 `u,v` 合并为一个顶点 | `post_nonmanifold_collapse_tol` = 0.10·r / 0.05·r / 0.02·r（几何偏差上限） |
| 2 | 顶点分裂 | 顶点关联面构成多分支时，把顶点拆为多个同位置顶点，每个分支一个，各自独立 | — |
| 3 | 删除多余面 + 补洞 | 坍缩导致几何偏差超限时，退化为删除多出的面，把产生的洞交给 S5 补洞 | `post_nonmanifold_delete_fallback` = true |
| 4 | 隔离面片剔除 | 上述均失败（数值退化）时，移除该连通分量并记录警告 | — |

> **为什么优先"坍缩边"而不是"删除面"**
>
> 1. **面积守恒**：删除面会直接造成表面积损失与几何凹陷；坍缩把两个顶点合并到中点，属于重分布，误差被摊薄到 `0.05·r` 量级（< 0.03 mm），远低于可见阈值。
> 2. **不制造新洞**：删除面必然产生边界环，把问题转嫁给 S5（需要重新生成几何）；坍缩不改变边-面计数，拓扑修复是"原地"的。
> 3. **UV chart 完整性**：删除面会撕裂 UV chart，xatlas 需要重新划分并可能产生新的接缝；坍缩在 chart 内部完成，不影响 chart 边界划分。
> 4. **可逆性/可审计**：坍缩保留了几何位置信息，导出的顶点属性（UV、法向）只做重映射，不产生 NaN。
> 5. **代价可控**：坍缩的代价上限由 `post_nonmanifold_collapse_tol` 显式约束，超过即回退到方案 3，行为可预期。

**边界环识别**（S5 依赖）

- 邻接面数 == 1 的边构成边界集合 → 把边视为图的边、端点为顶点，追踪所有闭合回路。
- 回路分类：
  - 长度 < 3 边 → 退化，忽略。
  - 回路面积 `A`、周长 `P`、平面度（拟合平面残差 RMS）用于分级。

### 2.5 S5 孔洞缝合

**分级与处理**

| 级别 | 判据 | 处理 | 参数（快 / 标 / 高） |
|---|---|---|---|
| **H0 微孔** | 边界环长度 ≤ 3 边 且 面积比 ≤ `A_micro` | 直接三角填充（1 个三角形，不新增顶点） | `post_hole_area_micro_ratio` = **0.02 / 0.01 / 0.005** |
| **H1 小孔** | 面积比 ≤ `A_small` 且 拟合平面 RMS ≤ `0.15·r` | 平面内三角化填充（内部顶点落在拟合平面上）；**边界顶点保持原位不动**（见 §2.5.1 (1)） | `post_hole_area_small_ratio` = **0.20 / 0.10 / 0.05** |
| **H2 中孔** | 面积比 ≤ `A_large` | 孔洞局部 2D Delaunay 三角化（在拟合平面上），边界顶点投影到平面后再投影回原始曲面（`p = p_plane + n·h(p_plane)`，h 取自最近三角形高度场） | `post_hole_area_large_ratio` = **3.0 / 1.5 / 0.8** |
| **H3 大孔** | 面积比 > `A_large` | **不自动填充**。改做局部二次泊松：以孔洞边界环为约束、以边界外 2·r 邻域点云为输入、深度取全局 `D-2`，生成补片后裁剪到孔洞区域 | `post_hole_patch_depth_offset` = -2 |
| **H4 贯穿孔** | 拟合平面 RMS > 0.5·r（孔洞跨越明显曲面） | 视为真实结构或扫描缺失，**不填充**，在报告中列出坐标与面积，由用户决定 | — |

> **单位口径（唯一）**：三个面积阈值**一律用比值**表达，单位为「孔洞面积 / 网格总面积」的无量纲比值，取值与 08 文档的 `post_hole_area_micro_ratio` / `post_hole_area_small_ratio` / `post_hole_area_large_ratio` **完全一致**（0.02 / 0.20 / 3.0 等）。
> 例如 `post_hole_area_micro_ratio` = 0.02 表示微孔面积占网格总面积的 **2%**，不是 0.02%。§2.5 早期版本曾以"百分比"书写（0.02% / 0.2% / 3%），与 08 的比值口径差 100 倍，**已统一为比值口径**。
>
> **尺度无关性**：MONO 分支在 S5 执行时尺度可能尚未标定，因此三个阈值用**相对面积比**表达，不依赖米制尺度。标定完成后（07 文档）可在报告中换算为绝对面积（mm²），但不影响补洞决策。

#### 2.5.1 实现修正（实测）

以下为实现阶段实测到的、与前文描述不一致之处，**以本节为准**。

**（1）孔洞填充必须复用原边界顶点**

前文 H1 的处理写的是「边界点重投影到拟合平面」。若把「投影后的边界点」实现成
**新顶点**并用新顶点组环，则原边界边 `(v_i, v_{i+1})` 依然只被 1 个面使用 →
① 孔洞根本没被闭合；② 补片自身又带一圈边界边，等于凭空多出一个边界环。

实测（球面，泊松 + 本流程）：每个这样的洞净增 2 个边界环，19 个投影洞 →
边界环比未填孔洞数多 38，与实测差值（1715 − 1677）完全吻合。

**现版**：填充面**一律复用原边界顶点**（几何零损失，既有面片一个不动），
新增顶点只允许出现在**内部**（n ≥ 5 的重心扇形），且落在拟合平面上 ——
满足 H1「消除台阶」的意图，同时不触碰既有几何。

**（2）新增对角线必须避开网格已有的内部边**

四边形洞沿对角线剖分时，洞的 4 个边界顶点之间**可能早已存在一条对角线**
（洞外侧的两个面共用它）。若再补一条同名的，该边会变成 4 面共享 → 非流形边
→ 兜底 S4 拆点 → 刚闭合的洞被重新撕开。

**现版**：填充时维护**可变边表**（边 → 面数），逐边核对 —— 待写入的边若已有
≥ 2 个面，本次填充直接放弃（计入未填）。四边形优先选空闲对角线；两条都被占用
时改用重心扇形（内部顶点新建，边全是新边）；耳切三角化在选耳时同样跳过会与
内部边冲突的对角线。

**（3）S4 与 S5 必须成对迭代**

见 §2.0 的顺序表。**现版**：`RunMeshPipeline()` 固化
「净化 → S4 → S5 → 兜底(S4 → S5)×N → 兜底净化 → S6」，兜底 ≤ 4 轮。

**（4）重复面必须在补洞前清除**

泊松 MC 提取在歧义 case 下会对同一组顶点产出两个三角形（绕序相同或相反）。
这类重复面在边表上看不出异常（那条边仍是 2 个面），但补洞往同一条边加面时
会把它变成 3~4 面共享。**现版**在净化阶段增加 `RemoveDuplicateTriangles()`
（按排序后的顶点三元组判重，忽略绕序）。

**（5）边界环计数口径必须唯一**

旧版 `AnalyzeMesh` 用并查集数「边界顶点连通分量」，S5 用边行走法数「闭合链」，
在 pinch 点（两条环一点相交）前者得 1、后者得 2 —— 口径不一致导致
「边界环数 = 未填孔洞数」这条验收判据永远对不上。

**现版**：两者共用 `CollectBoundaryLoops()`；走环时在边界度 > 2 的顶点按
**最直行**原则选下一条边 —— 直行的那条正是同一条环的延续，另两条属于另一条环。

**（6）填充算法的分级降级**

| 环长度 | 算法 | 新增顶点 |
|---|---|---|
| 3 | 1 个三角形 | 无 |
| 4 | 沿空闲对角线剖分为 2 个三角形；两条对角线都被占用时改用重心扇形 | 0 或 1 |
| ≥ 5 且重心星形可见 | 重心扇形（内部顶点落在拟合平面上） | 1 |
| ≥ 5 且凹多边形 | 耳切三角化（只用原边界顶点）+ 面积自检 | 0 |

**（9）面绕序统一（新增步骤）**

Bourke 标准 MC 表在 15 个歧义 case 上只固定了一种连接方式，相邻体素之间
可能出现**三角形绕序不一致**（实测球面 depth=9：内部边 684 条中 49 条不一致；
网格变细后达 1663 条）。

绕序不一致会破坏下游的一切局部一致性判据：边界环的「侧别」判据失效 →
两条边界环被混成一条 → 非简单环；逐顶点法向重算得到正负混杂的法向场。

**现版**：新增 `OrientFacesConsistently()`，按共享边做 BFS 传播，若两个面在
同一条边上方向相同则翻转邻居。**只交换索引顺序，顶点位置一个不改** →
几何精度零损失。该步骤在流水线的**两个位置**各跑一次：
净化后（修 MC 歧义 case）、S4 + 顶点分裂后（顶点分裂改变了面↔边的邻接关系，
实测会新产生 58 条不一致）。

**（10）孤立面片必须删除而不是补面**

泊松 MC 在外扩区会产出孤立的三角形碎片 —— 它的 3 条边都只有它自己一个面使用，
因此看起来像一个「三角洞」。但它不是洞，而是噪声碎片。

给碎片补一个面会造出与它**完全重合**的面（两个面在共享边上同向 = 在边的同一侧）
→ 绕序不一致 + 穿模几何。实测不删碎片时补洞后绕序不一致边 5541 条
（≈ 填充面总数），且补出的盖子全部穿进网格内部。

**现版**：净化阶段新增 `RemoveIsolatedFacePatches()`（删除单面连通分量）。
删掉碎片后它的边界环自然消失，无需再补。

**（11）补洞必须校验绕序，否则会造出穿模几何**

填充面必须与相邻原面在共享边上**方向相反**。同向意味着两个面在边的**同一侧**
→ 补片穿进网格内部。这不是真洞，而是网格的**外边界**（外扩区切口）。

**现版**：`FillOneLoop` 在落地前逐边校验绕序，同向则放弃该洞（计入未填）。

**（12）非流形顶点必须按扇区分裂**

顶点处的关联面按共享边可分成若干连续扇区。合法流形曲面上每个扇区贡献
0 或 2 条边界边，因此**边界度 = 2 × 扇区数**。边界度 ≥ 4 意味着该顶点处
曲面本身非流形（两个曲面片在该点交汇）。

两个扇区各带一条边界环，两条环在该顶点**相交** → 走环时无论用几何直行、
转向量符号还是侧别判据，都无法把两条环分开 → 环内出现重复顶点 → 非简单环。
实测（球面 depth=9）：边界度分布 度2=6152、**度4=297**、度6=7。

**现版**：新增 `SplitNonManifoldVertices()`，把每个扇区分配到独立顶点副本。
新顶点位置 = 原顶点位置 → 几何精度零损失。实测非简单环 156 → 接近 0。

**（13）走环判据的三次演进（记录以免重蹈）**

| 判据 | 非简单环数 | 失效原因 |
|---|---|---|
| 几何最直行 | 156 | 两条环交叉时几何上未必是「直穿」关系，会把两条环混成一条 |
| 转向量点乘面法向 | 105 | 该符号取决于**局部曲率**，在凹区域反号 |
| **侧别一致**（曲面恒在同一侧） | **接近 0** | 与曲率无关 ✓ |

**（15）MC 表的角点/棱编号体系必须与表的来源一致（本模块最严重的缺陷）**

表数据来自 PoissonRecon 随附的 MC 实现，它用的是
`Cube::CornerIndex(x,y,z) = (z<<2)|(y<<1)|x`（即 **x + 2y + 4z**）与
`Cube::EdgeIndex(orientation,i,j) = (i|(j<<1))|(orientation<<2)`。

而早期实现按 **L. P. Bourke 的经典顺序**写 `kCornerOffset` / `kEdgeCorners`
（corner 2/3、6/7 互换，棱按底面/顶面/竖直棱分组）——
**12 条棱里有 8 条端点错位**。

后果是双重的：
1. 棱交点位置落在错误的棱上 → 几何失真；
2. `kEdgeMask` 标记的棱与 `kTriangles` 引用的棱对不上 → `edge_vertex[e]`
   未被填充 → 三角形被 `v0 == 0xFFFFFFFF` 过滤掉。

实测（球面 D=9）：活跃单元 135 万、58.9% 跨越 iso，却只产出 30 万三角形、
边界环 11.4 万、**非流形边 3262**、网格覆盖率 14.4%。
修正后：产出 **181 万**三角形、边界环 6.3 万、**非流形边 0**、覆盖率 88.8%。

**验证方法**（已固化为单测 `TestMcTableConsistency`）：
`kEdgeMask[1] = 273 = 0b100010001` → 棱 0,4,8 → 按上游编号是
`(0,1)`、`(0,2)`、`(0,4)`，三条棱**恰好都围绕 corner 0** ✓；
另对全部 256 个 case 校验「`kTriangles` 引用的每条棱都在 `kEdgeMask` 内」
（820 个三角形，0 处越界）。

**（16）点云切平面致密化（新增步骤）**

活跃单元 = 「点云支撑 + 一环」。点云间距若为单元边长的 k 倍，每个点的
3×3×3 单元团就**互不连通** → 求解域断开 → `value_at()` 对未覆盖格点返回
0.0，而 `iso` 也≈0 → 未定义区恰好落在等值面上 → MC 产出杂乱碎片。

**现版**：`DensifyOnTangentPlane()` 把每个点沿切平面展开成 k×k 个虚拟点
（间距 = r），使活跃单元连成片。实测 D=9 时活跃单元从「互不连通的点状团」
变成 135 万连通的单元、**未定义格点查询 0 次**。

**（17）screened 项强度必须远小于对角项**

screened 项写成 `4·h⁻²·min(1,w)` 时相当于对角项 `6·h⁻²` 的 **67%**，
远比 PoissonRecon 的 ~17% 强 —— 后果是整个点云区域被**压平**在 iso 上，
而等值面 f = iso 在整块区域内部根本不存在（每处都等于 iso）。

**现版**：改为 `0.7·h⁻²·min(1,w)`（≈ 12%），只固定 gauge（消除常数自由度），
f 沿法向的变化由 ∇f ≈ V 驱动 → 等值面真正穿过薄壳。

**（18）同一条逻辑写两遍必然漂移（裁剪的 τ 计算）**

裁剪的外推区阈值 `τ = factor · max(r, 点云采样间距)` 需要点云间距。
早期实现在裁剪处**又写了一遍**「最近邻距离中位数」，但**漏了排除自身** →
每个点的最近邻就是它自己 → 距离恒为 0 → `cloud_spacing = 0` →
`τ = 2·max(r, 0) = 2r` 退化成绝对值。

后果：`τ = 0.43 mm` 小于「网格顶点到点云距离的中位数 0.59 mm」→
**主体网格被裁掉一半**（实测三角形 181 万 → 38 万，删 79%，覆盖只剩 17.5%）。

**现版**：裁剪处直接复用 `EstimatePointSpacing()`，只保留一份实现。

**（20）S7 短边坍缩：狭长面的真正成因是「极短边」**

实测（球面 depth=7，12.4 万三角形）狭长面（最长边/最短边 > 10）的构成：

| 量 | 值 | 折算 |
|---|---|---|
| 最短边中位 | 0.0537 mm | **0.062 × r**（约 1/16 个单元） |
| 最长边中位 | 0.9193 mm | 1.07 × r（正常） |

**所以成因不是「三顶点几乎共线」，而是「有一条极短边」** —— 这决定了
边翻转救不了它（四边形同样含那条短边，翻转后依旧狭长）。

**现版**：`CollapseShortEdges()` 坍缩长度 < `0.25 × r` 的边，两端点合并到**中点**。

**精度代价**：最大位移 = 边长 / 2 ≤ 0.125 × r，而泊松的形状误差量级是
**0.5 × r** → 这是「用 1/4 的形状误差换掉一整类退化面」。

**两类边分别处理（都必须过 link condition）**：

| 边类型 | 面数 | 端点条件 | 公共邻居数 | 拓扑效果 |
|---|---|---|---|---|
| 内部边 | 2 | 两端都**不是**边界顶点（边界度 = 0） | 恰为 **2** | 边界环严格不变 |
| 边界边 | 1 | 两端边界度都**恰为 2**（合法流形边界） | 恰为 **1** | 环 `…e′—a—b—f′…` → `…e′—a—f′…`，**环数不变、少一个顶点** |

**为什么必须允许边界边**：碎片化的网格里（实测 11 万个边界环）绝大多数顶点
都在边界上，只坍缩内部边会把 95% 的候选挡掉（实测坍缩数 5882 → 257）。

**两次踩坑**：

| 错误 | 后果 |
|---|---|
| 不用 `touched` 标记（允许一个顶点连续合并多个邻居） | `nbr` 快照过时 → link condition 失效 → **非流形边出现** |
| 只保护「边界顶点」而不区分边界边 | 坍缩数骤降到 257，效果几乎归零 |

**必须放在流水线的「兜底 S4 → S5 迭代」之前**：坍缩偶发产生非流形边
（实测 144 万三角形里 6 条），需要由后续迭代兜住；若放在迭代之后，
这些边没人修，S5 也已跑完、撕开的洞没人补。

**实测收益（球面 depth=7）**：

| 指标 | S7 前 | 仅边翻转 | **短边坍缩 + 边翻转** |
|---|---|---|---|
| 最小内角 P1 | 2.69° | 3.35° | **5.06°** |
| 最小内角 P5 | 5.44° | 7.13° | **10.75°** |
| 最小内角中位 | 34.78° | 34.83° | 36.73° |
| 狭长面 | 5843（4.7%） | 4402（3.5%） | **1279（1.1%）** |
| 非流形边 | 0 | 0 | **0** |

**P5 = 10.75° 已超过 §2.7 的 9° 目标**；P1 仍有 5.06°，残余是真正退化的
薄片（坍缩和翻转都无解）。

**（20b）S7 边翻转：零精度损失的质量改善**

在「几何精度 > 拓扑完整性 > 纹理质量」的铁律下，S7 的五个子步骤里只有
**边翻转**是**零精度损失**的 —— 它不移动任何顶点，只改变连接关系；
而且只翻转恰有 2 个面的内部边，**不改变边界环**。

**判据**：内部边 (p,q) 的两个对面为 c、d，翻转为 (c,d) 后要求
① 新边 (c,d) 尚不存在（含本轮新产生的边）
② 两个新三角形面积 > 0
③ `min(新内角) > min(旧内角) + eps`（单调改善 → 收敛，不震荡）

**绕序必须按实际有向边推导**（这是两次踩坑的教训）：
`MakeEdge` 只保证 `a<b`（无向键），**与面的绕序无关** ——
T1 完全可能按 `q→p` 使用该边。若按固定的 `a→b` 推导翻转公式：

| 错误 | 后果 |
|---|---|
| 写成 `T1'=(c,d,a)`、`T2'=(d,c,b)` | 外部边 `(c,a)`/`(a,d)` 方向反转 → 非流形边 0→1、边界环错位 |
| 按固定 `a→b` 推导（不查实际方向） | **90% 的翻转绕序翻反**（实测 7413 条 → 绕序不一致 403→7093） |

正确形式：先查 T1 在共享边上的实际有向边 `(p,q)`，再 `T1'=(d,c,p)`、`T2'=(c,d,q)`。

**实测收益**（单独使用，不含短边坍缩）：最小内角 P1 2.69° → 3.35°、
P5 5.44° → 7.13°、狭长面 4.7% → 3.5%；边界环 11282 → 11282（不变）、
绕序不一致 403 → 404、非流形边 0。翻转 7413 条后收敛（8 轮与 3 轮差 51 条）。

**与短边坍缩的组合效果见 (20)** —— 两者是必需的搭配：坍缩消除成因，
翻转再优化残余。

**试过但否决的方案**：Delaunay 判据（对角和 > 180°）。理论上 Lawson 算法保证
收敛且全局最优，但实测更差 —— 翻转 6540 条、P1 3.28°、狭长面 4.1%
（对比「min 改善」判据的 7413 / 3.35° / 3.5%）。
原因：Delaunay 优化的是「角度能量总和」，而这里的目标是「最小角」，
两者不同向。

**（21）S7 剩余子步骤的可行性结论（尚未实现）**

| 子步骤 | 精度影响 | 结论 |
|---|---|---|
| **顶点重分布**（切向 Laplacian 平滑 + 投影回原曲面） | **零损失**（若投影回 S7 前的网格副本） | 优先级**下调**：短边坍缩已把狭长面降到 1.1%、P5 超 9° 目标；剩余 1.1% 是真退化薄片，收益 < 成本。需要「最近三角形」空间索引（约 250 行） |
| 边坍缩（短边合并） | 移动几何 | 仅在「边长 < 0.1·r」的极端情况下启用 |
| 顶点度数规整（deg<3 坍缩 / deg>8 拆分） | 拆分零损失、坍缩有损失 | 拆分可做，坍缩需谨慎 |
| 特征保护（二面角锁定） | 保护精度 | 与顶点重分布配套实现 |

**为什么顶点重分布是零损失**：投影目标是 **S7 之前的网格**（分段线性曲面），
把平滑后的顶点投影回该曲面的最近点 → 顶点仍在原曲面上 →
**相对于 S7 前的网格，几何精度零损失**。这是 docs/06 §2.7 原文
「每次迭代后把顶点投影到 S7 之前的原始曲面（最近点投影）」的正确含义。

**（23）S8 UV 展开：回退路径已实现，xatlas 主路径待接入**

规格里 xatlas 是主路径、立方体投影是失败回退。当前**只实现了回退路径**
（`core/src/mesh/uv_unwrap.cpp`，MIT 自研，零外部依赖）：法向聚类 chart 分割 →
逐 chart 平面正投影 → shelf 图集打包。

**为什么先做回退路径**：xatlas 需从 GitHub 下载（项目规则要求下载前先确认 VPN），
而回退路径是规格明确要求的、零依赖、可静态链接进移动端，且对**块状/多面体**
扫描物体已经够用。

**三个实现要点（都是踩过坑的）**：

| 要点 | 错误做法 | 后果 |
|---|---|---|
| **chart 必须同时满足「法向相似」与「面连通」** | 只按法向聚类 | 同一 chart 含互不连通的两块 → 平面投影后 UV 重叠 → 纹理错乱 |
| **尺度按 2D 投影的「实际面积」定** | 按 2D 包围盒面积定 | 不规则 chart 在包围盒里留大片空白 → UV 面积只有目标值的 60% → 纹理分辨率白浪费（实测球面 mean_stretch = 0.595） |
| **拉伸比的分母用「实际总 UV 面积」** | 用「理想占比」`area3d/total_3d` | 把「打包利用率 63%」误算成「处处被压缩到 0.63」（实测平板网格报 0.62，而它其实是完美展开） |

另：**不限制单个 chart 的面数**。早期按面数占比（25%）硬切，导致平板网格被切成
4 块（本应 1 块）；UV 面积本就按 3D 面积比例分配，大 chart 不会「挤压」小 chart。

**实测（`tests/unit/test_uv.cpp`）**：

| 测试网格 | chart | 接缝新增顶点 | 图集利用率 | 平均面积拉伸 | 最大拉伸 |
|---|---|---|---|---|---|
| 平面（20×20） | **1** | 0 | 63.0% | **1.000** | 1.000 |
| 立方体 | **6** | 16（= 24 − 8） | 62.0% | **1.000** | 1.000 |
| 经纬球（24×48） | 52 | 646 | 63.5% | **1.002** | 1.061 |

**平均面积拉伸 1.000~1.002** 说明「UV 面积 ∝ 3D 面积」被严格保持 —— 即
**texel 密度均匀**，这是纹理烘焙质量的前提。

**已知限制**：

| 限制 | 影响 | 后续 |
|---|---|---|
| 图集利用率 63%（shelf 打包） | 业界 70~80%，约 10~15% 的纹理分辨率被浪费 | 换 MaxRects / Skyline 打包 |
| 平面投影在「法向与投影方向平行」处退化 | 球面极点等处的零面积 UV 三角形（规格 R4 要求导出前剔除并记录） | xatlas 的 LSCM/ABF 参数化可避免 |
| chart 数偏多（球面 52 个） | 接缝多，烘焙时接缝带更难处理 | xatlas 的 chart 合并（`joinAngle`） |
| **xatlas 主路径未接入** | 曲面物体（球、人脸）的拉伸与接缝不如 xatlas | 确认 VPN 后下载 `third_party/xatlas/`（MIT）并接入 |

**（24）S9 纹理烘焙：已解决（2026-10-30 第三轮；第四轮修正定向算法）**

> **最终状态**：单视图 RMSE **0.0115**、多视图 **0.0124**（目标 < 0.05），
> `test_bake` **已注册到 ctest**（9/9 全绿）。

**根因（架构级缺陷，非烘焙模块自身问题）**：

`RunMeshPipeline` 中**缺少「整体朝外定向」步骤**。

- `OrientFacesConsistently` 只保证**相邻面**绕序互相一致（局部一致），
  **完全不保证整体朝外**。整片网格可以「一致地朝内」。
- 实测：标准经纬球 **36480 个面全部朝内**（`n·外法向 = −1.0000`）。
- 后果链：`cos_ang < 0` → `w_ang = cos^α = cos⁸ ≈ 1e-6` → 权重塌到
  `min_weight_sum`(1e-3) 以下 → `BakeTexture` 把整片纹理写成**黑色** → RMSE 0.51。
  同理，渲染的背面剔除会把整个物体剔掉。
- `OrientNormalsOutward` 虽早已实现（§2.6 第 2 步明确要求有符号体积判据），
  但**从未被 `RunMeshPipeline` 调用**。

**修复（第一版，第三轮）**：新增 `OrientMeshOutward`，在流水线**末端**
（S6 之前）接入。判据用**有符号体积** `V = (1/6)Σ(a·(b×c))`。

**定位过程（方法论可复用）**：

用 `tools/bake_probe.cpp`（临时诊断工具）做**二分法**：

| 场景 | RMSE（写色判据） | 结论 |
|---|---|---|
| 平面 + 单视图（弦高 0、UV 单 chart） | **0.0023** | 烘焙核心/投影/采样/融合**全部正确** |
| 球面 + 单视图（原始绕序） | 1.0000 | 权重全塌（覆盖 0%） |
| 球面 + 单视图（**翻转绕序后**） | **0.0115 ✅** | **根因 = 绕序** |

平面场景把「弦高误差」与「UV 多 chart」两个变量排除掉后，球面剩下的唯一
差异就是**朝向**——翻转绕序立即达标，链条闭环。

**次要缺陷（同步修复）**：测试判据与生产判据不一致。
`CompareRmse` 用 `weight_sum > 0` 判「有值」，而 `BakeTexture` 用
`> min_weight_sum`(1e-3) 才写色 —— 中间那段极小权重的 texel 被写成黑色
（`rgb = 0`）却计入 RMSE，虚高到 0.34（真实采样误差 0.0115）。
**修法**：`CompareRmse` 增加 `min_weight` 参数，默认 1e-3，与生产判据对齐。

**过时判据的更正**：`TestSingleView` 原判据 `cov > 0.50` 是基于**错误状态**
的假设。修复后单视图真值覆盖率 = **21.5%**，与几何核算吻合：
相机距球心 250 mm、球半径 50 mm → 可见球冠 `(1 − 50/250)/2 = 40%`；
叠加 `w_ang = cos⁸` 把掠射区（α > 60°）压到阈值以下 → ≈25% × UV 利用率 0.87
≈ 21.5%。已改为 `cov ∈ [0.18, 0.35]` 的区间判据。

**（26）整体朝外定向的算法修正（2026-10-30 第四轮）**

> 第一版接线后 `test_bake` 已达标，但 `test_poisson` 的朝向回归判据只到
> **61.3%** 朝外，远低于预期。逐层诊断后推翻了两处实现决策。

**诊断工具**：`tools/orient_probe.cpp` / `pipeline_probe.cpp` / `winding_probe.cpp`
（均为临时工具，验证后已删除）。手法：**逐阶段重放流水线**，每阶段打印
「面积加权朝外占比 / mean(n̂·ĉ) / 强朝内面积占比 / 绕序不一致边数」。

**关键实测（球面 12000 点、depth=7，泊松原始 134722 面）**：

| 阶段 | 面积朝外 | mean(n̂·ĉ) | 强朝内面积 |
|---|---|---|---|
| 0 raw | 12.4% | −0.688 | 80.3% |
| 1 + 逐分量符号翻转（**不传播**） | **87.8%** | **+0.690** | **7.5%** |
| 2 + 净化 | 87.6% | +0.689 | 7.7% |
| 3 + `OrientFacesConsistently`（BFS） | **66.8%** ↓ | +0.317 | **27.2%** ↑ |
| … 后续 S4/S5/S7 | 66.8% → 67.0% | — | — |
| 末端 `OrientMeshOutward`（含 BFS） | 70.8% | +0.384 | 23.8% |

**修正一：`OrientMeshOutward` 内部删掉 BFS 传播。**

原实现第一步调用 `OrientFacesConsistently`。实测证明这一步**有害**：

- **泊松 MC 原始输出大体一致朝内**（主分量全体 n̂·ĉ ≈ **−0.86**，
  `|n̂·ĉ| ≥ 0.9` 的「法向明确面」占面积 64.5%）。它本来不需要「统一绕序」。
- 2 面共享边图会把**物理上互不相邻的面片**经「恰好共用一条边」拼进同一
  连通块（外推区尤甚）。BFS 从种子面沿边传播，**把种子朝向强加给整块** ——
  种子附近一条冲突边就能把整块（主块占球面 40% 面积）**级联**翻错。
- 结果：面积朝外 87.8% → **66.8%**，强朝内 7.5% → **27.2%**，
  且此后按分量整体翻转**再也修不回来**（块内已互相冲突）。
- 验证：逐阶段重放中**去掉这一步**，面积朝外全程稳定在 **87.6%**。

**修正二：把两处 `OrientFacesConsistently` 换成不传播的局部修复。**

新增 `FixLocalWindingErrors`：只对每个面统计其邻面中「绕序冲突」的条数，
**冲突占多数**才翻转该面。内部一致的分量**零损失**，孤立翻错的面被修正。
实测：主分量（87.6%）零变化，补洞指标反而**更好**（已填 34 vs 33、
非简单环 2071→2062、非流形边同为 0）。

**修正三：`FlipEdgesForQuality`（S7b 边翻转）加绕序守卫。**

边翻转的公式假设 T1、T2 在共享边上**绕序相反**。碎片化网格里存在本来
绕序冲突的边（假邻接 / 孤立翻错），对它套用公式会把外部边方向改错 ——
实测绕序不一致 7180 → **8101**、面积朝外 87.6% → 84.7%。已加
`if (t1_dir == t2_dir) continue;` 跳过此类边：绕序不一致保持 7180 不变。

**修正四：「绕序一致」与「朝向正确」互斥，取舍明确。**

这是本项目最重要的架构结论之一：

- 要压低「绕序不一致」，必须做**全局 GF(2) 求解**（≡ BFS 传播）。BFS 的
  翻转向量从种子级联到整块 → **必然翻错大量面** → 朝向崩坏且不可逆。
  实测残余可压到 0.45%（球面）/ 0.26%（致密化），代价是朝外只剩 61~67%。
- 要朝向正确，必须**放弃**全局传播，残余绕序不一致停在
  「泊松 MC 不可定向结构 + 假邻接边」水平（球面 **6.7%**、致密化 **6.7%**）。
- **取舍依据**：绕序不一致**不阻碍**流水线目标。实测（改用局部修复后）
  补洞已填 34 + 非流形边 0 + **test_bake RMSE 0.0115** 全部正常。
  故 **朝外定向 = 硬判据**，**绕序一致 = 参考量**（原 `<1%` 硬判据是
  「测代理不测目标」的典型误用，已降级为打印观察项）。

**判据更正（`test_poisson`）**：原判据「全网格 >95% 面朝外」把泊松外推区的
**近切向薄片**（面法向 ⟂ 径向，|n̂·ĉ| < 0.5，占面积 ~12%）也算进去 ——
这类面对「朝外」**原理上不可判**（同一平面片朝内朝外都有理）。改为**双层判据**：

| 判据 | 阈值 | 实测（球面） |
|---|---|---|
| 有符号体积 **符号** | `> 0` | +3.99e-4 ✅ |
| **法向明确面**（`\|n̂·ĉ\| ≥ 0.7`）朝外占比 | `> 0.85` | **93.8%** ✅ |

（全体面朝外 88.3% 如实打印供参考；`|n̂·ĉ| ≥ 0.9` 的极端明确面达 **94.4%**。）

### 2.6 S6 法向统一矫正

> **实现修正（2026-10-30 第四轮）**：下表的「第 3 步 局部翻转传播」**未采用**
> BFS 传播 —— 实测它会在泊松碎片化输出上沿假邻接边级联翻错整块。实际实现为
> **局部多数表决**（`FixLocalWindingErrors`）+ **逐分量符号翻转**
> （`OrientMeshOutward`）。完整实测与推导见 §2.5.1 (26)。

| 步骤 | 算法 | 参数 |
|---|---|---|
| 1. 连通分量划分 | 按「恰有 2 个面的共享边」求连通分量 | — |
| 2. 整体朝外定向 | **逐分量**累加面积加权径向符号 `S = Σ area(t)·sign(n(t)·(center(t) − G))`（`G` = 顶点平均质心）；`S < 0` → 整个分量翻转（`OrientMeshOutward`）。**刻意不做 BFS** | `post_normal_target_volume` = 正 |
| 3. 局部绕序修复 | **不传播**：逐面统计邻面中「绕序冲突」条数，冲突占多数才翻转该面（`FixLocalWindingErrors`）；迭代至收敛 | — |
| 4. 逐顶点法向重算 | 面法向按面积加权求和归一化 → 顶点法向 | `post_normal_area_weighted` = true |
| 5. 一致性校验 | 统计全部相邻面对的"边方向一致且点积 > 0"比例 `C` | 阈值 `C ≥ 0.98` 通过；< 0.98 → 记 `W_MESH_NORMAL_INCONSISTENT`（实测泊松碎片化输出残余 ~7%，属 MC 不可定向结构，不作硬失败） |

**为什么第 2 步用「径向符号」而不是「有符号体积」**：泊松输出是**开放壳**
（大量边界环），散度定理的体积**量级**没有严格几何意义（实测仅球真值的
~20%）；且碎片分量的体积也不可靠。径向符号对**开口与闭合分量都有效**，
对近似星形（凸 / 球状）物体判据稳健。

**为什么第 3 步不做 BFS 传播**：2 面共享边图会把物理上互不相邻的面片经
「恰好共用一条边」串成一块，BFS 沿其传播会把整块朝向翻错（实测面积朝外
87.8% → 66.8%），且不可逆。局部多数表决则对内部一致的分量零损失。


**局部翻转传播的判据公式**

对共享边 (a,b)，面 A 包含 (a,b,c)，面 B 包含 (b,a,d)（反向）：

```
consistent = dot(cross(b-a, c-a), cross(a-b, d-b)) > 0
```

若 `consistent == false`，则 B 的绕序与 A 相反（或法向反向），翻转 B。

**输入**：`FinalMesh` + `Atlas` + 全部关键帧（RGB + 深度图 + 位姿 + 内参）。

**步骤**

| 步 | 算法 | 参数 |
|---|---|---|
| 1 | 为每帧计算对网格的可见性：把网格顶点投影到该帧，深度一致性测试（`z_proj` 与该帧深度图之差 < `τ_vis`） | `post_bake_visibility_tol_mult` = 4.0 / 3.0 / 2.0（× 该帧深度像素足迹） |
| 2 | 视角评分：`s_view = w_vis · w_ang · w_res · w_blur` | — |
| 3 | 按 chart 逐三角形投影采样颜色并累积加权 | — |
| 4 | 融合（加权平均 或 梯度域 Poisson 融合） | `post_bake_blend_mode` |
| 5 | 生成图集纹理（PNG / JPEG） | `post_bake_texture_size` = 2048 / 4096 / 8192 |

**权重公式（完整定义）**

对图集像素 `p`，其对应的 3D 表面点 `x`，表面法向 `n`，候选视图 `i`（相机中心 `C_i`）：

```
w_ang   = max(0, dot(n, normalize(C_i - x)))^alpha        # 入射角
w_res   = clamp(1 - |z_proj(i,x) - z_ref(x)| / tau_vis, 0, 1)
w_area  = (pixel_footprint(i) / target_footprint)^2      # 分辨率匹配
w_blur  = 1 - motion_blur_score(i)
w_vis   = 1 if 该点通过深度一致性测试 else 0

w(i) = w_vis * w_ang * w_res * w_area * w_blur
C(p) = Σ_i w(i) * c_i(p) / max(Σ_i w(i), 1e-6)
```

| 参数 | 快 | 标 | 高 | 说明 |
|---|---|---|---|---|
| `post_bake_alpha` | 4 | 8 | 16 | 入射角指数，越大越偏好正视 |
| `post_bake_visibility_tol_mult` | 4.0 | 3.0 | 2.0 | 深度一致性容差（× 深度足迹），同上 |
| `post_bake_tau_vis_mult` | 4.0 | 3.0 | 2.0 | 残差项的 σ（× 深度足迹） |
| `post_bake_target_footprint` | 0.5 | 0.35 | 0.25 | 目标像素足迹（mm/px），由图集尺寸与物体尺寸算出 |
| `post_bake_min_weight_sum` | 1e-3 | 1e-3 | 1e-3 | 权重和下限，低于此值的像素标记为"未覆盖" |
| `post_bake_blend_mode` | `average` | `average` | `poisson` | 见下 |
| `post_bake_poisson_lambda` | 0.05 | 0.05 | 0.03 | 梯度域正则权重（`poisson` 模式有效） |
| `post_bake_poisson_iters` | 30 | 50 | 80 | 梯度域求解迭代数 |
| `post_bake_texture_size` | 2048 | 4096 | 8192 | 输出纹理边长（与 `post_uv_atlas_size` 强制相等） |
| `post_bake_color_space` | `linear` | `linear` | `linear` | 融合在线性空间做，导出时转 sRGB |
| `post_bake_normal_map` | false | false | true | 是否输出切空间法线贴图 |

**两种融合模式对比**

| 模式 | 算法 | 优点 | 缺点 | 使用条件 |
|---|---|---|---|---|
| `average` | 加权平均（公式上式） | 快、无额外依赖、数值稳定 | 视角切换处出现"半透明叠影" | 视角数 < 8 或纹理高频 |
| `poisson` | 梯度域融合：解 `min_C Σ_i w_i abs(∇C - ∇c_i)² + λ abs(∇C)²`（泊松拉普拉斯 + 边界条件），使用 `third_party/poisson_recon/Poisson/Solve.h` 的多网格求解器（MIT） | 视角切换处无缝，保留高频细节 | 耗时 3~6×；梯度域求解需每 chart 独立求解，chart 数多时开销线性增长 | 视角数 ≥ 8 且存在大视角变化 |

> **工程约束**：`poisson` 融合的梯度域求解器逐 chart 独立工作，chart 边界处由 Dirichlet 边界条件锁死，边界像素仍可能出现接缝。因此 `poisson` 模式**不保证**跨 chart 无缝，只保证 chart 内部无缝。

## 3. 导出

### 3.1 三种格式的通用规范

| 项 | GLB | OBJ + MTL | PLY |
|---|---|---|---|
| 容器 | 单文件二进制（glTF 2.0） | `.obj` 文本 + `.mtl` 文本 + 贴图 | `.ply`（binary little-endian 或 ascii） |
| 单位 | **米**（glTF 官方即米） | **米**，无内建单位字段 → 在 `.obj` 首行写 `# units: meter` | **米**，写入 header 注释 `comment units meter` |
| 轴向 | Y-up，右手系 | Y-up，右手系（注释声明） | Y-up，右手系（注释声明） |
| 顶点 | `POSITION` = VEC3 float32（必填） | `v x y z`，6 位小数 | `x y z` float32（`double` 可选） |
| 法线 | `NORMAL` = VEC3 float32 | `vn x y z`，6 位小数，索引独立 | `nx ny nz` float32 |
| UV | `TEXCOORD_0` = VEC2 float32，V 轴向下（glTF 约定） | `vt u v`，V 轴向上 → **导出时做 `v' = 1 - v` 翻转** | `s t` float32，V 轴向下（ply 惯例与 glTF 一致） |
| 切线 | `TANGENT` = VEC4 float32（w = ±1） | `f` 的第二分量不用 | 可选 `tx ty tz` |
| 索引 | `SCALAR` + `UNSIGNED_SHORT` / `UNSIGNED_INT` | 1-based，`f v/vt/vn` | `element face` list uint32 |
| 材质 | PBR metallic-roughness | `mtllib` + `usemtl` | 无材质（顶点色） |
| 颜色 | 顶点色 `COLOR_0` = VEC3/VEC4 ubyte（normalized） | 顶点色扩展 `v x y z r g b`（非标准，仅自研工具链解析） | `red green blue` ubyte |
| 附加 | `KHR_materials_emissive_strength` 不使用 | — | — |

#### 索引类型规则

```
vertex_count <= 65535  →  UNSIGNED_SHORT (GLB) / 1-based 短索引 (OBJ)
vertex_count >  65535  →  UNSIGNED_INT  (GLB) / 1-based 长索引 (OBJ)
```

- GLB：`accessor.componentType = 5123`（UNSIGNED_SHORT）或 `5125`（UNSIGNED_INT）。依据 glTF 2.0 规范（§3.6.2.2 Accessors / §3.6.2.4 Mesh Primitives）：
  - 索引 accessor 的 `componentType` 只能是 `5121`(UNSIGNED_BYTE) / `5123`(UNSIGNED_SHORT) / `5125`(UNSIGNED_INT) 三者之一；
  - 使用 `UNSIGNED_BYTE` 或 `UNSIGNED_SHORT` 时，被索引的顶点属性 accessor 的 `count` **必须大于索引中的最大顶点索引值**（即索引值必须落在 `0 .. count−1` 范围内）；
  - 规范**不要求**索引 accessor 本身必须使用 `UNSIGNED_INT`——`UNSIGNED_SHORT` 是规范允许的合法取值，仅在顶点数超过 65535 时不可用。
  - 本项目为保证"零错误"与最大兼容性，实现策略如下：
    - **默认（`export_index_mode = auto`）**：顶点 ≤ 65535 → `UNSIGNED_SHORT`，否则 `UNSIGNED_INT`。
    - **保守模式（`export_index_mode = uint32`）**：始终 `UNSIGNED_INT`。若目标工具链已知支持短索引，可用 auto 减小体积。
- OBJ/PLY：始终输出 32 位索引值（文本为十进制数字，无位宽问题）。

#### 三角形绕序

统一为**逆时针（CCW）**，从外侧观察为正面（右手系、右手定则）。

- 导出前由 §4.1 的校验确保所有三角形满足 CCW。
- GLB 规范规定 CCW 为正面，无 `doubleSided` 概念；本项目所有材质 `doubleSided = false`。
- OBJ 沿用 CCW 惯例，Maya/3ds Max/Blender 导入 OBJ 默认即为 CCW 正面。

### 3.2 各格式详细写出规格

#### GLB

```
┌────────────┬──────────────┬──────────────┬──────────────┐
│ magic      │ version      │ length       │ chunk0       │
│ "glTF"     │ 2 (uint32)   │ (uint32)     │ JSON (padded) │
├────────────┴──────────────┴──────────────┼──────────────┤
│ chunk1 length (uint32) | chunk1 type    │ BIN (padded) │
│                          0x004E4942     │              │
└─────────────────────────────────────────┴──────────────┘
```

| 段 | 规范 |
|---|---|
| header | `magic=0x46546C67`（"glTF"）、`version=2`、`length` = 文件总长 |
| chunk0 | `chunkLength` = JSON 字节数（含 padding）、`chunkType` = 0x4E4F534A（"JSON"）、JSON 文本以 0x20 空格补齐到 4 字节 |
| chunk1 | `chunkLength` = BIN 字节数、`chunkType` = 0x004E4942（"BIN\0"）、数据以 0x00 补齐到 4 字节 |
| JSON | `asset.version="2.0"`, `asset.generator="recon_core/<version>"`；`scene=0`；`scenes[0].nodes=[0]`；`nodes[0].mesh=0`；`meshes[0].primitives[0].attributes={POSITION,NORMAL,TEXCOORD_0,(TANGENT),(COLOR_0)}`；`material` 见下 |
| POSITION accessor | `bufferView`, `componentType=5126`(FLOAT), `count=vertex_count`, `type="VEC3"`, **必须带 `min`/`max`** |
| 索引 accessor | `componentType=5123` 或 `5125`, `type="SCALAR"`, `count=3*triangle_count` |
| 材质 | `pbrMetallicRoughness.baseColorTexture.index`，`metallicFactor=0.0`，`roughnessFactor=0.65`，`doubleSided=false`，`alphaMode="OPAQUE"` |
| 纹理 | `images[0].mimeType="image/png"`, `bufferView` 指向 BIN 内 PNG 字节；`samplers[0].wrapS=wrapT=33071`(CLAMP_TO_EDGE), `magFilter=9729`(LINEAR), `minFilter=9729`(LINEAR) |
| 采样器过滤说明 | 本项目导出**单层 PNG**（不生成 mipmap 链），因此 `minFilter` **不得**设为 `9987`(LINEAR_MIPMAP_LINEAR) 或 `9986`(LINEAR_MIPMAP_NEAREST)——无 mipmap 时该设置会导致纹理在缩小场景下采样行为未定义。`minFilter` 与 `magFilter` 统一取 `9729`(LINEAR)。若后续引入 mipmap 生成（多级 PNG 或 KTX2），须同步改为 `9987` 并在 `recon_mesh_info.json` 记录 `texture_mipmaps = true` |
| 附加扩展 | 顶点色存在时使用 `COLOR_0`（ubyte normalized）；不使用 `KHR_draco_mesh_compression`（避免运行时依赖） |
| 单位 | glTF 规范定义单位为米，内部不缩放 |

#### OBJ + MTL

```
# units: meter
# up_axis: Y
# forward_axis: Z
# generator: recon_core v1.0
mtllib model.mtl
o model
v  0.012345  0.123456  0.234567
v  0.023456  0.134567  0.245678
v  0.034567  0.145678  0.256789
v  0.045678  0.156789  0.267890
vn 0.000000  0.000000  1.000000
vn 0.000000  0.000000  1.000000
vn 0.000000  0.000000  1.000000
vn 0.000000  0.000000  1.000000
vt 0.123456 0.876544
vt 0.223456 0.876544
vt 0.223456 0.776544
vt 0.123456 0.776544
usemtl default
f  1/1/1  2/2/1  3/3/1
f  1/1/1  3/3/1  4/4/1
```

| 规范 | 值 |
|---|---|
| 坐标格式 | `%.6f`（微米级精度，对 1 m 物体误差 < 1 µm） |
| 索引基 | 1-based。顶点/法线/UV 各自独立计数 |
| 面语法 | `f v/vt/vn`（三者齐全）；无 UV 时 `f v//vn`；无法线时 `f v/vt` |
| 分组 | 单一 `o model` + 单一 `usemtl default`（多材质时按材质分段 `o`/`usemtl`） |
| 平滑组 | **不写 `s` 指令**。法线由显式 `vn` 提供，避免导入器按 `s` 重算导致与我们的法向不一致 |
| MTL | `newmtl default` + `Ka 0 0 0` + `Kd 1 1 1` + `Ks 0 0 0` + `d 1` + `illum 2` + `map_Kd <texture>.png` |
| 贴图引用 | 相对路径，纹理与 obj 同目录 |
| UV 方向 | OBJ 惯例 V 向上，glTF 惯例 V 向下 → 导出 OBJ 时 `v_out = 1 - v_in` |

#### PLY

```
ply
format binary_little_endian 1.0
comment generator recon_core v1.0
comment units meter
comment up_axis Y
element vertex N
property float x
property float y
property float z
property float nx
property float ny
property float nz
property float s
property float t
property uchar red
property uchar green
property uchar blue
element face M
property list uchar int vertex_indices
end_header
<binary data>
```

| 规范 | 值 |
|---|---|
| 格式 | `binary_little_endian`（`export_ply_ascii = false` 时）；ascii 仅调试用 |
| 顶点属性顺序 | `x y z` → `nx ny nz` → `s t` → `red green blue`，顺序固定不可调（导入器按名读取，但保持一致便于 diff） |
| 顶点色 | `uchar` 0~255；若网格无色则省略该三项属性 |
| 面 | `list uchar int vertex_indices`，每面固定 3 个索引 |
| UV 方向 | `s t` 采用 V 向下（与 glTF 一致），与 OBJ 相反 → **导出 PLY 时同样做 `v_out = 1 - v_in`** |
| 无纹理引用 | PLY 不引用纹理文件；纹理另存为同名 `*_albedo.png` 并在 `recon_mesh_info.json` 记录 |

### 3.3 大模型分块导出策略

**触发条件**

```
triangle_count > export_chunk_triangle_max  (默认 4,000,000)
或
vertex_count   > export_chunk_vertex_max    (默认 2,000,000)
或
生成文件预估大小 > export_max_file_mb       (默认 512 MB)
```

**分块规则**

| 规则 | 内容 |
|---|---|
| 切分粒度 | 按**连通面片簇**（相邻面聚类）贪心聚类直到达到面数上限，避免切断单个连通体 |
| 切分边界 | 在被切断的边上复制顶点（位置相同、UV 相同、法线按相邻面加权），保证各块顶点/索引自洽（块边界为**开放边**，需按 §2.5 独立补洞） |
| 命名 | `model_000.glb`、`model_001.glb`、`model_002.glb`（块序号从 000 起连续递增，宽度 3 位，不足补零）；OBJ 追加 `model_000.obj`、`model_001.obj` 等；PLY 同理 |
| 清单 | 生成 `model.manifest.json`：块列表、每块面数/顶点数/包围盒、装配变换（identity）、整体包围盒、是否需按清单装配 |
| 装配约定 | 所有块使用**同一世界坐标系**，导入端按 manifest 逐块导入即可自动对齐，无需手工变换 |
| 单文件导出 | 用户显式选择"单文件"且预估大小 < `export_max_file_mb * 2` 时不分块 |

**分块的已知限制（诚实披露）**

- 分块导出的模型在导入端是**多个网格对象**，不是单一连续网格。若下游需要单一闭合网格，必须导入后合并并重算法线。
- `model.manifest.json` 中的 `requires_merge = true` 标记用于提示。
- 分块不改变任何几何精度，仅改变文件组织方式。

## 4. 导出零错误保证

### 4.1 校验项与判据（`tools/export_check.py` 与 C++ 侧 `core/export/validator.cpp` 双重实现）

| 编号 | 校验项 | 检测方法 | 阈值 | 失败错误码 |
|---|---|---|---|---|
| V1 | **NaN / Inf** | 遍历所有顶点属性与法线，`std::isfinite` | 任一非有限值即失败 | `RECON_ERR_EXPORT_NAN` |
| V2 | **索引越界** | 三角索引 `max < vertex_count`，`min ≥ 0` | 任一越界即失败 | `RECON_ERR_EXPORT_INDEX_RANGE` |
| V3 | **三角形绕序一致** | 对每条内部边，统计它被两个面以**相反方向**引用的次数；必须恰为 1 | 存在同向引用（缠绕）或引用数 ≠ 2 → 失败 | `RECON_ERR_EXPORT_WINDING` |
| V4 | **有向体积为正** | `V = (1/6) Σ (v0 × v1)·v2`，应 > 0（外法向朝外） | `V ≤ 0` → 失败（闭合网格） | `RECON_ERR_EXPORT_ORIENTATION` |
| V5 | **法线单位化** | `‖n‖` 与 1 的偏差 | `abs(‖n‖ - 1) > 1e-3` → 失败 | `RECON_ERR_EXPORT_NORMAL_NORM` |
| V6 | **法线与几何法向一致性** | 顶点法向与关联面面积加权几何法向的夹角 | > `export_normal_angle_max_deg`（默认 60°）的顶点占比 > 1% → 失败 | `RECON_ERR_EXPORT_NORMAL_MISMATCH` |
| V7 | **UV 越界** | 所有 `u, v ∈ [0, 1]`（容差 1e-4） | 任一越界 → 失败 | `RECON_ERR_EXPORT_UV_RANGE` |
| V8 | **UV 三角形退化** | UV 三角形面积 | `< 1e-8`（归一化 UV 面积）的面占比 > 0.1% → 失败 | `RECON_ERR_EXPORT_UV_DEGENERATE` |
| V9 | **孤立顶点** | 顶点未被任何三角形引用 | 数量 > 0 即失败（导出前剔除，但若剔除后顶点数变化需同步索引） | `RECON_ERR_EXPORT_ORPHAN_VERTEX` |
| V10 | **重复顶点** | 位置 + 法线 + UV 三者均相同的顶点分组 | 同组数量 > 1 且占比 > 0.5% → 失败 | `RECON_ERR_EXPORT_DUPLICATE_VERTEX` |
| V11 | **重复三角形** | 顶点三元组（排序后）哈希 | 重复数 > 0 → 失败 | `RECON_ERR_EXPORT_DUPLICATE_FACE` |
| V12 | **索引类型合法性** | 顶点数 > 65535 时索引必须为 32 位 | 不符 → 失败 | `RECON_ERR_EXPORT_INDEX_TYPE` |
| V13 | **图集尺寸匹配** | 纹理实际尺寸 == `post_bake_texture_size` | 不符 → 失败 | `RECON_ERR_EXPORT_TEXTURE_SIZE` |
| V14 | **材质/贴图引用存在** | OBJ 的 `map_Kd` / GLB 的 `images[].uri` 指向的文件存在且非空 | 缺失 → 失败 | `RECON_ERR_EXPORT_MISSING_TEXTURE` |
| V15 | **包围盒合理性** | 三轴尺寸均 > 1 mm 且 < 100 m；三角形数 > 0 | 不符 → 失败 | `RECON_ERR_EXPORT_BBOX` |
| V16 | **非流形残留** | 边-面邻接计数 > 2 的边数 | > 0 即失败（修复阶段必须清零） | `RECON_ERR_EXPORT_NONMANIFOLD` |
| V17 | **文件可重解析** | 用目标格式的解析器重新读回文件，统计顶点/面/UV/法线数量与写出时一致 | 不一致 → 失败 | `RECON_ERR_EXPORT_ROUNDTRIP` |

> **V17 往返校验**是"零错误"的最终保险：写出后立即重新解析并逐项比对，任何结构损坏在这一步暴露，而不是等到用户打开 Blender 才发现。

**错误码编号规划（`core/include/recon/status.h`，与 01 文档对齐）**

| 区间 | 模块 |
|---|---|
| `0x03xx` | mesh（泊松、裁剪、简化） |
| `0x04xx` | postproc（拓扑修复、UV、烘焙） |
| `0x05xx` | export（写出、校验） |

> `status.h` 的最终编号由 01 文档统一定义；本文档只声明归属区间，若 01 文档已占用相同数值，以 01 文档为准并回改本文档。

### 4.3 DCC / 引擎侧验证方式

#### Blender（3.6 LTS / 4.x，Python 控制台）

```python

bpy.ops.wm.read_factory_settings(use_empty=True)
bpy.ops.import_scene.gltf(filepath="model.glb")   # 或 bpy.ops.wm.obj_import(filepath="model.obj")
ob = next(o for o in bpy.context.scene.objects if o.type == 'MESH')
bm = bmesh.new(); bm.from_mesh(ob.data)

assert bm.verts and bm.faces, "mesh empty"

nonmanifold_e = sum(1 for e in bm.edges if len(e.link_faces) > 2)
boundary_e    = sum(1 for e in bm.edges if len(e.link_faces) == 1)
loose_v       = sum(1 for v in bm.verts if not v.link_faces)
dup_v         = len(bm.verts) - len({(round(v.co.x,6), round(v.co.y,6), round(v.co.z,6)) for v in bm.verts})

print("verts", len(bm.verts), "faces", len(bm.faces))
print("nonmanifold_edges", nonmanifold_e, "boundary_edges", boundary_e)
print("loose_verts", loose_v, "dup_verts", dup_v)

assert nonmanifold_e == 0, "non-manifold edges found"
assert loose_v == 0, "loose vertices found"

# 法线方向：体积应为正
vol = bm.calc_volume(signed=True)
print("signed_volume", vol)
assert vol > 0, "inverted normals (negative volume)"

# UV 越界
uvbad = 0
for p in bm.loops:
    if p.uv is None: uvbad += 1; continue
    if not (0.0 <= p.uv.x <= 1.0 and 0.0 <= p.uv.y <= 1.0): uvbad += 1
print("uv_out_of_range", uvbad)
assert uvbad == 0, "UV out of range"

# 面法向是否与顶点法向大致同向
flip = sum(1 for f in bm.faces if f.normal.length > 0 and f.calc_center_median().dot(f.normal) < -1e-6)
bm.free()
print("BLENDER_IMPORT_CHECK_OK")
```

#### 3ds Max（2022+，MAXScript）

```maxscript
-- 3ds Max 侧抽查脚本：导入成功 + 顶点/面数 + 非流形边计数
-- 非流形边判定：按"边 → 相邻面数"建表，任一边的相邻面数 > 2 即为非流形边
fn collectNonManifoldEdges obj =
(
    local edgeMap = #()          -- 键为 "v1:v2"（v1<v2），值为相邻面数
    local nf = (getNumFaces obj) as integer
    for f = 1 to nf do
    (
        local v1 = (getFaceVert obj f 1) as integer
        local v2 = (getFaceVert obj f 2) as integer
        local v3 = (getFaceVert obj f 3) as integer
        local tri = #(v1, v2, v3)
        for e = 1 to 3 do
        (
            local a = tri[e]
            local b = tri[(e mod 3) + 1]
            local key = if (a < b) then (a as string) + ":" + (b as string) \
                        else (b as string) + ":" + (a as string)
            if (edgeMap[key] == undefined) then edgeMap[key] = 0
            edgeMap[key] = edgeMap[key] + 1
        )
    )
    local bad = 0
    for k in edgeMap.keys do
    (
        if (edgeMap[k] > 2) then bad = bad + 1
    )
    bad
)

fn verifyMaxMesh filePath =
(
    local ok = true
    resetMaxFile #noPrompt
    importFile filePath #noPrompt using:FBX
    local objCount = 0
    for o in objects where (superClassOf o == GeometryClass) do
    (
        local nm = (getNumVerts o) as integer
        local nf = (getNumFaces o) as integer
        local bad = collectNonManifoldEdges o
        objCount = objCount + 1
        format "mesh % verts=% faces=% nonmanifold_edges=%\n" o.name nm nf bad
        if (nm == 0 or nf == 0) do ( ok = false; format "EMPTY MESH\n" )
        if (bad > 0) do ( ok = false; format "NON-MANIFOLD EDGES FOUND\n" )
    )
    if (objCount == 0) do ( ok = false; format "NO MESH IMPORTED\n" )
    if ok then ( format "MAX_IMPORT_CHECK_OK\n" ) else ( format "MAX_IMPORT_CHECK_FAILED\n" )
)
verifyMaxMesh "E:\\out\\model.obj"
```

> 3ds Max 官方脚本编辑器不提供"非流形边计数"的直接 API，上述脚本以导入成功 + 顶点面数 + 空网格检查为主；非流形检查以 §4.1 的 `export_check.py` 为准（3ds Max 侧做抽查）。

#### Unity（2021.3 LTS+，Editor 脚本）

```csharp
#if UNITY_EDITOR
using System.Linq;
using UnityEditor;
using UnityEngine;
using UnityEngine.Rendering;

public static class ReconImportCheck
{
    [MenuItem("Recon/Validate Imported Mesh")]
    static void Validate()
    {
        var mf = Selection.activeGameObject.GetComponent<MeshFilter>();
        if (mf == null) { Debug.LogError("no MeshFilter"); return; }
        var m = mf.sharedMesh;

        Debug.Log($"verts={m.vertexCount} tris={m.triangles.Length/3} submeshes={m.subMeshCount}");

        var bad = m.triangles.Where(i => i < 0 || i >= m.vertexCount).Count();
        if (bad > 0) Debug.LogError($"out-of-range indices: {bad}");

        var norms = m.normals;
        int badN = 0;
        for (int i = 0; i < norms.Length; i++)
            if (float.IsNaN(norms[i].x) || Mathf.Abs(norms[i].magnitude - 1f) > 1e-3f) badN++;
        if (badN > 0) Debug.LogError($"bad normals: {badN}");

        for (int s = 0; s < m.subMeshCount; s++)
            Debug.Log($"submesh {s}: {m.GetTriangles(s).Length/3} tris");

        // 网格导入设置核对
        var imp = AssetImporter.GetAtPath(AssetDatabase.GetAssetPath(mf.gameObject)) as ModelImporter;
        if (imp != null)
        {
            if (!imp.importNormals) Debug.LogWarning("ModelImporter.importNormals is OFF");
            if (imp.isReadable == false && imp.importBlendShapes) { /* 无影响 */ }
            if (imp.weldVertices) Debug.LogWarning("weldVertices ON may merge UV seams");
        }
        Debug.Log("UNITY_IMPORT_CHECK_DONE");
    }
}
#endif
```

**Unity 侧特别注意**

| 项 | 要求 |
|---|---|
| `ModelImporter.importNormals` | 必须为 `Import`，否则 Unity 会用自己重算法线，掩盖我们的法向问题 |
| `ModelImporter.weldVertices` | 必须为 `Off`，否则 UV 接缝处的顶点被合并，纹理错位 |
| `ModelImporter.importTangents` | 有法线贴图时必须为 `Import` |
| `ModelImporter.meshCompression` | 建议 `Off`（精度优先），`Medium` 会压缩顶点精度 |
| `ModelImporter.indexFormat` | 自动：>65535 顶点时 Unity 自动切 32 位；导入后可读 `mesh.indexFormat` 确认 `IndexFormat.UInt32` |

### 4.4 零错误保证的实现承诺

| 承诺 | 实现手段 |
|---|---|
| 结构层面零错误 | 写出前 V1~V16 全项通过 + V17 往返解析比对，任一失败则**拒绝写出**并返回错误码（不产出半成品文件） |
| 属性层面零错误 | 法线、UV、切线全部显式写出，不依赖导入器推断；不写 `s` 平滑组指令；GLB 的 POSITION accessor 强制带 `min`/`max` |
| 兼容层面零错误 | OBJ 全部使用 `v/vt/vn` 三段式；PLY 属性名与顺序固定；GLB chunk padding 合规；索引位宽自动匹配顶点数 |
| 精度层面零错误 | 全流程米制，无隐式缩放；导出不做任何坐标变换；V15 包围盒合理性检查拦截"单位错 1000 倍"这类事故 |
| 可追溯 | 每次导出产出 `export_check_report.json` + `recon_mesh_info.json`，记录全部参数生效值 |
