## 0. 设计约定

### 0.1 命名与映射

| 规则 | 内容 |
|---|---|
| 键名格式 | `snake_case`，全小写，下划线分隔，无前缀缩写歧义 |
| 键名 ↔ C++ 成员名 | **一一对应**：键名去掉分组前缀（见 §1）后即为 C++ 结构体成员名，成员名本身也是 `snake_case` |
| C++ 承载 | `core/include/recon/params.h` 中定义 12 个 POD 结构体（§1），由 `recon::ParamSet` 统一持有 |
| 跨语言 | 全部参数经 `recon_c_api.h` 的 `recon_params_*` 系列函数读写（01 文档定义），Swift/Kotlin 侧不得直接访问结构体内存 |
| 单位 | 每个参数必须在表内标注单位；无单位者写 `—` |
| 布尔 | C++ 用 `uint8_t`（0/1）承载，保证 POD 与 ABI 稳定 |

### 0.2 分组前缀与承载结构体

| 组号 | 组名 | 键名前缀 | C++ 结构体 | 所在头文件 | 模块归属 |
|---|---|---|---|---|---|
| G1 | 采集类 | `cap_` | `recon::CaptureParams` | `params.h` | `core/capture/` |
| G2 | 时间同步类 | `sync_` | `recon::SyncParams` | `params.h` | `core/sync/` |
| G3 | VIO 类 | `vio_` | `recon::VioParams` | `params.h` | `core/vio/` |
| G4 | SfM 类 | `sfm_` | `recon::SfmParams` | `params.h` | `core/sfm/` |
| G5 | MVS 类 | `mvs_` | `recon::MvsParams` | `params.h` | `core/mvs/` |
| G6 | 深度融合类 | `rgbd_` | `recon::RgbdParams` | `params.h` | `core/rgbd/` |
| G7 | 网格化类 | `mesh_` | `recon::MeshParams` | `params.h` | `core/mesh/` |
| G8 | 后处理类 | `post_` | `recon::PostProcParams` | `params.h` | `core/postproc/` |
| G9 | 尺度类 | `scale_` / `calib_` | `recon::ScaleParams` | `params.h` | `core/calib/` |
| G10 | 导出类 | `export_` | `recon::ExportParams` | `params.h` | `core/export/` |
| G11 | 性能类 | `perf_` | `recon::PerfParams` | `params.h` | `core/util/` |
| G12 | 扫描与关键帧类 | `scan_` | `recon::ScanParams` | `params.h` | `core/capture/` |

> **G9 双前缀**：`scale_` 用于尺度策略与手动微调，`calib_` 用于参照物检测与解算。二者同属 `recon::ScaleParams`，成员名去掉各自前缀后唯一（无重名）。

> **G12 单一前缀 + 语义子段**：`scan_` 是 G12 的分组前缀，键名去掉该前缀后为 C++ 成员名。G12 内部按语义分四个子段，成员名自带子段前缀以保证唯一与可读：
>
> | 子段 | 成员名前缀 | 语义 |
> |---|---|---|
> | 扫描模式与引导 | `scan_` | 模式、点位集、点位容差、停留时长、角度步长、理想距离 |
> | 关键帧判据 | `scan_kf_` | 几何增量、视角增量、质量分判据、优先级权重 |
> | 抖动补偿 | `scan_stab_` | 稳像低通截止、旋转上限、抖动判定阈值 |
> | 确认自检 | `scan_review_` | 自检清单的通过阈值 |
> | 底面处理 | `scan_bottom_` | 底面处理模式与翻转模式开关 |
>
> **历史键名映射**：03 文档早期版本使用点分前缀（`scan.mode` / `kf.*` / `stab.*` / `review.*` / `bottom.*`），该命名体系已废弃。全部 32 个参数在本文档统一改为下划线形式，映射见 §5.6。

### 0.3 精度维度词表（"影响的精度维度"列取值）

| 词 | 含义 | 典型观测指标 |
|---|---|---|
| 几何分辨率 | 网格能表达多细的特征 | 三角形平均边长 |
| 几何绝对精度 | 曲面相对真实位置的偏差 | 与标定物/激光扫描比对的最大偏差 |
| 拓扑完整性 | 流形性、孔洞、非流形边 | 非流形边数 / 边界环数 |
| 尺度精度 | 尺度因子 `s` 的正确性 | `σ_s/s` |
| 纹理质量 | 纹理的清晰度、覆盖度、色彩正确性 | Laplacian 高频能量、覆盖缺口占比 |
| 定位精度 | 相机位姿 / 特征点位置精度 | 重投影误差、位姿漂移 |
| 抗噪性 | 对输入噪声的鲁棒 | 噪声注入下的退化幅度 |
| 求解收敛性 | 优化器收敛概率 | 收敛率、残差下降 |
| 速度 | 耗时 | 阶段耗时（s） |
| 内存 | 峰值内存 | 峰值 RSS（MB） |
| 能耗 | 电池消耗 | 平均功率（W） |

### 0.4 用户可调列取值

| 值 | 含义 |
|---|---|
| 是 | UI 参数面板暴露，可实时修改 |
| 否 | 内部参数，由算法自动决定或受其他参数约束；UI 不暴露 |
| 专家 | 默认隐藏，需在"专家模式"开关打开后可见（09 文档定义） |

> **R-PREC-6 落实**：所有精度相关阈值必须可被用户覆盖。上表中标"否"的参数必须是**非精度类**（性能、内存、诊断）或**由其他用户可调参数唯一决定**（派生量）。§5.2 给出逐项核查结论。

### 0.5 生效时机列取值

| 值 | 含义 |
|---|---|
| 采集前 | 修改后必须**重新开始采集**才生效 |
| 重建中 | 修改后需从该帧起重跑重建（需保留原始帧） |
| 重建后 | 修改后需重跑重建后段（网格化及其后） |
| 导出时 | 仅影响导出结果，可热更新 |

## 1. 参数组总表（G1 ~ G12）

> **列语义说明（"默认值" 与 "快/标/高" 的关系）**
>
> | 列 | 含义 |
> |---|---|
> | **默认值** | 应用**首次启动、尚未选择预设**时写入 `ParamSet` 的值。这批参数一律取**精度最高**的档位值（与 00 R-PREC-2"出厂配置为最高精度"一致），例如 `mvs_image_scale` = 1.0（不降采样）、`mvs_patch_size` = 11、`export_texture_max_size` = 8192、`post_bake_normal_map` = 1。**默认值不等于标准档** |
> | **快/标/高** | 三档预设（`fast` / `standard` / `high`）分别写入的值，格式为 `快速/标准/高精度`。用户切换预设后按 §3.4 覆盖（被用户锁定的参数除外） |
>
> 数值型参数中，**默认值与标准档相同**的项占绝大多数；不同的 8 项均为"默认取高精度值"的精度敏感参数（`mvs_image_scale` / `mvs_num_views` / `mvs_patch_size` / `export_texture_max_size` / `post_bake_normal_map` 及三处数值格式差异如 `50.0` vs `50`）。**恢复出厂**（§4.3）会把预设置为 `standard`，此时这些参数才落到标准档值。

## 2. 三档预设

### 2.1 预设定义

| 预设 | 键名 | 说明 |
|---|---|---|
| 快速 | `fast` | 优先速度，精度阈值降到"仍可用"的下限 |
| 标准 | `standard` | 默认档，精度与耗时的平衡点 |
| 高精度 | `high` | 精度阈值拉到可行上限，代价是时间与内存显著上升 |

**预设只改参数值，不改算法分支。**

| 规则 | 说明 |
|---|---|
| P1 | 预设是参数值的集合。切换预设**不改变** `BRANCH_RGBD` / `BRANCH_MONO` 的选择（由 00 文档 §5.2 能力探测决定） |
| P2 | 预设**不改变**任何算法是否启用的布尔语义（如"简化默认关闭"在三档中都关闭） |
| P3 | 预设**不改变**降级策略的白名单/黑名单归属 |
| P4 | 切换预设时，逐参数比较：被预设覆盖的参数写入新值；**用户手动改过且被标记为"锁定"的参数保持不变**（见 §3.4） |
| P5 | 高精度档在移动端可能超出设备能力（内存/时间）。此时**只允许**按 00 文档白名单降级（并行度、批大小、分块），并向用户明示降级项 |

### 2.2 快速档（`fast`）

| 目标 | 取值策略 |
|---|---|
| 采集 | 30fps / 1280×720 / 自动曝光 / 自动白平衡 |
| VIO | 200 特征点、12 次迭代、8ms 时限 |
| SfM | 8000 特征点、RANSAC 5000 次、BA 50 次 |
| MVS | 0.5× 缩放、7px patch、5 视图、深度 0.08~1.5 m |
| 深度融合 | 4mm 体素、32 块分块、64 块常驻 |
| 泊松 | depth 9、samplesPerNode 1.0、sharpness 1.0、bType off |
| 后处理 | UV 2048、烘焙 average、图集 2048 |
| 尺度 | 参照物检测 1024px、闭运算 1 次、不做联合优化 |
| 导出 | 分块上限 200 万面、单文件 256MB |

### 2.3 标准档（`standard`）

| 目标 | 取值策略 |

| 采集 | 30fps / 1920×1080 / 手动锁定曝光 8000μs / ISO 400 |

### 2.4 高精度档（`high`）—— 全力拉满清单

**核心原则**：把**所有**精度一阶因子推到可行上限，不做任何以精度换速度的妥协。

| 参数 | 键名 | 高精度取值 | 相对标准的增益 | 代价 |

| 指标 | 标准档 | 高精度档 | 倍数 |
|---|---|---|---|
| 重建总耗时（100 帧、0.3 m 物体） | ~8 min | ~35 min | 4.4× |
| 峰值内存 | ~2.5 GB | ~9 GB | 3.6× |

| 导出文件大小 | ~180 MB | ~420 MB | 2.3× |

**高精度档在移动端的可执行性**

| 设备档位 | 高精度档是否可跑完 | 处置 |
|---|---|---|
| 高端（≥8 GB RAM） | 可跑完，峰值约 9 GB | 直接执行 |

## 3. 参数校验与夹取

### 3.1 夹取（clamp）策略

**所有参数在进入 core 之前统一过一遍 `ParamSet::clamp()`。** 夹取规则：

| 规则 | 内容 |
|---|---|
| C1 数值型 | `value = min(max(value, lo), hi)`，`lo`/`hi` 取 §1 表中的"合法范围" |
| C2 枚举型 | 值不在枚举集合内 → 回落到该参数的**默认值**，并记录警告 `W_PARAM_ENUM_FALLBACK` |
| C3 布尔 | 非 0 值一律归一为 1 |
| C4 字符串 | 长度截断到 256 字节；路径必须落在沙盒内，否则清空 |
| C5 联动约束 | 见 §3.2 的冲突检测表，冲突时按表中的**仲裁方向**调整 |
| C6 无静默回退 | 夹取发生时**必须**记录 `W_PARAM_CLAMPED`，并在 UI 参数面板对应条目上显示"已修正"标记与原值（R-PREC-6） |

**夹取不是静默的**：用户输入 9999 的 `mesh_poisson_depth` 会被夹到 14，UI 显示"已修正（14）"，`recon_mesh_info.json` 中记录 `clamped_params` 列表。

### 3.2 联动约束与冲突检测

| # | 约束 | 检测条件 | 仲裁方向 | 说明 |
|---|---|---|---|---|
| L1 | 图集尺寸 = 纹理尺寸 | `post_uv_atlas_size != post_bake_texture_size` | 把 `post_bake_texture_size` 同步为 `post_uv_atlas_size` | 否则 UV 越界 |
| L2 | TSDF 截断 ≥ 2× 体素 | `rgbd_tsdf_truncation < 2 * rgbd_tsdf_voxel_size` | 提升 `rgbd_tsdf_truncation` 到 `2 * voxel` | 截断过小导致融合出现空洞 |
| L3 | 泊松深度 vs 内存预算 | 估算 `N_cells = S/r²`（r 由 depth 决定）× 220 B > `perf_memory_budget` | **不改 depth**，改为置 `mesh_chunked_enabled=1` 并降低 `rgbd_max_blocks_in_memory` / `perf_gpu_batch_size` | R-PREC-4：depth 不可降级 |
| L4 | MVS 深度范围 vs 泊松尺度 | `mvs_depth_max` 远大于实际物体尺度（包围盒对角线 > 3× `mvs_depth_max`） | 提示用户收窄深度范围；不自动改 | 影响 MVS 速度与深度步长精度 |
| L5 | BA 迭代 vs 收敛容差 | `sfm_ba_max_iterations` 过小而 `sfm_ba_convergence_tolerance` 过严 | 提示"可能不收敛"；不自动改 | — |
| L6 | 标定尺度 vs 手动尺度 | `scale_manual_enabled=1` 且手动值与自动值差 > 10% | 手动值生效（07 文档 §3.3），但 UI 强提示差异百分比 | 手动是最终权威 |
| L7 | 简化 vs 拓扑约束 | `post_simplify_enabled=1` 且 `post_simplify_error_threshold=0` 且 `post_simplify_target_faces=0` | 视为"无目标"，不执行简化并提示 | 避免无效运算 |
| L8 | 简化 vs UV chart | `post_simplify_enabled=1` 且 `post_simplify_uv_preserve=1` | 简化时按 chart 边界分块独立简化 | 防止 chart 被破坏 |
| L9 | 简化 vs 最低面数 | `post_simplify_target_faces < 500` | 夹取到 500 | 低于此值无实用价值 |
| L10 | 深度角色 vs 分支 | `rgbd_lidar_role=3`（全量融合）但设备为 `ALGO_DEPTH` | 强制回落到 1（尺度锚定+先验） | 运动深度不得作全量 TSDF 主输入 |
| L11 | VIO 关闭 vs IMU 尺度先验 | `cap_imu_enabled=0` 且分支为 MONO | `scale_imu_prior_relative_sigma` 失效，尺度来源只剩参照物/手动 | — |
| L12 | 纹理格式 vs 透明 | `export_texture_format=1`（JPEG）且材质需要 alpha | 报错，拒绝导出 | JPEG 无 alpha 通道 |
| L13 | 切线 vs 法线贴图 | `post_bake_normal_map=1` 且 `export_write_tangents=0` | 自动置 `export_write_tangents=1` | 否则法线贴图无意义 |
| L14 | UV vs 贴图输出 | `post_uv_*` 已执行但 `export_write_uv=0` | 允许，但导出报告记录"无 UV 模型" | — |
| L15 | 内存水位 vs 缓存 | `perf_memory_high_water_ratio` 触发时 | 按 13 文档顺序：落盘 → 分块 → 降低并行度 | 绝不通过丢精度数据降内存 |
| L16 | 目标距离 vs 理想距离区间 | `scan_viewpoint_distance_m` 超出 `[scan_ideal_distance_min_m, scan_ideal_distance_max_m]` | 提示"目标距离不在理想区间"，**不自动改**（用户显式设定优先） | 理想区间只影响 MVS 视差与像素覆盖，不构成硬约束（03 §6.1 IC-1） |
| L17 | 引导点位距离 vs 可达性硬界 | 由包围盒推出的目标距离 `clamp(1.6×B, 0.30, 0.80)` 超出 `[0.25, 1.20]` | 把 `scan_viewpoint_distance_m` 夹取到该区间并记 `W_PARAM_CLAMPED` | `scan_viewpoint_distance_m` 是标量默认值，实际生效距离由包围盒缩放（03 §4.3.2 V-3） |

### 3.3 用户改参数的即时生效范围

| 类别 | 代表参数 | 生效时机 | 是否需重新采集 | 是否需重跑重建 | 说明 |
|---|---|---|---|---|---|
| **A 采集参数** | `cap_*` | 采集前 | **是** | — | 影响传感器配置，必须新会话 |
| **B 同步参数** | `sync_*` | 重建中 | 否 | 是（从原始帧重放） | 原始帧在磁盘，可重放 |
| **C 估计参数** | `vio_*`, `sfm_*`, `mvs_*`, `rgbd_*` | 重建中 | 否 | 是（从该阶段起重跑） | 需要保留上游中间结果 |
| **D 网格化参数** | `mesh_*` | 重建后 | 否 | 否（只重跑泊松及后） | 需要保留稠密点云 |
| **E 后处理参数** | `post_*` | 重建后 | 否 | 否 | 需要保留网格 |
| **F 尺度参数** | `scale_*`, `calib_*` | 重建前 | 否 | 部分（尺度注入后需重跑 MVS 及之后） | 改尺度会改变 MVS 深度度量 |
| **G 导出参数** | `export_*` | 导出时 | 否 | 否 | 纯热更新 |
| **H 性能参数** | `perf_*` | 热更新 | 否 | 否 | 立即生效 |
| **I 扫描与关键帧参数** | `scan_*` | 采集前 / 重建中 | **部分**：模式与点位集需重新采集；关键帧判据可从原始帧重放 | 关键帧判据变化需从关键帧判定起重跑 | 关键帧判据影响入库集合，需从原始帧重算 |

**热更新矩阵（可即时生效，无需任何重跑）**

| 参数 | 支持热更新 |
|---|---|
| `perf_*` 全部 | 是（下一批次生效） |
| `export_*` 全部 | 是 |
| `post_*` 全部 | 是（下次进入后处理阶段生效） |
| `mesh_*` 全部 | 是（下次进入网格化阶段生效） |
| `rgbd_*`, `mvs_*`, `sfm_*`, `vio_*`, `sync_*` | 否（需重跑重建） |
| `cap_*` 全部 | 否（需重新采集） |
| `scale_*`, `calib_*` | 部分（见 §3.4） |
| `scan_*` 采集前类（`scan_mode` / `scan_viewpoint_*` / `scan_dwell_*` / `scan_bottom_*`） | 否（需重新采集） |
| `scan_kf_*` / `scan_stab_*` | 否（需从原始帧重跑关键帧判定与稳像） |
| `scan_review_*` | 是（仅影响自检判定，立即生效） |

**UI 行为**

| 场景 | 行为 |
|---|---|
| 用户改 H 类参数 | 立即写回 `ParamSet`，无需中断 |
| 用户改 D/E 类参数 | 提示"将在下次重建阶段生效"，提供"立即重建"按钮 |
| 用户改 C 类参数 | 提示"需要重新运行重建"，显示预计耗时；当前重建若在运行则先取消 |
| 用户改 A 类参数 | 提示"需要重新开始采集"，当前会话的结果保留但标记为"旧参数" |
| 用户改 F 类参数（尺度） | 若当前已有重建结果：提供"仅重算尺度并重跑 MVS 及之后"与"完全重跑"两个选项 |

### 3.4 用户覆盖与预设切换的交互

**参数锁定机制**

每个参数在 `ParamSet` 中带一个 `locked_by_user` 标志位：

| 事件 | 行为 |
|---|---|
| 用户手动修改参数 X | `X.locked_by_user = 1`，写入 `overrides` 表 |
| 切换预设 | 对每个参数：若 `locked_by_user=1` 则**保持用户值**；否则写入新预设值 |
| 切换预设的 UI 提示 | 列出"本次被预设覆盖的 12 项"与"因用户锁定而保留的 3 项"，逐项可见 |
| 用户"恢复默认" | 清空 `overrides` 表，全部回到当前预设值 |
| 用户"恢复出厂" | 预设重置为 `standard`，`overrides` 清空，`locked_by_user` 全清 |

**overrides 表结构**（持久化，见 §4）

```
overrides: { "<param_key>": { "value": <typed value>, "locked": true } }
```

## 4. 参数持久化

### 4.1 存档格式

**文件位置**

```
<sandbox>/sessions/<session_id>/params.json          # 当前会话的参数
<sandbox>/sessions/<session_id>/recon_mesh_info.json  # 参数生效值 + 阶段状态 + 导出报告
<sandbox>/presets/<preset_name>.json                 # 三档预设的定义（随 App 发布，不可编辑）
```

**`params.json` 结构**

```json
{
  "schema_version": 2,
  "session_id": "20261029-153042-a7f3",
  "created_at": "2026-10-29T15:30:42+08:00",
  "app_version": "1.0.0",
  "core_abi_version": 7,
  "preset": "high",
  "device": {
    "model": "iPhone15,3",
    "platform": "ios",
    "capability_probe": { "branch": "BRANCH_RGBD", "depth_tier": 3, "depth_source": "HW_LIDAR" }
  },
  "params": {
    "cap_frame_rate": 60,
    "sfm_feature_count": 20000,
    "mesh_poisson_depth": 11,
    "rgbd_tsdf_voxel_size": 0.0005
  },
  "overrides": {
    "post_bake_blend_mode": { "value": 1, "locked": true },
    "export_format": { "value": 2, "locked": true }
  },
  "clamped_params": [
    { "key": "mesh_poisson_depth", "requested": 20, "applied": 14, "reason": "range_clamp" }
  ],
  "warnings": [
    { "code": "W_PARAM_ENUM_FALLBACK", "key": "post_bake_blend_mode", "requested": 9, "applied": 1 }
  ]
}
```

**字段说明**

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | int | 存档格式版本。当前 `2`。读入时版本低于当前则走迁移；高于当前则拒绝并提示升级 App |
| `core_abi_version` | int | 必须与 `recon_c_api.h` 的 `RECON_ABI_VERSION` 一致，不一致直接拒绝加载 |
| `preset` | string | 当前预设名 |
| `params` | object | **仅存储与预设不同的参数**（稀疏存储）。加载时先铺预设值，再叠加此表 |
| `overrides` | object | 用户锁定项。同时出现在 `params` 中，此处记录锁定状态 |
| `clamped_params` | array | 加载时发生的夹取记录，供 UI 展示 |
| `warnings` | array | 加载时的警告 |

**稀疏存储的理由**：预设值由 `presets/*.json` 提供，存档只存差异项。这样升级 App 调整预设默认值时，老存档会自动继承新默认值，同时保留用户显式覆盖。

### 4.2 导入 / 导出

| 操作 | 格式 | 说明 |
|---|---|---|
| 导出参数档 | `.reconparams.json` | 独立文件，含 `schema_version` + `preset` + `params` + `overrides`，**不含** `device` 与 `session_id` |
| 导入参数档 | `.reconparams.json` | 读入后**必须**过一遍 §3.1 夹取与 §3.2 冲突检测，再应用到当前会话 |
| 跨设备迁移 | 同上 | 导入后重新跑能力探测，若 `BRANCH_*` 与存档不同则提示"参数来自不同分支，部分参数不适用"并列出被忽略的键 |
| 分享 | 同上 + 二维码/文本 | `params` 部分体积小，可编码为 base64 文本用于分享 |

**导入时的拒绝条件（硬失败，不做部分应用）**

| 条件 | 处置 |
|---|---|
| `schema_version` > 当前 | 拒绝，提示升级 |
| `core_abi_version` ≠ 当前 | 拒绝，提示 App 与 core 版本不匹配 |
| JSON 解析失败 | 拒绝，保留原参数 |
| 存在未知键名 | **忽略未知键并记录警告**，其余正常应用（前向兼容） |
| 夹取后仍存在不可用参数（如 `rgbd_lidar_role=3` 在无 LiDAR 设备） | 该参数按 §3.2 L10 回落，其余正常应用 |

> **不做部分应用**：以上拒绝条件触发时，整个导入失败，原参数保持不变。这避免出现"一半新一半旧"的隐晦状态。

### 4.3 默认值恢复

| 操作 | 行为 |
|---|---|
| 恢复默认（当前预设） | 清空 `params` 中的差异项与 `overrides`，回到当前预设值 |
| 恢复出厂 | `preset` 置 `standard`，同时清空 `params` 与 `overrides`，并清空 `clamped_params` / `warnings` |
| 单项恢复默认 | 删除该键的 `params` 项与 `overrides` 项，保留其余 |
| 预设定义文件被篡改 | `presets/*.json` 随 App 发布且带 SHA-256 校验（`assets/presets.sha256`）；校验失败则回落到内置的硬编码默认表 |

**内置硬编码默认表**：每个参数在 `core/util/params.cpp` 中有一份编译期常量定义（`constexpr` 数组），作为最终兜底。即使 `presets/*.json` 全部损坏，应用仍能以默认值启动。

### 5.3 关于 `vio_feature_count` 与 `sfm_feature_count` 的量纲说明

00 文档 R-PREC-4 黑名单列出「特征点提取数量上限」。本产品的两处特征数量含义不同，不可直接比较：

| 参数 | 含义 | 量级 | 黑名单属性 |
|---|---|---|---|
| `vio_feature_count` | VIO 每帧**同时跟踪**的特征点数（滑窗优化变量） | 200 ~ 400 | 黑名单（不得因速度降低） |
| `sfm_feature_count` | SfM 每帧**提取并描述**的 SIFT 特征点数（离线匹配） | 8000 ~ 20000 | 黑名单（不得因速度降低） |

二者都受黑名单约束：任何降级策略都不得下调这两个值。
