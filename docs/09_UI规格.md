## 1. 设计原则（写死，不给例外）

### 1.1 总纲

| 编号 | 原则 | 判定方式 |
|---|---|---|
| U-D-1 | 完全写实：预览就是相机原始画面，不加滤镜、不加风格化、不加美化 | 代码审查 |
| U-D-2 | 无 AI 化：界面中不出现任何模型生成、风格化、补全、AI 增强相关入口或文案 | 代码审查 + 文案表 |
| U-D-3 | 无花哨动画：仅允许系统级转场（iOS 默认 push、Compose 默认 fade-through 不使用），元素自身的动画时长上限见 §1.6 | 代码审查 |
| U-D-4 | 无浮夸视觉：不用大标题堆叠、不用装饰插画、不用品牌色块铺底 | 设计走查 |
| U-D-5 | 极简实用：任一界面上的可交互元素数量不超过 8 个（顶层导航栏内的次要项计入） | 元素清单表计数 |
| U-D-6 | 功能优先：所有精度相关参数可见、可调、可恢复默认（08 §3.3 / §3.4） | 参数面板核对 08 文档 |
| U-D-7 | **不隐藏失败**：任何失败、降级、回退、夹取都必须在界面上有文字说明（08 C6、00 R-PREC-6） | 逐项核对 §5 文案表 |
| U-D-8 | 零营销文案：界面上不出现"打造""赋能""极致""智能""一键生成"类词汇 | 文案表审查 |

### 1.2 视觉禁令清单（命中即驳回）

| 编号 | 禁止项 | 具体判定 |
|---|---|---|
| U-X-1 | 渐变 | 任何 `LinearGradient` / `RadialGradient` / `SweepGradient` / CSS `linear-gradient`。包括按钮背景、卡片背景、预览遮罩、进度条、图标 |
| U-X-2 | 阴影卡片堆叠 | `shadow` / `elevation` > 0 且用于承载布局分组。分隔一律用 1px 分隔线或留白 |
| U-X-3 | 圆角胶囊按钮滥用 | 主按钮圆角固定 8pt（见 §1.5），禁止 `capsule` / `rounded-full` / 半径 ≥ 高度/2 |
| U-X-4 | 入场动画 | 禁止页面级 fade-in / slide-up / scale-in。列表项禁止逐项淡入、禁止对勾弹跳、禁止骨架屏闪烁 |
| U-X-5 | 粒子 / 发光 / 毛玻璃 | 禁止粒子系统、外发光（glow）、`blur` / `backdrop-filter` / `UIVisualEffectView` / `Modifier.blur`。**唯一豁免**：系统原生 Liquid Glass（iOS 26+），见 §1.2.1 |
| U-X-6 | emoji 图标 | 界面中不出现任何 emoji。图标一律用系统 SF Symbols（iOS）/ Material Symbols（Android），或纯文字 |
| U-X-7 | 贴纸式角标 | 禁止在图标上加数字气泡、禁止在按钮上加红点、禁止在列表项右上角挂浮动计数 |
| U-X-8 | 骨架屏 / 加载转圈 | 加载态用文字 + 确定性进度条，禁止无限旋转指示器（相机预览与导出写盘除外，见 §1.6 豁免表） |
| U-X-9 | 玻璃拟态 / 透明叠加面板 | 除预览上的纯色遮罩（§1.4 `scrim`）外，任何半透明面板一律禁止。**唯一豁免**：系统原生 Liquid Glass（iOS 26+），见 §1.2.1 |
| U-X-10 | 圆点指示器分页 | 禁止圆点分页（dots）。用文字 `3/16` |

#### 1.2.1 Liquid Glass 豁免条款（iOS 26+）

> **背景**：产品要求在高版本 iOS 上使用系统原生 **Liquid Glass** 材质。该材质本质是系统级毛玻璃 + 半透明叠加，与 U-X-5（禁 `blur` / `UIVisualEffectView`）和 U-X-9（禁玻璃拟态 / 半透明面板）**字面冲突**。本条是经过裁定的**唯一豁免**，不推翻两条禁令的其余全部效力。

| 编号 | 规则 | 判定 |
|---|---|---|
| LG-1 | **只允许系统原生实现**。iOS 26+ 使用 `.glassEffect(_:in:)` / `GlassEffectContainer` / `.glassEffectID(_:in:)`。禁止任何自绘毛玻璃（自绘 `blur` 滤镜、自绘半透明图层叠加、引入第三方玻璃库） | 代码审查 |
| LG-2 | **只允许出现在系统级表面**：导航栏、工具栏、浮动操作按钮（FAB）、底部 Sheet、Alert 附属按钮。**业务内容区一律不透明**（列表、表单、参数行、结果统计、预览遮罩面） | 元素清单核对 |
| LG-3 | **必须版本守卫**。所有 Liquid Glass 调用须置于 `if #available(iOS 26.0, *)` 内；iOS 15.0–25.x 走回退路径 | 代码审查 |
| LG-4 | **回退路径必须显式指定**。回退一律用 `.ultraThinMaterial`（系统材质）或直接纯色 `bg.secondary`；不允许静默无样式、不允许回退成自绘玻璃。回退视为**降级**，按 U-D-7 须在「关于」页可见说明 | 代码 + 走查 |
| LG-5 | **不叠加**。Liquid Glass 表面上不再叠加 `shadow` / `elevation` / 渐变 / 自绘边框（U-X-2 / U-X-1 在此表面上仍生效） | 代码审查 |
| LG-6 | **不用 `.clear` 变体**。`.regular`（含 `.tint` / `.interactive`）可用；`.clear` 在内容上会导致可读性不合格，禁止 | 代码审查 |
| LG-7 | **不放在 `Form` / `List` 容器内**，且玻璃元素不得位于 `.clipped()` / `.mask()` 修饰的作用域内（会杀死材质效果，表现为"看似启用实际无效果"） | 代码 + 走查 |
| LG-8 | `.interactive()` 仅 A17 Pro 及以上生效，旧设备**静默降级为静态玻璃**——这属于系统行为，不视为缺陷，但不得据此声称"所有设备都有交互玻璃" | 真机走查 |
| LG-9 | **对比度不变**。玻璃表面上的文字仍须满足 §1.7 的对比度要求（含白字在玻璃上的实际合成背景） | 对比度工具实测 |
| LG-10 | **Android 不使用**。Android 侧（Jetpack Compose）无对应豁免，U-X-5 / U-X-9 原样全效 | 代码审查 |

> **与 `scrim` 的关系**：§1.4 的 `scrim`（`#000000` @ 60% 纯色遮罩）继续有效且**不允许**被 Liquid Glass 替代——预览上的文字承载面必须保持不透明的纯色遮罩，以保证 ≥ 7:1 对比度。
>
> **部署目标不变**：本豁免**不改变** docs/12 §4.6 的结论（最低部署 iOS 15.0）。Liquid Glass 是 iOS 26+ 的**增强层**，不是最低要求。

#### 1.3.3 色板取值的工程理由

| 项 | 说明 |
|---|---|
| 为什么不直接用系统灰阶 | iOS `secondaryLabel`（`rgba(60,60,67,0.6)`）在白底上的对比度约 3.26:1，Android `onSurfaceVariant` 在浅色主题下约 4.0:1，均不满足本文 §1.7 的 AA 要求。因此文字色单独定义 `txt.*` 一族，与系统观感差异只在灰阶明度上，色相保持一致 |
| 暗色模式强调色 | `sys.accent.solid` 暗色下用 `#0A84FF`，白字对比度 4.37:1，低于正文 4.5:1，因此暗色主按钮文字**必须**用 `Headline` 17pt 及以上（按 WCAG 大字号 3:1 阈值判定通过），不得缩小字号 |
| 深浅色不做自动反转 | 所有色值成对手写，禁止代码内 `dynamicColor` 反色计算 |
| 预览遮罩 | 预览上的文字一律放在 `scrim` 上（`#000000` @ 60%），保证白字对比度 ≥ 7:1。禁止用模糊，仅用纯色叠加 |

### 1.6 动效

| 场景 | 允许 | 禁止 |
|---|---|---|
| 页面转场 | 使用系统默认转场（iOS push / Android 默认），可关闭 | 自定义滑入、缩放、淡入 |
| 列表增删 | 无动画，立即重排 | 逐项淡入、位移 |
| 进度条 | 数值变化时 200ms 线性插值，**无循环、无呼吸、无光泽** | 循环扫描光条 |
| 数值刷新 | 立即替换 | 滚动数字动画 |
| 相机预览 | 30/60fps 实时画面 | 任何叠加动效 |
| 导出写盘 | 环形不确定进度（系统 `UIActivityIndicatorView` / Compose `CircularProgressIndicator`），仅此一处豁免 U-X-8 | 自制转圈动画 |
| 提示条出现 | 立即出现 / 立即消失 | 滑入、淡出、弹跳 |

| 编号 | 规则 |
|---|---|
| U-M-1 | 除上表列出项外，全 App 零自定义动画 |
| U-M-2 | `prefers-reduced-motion` / `Animations.scale = 0` 时，所有自定义插值时长归零，功能不受影响 |
| U-M-3 | 禁止以动画表达"进度不确定"，不确定进度只能靠文案表达（见 §5.4） |

### 1.7 触控与对比度

| 项 | 要求 |
|---|---|
| 最小触控热区 | iOS **44×44 pt**，Android **48×48 dp**。两者取严者：**48×48** |
| 热区与视觉解耦 | 图标按钮的可视尺寸可小于热区，但热区不得小于 48×48，且四周留白不得被其他元素侵占 |
| 相邻热区间距 | ≥ 8 |
| 正文对比度 | ≥ 4.5:1（WCAG 2.1 AA） |
| 大字号对比度 | ≥ 3:1，字号 ≥ 17pt semibold / 18pt bold / 24px regular 时适用 |
| 非文字元素对比度 | 分隔线、图标边框、进度条前景、开关轨道与相邻背景 ≥ 3:1 |
| 焦点可见 | 键盘/手柄导航必须有 ≥ 2px 可见焦点环（`sys.accent` 实色，不发光） |
| 错误提示色彩 | 不得仅靠颜色传达，必须同时有文字（U-D-7） |

### 1.8 图标

| 项 | 规则 |
|---|---|
| iOS | SF Symbols，线宽 `.regular`，尺寸 17pt（列表）/ 20pt（工具栏）/ 24pt（结果页统计区） |
| Android | Material Symbols Outlined，同样尺寸换算（24dp / 24dp / 32dp） |

> **为什么此前没有这一节（缺口的性质与处置）**
>
> 本节（`Reviewing` 态）在 **三处**都缺席：§2 界面清单没有它的行、§3 小节序列
> 从 3.5 `U-05` 直接跳到 3.6 `U-06`、§2 末尾的导航结构图也不画它。但**同一份
> 契约体系内**有**五处**规定它必须存在：
>
> ① §4.1 状态图把它画成节点（`│ │ Reviewing │ │ 自检清单 │`），并给出入边
>    （`Capturing` —点「完成扫描」→ `Reviewing`）与出边（清单通过 → 确认重建）；
> ② §4.2 有**五条**迁移以它为源或目标 —— `T-11`（`Capturing → Reviewing`）、
>    `T-16`（severe 未过，确认按钮禁用，状态保持）、`T-17`（**确认 → `Processing`**，
>    副作用含 `recon_finish_capture` + `recon_run_reconstruction`）、
>    `T-18`（继续扫描 → `Capturing`）、`T-19`（✕ → `Cancelled`）；
> ③ docs/03 §7.1.2 给出完整的 `CK-1..CK-7` 呈现规则；
> ④ docs/03 §7.1.1 给出 `S1..S14` 判据表与严重级；
> ⑤ §5.6 `Q-05` 给出确认框文案（`仍有 N 项未通过，确认后将按当前数据重建？`）。
>
> 这**不是**两份契约相互冲突（那种情形按铁律只登记、不擅自裁决），而是
> **同一契约体系内的界面规格漏登记** —— 与 §3.3 的 `Previewing` 补登记
> （见 §3.3 内「`Previewing` 态的界面元素」）、§5.5 `R-15` / §5.4 `D-7`
> 属**同一形态**。处置一致：**补登记 + 新增对应文案键 + 写明依据**。
>
> **缺了它的实际后果（这不是纸面问题）**：`Reviewing` 的四条出边若无界面承载，
> 状态机在用户点「完成扫描」后**彻底卡死** —— `confirmReconstruct()`
> （`T-17` 的唯一实现）**全仓零调用点**，重建永不开始。
>
> **实现边界的如实登记**：docs/03 §7.1.1 的 `S1..S14` 判据**在内核中大部分尚未
> 实现**（`azimuth_coverage` / `elevation_coverage` / 全部 `anomaly_*` 零赋值，
> `q_total` 不存在，8 个 `scan_review_*` 阈值键未注册，C ABI 无自检查询接口）。
> 故当前实现**只真实判定 `S1`**（数据源 `recon_scan_stats.keyframes` 真实可读），
> 其余 13 项显示为 `— 未接入` 并附说明，**不伪造 `✓`**。这与 §5.5 `R-15`
> 的 `msg.result.preview_pending`（`线框预览尚未接入…`）同一方针。
> 内核补齐 `S2..S14` 判据后，本界面无需改文案，只需接上数据源。

**3.8.1.1 G12（`scan_`）在面板中不显示的裁定（2026-10-31 实测）**

08 §1 把「扫描与关键帧类」定义为 **G12**（前缀 `scan_`，声明 **32 项**），但本表
（§3.8.1）只定义 G1–G11，**没有第 12 组的控件形态、分组标题与条目数**。三处实测事实
决定了当前处置：

| 事实 | 实测值 | 判据来源 |
|---|---|---|
| 代码注册的 `scan_*` 键数 | **16**（非 32） | `core/src/util/params.cpp` 第 707–742 行，`grep -c "p\.Register(keys::kScan" ` |
| 与 08 §1 G12 表**键名一致**的项 | **4 / 16**（`scan_mode`、`scan_viewpoint_distance_m`、`scan_ideal_distance_min_m`、`scan_ideal_distance_max_m`） | 逐键比对 |
| 其余 12 项 | **同语义、异键名**。例：08 表 `scan_kf_geom_rot_thresh_deg` ↔ 代码 `scan_kf_min_rotation_deg`；08 表 `scan_azimuth_bins`（代码有）↔ 08 表无 | 逐键比对 |
| 这 16 项在 `core/src/` 的**消费点** | **0**（`grep -rn "kScan" --include=*.cpp` 排除 `params.cpp` 注册行后，只剩 `OrchestratorState::kScanning`，与参数无关） | 全局符号搜索 |

**裁定：`ParamGroup.groupIndex(forKey:)` 对 `scan_` 前缀返回 `nil`，面板不显示这 16 项。**

理由（三条，缺一不可）：

1. **未接入 = 改了不生效**。这 16 项无任何消费点，若显示为可编辑，用户改动会
   **静默不生效** —— 直接违反 08 §5.1.3 的「不得让用户误以为改动即生效」与
   R-PREC-6 的口径。显示它比不显示更坏。
2. **不臆造控件形态**。§3.8.1 未定义第 12 组，本表也无 G12 的控件类型分布。凭空
   造一组会与 08 §1 的定义脱钩（08 是唯一来源）。
3. **键名漂移未收敛前，分组计数不可信**。4/16 的键名一致率意味着：即便照 08 §1
   的 32 项建组，面板也只会显示 16 项中的 4 项，折叠行标题写的数字与展开后的行数
   **必然自相矛盾** —— 这正是本表上一段引用块所警告的情形。

**补齐 G12 归属的前置条件（按序满足后方可加入本表）**：

| 序 | 前置条件 | 现状 |
|---|---|---|
| 1 | 08 §1 G12 与代码键名**收敛为同一套**（择一为准） | ❌ 4/16 一致 |
| 2 | `scan_*` 在 `core/` 有**真实消费点**（或明确标注「功能开发中」并加禁用态） | ❌ 0 个消费点 |
| 3 | 本表补 G12 行：组名 / 面板标题 / 条目数 / 控件类型分布 | ❌ 未定义 |
| 4 | `ParamGroup.groupIndex` 放开 `scan_` 前缀 | ❌ 当前返回 `nil` |

> 上述四条同时登记于 `docs/09` 本处与 `docs/14_验收测试.md` §5.1.3 缺口 D。
> **这不是遗漏，是显式裁定** —— 与「诚实文案 vs 规格文案冲突时，选不误导」同源。

> 只陈述事实 + 错误码，符合 C-3。

> 未接线）。若沿用「正在准备预览」文案，用户会**无限等待**一个永远不会到来的预览。
> 处置：新增 `msg.result.preview_pending`，**如实告知功能尚未接入**并点明所需组件
> —— 符合「诚实文案 vs 规格文案冲突时，选不误导」（见 MEMORY.md）。原

> Swift 枚举 `L10nKey.exportValidationPending`。

### 6.3 深色模式

| 项 | 规则 |
|---|---|
| 跟随系统 | 默认跟随系统（`UIUserInterfaceStyle` / `Theme.Material3.DayNight`）。用户可在设置中强制「始终浅色」/「始终深色」 |
| 切换时机 | 跟随系统时，App 在前台运行中收到主题变更立即重绘；不重启界面 |
| 重绘范围 | 全部界面。预览层不重绘（相机画面不随主题变化） |
| 禁止 | 禁止在深色模式下降到低于浅色模式的信息密度（不隐藏次要说明、不折叠区块） |
| 截图/校验 | 深色模式下重新跑一次对比度校验脚本 |

### 6.4 字号放大

| 项 | 规则 |
|---|---|
| 支持范围 | 系统字号 85% ~ 200%（iOS Dynamic Type / Android `fontScale`） |
| 布局适配 | 文本容器不得固定高度；行高随字号缩放；列表项高度自适应 |
| 截断 | 数值列不截断（等宽字体 + 允许换行到下一行）；文案行按 §1.4 截断 |
| 按钮 | 主按钮文字在 200% 时允许换行两行，按钮高度自适应，**不裁切** |
| 引导文字 | 200% 时允许两行，不使用省略号截断核心指令（`请移到物体右前方` 必须完整可读） |
| 参数面板 | 数值输入框在 200% 时改为上下布局（左标签 / 右输入），不压缩输入宽度 |
| 图形标记 | 引导三角标记为固定像素尺寸，不随字号缩放（避免遮挡预览） |
| 最低保证 | 在 200% 缩放下，所有可交互元素仍满足 48×48 热区（必要时热区扩大，不缩小文字） |

### 6.5 本地化相关的工程约束

| 编号 | 约束 |
|---|---|
| L-1 | locale 文件为**扁平 JSON**，键值对；结构与 Arnis-CN 一致，便于复用其翻译流程 |
| L-2 | iOS 用 `String(localized:bundle:)`（`.strings` 转换由构建脚本从 JSON 生成）；Android 用 `strings.xml`（同样由 JSON 生成），**禁止**在两端各维护一份手写文案 |
| L-3 | 文案中的数字与单位插值一律用 `fmt.*` 格式串，禁止在代码里拼接句子 |
| L-4 | RTL locale 布局镜像由系统处理；代码中禁止出现 `if (isRTL)` 的手工镜像分支，除非是内容本身需要保持 LTR（如路径、代码、坐标） |
| L-5 | 每个 locale 文件带 `meta.version` 与 `meta.updated_at`，CI 校验版本一致 |
| L-6 | 缺键时 UI 显示 key 本身并写入本地诊断日志（`perf_log_level >= 2` 时可见），**不显示空白** |
