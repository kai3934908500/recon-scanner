### 0.2 核心命题（一句话）

> **两条管线分支共用同一套验收指标。任一分支、任一机型、任一档位达不到阈值即判定为缺陷，不得以「机型差异」「档位差异」「分支差异」为由豁免。**

这条命题出自 00 §4.6 的原文：

> 两条分支共用同一套验收指标，**任一分支达不到即判定为缺陷，不得以"机型差异"为由豁免**。

它不是一句口号，而是三条具体约束的合体：

| 约束 | 内容 | 落地位置 |
|---|---|---|
| **AC-1** | 阈值表只有**一份**。不允许出现「iOS 用 A 阈值、Android 用 B 阈值」「LiDAR 用 C 阈值」 | §3 全部阈值表 |
| **AC-2** | 三档预设（fast / standard / high）**不改变**阈值。三档都必须达标 | §3.1 明确 |
| **AC-3** | 「中端机跑得慢」「低端机内存紧」**不是**放宽精度的理由。只允许通过白名单手段（并行度 / 批大小 / 分块）适配，且适配后精度必须与高端机**一致** | §3.1 明确 |

## 1. 验收原则

### 1.1 双分支精度能力矩阵（引自 00 §4.6）

> 下表是**唯一**的验收口径来源。本文 §3 的全部阈值必须能追溯到本表的某一行或某一行加上本表脚注的补充说明。

| 验收项 | 指标 | RGBD 分支 | MONO 分支 | 备注 |
|---|---|---|---|---|
| 相对几何误差 | 对称面重投影中位数 | ≤ 0.5 px | ≤ 0.5 px | 同一口径 |
| 尺度相对误差 | 相对参照物真值 | ≤ 1.0% | ≤ 1.0% | MONO 依赖 07 标定 |
| 尺度重复性 | 10 次独立扫描的尺度标准差 | ≤ 0.5% | ≤ 0.5% | — |
| 拓扑完整性 | 非流形边数 | 0 | 0 | — |
| 拓扑完整性 | 未闭合孔洞面积占比 | ≤ 0.05% | ≤ 0.05% | — |
| 网格分辨率 | 泊松等效半径 | ≤ 体素边长 | ≤ 体素边长 | 同档位同精度 |
| 导出可用性 | Blender/Maya 打开零错误 | 必须 | 必须 | — |

**本表的四条补充解释（工程口径，防止执行时歧义）**

| 编号 | 补充 |
|---|---|
| S-1 | **「对称面」的定义**（承接 05 §4.8）：在 BA 优化后的相机平面重投影中，对**同一条 3D 边**由两个不同视角分别投影得到的两个像点，取其距离的中位数。度量的是稀疏点集在优化后相机平面上的**自洽性**，不是稠密曲面的绝对形状偏差 |
| S-2 | **「对称面重投影中位数 ≤ 0.5 px」与「形状误差 0.17 mm」是两个独立验收项**（05 §6.1.2 已明确二者相差约 2.4 倍，度量对象不同）。本文 §3.2 补充「点到面距离」系列指标用于覆盖形状误差，**不替代**本表的 0.5 px 项 |
| S-3 | **「泊松等效半径 ≤ 体素边长」在 MONO 分支的读法**（承接 06 §1.4）：MONO 无 TSDF 体素，基准换算为「MVS 点云等效间距」，即 `r_mesh ≤ h_ref / 8`，`h_ref = Z_mean / f_px × 1 px`。实现时由 MVS 阶段实测 `h_ref` 并写入 `recon_mesh_info.json` 的 `mesh_resolution_reference` |
| S-4 | **三档预设都按本表验收**。`fast` 档同样必须达到 0.5 px / 1.0% / 0 非流形边 / 0.05% 孔洞。预设只改变耗时与内存（08 §2.1 P1/P2），不改变精度口径 |

### 1.2 精度优先原则的量化体现

「精度优先」不能只写进文档首页，必须落成**可测量的判据**。本文给出六条量化体现：

| 编号 | 原则 | 量化判据 | 检验方式 |
|---|---|---|---|
| Q-1 | 精度 > 拓扑 > 纹理 > 速度 | 在**同一输入**上，四项指标的**违反项数**必须满足：精度违反 → 0；拓扑违反 → 0；纹理违反 → ≤ 1（且仅在弱纹理/镜面物体上允许）；速度违反 → 不计（速度无阈值） | 黄金回归报告逐用例统计 |
| Q-2 | 不接受以精度换速度 | 黄金回归中**同一用例**的「fast 档精度」与「high 档精度」之差 ≤ 该指标的 10%（非流形边与孔洞除外，必须严格为 0 与 0） | 逐用例比对 |
| Q-3 | 不做「降采样预览」 | CI 中**不存在**任何「自动降级到低精度」的代码路径。降级触发时，`recon_mesh_info.json` 的 `degradation_summary.blacklist_touched` 恒为空 | 运行时断言测试（§5.3）+ 静态扫描（§5.6） |
| Q-4 | 关键帧不丢 | 黄金回归中「输入关键帧数」与「参与 BA 的关键帧数」**必须相等**；「参与 MVS 的参考帧数」与「输入关键帧数」之比 ≥ 0.95（差额为 MVS 主动跳过的不足视图帧，见 05 `E_MVS_INSUFFICIENT_VIEWS`） | `recon_mesh_info.json` 的统计项交叉比对 |
| Q-5 | 全参数用户可调 | 08 文档登记的 313 个参数中，精度相关项 100% 可被用户覆盖（08 §5.2 已达成）；CI 中 `tools/check_params.py` 校验键名一致 | CI 任务 12 |
| Q-6 | 覆盖后不静默回退 | 用户把 `mesh_poisson_depth` 从 11 改成 99 时，被夹取到 14，UI 显示「已修正（14）」，`recon_mesh_info.json` 的 `clamped_params` 记录原值与新值 | 参数校验集成测试（§5.3） |

### 1.3 验收的三个层级

| 层级 | 内容 | 判定 | 频率 |
|---|---|---|---|
| **L-1 算法正确性** | 单测：预积分、位姿图、BA、深度融合、泊松、UV、导出校验 | 全绿 | 每次 PR |
| **L-2 端到端精度** | 黄金数据集回归（合成 + 真实） | 全用例在容差内 | 每次 PR |
| **L-3 合规与体验** | 许可扫描、零网络、权限、UI 降级提示、实机长跑 | 全绿 | 每次 PR（合规）+ 每日（实机长跑） |

### 2.4 尺度真值的获取方式

**方法一：千分尺测量（主）**

| 项 | 规格 |
|---|---|
| 量具 | 数显卡尺（分辨率 0.01 mm，精度 ±0.01 mm）；高价值校准件（`REAL-SPH-CAL-60` / `REAL-BLOCK-CAL-50`）用三坐标测量机（CMM，精度 ±0.002 mm） |
| 测量点 | 每个物体取**三轴各 3 个测量点**，取中位数；同时记录最大偏差 |
| 记录 | 写入 `groundtruth/dimensions.json`：`{"axis_x_mm": 265.0, "axis_y_mm": 88.0, "axis_z_mm": 112.0, "uncertainty_mm": 0.3, "instrument": "digital_caliper_0.01mm"}` |
| 不确定度 | `σ_L = 不确定度 / √3`（均匀分布假设，与 07 §2.1 的 `σ_L = 0.29 mm` 推导口径一致） |
| 复核 | 每条用例在**不同日期**重复测一次（间隔 ≥ 7 天），两次差值 > 0.5 mm 则重新测量并更新真值 |

**方法二：参照物（辅，用于交叉验证）**

| 项 | 规格 |
|---|---|
| 参照物 | 银行卡 CR-80（85.60 × 54.00 mm，公差 ±0.50 mm，`σ_L = 0.29 mm`，07 §2.1）/ A4 纸（210 × 297 mm，`σ_L = 1.0 mm`）/ `REAL-BLOCK-CAL-50` 量块 |
| 摆放 | 参照物**平贴**在被测表面上（07 §2.3.4；离面弯曲 > 2 mm 标记低置信） |
| 用途 | ① 验证千分尺真值；② 为 MONO 分支提供运行时可得的尺度锚点；③ 验证 07 §2.9 多视角联合标定路径 |
| 一致性判据 | 参照物解出的尺度与千分尺真值之差 > 1.0% → 该用例标记 `scale_anchor_inconsistent`，**不进入精度统计**，但进入 §5.4 实机标定排查队列 |

**方法三：激光扫描参考（用于形状误差）**

| 项 | 规格 |
|---|---|
| 设备 | 结构光扫描仪（精度 ±0.02 mm）或 CMMS |
| 输出 | 真值网格（STL/PLY）+ 坐标系定义 |
| 对齐 | 用 ICP（点到面）把重建网格对齐到真值网格，再算点到面距离（§3.2）。ICP 只用于**测量**，不参与重建 |
| 对齐残差 | ICP 最终残差 > 0.05 mm 的样本，该用例标记 `reference_alignment_failed`，不进入形状误差统计 |

> **诚实披露**：真实物体的「真值网格」本身也有误差（扫描仪 ±0.02 mm + ICP 对齐残差）。因此 §3.2 的阈值是**相对真值网格**的偏差，不是相对绝对真值。真值网格的精度必须记录在用例元数据中（`groundtruth/reference_mesh_accuracy_mm`）。

## 3. 精度验收指标与判据

### 3.1 阈值适用规则

| 规则 | 内容 |
|---|---|
| T-1 | 下表阈值适用于**三档预设**（fast / standard / high）与**所有分支**（RGBD / MONO）与**所有机型**。**不因机型、档位、分支而异**（AC-1 / AC-2 / AC-3） |
| T-2 | 合成数据集（SYN-*）与真实数据集（REAL-*）**分开统计**，不混合平均 |
| T-3 | 镜面 / 透明物体（`REAL-METAL-120`、`REAL-GLASS-90`）的**几何精度指标**不计入总体合格率统计——00 §4.5.5 已明确这是**物理限制**而非工程缺陷。但它们仍必须：① 成功产出模型；② 拓扑指标（非流形边、孔洞）达标；③ `unreliable_regions` 正确标注对应区域 |
| T-4 | 弱纹理物体（`REAL-PLASTER-90`、`REAL-PLASTIC-80`）的几何精度采用**弱纹理档阈值**（§3.2 的 T2 档），但**必须**在报告中单列，不混入强纹理统计 |
| T-5 | 底面推断区（`bottom_face_scanned = false` 的用例）不参与形状误差统计，但**必须**满足推断区标注要求（03 §4.7.4 BS-1） |
| T-6 | 每项指标需给出**三档预设各自的实测中位数**，用于观察预设间的单调性。出现「high 档精度差于 standard 档」超过 5% 的情形 → 判为缺陷（说明高预设的某项参数设置有误） |

### 3.2 几何误差（点到面距离）

**度量方法**

| 项 | 规格 |
|---|---|
| 定义 | 对重建网格的每个采样点，求到真值网格的**最小点到面距离**（不是点到点距离） |
| 采样 | 重建网格按**面积均匀采样**（不是按顶点均匀），采样点数 = min(200 000, 网格面数) |
| 对齐 | 先用 ICP（点到面，阈值 0.05 mm）把重建网格对齐到真值网格，**只对齐不缩放**（尺度误差单独度量） |
| 剔除 | 剔除「推断区」顶点（03 §4.7.4 标注的 bottom_face_source ≠ observed 的区域）与 `unreliable_regions` 内的顶点 |
| 剔除的记录 | 剔除的顶点数与占比必须写入报告（占比 > 20% 的用例标记 `low_evaluated_ratio` 并人工复核） |

**阈值**

| 指标 | 强纹理 T3 | 中等纹理 T2 | 弱纹理 T1 | 判定方式 |
|---|---|---|---|---|
| **点到面距离中位数** | ≤ **0.12 mm** | ≤ **0.20 mm** | ≤ **0.40 mm** | 该指标 ≤ 阈值 |
| **点到面距离 P95** | ≤ **0.35 mm** | ≤ **0.55 mm** | ≤ **0.90 mm** | ≤ 阈值 |
| **点到面距离 RMS** | ≤ **0.20 mm** | ≤ **0.30 mm** | ≤ **0.55 mm** | ≤ 阈值 |
| **点到面距离最大值** | ≤ **1.50 mm** | ≤ **2.50 mm** | ≤ **4.00 mm** | ≤ 阈值（单点尖刺容差） |
| **平面区平坦度**（`SYN-CUBE-*` / `REAL-BLOCK-CAL-50`） | RMS ≤ **0.05 mm** | 同 | 同 | ≤ 阈值 |
| **球面拟合半径误差**（`SYN-SPHERE-100` / `REAL-SPH-CAL-60`） | ≤ **0.05 mm** | ≤ **0.10 mm** | — | ≤ 阈值 |

**阈值依据**

| 阈值 | 依据 |
|---|---|
| 强纹理 T3：RMS ≤ 0.20 mm | 05 §6.1.2 逐级传递表算得标准档形状误差 **0.171 mm**（强纹理），留约 17% 余量 |
| 高精度档（T3 + high 预设） | 05 §6.1.3 算得 **0.119 mm**，阈值不变（high 应**优于**阈值，这就是 Q-2 的量化点） |
| 中等纹理 T2：RMS ≤ 0.30 mm | 05 §6.1.2 结论「0.25 ~ 0.45 mm（中等到弱纹理区域，δd 劣化到 0.25 px 时）」的下界附近 |
| 弱纹理 T1：RMS ≤ 0.55 mm | 同上的上界 0.45 mm + 20% 余量 |
| 平面 0.05 mm | 05 §6.1.2 第 0 级「像素量化」= 0.070 mm/2 = 0.035 mm（半量化误差），留余量 |
| 球面 0.05 mm | 球面是曲率最易暴露误差的形状；05 §6.1.2 第 8 级泊松偏差 0.097 mm 会被拟合半径吸收一部分 |

**对称面重投影（00 §4.6 原始项，不可省略）**

| 指标 | 标准档 | 快档 | 高精度档 | 判定 |
|---|---|---|---|---|
| 对称面重投影中位数 | ≤ **0.5 px** | ≤ **0.7 px** | ≤ **0.35 px** | 05 §4.8（快/高档值为 05 的 `sfm_reprojection_median_max_px`） |
| 对称面重投影 P95 | ≤ **2.0 px** | ≤ **3.0 px** | ≤ **1.5 px** | 05 §4.8 |
| 对称面深度一致性 `max|Z_left − Z_right| / Z̄` | ≤ **0.10** | ≤ **0.15** | ≤ **0.05** | 05 §4.8 |

> **口径冲突的处理**：00 §4.6 要求「≤ 0.5 px」为**两分支统一**阈值，05 §4.8 给出快/高档的不同值。本文档采用**取严**原则：验收阈值一律按**标准档的 0.5 px**（两分支、全部机型、全部档位）；快档与高精度的差异值只作为**产品目标**记录在报告中，不作为验收放行条件。这样才符合 AC-1 / AC-3。

### 3.3 尺度误差

**度量方法**

| 项 | 规格 |
|---|---|
| 包围盒尺寸 | 重建网格的轴对齐包围盒三轴边长（Y-up 世界系，米） |
| 参照物 | 拍摄时放在被测表面上的参照物（银行卡 / 量块），其角点在图像中的位置由 07 §2.3 的亚像素直线拟合给出 |
| 尺度因子 | `s` 由 07 §2.9 的多视角联合优化路径求解（`calib_refine_enabled = 1` 且 `calib_triangulate_min_views ≥ 3`） |
| 重复性 | 同一物体、同一摆位、同一操作者，独立扫描 **10 次**（每次重新采集、重新标定） |

**阈值**

| 指标 | RGBD | MONO | 判定 | 依据 |
|---|---|---|---|---|
| **尺度相对误差**（包围盒三轴各自 + 对角线，取最大值） | ≤ **1.0%** | ≤ **1.0%** | ≤ 阈值 | 00 §4.6 原文 |
| **尺度重复性**（10 次扫描的尺度标准差 / 均值） | ≤ **0.5%** | ≤ **0.5%** | ≤ 阈值 | 00 §4.6 原文 |
| 尺度残差自洽 `\|s/s_ref − 1\|`（BA 内部） | ≤ **0.02** | ≤ **0.02** | ≤ 阈值 | 05 §4.8 |
| 包围盒合理性（三轴均 > 1 mm 且 < 100 m） | 必须 | 必须 | 06 V15 | — |

**分物体尺寸的收紧要求**

| 物体最大边 | 尺度相对误差上限 | 理由 |
|---|---|---|
| ≤ 50 mm | ≤ **1.0%**（同全局） | 小物体的千分尺测量不确定度占比更大，故真值测量必须更严（`REAL-BLOCK-CAL-50` 用 CMM） |
| 50 ~ 200 mm | ≤ **1.0%** | 全局阈值 |
| > 200 mm | ≤ **1.0%** | 全局阈值 |

> **不按物体尺寸放宽阈值**：这是 AC-1 的直接体现。1.0% 在 12 mm 的螺母上是 0.12 mm，在 450 mm 的椅面上是 4.5 mm——量级不同但**相对误差**相同，这是绝对精准物理尺度的正确表达。

**已知的能力边界（不计入缺陷）**

| 情形 | 说明 |
|---|---|
| 单帧参照物闭式解 | 05 §6.1.4 算出 **2.08%**（300 mm 物体），**不满足** 1.0%。因此 MONO 分支的参照物标定**必须**走多视角联合优化路径（1.04%）或手动尺寸路径（0.35%）。单帧闭式解的结果**不进入验收统计**，且该路径必须在 UI 上标注为「低置信」 |
| 深度设备的温漂 | 07 §1.3：LiDAR / ToF 在 10 分钟内可漂移 0.5% ~ 2%。因此**每条用例的采集时长 ≤ 10 分钟**，且尺度复核必须在采集**结束后立即**进行 |
| 镜面 / 透明物体 | 参照物本身若被遮挡或反光，标定置信度降级。此类用例的尺度指标按 §3.2 T-3 处理 |

### 3.4 拓扑指标

| 指标 | 方法 | 阈值（两分支、全部档位） | 依据 |
|---|---|---|---|
| **非流形边数** | 统计「边—面邻接计数 > 2」的边 | **= 0**（硬闸门） | 00 §4.6；06 V16 |
| **边界环数** | 统计「边—面邻接计数 = 1」的边构成的连通环 | **不作硬闸门**（见下方"边界环口径修正"） | 00 §2 术语表「拓扑完备度」包含边界环数 |
| **未闭合孔洞数** | 边界环的数量（同上） | **不作硬闸门**（同因） | — |
| **未闭合孔洞面积占比** | 孔洞区域面积 / 网格总表面积 | ≤ **0.05%** | 00 §4.6 原文 |
| **孔洞计数**（辅助） | 面积 > `post_hole_area_large_ratio × 总面积` 的大孔数量 | ≤ **0** 个 | 06 §2.5 H3 大孔超过 `post_hole_area_large_ratio` 即为缺陷 |
| **法线一致性** | `post_normal_consistency_min`（快 0.95 / 标 0.98 / 高 0.99） | 满足对应档位 | 06 §2.6 / 08 G8 |
| **有向体积符号** | `V = (1/6) Σ (v0 × v1)·v2` | **> 0**（外法向朝外） | 06 V4 |
| **三角形绕序一致** | 每条内部边被两个面**相反方向**引用的次数必须恰为 1 | 100% | 06 V3 |
| **Euler 特征**（合成数据） | `V − E + F` | 凸体 = 2（球 / 立方体 / 圆柱）；带通孔体 = 0 | 拓扑基准 |
| **薄结构保留率** | `REAL-GEAR-60` 的齿顶高度保留比例 | ≥ **90%** | 06 §1.6「薄结构丢失」缺陷的量化 |
| **凹陷保留率** | `SYN-CONCAVE-120` 凹坑中心深度（相对切平面）保留比例 | ≥ **85%** | 同上 |

> **⚠️ 边界环口径修正（2026-10-31 第十轮实测裁定，务必先读）**
>
> 早期本节要求「边界环数 = 0」与「未闭合孔洞数 = 0」为**绝对闸门**。但实测证明**该判据在当前
> 实现下不可达**，且**未列入根契约**：
> 1. **泊松原始输出本身就带边界环** —— 理想闭合球面（4085 个边界环）、理想立方体（969 个）
>    的 PoissonRecon 输出在**未经后处理**时即有大量边界环，这是漫游体素（marching-cubes
>    等值面）在八叉树叶级截断处的**固有产物**，不是缺陷。
> 2. **根契约未列该错误码** —— `core/include/recon/recon_c_api.h` 的导出错误码只有
>    `RECON_ERR_EXPORT_NONMANIFOLD`（2575），**没有**「边界环非零」错误码；docs/06 §4.1 的
>    V1–V17 校验项也**不含**边界环。
> 3. **决策** —— 按「导出闸门只能架在『可达 + 契约明列』的量上」，**移除该闸门**。
>    拓扑**硬判据只保留「非流形边 = 0」**。
>
> **因此**：本节「边界环数」「未闭合孔洞数」由**绝对阈值**降级为**参考观测指标**
> （记录数值、趋势对比，不用于判定通过/失败）。**未闭合孔洞面积占比 ≤ 0.05%** 仍是量化
> 目标（可测、可达），但也不再作为单一否决条件。
> **遗留**：`docs/06_网格化与后处理.md` §2.5 已记录实测事实（补片自身会带一圈边界边，
> 实测「净增 2 个边界环/洞」，并给出 `1715 − 1677 = 38` 的吻合验证），**未**承诺
> 「边界环 = 0」。两份文档口径现已一致，无矛盾。

**拓扑指标的采样口径**

| 项 | 规格 |
|---|---|
| 度量对象 | 导出前的 `FinalMesh`（06 §2.0 S11 之后），**不含**用户显式触发的简化结果 |
| 面积计算 | 三角形面积求和（不做面积加权平均） |
| 边界环判定 | 每条边界边关联 2 个顶点构成一条边；连通分量即一个环 |

### 3.5 网格分辨率

| 指标 | 方法 | 阈值 | 依据 |
|---|---|---|---|
| **泊松等效半径** `r` | `r = s × L_max / 2^D`（06 §1.3） | **≤ h_ref / 8** | 00 §4.6「泊松等效半径 ≤ 体素边长」+ 06 §1.4 的 8× 关系 |
| `h_ref`（RGBD） | `rgbd_tsdf_voxel_size` | — | 06 §1.4 |
| `h_ref`（MONO） | MVS 点云等效间距 `= Z_mean / f_px × 1 px`（实测中位数） | — | 06 §1.4 分支化说明 |
| **实测等效半径** | 三角形边长分布的**加权均值**（按面积加权） | 与理论 `r` 之比 ∈ **[0.8, 1.2]** | 06 §6 待实测表「深度足迹与网格分辨率的对应：经验比 0.8~1.2」 |
| **三角形边长分布** | 全部三角形三边长的变异系数 `CV = σ/μ` | ≤ `post_regularize_cv_threshold`（快 0.55 / 标 0.45 / 高 0.35） | 06 §2.7 / 08 G8 |
| **最小内角分布** | 全部三角形最小内角 | P5 ≥ `post_regularize_min_angle_deg`（快 12° / 标 9° / 高 6°） | 06 §2.7 |
| **顶点数与面数比例** | 顶点 / 三角面 | ≥ **0.45** | 健康网格的经验比例；过低说明存在大量冗余顶点或退化三角形 |
| **分辨率一致性** | 同一用例的 `r` 在 fast / standard / high 三档间的比值 | ≈ 2 : 1 : 0.5（D=9/10/11） | 06 §1.3 的 `4^(D−10)` 关系 |

**分辨率阈值的量化体现**

| 档位 | 理论 `r`（L_max = 0.3 m, s = 1.1） | `h_ref` | 约束 | 实际要求 |
|---|---|---|---|---|
| fast（D=9） | 0.645 mm | RGBD: 4 mm；MONO: ~0.15 mm | RGBD 约束 `r ≤ 0.5 mm` → **不满足**（0.645 > 0.5） | ⚠️ 见下 |
| standard（D=10） | 0.322 mm | RGBD: 2 mm → `r ≤ 0.25 mm` → **不满足**；MONO: ~0.15 mm → `r ≤ 0.019 mm` → **不满足** | |
| high（D=11） | 0.161 mm | 同上 | **仍不满足** | |

> **口径澄清（重要）**：00 §4.6 的「泊松等效半径 ≤ 体素边长」在 06 §1.4 被解释为「`r_mesh = h_voxel / 8`」。而 06 §1.4 的对照表显示：在 `L_max = 0.3 m`、`h_voxel = 2 mm` 时，需要 `D = 11` 才能满足 `r ≤ h_voxel/8 = 0.25 mm`（`r = 0.161 mm`）；而 `D = 11` 时峰值内存 2.4 GB（06 §1.3）。
>
> **因此本项验收按两条独立规则执行**：
> 1. **「实际等效半径 ≤ 上限」**：实测等效半径（面积加权平均边长）≤ `h_ref / 8 × 1.2`（1.2 是 06 §6 的经验比上界）。
> 2. **「参数一致性」**：`recon_mesh_info.json` 的 `mesh_poisson_depth_effective` 与 `mesh_resolution_reference` 满足 06 §1.4 的推导关系，即推导正确；**不要求** `D` 一定等于推导值——若因内存走分块泊松（06 §1.7），`D` 可以更小但**分辨率 `r` 必须保持与全局一致**（06 §1.7 A2 的硬要求）。
>
> 换言之：**验收的是「分辨率 r」这个物理量，不是「D」这个参数**。D 只在 `mesh_poisson_depth_mode = from_voxel` 模式下被直接验收。

### 3.6 纹理指标

| 指标 | 方法 | 阈值 | 依据 |
|---|---|---|---|
| **UV 重叠率** | 逐像素统计被 ≥ 2 个三角形覆盖的图集像素占比（按 `post_uv_atlas_size` 分辨率栅格化） | ≤ **0.10%** | 06 §4.2 检查 11；重叠会导致烘焙渗染 |
| **UV 越界像素** | `u, v ∉ [0,1]`（容差 1e-4）的像素数 | **= 0** | 06 V7 |
| **UV 退化三角形占比** | 归一化 UV 面积 < 1e-8 的面占比 | ≤ **0.1%** | 06 V8 |
| **chart 覆盖率** | 被 chart 覆盖的图集面积 / 全图集面积 | ≥ **85%** | 未覆盖部分即「未烘焙区」 |
| **接缝数** | chart 边界（共享顶点数 ≥ 1 的不同 chart 对） | ≤ **chart 数 + 视锥边界数** | 超过说明 R1/R2 强制断边规则被违反（06 §2.8） |
| **接缝可见度** | 接缝带（宽 = `post_uv_gutter`）上的颜色梯度 | 邻接像素亮度差 P95 ≤ **6/255** | 06 §2.8 R5（过渡带取更靠近自身的图） |
| **未覆盖像素占比** | 权重和 < `post_bake_min_weight_sum` 的像素占比 | ≤ `post_tex_coverage_max_ratio`（快 0.5% / 标 0.2% / 高 0.05%） | 06 §2.10 |
| **高频能量** | `E_hf = Σ abs(Δ²I) / Σ abs(I)`（Laplacian 金字塔第 1 层） | ≥ `post_tex_hf_energy_min`（快 0.012 / 标 0.020 / 高 0.030） | 06 §2.10 |
| **色域裁剪占比** | 落在 [0,2] 与 [253,255] 的线性通道像素占比 | ≤ `post_tex_clipping_max_ratio`（快 2.0% / 标 1.0% / 高 0.5%） | 06 §2.10 |
| **色彩空间** | 输出图集 | **sRGB 8bit PNG** | 06 §2.10 / `post_tex_require_srgb` |
| **图集密度** | texel per screen px | ≥ `post_tex_density_min`（快 3.0 / 标 4.0 / 高 6.0） | 06 §2.10 |
| **纹理 PSNR** | 重建纹理 vs 参考纹理（合成数据有参考真值；真实数据用参考扫描的烘焙纹理） | ≥ **28 dB**（合成）/ ≥ **22 dB**（真实，T3）/ ≥ **18 dB**（真实，T2）/ 不考核（真实，T1/T0） | 需实测标定 |

**纹理 PSNR 的适用范围说明**

| 类别 | 是否考核 PSNR | 理由 |
|---|---|---|
| 合成数据 | ✅ | 渲染时即知真值纹理，可直接 PSNR |
| 真实 T3（强纹理） | ✅ | 纹理可辨识，PSNR 有意义 |
| 真实 T2 | ✅（放宽） | 部分区域不可辨 |
| 真实 T1 / T0 | ❌ | 弱纹理/镜面下 PSNR 不反映质量（过平滑反而会拉高 PSNR）。改用**高频能量下限**与**未覆盖像素上限**考核 |

> **诚实披露**：PSNR 在纹理任务中不是好指标（过平滑会提高 PSNR）。因此 PSNR 只是**上界检查**，真正的纹理质量判据是「高频能量 ≥ 下限」（防过平滑）与「未覆盖像素 ≤ 上限」（防漏烘焙）。这一组合是 06 §2.10 已定的口径，本文档只是把 PSNR 补为参考项。

#### 缺口 H 处置（IMU 比力语义，2026-10-31 第三十四轮实测）

**事实链**（三处独立证据指向同一结论）：

| 来源 | 原文 | 含义 |
|---|---|---|
| `core/include/recon/recon_c_api.h` 第 68 行 | `double accel[3]; /**< 加速度计，比力单位 m/s^2（含重力） */` | 跨边界约定 = **比力** |
| `docs/02_采集与同步.md` 第 563 行 | `a_m = R(a_W − g_W)`；`g_W = 9.80665` | 内核按「比力」使用，自行减重力 |
| `docs/11_平台权限与集成.md` 第 581 行 | `CMAccelerometerData.acceleration`（**已含重力**）→ `recon_imu_sample.accel`（**核心层减重力**） | 平台侧应传**含重力**值 |
| `ui/ios/.../Platform/CameraCapture.swift` 第 197-198 行 | `accel: SIMD3(dm.userAcceleration.x, ...)` | ❌ 实际传的是 **CoreMotion 已去重力**的值 |

**后果**：核心层按契约「再减一次重力」→ 静止时本应 ≈0 的加计残差变成 ≈ −9.81 m/s²
→ VIO 预积分（docs/02 §3.5）的 `Σ_a` 与残差被系统性偏置。**静默失效**（数值仍在
合法范围内，不触发任何范围检查）。

**两个可选修法（尚未最终裁决语义层面，但平台层已按 H-1 实施）**：

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| H-1（改 Swift 侧） | `CameraCapture` 改用 `dm.gravity + dm.userAcceleration` 合成含重力比力 | 不动 C ABI（已冻结）；与 docs/11 契约一致 | 需确认 `gravity + userAcceleration` 的数值精度等价于 `CMAccelerometerData.acceleration`；**真机验证未做** |
| H-2（改 C ABI 语义） | 把 `accel` 语义改为「去重力」，内核不再减重力 | 与 CoreMotion 原生输出一致 | **改 ABI 语义 = 破坏性变更**，Android 侧需同步；违反「C ABI 是冻结契约」 |

**当前实施状态（第三十四轮）**：平台层已按 **H-1** 实施 ——
`CameraCapture.startMotion()` 现在合成 `accelIncludingGravity = gravity + userAcceleration`，
并已删除那个「C ABI 根本不存在的 `gravity` 字段」写入。
代码引用：`ui/ios/Recon/Sources/Platform/CameraCapture.swift` 第 226–232 行。

**仍不擅自裁决的部分**：H-1 与 H-2 在**语义层面**各有合理依据；且本机无真机/无 macOS，
无法验证 `gravity + userAcceleration` 与 `CMAccelerometerData.acceleration` 的数值等价性
（CoreMotion 的 `gravity` 是融合估计值，非原始加计读数）。按项目铁律「发现两份契约
冲突时不擅自裁决，登记基线锁住现状」，此处保留 H-2 为备选并登记真机验证待办。
**必须声明：修复只到「按对接表口径合成比力」为止，数值等价性未经实测。**

>   另：`docs/04 §3.5.3` 的**完整重投影映射**（一般不同心情形 `R_cd/t_cd` 外参路径）
>   仍未接入 —— 当前只实现「同光心假设」下的内参换算，符合 ARKit/ARCore 路径；
> ⑦ 本轮全部验证均为**静态闸门 + 内核单测/CLI 实测**，**iOS 端未做真机或编译验证**
>   （无 macOS/Xcode），Swift 语法正确性仍只有静态闸门保障。
> ⑧ **M 的 Android 侧 JNI 薄封装已接线**（第三十六轮）：`imu-bridge.cpp`（JNI）+
>   `ImuRingBuffer.kt`（Kotlin 门面）已创建并**注册进根 CMakeLists 的
>   `recon_platform_android` target**；`CaptureActivity.startPreview()` 已接
>   `ImuRingBuffer.reset()`，IMU 订阅的接线点以注释登记。**但 Android 的
>   `SensorManager` 订阅本身仍未实现**，且因缺口 O（accel 口径未裁决）而
>   **刻意不写** —— 故「Android 的 IMU 采集链路」仍是**未开始**，不是"已经好使"。
>   深度换算**不需要** Android 侧 JNI：Android 深度是 `DEPTH16`（uint16 毫米），
>   不经 Float32→毫米换算（那是 iOS `ARFrame.sceneDepth` 路径专属）。
> ⑨ **M 的负向注入只覆盖了 iOS 重写切窗与 Android 重写换算两个方向**；
>   「Android 重写切窗」「iOS 重写换算」两个另外的方向未单独注入 —— 但判据是对
>   两端同源扫描的（`_scan_impl_leak` 对 `ui/ios/**/*.swift` 与 `android/**/*.kt`
>   各扫一遍），特征集相同，故覆盖无空洞。
> ⑩ **O 的 accel 口径未裁决**：Android 的 `SensorManager` 订阅在裁决前不实现，
>   故**当前没有任何重力处理被固化**。裁决需要真机实测（对比
>   `gravity + userAcceleration` 与 `TYPE_ACCELEROMETER` 的静止残差）——
>   本机无 Android 设备、无 NDK，**无法验证**。
> ⑪ **`imu-bridge.cpp` / `ImuRingBuffer.kt` / `CaptureActivity.kt` 均未经编译**：
>   本机无 Android SDK/NDK/JDK，Kotlin 与 JNI 的语法正确性**只有静态闸门保障**
>   （闸门 9 的声明↔实现闭合 + 源文件注册），**不是编译验证**。
>   已知待补判据：闸门 9 **不做参数类型/返回类型对账**（JNI 签名描述符未解析），

#### 5.1.2 平台适配层（第三十二轮，2026-10-31）

`platform/` 此前**为空目录**（0 文件）—— 最终交付形态要求的 iOS + Android 双端 App
一行代码都没有。第三十二轮起建立适配层，遵循「**平台无关逻辑下沉共享、平台专属实现各自薄封装**」：

| 层 | 位置 | 内容 | 可本机验证 |
|---|---|---|---|
| 平台无关（共享） | `platform/common/` | 采集状态机（docs/09 §4.1/§4.2 的 10 状态 + 30 条迁移） | ✅ `test_capture_state`（T-01..T-30 全覆盖） |
| Android 专属 | `platform/android/` | Gradle 工程 + `AndroidManifest.xml`（权限/零网络）+ JNI 桥（`native-lib.cpp`/`platform-bridge.cpp`）+ Kotlin（Activity/Service/Bridge） | ⚠️ 需 Android SDK/NDK r28b |
| iOS 专属 | `platform/ios/` | `Info.plist`（权限键）+ `PrivacyInfo.xcprivacy` + Swift（`ReconCore.swift`）+ ObjC++ 桥（`CaptureStateBridge.mm`） | ⚠️ 需 Xcode |
| 构建工具链 | `cmake/toolchains/android.cmake` | NDK r28 硬断言 + 16 KB 页对齐 + 隐藏可见性 | 部分（语法层） |
| 契约闸门 | `tools/check_platform_parity.py` | 双端对等：权限 / 零网络 / 状态机序号 / C ABI 调用面 | ✅ 任何机器 |

**关键设计决策**：采集状态机是**双端共享契约**（UI 层迁移规则），若在 Kotlin 与 Swift
各写一份必然漂移（铁律）。故以一份 C++ 实现（`capture_state.cpp`）承载，两端各以
JNI / ObjC++ 薄封装暴露 —— 序号与逻辑**同源**，由 `check_platform_parity` 锁死。

**诚实披露（未做）**：①平台专属采集（真实相机帧流、IMU 订阅、AR 会话）仍是**骨架**；
②双端构建**未在本机验证**（本机无 Android SDK/NDK、无 Xcode）；③状态机单测**不覆盖**
真实设备接入路径（那需要真机测试，见 docs/11 与 docs/14 §6）。

### 6.2 容差表

| 指标类别 | 指标 | 容差 | 理由 |
|---|---|---|---|
| **几何精度** | 对称面重投影中位数 / P95 | **+15% / −10%** | 精度类指标允许小幅波动，但劣化累积必须被发现 |
| | 点到面距离 中位数 / P95 / RMS | **+15% / −10%** | 同上 |
| | 平面平坦度 / 球面半径误差 | **+20% / −10%** | 绝对值小的指标用相对容差易失真，故用相对值但基数小 → 实际绝对容差极小 |
| **尺度** | 尺度相对误差 | **+20% / −10%**，且绝对值 ≤ 1.0% | 两条同时满足 |
| | 尺度重复性 | ≤ 0.5%（绝对阈值，不设相对容差） | 00 §4.6 绝对项 |
| **拓扑** | 非流形边数 | **= 0**（绝对，硬闸门） | 00 §4.6 |
| | 边界环数 | **参考观测**（不设绝对阈值，见 §3.4 口径修正） | §3.4 |
| | 孔洞面积占比 | **+20% / −10%**，且 ≤ 0.05% | 两条同时满足 |
| | 有向体积符号 | **> 0**（绝对） | 06 V4 |
| **分辨率** | 泊松等效半径 | **±8%** | 分块泊松的块边界会带来小波动（06 §1.7） |
| | 三角形边长 CV | **±15%** | 规整迭代的随机性 |
| | 网格分辨率一致性（fast:standard:high） | **±10%** | 06 §1.3 的 4^(D−10) 关系 |
| **纹理** | UV 重叠率 | **+30% / −10%**，且 ≤ 0.10% | xatlas 的打包有随机性 |
| | 纹理未覆盖像素占比 | **+25% / −10%**，且 ≤ 档位阈值 | 同上 |
| | 高频能量 | **−10% / +15%**，且 ≥ 档位阈值 | — |
| **计数** | 三角面数 / 顶点数 | **±8%** | 泊松与 xatlas 的输出有小幅波动 |
| **导出** | GLB 字节哈希 | **不比对哈希**（只比对结构与 V1–V17） | 二进制的字节级差异不代表质量下降 |
| **性能** | 各阶段耗时 | **+30% / −25%** | 见 §6.3 |
| | 峰值 RSS | **+20% / −15%** | 见 §6.3 |
| **跨平台容差** | 在非基线平台（macOS / Windows）上跑 | 上述容差 **× 3** | 12 §5 的 FP-1：浮点末位差异 |

**容差规则**

| 编号 | 规则 |
|---|---|
| TO-1 | **绝对阈值优先**。若基线在容差内但超绝对阈值 → 仍判 **fail** |
| TO-2 | 容差是**双向**的：劣化超上界 → fail；改善超下界 → 记 `IMPROVED`（不 fail，但要人工确认不是「跳过了某些步骤」） |
| TO-3 | 合成数据的容差取**绝对值**（如点到面中位数 ≤ 0.12 mm 且 ≤ 基线 + 0.02 mm），不用相对值（基数小，相对容差无意义） |
| TO-4 | 镜面 / 透明用例（`REAL-METAL-120` / `REAL-GLASS-90`）的几何精度**不比对基线**（T-3），只比对拓扑与绝对阈值 |

### 6.3 性能回归

**原则（与 12 §6.3 一致）**

> **性能回归不得因精度达标而豁免。**
> 精度与性能是**两条独立的门禁**：精度达标不豁免性能超差，性能优化不豁免精度不达标。

| 项 | 规格 |
|---|---|
| 采集的指标 | 各阶段耗时、总耗时、峰值 RSS、峰值显存、各阶段的关键帧数 / 视图数 |
| 基线 | `tests/golden/baseline/perf_baseline.json`（**独立文件**，与精度基线分离） |
| 基线环境 | 固定的 CI runner 规格（4 vCPU / 8 GB RAM / 无 GPU），不随 runner 池变化 |
| 测量次数 | 每条用例 `--repeat 3` 取**中位数**（去掉首次的冷启动） |
| 容差 | 耗时 +30% / −25%；峰值 RSS +20% / −15%；峰值显存 +20% |
| 超差处理 | ① 单次超差 → 记 `perf_regression` 告警，PR 需说明；② 连续 3 次超上界 → **阻断合并**；③ 涉及 `perf_*` 参数的改动 → 必须附性能对比数据 |
| 每日刷新 | 每日 CI 任务 13 产出新基线并提交到 `perf_baseline` 分支的 PR，人工 review 后合入 |
| 与精度的关系 | 性能基线的刷新**必须**同时验证精度基线仍全绿。若某次性能优化导致精度超差 → **拒绝该优化**（这正是「精度优先」的实现方式） |

### 6.5 失败的判定与处理

| 情形 | 判定 | 处理 |
|---|---|---|
| **绝对阈值不达标** | 硬失败 | 生成缺陷（§7），**不允许**「记录后放行」 |
| **基线超容差** | 硬失败 | 同上。但若基线本身已失效（`params_hash` 变更）→ 转为「基线需更新」任务，不算回归失败 |
| **性能超差（连续 3 次）** | 硬失败 | 阻断合并；要求提交性能对比 |
| **性能超差（单次）** | 告警 | PR 需说明 |
| **模糊测试崩溃** | 硬失败（P0） | 阻断 |
| **用例因环境原因跳过** | 不算失败 | 必须记录 `skipped: reason`；连续 3 次跳过 → 视为失败 |
| **真实物体数据集缺失或损坏** | 硬失败 | 数据集是验收基础；`checksums.sha256` 不匹配即视为损坏 |

## 7. 缺陷分级

### 7.1 分级定义

| 级别 | 定义 | 判定示例 |
|---|---|---|
| **P0** | **阻断发布**。违反 00 文档的核心契约，或产物不可用，或存在合规风险 | ① **精度不达标**：§3 任一绝对阈值不满足（几何 / 尺度 / 拓扑 / 分辨率 / 导出）<br>② **导出错误**：V1–V17 任一 fail，或 DCC 打开报错，或导出内容与重建结果不一致<br>③ **崩溃**：任何可复现的崩溃、死锁、越界写、数据损坏<br>④ **违反合规**：许可扫描命中 GPL/AGPL/LGPL、零网络检查命中网络符号/权限、隐私清单缺失<br>⑤ **静默降级**：`degradation_summary.blacklist_touched` 非空，或黑名单参数被自动改写（CT-9 失败）<br>⑥ **黑名单操作**：任何以降低精度换内存/速度/温度的实现被触发<br>⑦ **数据丢失**：已落盘的关键帧被丢弃或损坏<br>⑧ **尺度错误**：尺度相对误差 > 1.0%（或重复性 > 0.5%）在非受限场景下发生 |
| **P1** | **必须在下一个版本修复**。功能异常但不阻断主流程，或非核心指标劣化 | ① 非绝对阈值的指标劣化超基线容差<br>② 功能异常（标定失败无法重试、导出路径错误、UI 状态文字与实际不符）<br>③ 性能连续超差<br>④ 模糊测试未捕获异常（应转为明确错误码）<br>⑤ 覆盖度统计、优先级标注等辅助功能错误（不影响几何） |
| **P2** | **可延后修复**。体验类、文档类、边缘情况 | ① 文案措辞、字号、间距类问题<br>② 低概率边缘情况（非默认配置、非主流机型）<br>③ 工具脚本的参数缺失<br>④ 文档不一致 |

**「非受限场景」的界定**：镜面 / 透明物体（00 §4.5.5 的物理限制）、弱纹理且用户未补光、底面未扫描、深度温漂超预算、参照物被遮挡或反光。出现这些场景的用例，其精度不达标**不判 P0**，但必须：

| 要求 | 内容 |
|---|---|
| 场景标注 | 用例报告中明确标注受限原因 |
| UI 标注 | `recon_mesh_info.json` 的 `unreliable_regions` / `bottom_face_source` 正确记录（03 §4.7.4 BS-1） |
| 用户告知 | UI 必须如实呈现（09 文档的能力说明） |
| 统计隔离 | 不计入总体合格率（§3.1 T-3） |

> **判定纪律**：P0/P1 的区分不得用于「降级处理」困难场景。困难场景的正确处置是**如实标注**，不是降级缺陷级别。

### 7.2 响应时限

| 级别 | 响应时限（从缺陷确认起） | 修复时限 | 临时缓解 | 发布策略 |
|---|---|---|---|---|
| **P0** | **4 小时**（工作时间内） | **24 小时** 提交修复 + **72 小时** 内发布热修 | 若无法修复：**立即停止分发 / Halt rollout**（12 §7.2 R-1） | 阻断发布；已发布则必须回滚或热修 |
| **P1** | **1 个工作日** | **下一个版本**（≤ 2 周） | 可用参数规避时，在文档中给出规避参数 | 不阻断发布，但需在发布说明中列出 |
| **P2** | **3 个工作日** | 后续版本（≤ 1 个月） | 无 | 不阻断发布 |

| 编号 | 规则 |
|---|---|
| D-1 | P0 的响应时限从**缺陷被 CI 或测试确认**的时刻起算，不从「被研发看到」起算 |
| D-2 | P0 若在 24 小时内无法修复，**必须**评估「停止分发」的成本。合规类 P0（许可 / 零网络）**无条件停止分发**，不做成本权衡 |
| D-3 | P0 的修复必须走**完整 CI**（12 §6.5 的 12 个前置任务），不得跳过 |
| D-4 | P0 的热修版本号：App 版本 PATCH +1；管线版本 PATCH +1（若涉及 core）；`RECON_ABI_VERSION` 不变（除非 ABI 确实变更） |
| D-5 | 每个 P0 关闭时必须补一条回归用例（进黄金数据集或单测），并在缺陷单中记录用例 ID |
| D-6 | P0/P1 的复现步骤必须包含：设备型号、OS 版本、App 版本、管线版本、参数档、数据集 ID 或最小复现数据集 |
| D-7 | 每周评审 P2 的积压量；连续 3 个版本未修复的 P2 升级为 P1 |
